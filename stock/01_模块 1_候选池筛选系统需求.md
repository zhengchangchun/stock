# 01_模块1_候选池筛选系统需求.md
## 模块定位
对标的做前置排雷、多因子打分，输出【短期 / 中期 / 长期】候选观察池；
所有行业经济学公式、财务因子、打分逻辑放在插桩脚本；主流程固定不变。

## 主流程（固定，不可修改）
1. 任务启动
2. 拉取标准化输入数据
3. 【固定前置通用排雷】硬性过滤暴雷标的
4. 调用插桩0：行业特殊排雷脚本
5. 过滤不通过标的，写入淘汰库，记录淘汰原因
6. 候选池分流路由：短期 / 中期 / 长期三条分支
7. 分别执行插桩1(短期打分)、插桩2(中期基本面景气打分)、插桩3(长期护城河打分)
8. 调用插桩4：风险权重修正脚本
9. 候选池入库管理，写入固定字段；更新标的状态
10. 保存候选池快照
11. 输出Markdown候选池报告
12. 判断是否触发AI优化子任务；触发则执行AI优化流程

## 插桩钩子清单（AI可动态修改，沙盒运行）
|插桩编号|名称|用途|输出约定结构体|
|---|---|---|---|
|0|行业特殊排雷脚本|行业专属风险过滤|pass_flag:bool, risk_note:[]|
|1|短期因子打分脚本|短期池：量价、资金、板块、事件因子|score[0‑100], pass_flag, reason, risk_list[]|
|2|中期景气&财务打分脚本|中期池，存放杜邦、库存系数、毛利率弹性等行业数学公式|score[0‑100], pass_flag, reason, risk_list[]|
|3|长期护城河打分脚本|长期池：ROE、自由现金流、竞争力打分|score[0‑100], pass_flag, reason, risk_list[]|
|4|风险权重修正脚本|对打分结果做风险加权扣减|final_score, risk_out[]|
|5|定期复盘分析脚本|AI优化子任务内部，计算因子胜率、回测指标|analysis_result, bad_case_list[]|

> **插桩5 现状（2026-09-21 核对）**：契约（`plugin/contract.py`）与 `plugin_scripts` 记录（v1.0.0）都在，**但调用点尚未接线**——`candidate run` 只走插桩 0/1/2/3/4，插桩5 目前只有 CLI 能调用。属「已定义未接线」，**不要当成已完成**。

## 存储
1. 插桩脚本版本库：id、版本号、插桩ID、脚本文本、创建时间、回测报告id、状态【线上/归档】
   > **澄清（D-3）**：实现里「状态」**不是列**——`plugin_scripts` 只有 id/plugin_id/version/源码/sha256/created_at，状态由 `plugin_audit` 事件流**折叠得出**（`draft/pending_review/rejected/active/archived`）。可查不可写；脚本行本身 append-only（禁止 UPDATE/DELETE，有触发器）。
2. 候选池快照库：每次运行完整候选池快照
3. 回测结果库：各脚本版本历史回测数据
4. 淘汰标的库：淘汰标的、淘汰原因

## AI优化子流程（主流程固定）
1. 读取历史快照、回测数据；同时接收模块2回流错判案例
2. AI分析因子有效性、错判案例
3. **产出**新版本插桩脚本 → ⚠️ **澄清（D-1）**：此步由**外部编码 agent + 人工**完成，系统内不实现自动生成；系统只负责收下这一版并跑 4/5/6
4. 沙盒环境执行新版本脚本，新旧版本对比回测 → ✅ **已实现**：`plugin sandbox`（ADR-017：以**调仓周期**为观测单元 / 70-30 时序切分 / **120 周期**门槛 / bootstrap CI / 基准 `index_300`）
5. 输出回测报告，标记过拟合风险 → ✅ 已实现：报告含 `overfit_flag`（`train − validate > 阈值` → `'suspected'`）。**它是「标记」，不是「拦截」**，不阻断流程
6. 人工审核；通过则切换线上版本，归档旧版本；驳回则丢弃新版本 → ✅ **已实现**：`approve` 只能人工 CLI（被源码扫描测试钉住）；**回滚 = 对 `archived` 版再 `approve`**，没有独立命令

## 候选池标的状态枚举
观察中 / 等待买点 / 已建仓 / 逻辑证伪移出

## 候选池数量建议
短期池：3‑6只；中期池：4‑8只；长期池：3‑5只；一只标的可同时入多个池子。
