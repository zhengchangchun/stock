**SEED_UNIVERSE（21 只）**：17 只个股 + 4 只 ETF，跨 10 个行业；**DEFAULT_UNIVERSE（6 只）**是行情采集的子集（仅美的、海尔 + 4 只 ETF），财报采集覆盖全部 17 只个股。

### 1.2 采集纪律

1. **白名单**：出网请求在 `ALLOWED_HOSTS`（精确匹配，无子域通配）内校验，IP 直连被拒。当前白名单：`qt.gtimg.cn`、`web.ifzq.gtimg.cn`、`push2.eastmoney.com`、`push2his.eastmoney.com`、`datacenter-web.eastmoney.com`、`vip.stock.finance.sina.com.cn`、`www.sse.com.cn`。
2. **raw_cache**：响应体落 `data/raw_cache/`，键含请求锚点（`end` 日 / `params_key`），当日时效（ADR-009）。盘中快照不进正式缓存。
3. **幂等**：所有写库入口以 `PRIMARY KEY + ON CONFLICT DO NOTHING` 或 `ON CONFLICT DO UPDATE` 实现幂等，重跑不重写。
4. **PIT**：`bars_daily.date`、`valuation_daily.date`、`money_flow_daily.date`、`financial_reports.notice_date` 均为 PIT 键；下游只允许读 `<pit_key> <= :asof`（ADR-011 D-01、ADR-016 D-01）。
5. **分页 fail-closed**：解析失败 / 非合法 JSON → 抛 `FetchError`，整批不落库；单标的失败记 `system_events` error 并计入 `failed`，不拖垮其它标的。
6. **空响应 = 合法空**：ETF 无财报（`ingest financials` 返回 0 期，不是错误）；ETF 无估值（源站返回空集，写 `system_events` warn 留痕）。

## 2. 组件二：脏数据校验

校验模块位于 `stocklab/quality/checks.py`（`check_bars`）。**原则：只报告、不修复。** 修复必须在抓取层显式完成并留痕，否则「悄悄改过的数据」比「明显错的数据」更危险。Issue 是 frozen dataclass，严重度：`error`（硬错误，调用方不得落库） / `warn`（可疑） / `info`（正常现象）。

### 2.1 已覆盖（行情）

| 规则 ID | 说明 |
|---|---|
| C1 OHLC 一致性 | `high >= max(open,close)` 且 `low <= min(open,close)`，任一价 ≤ 0 → error |
| C2 成交量 | 负量 → error；零量 → info（停牌正常） |
| C3 量额一致性 | `amount ≈ close × volume`（允差 ±1%）；偏差 > 1% → error，专门捕「手 / 万元单位错」 |
| C4 重复日期 | 同标的同日期出现两次 → error |
| C5 日历缺口 | 有交易日历时，相邻 bar 跨超过 1 个非休市日 → warn |

### 2.2 本轮新增（会计恒等式勾稽与量级检查）

`ingest financials` 落库前检查（见 `stocklab/data/ingest.py`）：

| 规则 | 条件 | 处理 |
|---|---|---|
| 会计恒等式 | `|资产 − 负债 − 权益| / 资产 ≥ 1e-6` | 记 issue（warn），**不拒写** |
| 总资产量级 | `total_assets` 超出 `[1e8, 1e14]` 范围 | 记 issue（warn），不拒写 |

注：不拒写的理由是「留痕不丢数据」——会计恒等式微偏通常是报表口径差异（如 TOTAL_EQUITY 字段是合计而非归母），是已知的结构性偏差，不是抓取错误，拒写会丢掉本来正确的数字行。

### 2.3 未覆盖（显式记账）

- 财报深度校验：营收/利润异常增长率、应收账款周转天数的跨期一致性
- 公告一致性：同一报告期的年度报告与更正公告之间的差异审计
- 审计意见类型（非标注记）：尚无数据来源
- **TOTAL_EQUITY 口径**（已定性，不再是「探针」）：DMSK 的 `TOTAL_EQUITY` 是**总资产 − 总负债，含少数股东权益**，**不是归母权益**；归母权益只在 F10 的 `TOTAL_PARENT_EQUITY`。后果：`roe` 与 `dupont` 口径打架且不报错。处置见 `docs/plans/2026-09-20-财报数据层设计评审.md` §E（新增 `parent_equity` 列、两个指标统一口径）。实现上仍保留 warn、不拒写。

## 3. 组件三：成本仿真

### 3.1 实现位置

`stocklab/config/costs.py::CostModel`（ADR-008）。已在生产中使用，**本节引用该实现，不重新规定**。

### 3.2 口径摘要

（摘自 ADR-008 与 `CostModel` 文档字符串）

| 项目 | 股票（`stock`） | 场内 ETF（`etf`） |
|---|---|---|
| 佣金 | 0.025%，双边 | 0.025%，双边（相同） |
| 最低佣金 | 5 元 / 笔 | 5 元 / 笔（相同） |
| 印花税（仅卖出） | 0.05%（财税法定） | **0**（场内 ETF 暂免） |
| 过户费（双边） | 0.001%（股票过户登记） | 0（建模约定，ETF 不走股票过户登记） |
| 滑点 | 5 bps，买入上滑 / 卖出下滑 | 5 bps（相同） |

`asset_class` 未知时**抛 `ValueError`**，不静默退化成股票费率（口径错是静默错误，代价是「回测看着更好」）。

## 4. 组件四：过拟合**标记**（不是拦截）

> **2026-09-21 订正**：本节此前写的是「stub / 未实现 / 没有代码层面的过拟合检测」，那是 09-20 之前的状态。09-20 已落地真回放，本节按现状重写（改动留痕见 `docs/plans/2026-09-21-需求澄清录.md` D-2）。

### 4.1 现状：**已实现**（ADR-017）

| 器件 | 位置 | 现状 |
|---|---|---|
| 回放引擎 | `stocklab/candidate/replay.py` | **真回放**：以**调仓周期**为观测单元；等权、持到下个调仓日、空池持现金（但计清仓成本）、扣成本、涨跌停不可成交 |
| 切分与判定 | `stocklab/plugin/sandbox.py` | 训练/验证按**周期序号 70/30** 切分；Δ 序列 bootstrap 95% CI；**有效周期 < 120 → `INCONCLUSIVE`** |
| 过拟合标记 | `sandbox.overfit_flag(train_mean, validate_mean)` | **真逻辑**：`train_mean − validate_mean > 阈值` → `'suspected'`；方向固定，只标「训练段更好」 |
| CLI | `stocklab/cli/plugin.py`（`plugin sandbox`） | 已接真回放；报告含相对 `index_300` 的超额与 `script_id` |

**关键限定：它是「标记」，不是「拦截」。** `'suspected'` 只写进报告、建议人工复查，**不阻断任何流程**（没有自动拒绝、没有自动回退）。

### 4.2 红线（CLAUDE.md《反过拟合红线》四条）—— 靠纪律 + 标记，仍未代码化

1. ❌ 全样本调参后再报全样本成绩
2. ❌ 因为某几天表现差就把样本删掉
3. ❌ 参数搜索越过 walk-forward 训练窗
4. ❌ 用「市场噪声」当万能解释（该结论必须有数据支撑，不是甩锅）

这四条**没有一条被代码强制**：`overfit_flag` 只覆盖第 1 条的形态之一，且仅是**标记**。所以本期仍是「纪律为主、标记为辅」；等 walk-forward 管道与足够样本（≥120 个调仓周期）齐备后，再考虑代码化。

## 5. 数据边界

只采**公开可采集**数据（东财 / 腾讯 / 新浪 / 上交所）。

依赖内部材料（调研纪要 / 渠道库存 / 订单能见度 / 管理层指引）的判断**一概不做**，因此本系统**不掌握信息优势**。

系统能做的事：在公开数据上更快、更一致、不受情绪干扰地执行已定义的规则。它**不能做**的事：预测市场参与者基于非公开信息的行为。

这个边界是已知约束，不是 bug，不需要绕过。
