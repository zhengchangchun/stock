P0 = 模块1（候选池筛选）与模块2（模拟人工交易闭环）共用的**地基**；不实现任何策略逻辑。

本文档描述四个横切组件的**当前现状**（已实现的是什么、边界在哪里、哪些尚未实现），而不是愿景列表。

### 1.2 采集纪律

1. **白名单**：出网请求在 `ALLOWED_HOSTS`（**精确匹配**，无子域通配；IP 直连被拒）内校验。当前 **11** 个 host：`qt.gtimg.cn`、`web.ifzq.gtimg.cn`、`push2.eastmoney.com`、`push2his.eastmoney.com`、`datacenter-web.eastmoney.com`、`vip.stock.finance.sina.com.cn`、`www.sse.com.cn`、`fund.eastmoney.com`、`ifzq.gtimg.cn`、`proxy.finance.qq.com`、`np-anotice-stock.eastmoney.com`（后 3 个是 P74a 的 K 线镜像 ＋ P88 的公告源；扩白名单必须留痕，断言是**精确相等**，见 ADR-028）。
2. **raw_cache**：响应体落 `data/raw_cache/`，键含请求锚点（`end` 日 / `params_key`），当日时效（ADR-009）。盘中快照不进正式缓存。
3. **幂等**：所有写库入口以 `PRIMARY KEY + ON CONFLICT DO NOTHING` 或 `ON CONFLICT DO UPDATE` 实现幂等，重跑不重写。
4. **PIT**：`bars_daily.date`、`valuation_daily.date`、`money_flow_daily.date`、`announcements.notice_date`、`financial_reports.notice_date` 均为 PIT 键；下游只允许读 `<pit_key> <= :asof`（ADR-011 D-01、ADR-016 D-01、P88 D2）。
5. **分页 fail-closed ＋ per-code 容错**：解析失败 / 非合法 JSON → 抛 `FetchError`，整批不落库；单标的失败记 `system_events` error 并计入 `failed`、**不拖垮其它标的**（P75 把 `UnpriceableTerms` 收成 `AdjustError` 子类、P76 把 ETF 的 `EtfChainUnsupported` 归为 `skipped`，两者都 `continue`）。
6. **空响应 = 合法空**：ETF 无财报（`ingest financials` 返回 0 期，不是错误）；ETF 无估值（空集，写 `system_events` warn 留痕）。
7. **K 线镜像回退（P74a）**：`web.ifzq.gtimg.cn` 被腾讯 WAF 拦成 HTTP 501 时，按 `KLINE_URLS` 顺序回退 `ifzq.gtimg.cn` → `proxy.finance.qq.com`（同载荷响应体逐字节相同）；4xx（≠429）与非白名单**不换 host**，全失败才抛聚合并点名三台 host。
8. **瞬时故障重试（P100，ADR-046）**：`ops close` / `ops monthly` 里**只有 `ingest *` 步**声明可重试（`CLOSE_RETRY_PLAN` / `MONTHLY_RETRY_PLAN`）：3 次尝试、15 s 退避；缺省 `retry_plan=None` ⇒ **零行为变化**；重试过会在回执里留下 `retried_steps`。日历未前滚时回执点名 `calendar_not_forward_rolled`。**这条救不了「DNS 连续挂 >30 s」**——那时链照旧如实报红。

## 2. 组件二：脏数据校验

校验分两处：**行情**在 `stocklab/quality/checks.py`（`check_bars` / `check_quote`），**财报**在 `stocklab/data/ingest.py`。**原则：只报告、不修复。** 修复必须在抓取层显式完成并留痕，否则「悄悄改过的数据」比「明显错的数据」更危险。Issue 是 frozen dataclass，严重度：`error`（硬错误，调用方不得落库）/ `warn`（可疑）/ `info`（正常现象）。

### 2.1 已覆盖（行情，`quality/checks.py`）

| issue_type | 严重度 | 说明 |
|---|---|---|
| `non_positive_price` | error | 任一价 ≤ 0 |
| `ohlc_inconsistent` | error | `high >= max(open,close)` 且 `low <= min(open,close)` 不成立 |
| `amount_volume_mismatch` | error | `amount ≈ close × volume` 允差 ±1%，专捕「手 / 万元单位错」 |
| `negative_volume` | error | 负量 |
| `zero_volume` | info | 停牌正常 |
| `duplicate_date` | error | 同标的同日期出现两次 |
| `dates_not_increasing` | error | 日期非递增 |
| `calendar_gap` | warn | 有交易日历时，相邻 bar 跨超过 1 个非休市日 |

真库 `data_quality` 现存 **43 行** `ohlc_inconsistent`（全部 error，多为 2009 年前后的深市源站脏行）——质量闸门**整批拒写**，不是「悄悄改过」。

### 2.2 财报勾稽与量级检查（`data/ingest.py`）

| 规则 | 条件 | 处理 |
|---|---|---|
| 会计恒等式 | `|资产 − 负债 − 权益| / 资产 ≥ 1e-6` | 记 issue（warn），**不拒写** |
| 总资产量级 | `total_assets` 超出 `[1e8, 1e14]` | 记 issue（warn），不拒写 |
| 公告日质检 | `notice_date` 缺 / 非法 | 记 issue；`notice_date_source` 落 `f10` 或 `statutory` 区分来源 |

注：不拒写的理由是「留痕不丢数据」——会计恒等式微偏通常是报表口径差异（如 `TOTAL_EQUITY` 是合计而非归母），是已知结构性偏差，不是抓取错误。

### 2.3 未覆盖 / 已消项

- **已消项（P53 落地）**：`TOTAL_EQUITY` 口径问题已处置 —— `financial_reports` 已新增 **`parent_equity`** 列与 **`notice_date_source`** 列（公告日改取 F10，取不到回退法定披露截止日）。旧版本文里「两指标口径打架且不报错」的定性仍成立，但**承载字段已经有了**，不再是「建议项」。
- 仍未覆盖：财报深度校验（营收/利润异常增长率、应收账款周转天数跨期一致性）、公告一致性（同一报告期年报与更正公告的差异审计）、审计意见类型（无数据来源）。

## 4. 组件四：过拟合**标记**（不是拦截）

### 4.1 现状：**已实现**（ADR-017）

| 器件 | 位置 | 现状 |
|---|---|---|
| 回放引擎 | `stocklab/candidate/replay.py` | **真回放**：以**调仓周期**为观测单元；等权、持到下个调仓日、空池持现金（但计清仓成本）、扣成本、涨跌停不可成交；**价格口径默认 PIT 复权价**（P94；`--price-mode raw|adj|both`） |
| 切分与判定 | `stocklab/plugin/sandbox.py` | 训练/验证按**周期序号 70/30** 切分；Δ 序列 bootstrap 95% CI；**有效周期 < 120 → `INCONCLUSIVE`** |
| 过拟合标记 | `sandbox.overfit_flag(train_mean, validate_mean)` | **真逻辑**：`train_mean − validate_mean > 阈值` → `'suspected'`；方向固定，只标「训练段更好」 |
| CLI | `stocklab/cli/plugin.py`（`plugin sandbox`） | 已接真回放；报告含相对 `index_300` 的超额与 `script_id` |

**关键限定：它是「标记」，不是「拦截」。** `'suspected'` 只写进报告、建议人工复查，**不阻断任何流程**（没有自动拒绝、没有自动回退）。

### 4.2 研究侧的**度量**（不是标记，也不出信号）

`research` 组（P78/P83/P82，**离线只读：不写任何表、不进 `ops close`、不进红线基线**）：

| 命令 | 作用 |
|---|---|
| `research xsec-topn` | 横截面单变量：持有集合「前 N」vs「池内全部合格」的 Δ 与 95% CI（需 `--prereg`，fail-closed） |
| `research rank-ic` | 信号有效性：逐调仓日 rank IC ＋ 分 5 层前向收益（**不出任何信号**） |
| `research factor-ic` | 因子级 IC 分解：把短池打分的**输入因子**逐个算 rank IC ＋ 裁剪诊断（P97 起支持 `--factor` 升格为主读数） |

### 4.3 红线（CLAUDE.md《反过拟合红线》四条）—— 靠纪律 + 标记，仍未代码化

1. ❌ 全样本调参后再报全样本成绩
2. ❌ 因为某几天表现差就把样本删掉
3. ❌ 参数搜索越过 walk-forward 训练窗
4. ❌ 用「市场噪声」当万能解释（该结论必须有数据支撑，不是甩锅）

这四条**没有一条被代码强制**：`overfit_flag` 只覆盖第 1 条的形态之一，且仅是**标记**。所以仍是「纪律为主、标记为辅」。

## 5. 数据边界

只采**公开可采集**数据（东财 / 腾讯 / 新浪 / 上交所）。

依赖内部材料（调研纪要 / 渠道库存 / 订单能见度 / 管理层指引）的判断**一概不做**，因此本系统**不掌握信息优势**。

系统能做的事：在公开数据上更快、更一致、不受情绪干扰地执行已定义的规则。它**不能做**的事：预测市场参与者基于非公开信息的行为。

这个边界是已知约束，不是 bug，不需要绕过。
