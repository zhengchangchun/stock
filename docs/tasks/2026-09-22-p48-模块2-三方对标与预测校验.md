## 1. 三方对标口径（唯一真源）

| 方 | 账户/数据 | 说明 |
|---|---|---|
| ① AI 模拟 | `arm-agent-<策略版本>`（**每个版本一行**，D-26） | 通路 A 的账户（P47/ADR-025）；没有版本就没有这一方，**不许拿别的账户顶替** |
| ② 人工镜像 | `arm-now` | 通路 B 的镜像账户（D-25）；它就是「我的实盘账本镜像」 |
| ③ 市场基准 | `sh000300`（`bars_daily`，指数口径 `adj_mode='none'`） | 指数**不可直接交易、无成本** ⇒ 与各臂比时口径偏乐观，**必须标注** |

**硬判据：**

1. **指标必须与 P41 绩效指标集同源**：五指标（名字与顺序见 ADR-023）与门禁（120 交易日）
   **复用既有实现**，不得在 `m2/` 或 `labweb/` 里平行实现第二套（源码扫描钉死 + 反向自检）。
2. **门禁与措辞纪律**：样本 <120 ⇒ `insufficient`，**只给读数**；
   逐词禁「跑赢/跑输/优于/劣于/领先/胜过」（沿用 ADR-023 的禁词表，页面文本也要过这条断言）。
3. **基准范围（本轮拍板，见澄清录 §8.3 D-43）**：
   - `sh000300` **必做**；
   - `sh000905`（中证500）**只在能证明「用既有采集路径落进 `bars_daily`、同一 `adj_mode='none'` 口径」时**才加
     （同一取数路径 + 同一指标函数）；
   - 拿不到 ⇒ **明文写「本轮只对沪深300」并说明代价**（哪个需求条未满足、要什么前置条件）。
     ❌ 不许换别的口径凑数、不许悄悄少一个基准。
4. **口径分工（D-30）**：模块1 只出「插桩版本对比相对 `index_300` 的超额」（`candidate/replay.py`
   已实现，`BENCHMARK_CODE='sh000300'`）；**模块2 才做三方对标**。两处不得混用、
   **不得出现两套「跑赢沪深300」**（发现第二套即上报，不许自己加一套「超额」新指标）。

## 2. 预测-验证校验（A3/B1 的五件读数）

**对象** = `m2_forecasts`（D-39：模块2 的预测**不进** `predictions`）。

**产物不许写回** `predictions` / `verifications`（后者的 `pred_id` 是外键，混进去会把插桩预测
卷进「模型准确率」统计 —— D-30 的口径分工）。

五件读数（需求书 §3 点名，逐件都要有）：

| # | 读数 | 口径要求 |
|---|---|---|
| 1 | **胜率**（方向命中率） | 命中定义必须与 `verify/` 的**方向判据逐位一致**（同一套「涨/平/跌」与 `FLAT_BAND` 阈值）；用**对拍测试**钉住（同输入同结果），不得另立定义 |
| 2 | **收益偏差分布** | `预测区间/关键位 vs 实际` 的偏差分布，按分位给（不要只给均值）；空样本 ⇒ 「无」不写 0 |
| 3 | **盈亏比** | 复用 P41/`backtest/metrics.py::profit_loss_ratio` 的既有语义（只有赢或只有输 ⇒ `None`）；**不许另写算法** |
| 4 | **最大回撤** | 复用既有净值/回撤实现（`paper/engine.py::drawdown`），不得另写 |
| 5 | **错判案例集** | 列出「方向错」的样本（`input_sha256` / 预测 / 实际 / `script_version`）；**归因字段恒空**（D-31：禁自动填充，人工确认是 P50 的事）；必须显示**样本总量**与**条数上限**，且**没有「挑好看的/最有利的」筛选参数**（要列就按时间倒序取最近 N 条） |

**落库判据（本轮拍板）**：校验结果**必须落库**（新表 `m2_forecast_scores`，append-only + 触发器），
不许「页面实时算不落库」——否则「当时的分数」不可复现，下一轮换口径后读到的就不是当时那个数
（错误日记 #36/#59 同型）。幂等键 = 一条预测一行分数；改口径 = 升 `script_version`，不覆盖历史行。

**分版本纪律（D-38 同型）**：所有读数按 `plugin_id` + `script_version` **分列**，
两版**不许相加、不许求平均**（并页面上写明这一点）。

**样本门禁**：A3/B1 的已评分预测对 <120 ⇒ 同样判 `insufficient`、同样禁结论文案。

## 3. 页面与报告

- 新页面 **`/lab/m2`**（导航「模块2」），三块：① 三方对标表 ② 预测校验读数 ③ 错判案例（折叠）。
- **同源**：页面与 `paper metrics` / 报告用**同一个取数函数**，页面**不重算**（判据同 P51 T6）。
- **只读**：页面不提供任何写入口（含「触发校验」按钮）；校验由 CLI 触发
  （`m2 score --asof <day>` 之类，具体名字由实现定，写进任务书进度表）。
- 缺数据 / 未跑过 ⇒ 写「无」+ 原因，**不写 0**（沿用既有纪律）。
