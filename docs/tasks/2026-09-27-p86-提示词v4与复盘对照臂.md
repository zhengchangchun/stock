## 0. 背景

### 0.1 一句话

用户 2026-09-26 要求 AI 操盘手具备「**不断分析市场、复盘总结自己**」的能力。
P84 把「市场状态 ＋ 自己的历史」写进了 PIT 上下文；P85 建好了 `paper_agent_reviews` 台账、
证据指针硬校验与 `facts` 回注。**P86 是把这两半接起来并用对照臂证明它有没有用**：

- 提示词 **v4 = v3 ＋「先复盘再决策」**（`tools/stock/prompts/trader-v4.txt`，已写好）；
- 生成器多一步：把模型同一次回答里的 `review` 拆出来，先落 `paper agent review`，再落 `paper agent decide`；
- 开 **新臂 `arm-agent-ds-v4`**（换提示词＝换口径 ⇒ 必须新账户，D-48）；
- 对照：**同模型、同池、同交易日，唯一差别＝有无复盘** ⇒ `arm-agent-ds-v3` 继续跑作对照臂。

### 0.5 锁定口径（G1–G6；要改先回来说）

- **G1 提示词 v4 与 v3 的关系**：v4 是 **v3 的超集** —— 除「先复盘」这一段与输出格式多了
  `review` 键之外，**决策部分的每一句措辞与 v3 逐字相同**。理由：对照臂只能有一个自变量。
  核对方式＝`diff <(去掉 v4 的复盘段) trader-v3.txt`，差异只许出现在 v4 顶部说明、
  「第一步：复盘」整节、`怎么想` 第 1 步、`输出格式` 一节。
- **G2 一次调用、两个产物**：模型**一次**回答里同时给 `review` 与 `decisions`/`cash_pct`/`rationale`。
  不拆成两次调用（那会引入第二个自变量：上下文与温度都变了）。
- **G3 写库顺序与失败策略**：`review` 先写、`decide` 后写。**复盘失败不阻断决策** ——
  `paper agent review` 非 0 退出时记 `review_written=false` ＋ 原因进回执，继续走 `decide`；
  **`decide` 失败则该日整条链失败**（与现状一致）。两件事都写进回执 JSON。
- **G4 幂等/重放**：`paper agent review` 撞 `(arm, asof, kind)` ⇒ exit 1 且零写入 ⇒ 生成器
  **视为成功**（「今天已经复盘过」），继续 `decide`；不许改写历史。
- **G5 兼容**：生成器必须同时支持 v3 输出（没有 `review` 键 ⇒ 跳过复盘步）。
  `--arm` 决定用哪套 prompt 与哪条臂；v3 臂的既有行为**逐位不变**。
- **G6 对照口径**：`arm-agent-ds-v3`（无复盘）与 `arm-agent-ds-v4`（有复盘）**同日各跑一次**，
  同模型 `deepseek/deepseek-v4-pro`、同池、同 `--asof`。两个差异面分开记账：
  ① **提示词要求复盘**（当日生效）；② **复盘回注上下文**（`recent_reviews`/`facts` 随样本累积才出现）。
  在样本 < 120 交易日之前，**任何「v4 更好/更差」的结论都不成立**（与 O9 同一条纪律）。

## 4. 未决与风险（先记账，不实现）

1. **复盘失败的连续性**：G3 让「复盘坏一天」不阻断决策，代价是该日 `facts` 样本缺一条。
   若连续多日失败，应在页面上可见（P85 的 `paper agent reviews` 只读列表面板）—— 由 nanobot 盯。
2. **两个差异面**：`recent_reviews`/`facts` 一进上下文，`decision_context_sha256` 就会**每天不同**，
   与「同输入同输出」的可复现性口径的关系：可复现的是「同一天同上下文 ⇒ 同输出」，
   不是「跨天同输出」。**这一点必须在预注册里写清**，免得以后把「sha 天天变」误读成异常。
3. **v4 的 token 增量**：复盘段会让输出变长（多出 items/lessons），网关预算与
   `MAX_TOKENS` 需实测一次（若撞上限则只加预算、不改口径）。
   → **已实测**（§7.4）：真模型一轮 total **11,470** tokens、**未撞**上限、无截断。

### 7.3 演练暴露并修掉的真 bug（当日重放的上下文自指）

同日重放时，第一次 ⑥ 写下的**当日净值行**会改变同一天的上下文（`own_history` 的净值/成交窗口按 P84
是 `date <= asof`）⇒ `context_sha256` 变 ⇒ `decide` 报「已经有一行决定」exit 1 ⇒ 旧码按失败处理、
修复轮再撞一次 ⇒ **rc=3 且回执根本不落盘**。修法：新增 `decision_settled` 判定（`decide` exit 1
且 stderr 含「已经有一行决定」⇒ 该日判 settled、沿用既有行、继续 ⑥、照常产回执），⑤ 日志分
「已写入」/「沿用既有行」两句，判据改为「G4 生成器退出码 0（该日已 settled，重放不染红）」＋
新增「G4 回执落盘」。

配套的口径修正（**这一条是 P86 触发的 P85 收口**）：`own_history` 的**复盘窗口＝`asof < 决策日`**
（`_iter_reviews`/`load_reviews`/`derive_facts` 加 `strict: bool = False`，`own_history.py` 传
`strict=True`；`paper agent reviews` / `facts` 列出口不传 strict、仍按 `<=` 陈列）。理由：生成器要
**先写当天复盘、再写当天决策**，若当天复盘进了当天上下文，② 取的 `context_sha256` 当场失效、
`decide` 的 D-49 闸门必拒。净值/成交窗口仍是 `date <= asof`（P84 原口径）。
