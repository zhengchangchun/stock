## 0. 一句话

把 `sh000905`（中证500）用**既有采集路径**落进 `bars_daily`（`adj_mode='none'`），
再从 `m2/config.DEFERRED_BENCHMARKS` 移进 `BENCHMARKS` —— 让 04 §P1-1「多指数同周期对标」
这一半成立；**拿不到就如实把原因写进 `DEFERRED_BENCHMARKS`**，不许换一个指数顶替。

## 1. 口径与判据

1. **先证明拿得到**（只读探针，不写库）：直接调 `data/fetch.py::fetch_index_daily`
   （`symbol="sh000905"`，窗口取最近 60 天）并把**返回行数、首末日期、`adj_mode`** 记进实施记录。
   拿不到 ⇒ **本站到此为止**：把 `DEFERRED_BENCHMARKS` 里的 `missing` 原文换成实测结论
   （试了哪个源、返回了什么），**代码零改动**也是合法交付。
2. **采集走既有路径**，不新写抓取：
   - 日链：`ops close` 的 `ingest index` **之后**加一步 `ingest index --symbol sh000905`
     （同一源、同一 `adj_mode='none'`、同一翻页守卫）。跨库守卫沿用（`ingest *` 不接受 `--db`）；
   - 月度链：加同一步（长窗回补，与 `ingest bars --days 12000` 同批）；
   - **首次长窗采集**由 nanobot 在验收后手工跑一次（见 §3），CC 的测试全用假源。
3. **日历不许被第二个符号搞坏**：`ingest index` 会顺带前滚交易日历
   （`Calendar.from_dates(...).save()` → `INSERT OR IGNORE`，**只能加行不能删行**）。
   判据：跑完第二个符号后，`trading_calendar` 的 `(date)` 集合**不小于**跑之前，
   且 `sh000300` 的行数与值逐行不变。
4. **接入 = 改配置两处**：`BENCHMARKS` 加入 `sh000905`；`DEFERRED_BENCHMARKS` **清空**。
   `/lab/m2` 与 `m2 report` 的三方对标表出现**第二个基准行**（各一行），
   「指数不可直接交易、无成本 ⇒ 口径偏乐观」的标注对**两个**基准都成立。
   反目标：**不许**把两个基准相减/取平均/合成一个「综合基准」；**不许**因为多了一行而改门禁 120 或指标定义。
5. **中间态要可见**（P48 已设计好，别绕过）：若「库里已有 `sh000905` 但配置还没接」，
   页面/报告必须显示**显式待办**（`deferred_blocked` 那条文案）。所以采集与配置翻转
   **必须成对做**，中间态最多存在一次收盘链，并在实施记录里写明先后顺序。
6. **真库只读（CC）**：CC 不得把 `ingest index` 跑向真库；真库的首次采集由 nanobot 执行
   （它是联网写库的生产动作，且要与配置翻转同批）。

## 3. 真库动作（nanobot 在验收后做，写进回执）

1. 备份（`data/backups/`）→ `ingest index --symbol sh000905 --days 12000`（长窗首次）；
2. 核对 `bars_daily` 里 `sh000905` 的行数 / 首末日期 / `adj_mode`；

4. 打开 `/lab/m2` 截图取证（第二个基准行 + 口径标注），交付给用户。
