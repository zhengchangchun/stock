创建：2026-09-26 ｜ 上游：P78（`research rank-ic`，合成分数 `IC_NOT_SIGNIFICANT`）／ADR-030／P77（打分价格口径）

## 0. 背景

### 0.1 一句话

`rank-ic` 已经证明**合成后的分数**对前向收益没有可测的横截面排序能力。但分数只是两个输入因子的
线性组合加裁剪 —— **信息可能本来就不在输入里，也可能被合成/裁剪毁掉**。本站把分数拆开，逐因子量。

### 0.2 代码事实（不是猜测）

| 事实 | 位置 |
|---|---|
| 现役短池打分插桩 = `plugin_scripts.script_id=7`（`plugin_id='1'`，v1.1.0，`source_sha256=558a6a08b62e508c…`） | 真库只读 |
| 它的分数 = `clip(50 + 150×mom20 + 30×(vr15−1), 0, 100)`，`mom20 = (C[-1]−C[-20])/C[-20]`、`vr15 = mean(V[-5:])/mean(V[-20:-5])` | 插桩源文本 |
| 打分用的 `ctx["bars"]` 走 PIT 复权价（P77 口径）；前向收益走 PIT 复权价（ADR-030 D3） | `candidate/run.py:136-168`、`data/adjust.py` |
| 合成分数的 IC 读数（并排参照） | `reports/research/2026-09-24-rank-ic-csi300-500.json`：验证段 −0.0158、CI [−0.0458, +0.0143] |
| 候选池管线里另有 5 个财务因子（`roe`/`gross_margin`/`gm_yoy_pp`/`inv_days`/`fcf_margin`），**现役短池插桩一个都没用** | `candidate/indicators.py:90-91, 210-212` |

### 0.3 不许回退的既有口径

| 口径 | 谁定的 | 本站 |
|---|---|---|
| IC = Spearman（并列平均名次）、分层 5 层、`MIN_XSEC_N=30`、`MIN_VALID_PERIODS=120`、bootstrap 2000/seed 20260918 | ADR-030（P78） | **数值全 import 自 `plugin/sandbox.py`，一个都不抄** |
| 前向收益 = `adj(d1)/adj(d0) − 1`，复权不可用回退未复权 + 计数 | ADR-030 D3/D4 | **复用，不另立** |
| 打分价口径（PIT 复权） | P77 / ADR-029 | **一字不动** |
| 插桩脚本、`plugin/` 生命周期、`approve` 人工闸门 | 多站 | **零改动** |
| `candidate/replay.py` 的收益价口径 | —— | **本站不碰**（P82 在评估，另案） |

## 0.5 锁定口径（按顺序执行；要改先回来说，不要自作主张）

- **D1｜只测已有输入，不扩充因子库**：主读数只含 `mom20`、`vr15`（现役插桩真正用的两个），
  次读数只含管线里已有的 5 个财务因子。**不许**加均线/换手/资金流等新因子 —— 那会把「度量」
  变成「因子挖掘」，且是多变量。
- **D2｜因子值必须来自打分用的同一个 ctx**：`candidate/run.py::_load_bars_adjusted` ＋
  `_cross_section_map` ＋ `score.build_ctx` 三条**原样复用**（不许在 research 侧另建价格口径）。
- **D3｜只增字段**：`PipelineResult` 只增 `factor_inputs: dict[str, dict]`；
  `score_pipeline(..., want_factors: bool = False)`，默认 `False` ⇒ **既有调用点零改动、逐位不变**。
  载荷形状锁定：`{code: {"closes": [≤20 个 float], "volumes": [≤20 个 float], "feats": {5 个财务因子键 + "period"}}}`。
- **D4｜公式复述 + 一致性用例**：`mom20`/`vr15` 的公式在 research 侧**复述一次**
  （注释点名 `script_id=7` / v1.1.0 / `source_sha256=558a6a08…`），并**必须**有用例钉住：
  同一 ctx 上 `clip(50 + 150×mom20 + 30×(vr15−1))` == 插桩实际返回的 `score`。
- **D5｜裁剪诊断只报不判**：逐日统计「被裁到 0 或 100 的标的本数 / 当日截面数」，
  出 P50 与极值；**不进任何 verdict**。
- **D6｜fail-closed 预注册**：新实验短名 `factor-ic`，`PREREG_FIELDS` 与预注册 md 里那段 json
  **逐字一致**；命令行实参任一不符 ⇒ exit 2、**零输出**。
- **D7｜只跑 `short` ＋ `csi300-500` ＋ 同窗**（`2015-01-01` 起）：别的池/宇宙样本不足，
  跑了也只有 `INCONCLUSIVE`。
- **D8｜只读**：真库 `data/stocklab.db` 跑前跑后 sha 相同；红线三目标 == 基线且**不 regen**；
  产物只落 `reports/research/`（gitignore）。
- **D9｜不做采纳**：本站只出读数与量尺。**改打分函数是另一次**决定（新预注册、单变量）。

### 7.10 偏离与取舍（逐条点名）

1. **改了 `stocklab/research/signal.py`**（边界允许「仅当需要抽公共 helper」）：三个
   helper 只**改名**成公开名，`git diff` 是纯改名、无一行逻辑改动；`rank-ic` 的 39 条
   既有用例全绿。**为什么必须动**：`factor.py` 要用同一套前向收益/汇总口径，复制一份
   会让两个实验的口径有分叉可能；而跨模块 import 下划线私有名会把它变成事实契约。
2. **`n_dates_skipped` 顶层是字典而不是标量**（T4 只给了键名，没给形状）：两个主因子的
   非空覆盖度不同，各自少算的天数不同，合成一个标量会掩盖差异。逐因子值同时也在
   `factors[name].n_dates_skipped` 里。如实写成「形状由本站定，留给决策方」。
3. **次读数的 `verdict` 是 `None`**（覆盖度不足时是 `"LOW_COVERAGE"`）：预注册说次读数
   「只报读数、不作判据」，而结论词汇表只有 4 个词、没有「不判」这一档 ⇒ 留空 ＋
   另给 `coverage_flag` 标记，**不硬塞一个词进 verdict**。
4. **`LOW_COVERAGE` 优先于 `INCONCLUSIVE`**：两者同时成立时（截面薄到每天都被跳过 ⇒
   覆盖度必然也不足）取 `LOW_COVERAGE`（更具体，它说出了**为什么**没有有效日期）。
   实测用例把两条路径分开了：覆盖度足而截面薄 ⇒ `INCONCLUSIVE`；覆盖度不足 ⇒
   `LOW_COVERAGE`。
5. **`universe` 在本站预注册里是必填**（`rank-ic` 是「缺席 ⇒ seed21」）：P83 只跑
   `csi300-500`，宇宙写进预注册才钉得住。站侧 `--universe` 的语义仍是「缺省 ⇒ seed21」，
   于是「预注册写 csi300-500、命令行不给」照样 exit 2。
6. **`rank_ic_reference` 是**常量引用**而非运行时读那份 json**：产物在 gitignore 里，
   运行时读它会在「产物不存在」时炸；用例改为把常量与预注册 §4.4 的 4 位小数对拍。
7. **未把 `factor_inputs` 采样点放在 `risk_adjust` 之前**：放在之后可以保住
   「键集合 == `scored["short"]`」这条更强的不变量；已核实 `risk_adjust` 是浅拷贝且只设
