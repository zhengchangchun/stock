## 0.5 锁定口径（D1–D12；要改先回来说）

**D1｜本档只做两层调度，且复用现有命令。** 新增 `ops weekly` / `ops quarterly` 两条链
＋ 两条 plist；站**不得**修改任何业务口径、不得为「凑齐需求条目」新写计算逻辑。

**D2｜`asof` 取「最近已收盘交易日」，不取运行当天。**
- 为什么与 `ops close` 不同：收盘链必须写**当天**（它负责把当天数据落地）；
  周/季度链是**读当天数据做汇总**，运行当天可能是休市（10-05 恰好是周一、国庆休市）。
- 取法：复用 `patrol.load_calendar/load_holiday_table/session_day` 的同一份判定 +
  库内 `bars_daily` 最大日，得到 `L = 最近已收盘交易日`。
- **fail-closed**：取不到 `L`（库不在 / 日历读不了 / `bars_daily` 空）⇒ **整轮拒绝**、
  exit 2、零步执行。不许猜一个日期跑。

**D3｜两条链都不做「非交易日跳过」。** 与 `ops monthly` 同构（维护/汇总活，幂等）。
理由：10-05 这类「周一恰逢休市」的周如果跳过，就**连续两周没扫**，而每周扫描正是要
「新增合格标的、剔除失效标的」的节拍。休市周跑出来的是与上周同样的读数 —— 无害、可复核。

**D4｜时刻表（必须与既有三条互不撞点）。**
- `weekly`：**周一 16:30**（`StartCalendarInterval` 5 槽，`Weekday=1`）。
  为什么不是 15:30/15:40：`close` 在 15:30 起跑、整轮预算 900 s（15 min），两条链
  都要**写同一个 SQLite 库** ⇒ 必须留 ≥45 min 余量，否则撞 `database is locked`，
  把收盘链判成 exit 2（P42 的教训，`test_no_two_jobs_fire_at_the_same_moment` 钉住）。
- `quarterly`：**5/1、9/1、11/1 09:00**（3 槽/年）。对应**财报法定披露截止日之后**：
  4/30（年报+一季报）、8/31（中报）、10/31（三季报）。选 09:00 而不是 08:00 是为了
  避开 `monthly` 的「每月 1 日 08:00」（间隔 1 h，且 monthly 自身预算 1800 s）。
- **07 约束 1（串行优先级）落地方式**：launchd **没有优先级队列**（这是 D-7 已修正过的
  认知）⇒ 用「时间不重叠 + 各自幂等」代替排队：季度 09:00 / 每周一 16:30 /
  每日 15:30 / 巡检 <15:00，四层两两不同分钟。**报告里必须写清这一条**，不许声称有队列。

**D5｜weekly 链（`WEEKLY_STEPS`）＝ 5 步 + 汇总报告。顺序 = 依赖顺序。**
1. `candidate run --run-kind weekly --asof {asof}`（模块1 全流程 → 新快照；**阻断**）
2. `candidate review --asof {asof}`（插桩5 复盘：错判案例回流台账；**非阻断**）
3. `m2 report --asof {asof}`（双账户 + 双基准绩效；**阻断**）
4. `m2 lifecycle due --asof {asof}`（冻结到期清单；**阻断**——失败说明台账读不了）
5. `plugin list`（版本清单；**阻断**）
6. **汇总报告**（本档新增的**渲染**步骤）：把上面 5 步的 stdout 载荷 + `m2 report`
   的 JSON 汇总成 `reports/weekly/<asof>-weekly.md`。**只汇总，不重算**。

**D6｜quarterly 链（`QUARTERLY_STEPS`）＝ 5 步 + 汇总报告。**
1. `ingest financials`（三表复核 → 重估基本面；**阻断**）
2. `candidate run --run-kind quarterly --asof {asof}`（**全量重打分**；**阻断**）
3. `m2 report --asof {asof}`（**阻断**）
4. `m2 lifecycle due --asof {asof}`（冻结到期/过期清单；**阻断**）
5. `m2 attribute scan --asof {asof}`（归因**候选**扫描；**非阻断**）
6. `plugin list`（**阻断**）
7. **汇总报告** → `reports/quarterly/<asof>-quarterly.md`。

**D7｜`ops quarterly` 不做「自动开新验证周期」、不做「全量 sandbox 跑批」。**
- 自动建新周期：P87 §4.2 明确**留待用户拍板**，本档**只出清单**（`m2 lifecycle due`）。
- 全量过拟合检测：`plugin sandbox` 是「一次一个 script_id、离线回放」且**多版本连跑很贵**；
  本档**只在报告里列出 active 版本清单 + 各自最近一次沙盒结论**，把它标成
  「**待人工决定是否逐个跑 `plugin sandbox`**」。不许静默跳过、也不许假装跑过。
- 风控全量复核（07 任务4 item4「行业集中度 / 单票仓位风险」）：**本档只出 `portfolio show`
  原始读数**。真要做集中度打分是**新口径**，另立任务书（本档不得自创风控算法）。

**D8｜报告落盘位置与「读得到」。**
- `reports/weekly/<asof>-weekly.md`、`reports/quarterly/<asof>-quarterly.md`
  （`reports/` 在 `.gitignore` 里；回执仍在 `<报告根>/ops/latest-{weekly,quarterly}.json`）。
- 报告必须**自带数据出处**：每个数字旁注明它来自哪一步 / 哪张表 / 哪个报告文件。
  无数据时写「无数据（原因）」——**不允许写 0 或留空**（ERROR_DIARY #50 同型的教训）。

**D9｜退出码语义与既有链同构。**
- `0` 全绿（含非交易日照跑）/ `1` 链跑完但有非 0 步或事后体检 `missing/stale` /
  `2` 断链（库不在 / 取不到 asof / 某步 ≥2 / 预算用尽 / 跨库守卫拒）。
- 整轮预算：`weekly`/`quarterly` 各 **1800 s**（候选池全量 + 财报复核是长跑）。
- 走 `ops/runner.py` 的 `run_steps` ＋ `journal.seal`，**不新写执行器**；
  跨库守卫（`cross_db_refusal`）照旧生效：链里含 `ingest *`/`doctor` ⇒ 非默认库直接拒。

**D10｜`/lab/ops` 页面同步到 4 条任务。** 页面现在写着「三条任务」；新增两条后要
把它改成读 `schedule.JOBS`（不得再写死 3），并把回执/日志/逐步退出码照旧展示。

**D11｜真库零写入。** 本档所有验证（含两条链的端到端演练）在 `/tmp/p89/copy.db`
副本上做；真库只允许**只读**。**站不执行 `ops schedule install`**（那是改本机
`~/Library/LaunchAgents` 的系统动作，留给 nanobot 在复核通过后做）。

**D12｜红线不 regen。** 三目标 sha 必须与基线逐位相同（`docs/baselines/redlines.json`）。

## 3. 站内纪律

1. **提交只用显式路径**（`git add <file>`），禁 `git add -A`；`git commit -m` 里**禁反引号**
   （用 `-F <文件>`）。
2. `ingest *`、`--fix`、任何写库动作**不许在真库上跑**；写实测只在 `/tmp/p89/copy.db`。

4. 测试**不许真起子进程**：注入假 runner（`conftest` 已 autouse 禁真实联网/禁子进程副作用）；
   CLI 用例必须换 `chain.default_runner`（ERROR_DIARY #55）。
5. 现有测试若因「3 条任务 → 5 条」而红：**改断言而不是改口径**，并在 §7 逐条点名改了哪些。
6. 落到「判据说不知道」的地方**不许自己拍**：停下、写进 §7 的偏离表，按最保守的选项做
