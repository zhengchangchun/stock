## 0. 背景

### 0.1 一句话

用户要的「小面额多成交」，**执行层已经具备**（整手向下取整、跨日不限次、每交易日一条决策 ——
见 §0.3 的代码事实）。缺的是三件**接口与读数**的事：

1. **输入侧没有「今天哪几只我根本买不起」的结论**：`tradability.by_code[c].affordable_lots`
   是个数，要模型自己去和 0 比；`pool.codes` 也不区分「买得起 / 买不起」。
2. **P79 落库的 `paper_agent_evals`（未成交腿的理由）一个消费者都没有**：写进了表，
   `paper show` / `/lab/paper` / 日报全都不读它 ⇒ 用户仍然看不到「AI 想买什么、为什么没买成」。
3. **「小面额能下手」这件事没有任何读数面**：池内一手成本分布、可下手只数、最小可成交权重，
   全要手工算 ⇒ 用户没法验证「小面额确实在下手」，我也没法在汇报里给一个可核对的数。

### 0.3 代码事实（不是猜测；本站**不许**回退它们）

- **整手硬约束**：`rules.plan_target_weight` → `qty = floor_lot(|delta| / fill_price, 100)`，
  `qty <= 0` ⇒ `hold`（P19 定，P79 复核，**一字不改**）。
- **跨日不限次**：每个交易日一条决策（`paper agent decide --asof`，`UNIQUE(arm, asof)`），
  加仓/减仓各自成腿 ⇒ 「反复加减」已经具备，**没有任何次数上限**。
- **同一天同一标的分多笔被硬拒**：`agent_decide.validate_payload` 的 `seen` 去重，
  报错原文「同一标的在同一天出现了两次 —— 两个目标权重会互相矛盾」。
  ⇒ **本站不做「同日拆单」**（同价同日拆 N 笔只多付 (N−1)×5 元最低佣金，不增信息）。
- **`C_ORDER_TARGET`（单笔 ≈1,000 元）只作用于纪律臂 ETF 腿**（`rules.plan_etf_buy`），
  对 AI 臂**不 binding**（AI 走 `plan_target_weight`，只看目标市值与整手）。
- `candidate/screen.py` **无价格/市值/流动性阈值**（只 `MIN_HISTORY_DAYS=250`）
  ⇒ 小面额标的**没有被筛掉**，问题不在选股门槛。
- 现金买不起一手时，执行层是 **fail-closed 的具名拒绝**（P65 `CashShortfall`, `code="cash"`），
  不是静默少买 —— 本站**不动**这道闸门。

### 0.4 为什么这值得单独立站

- **「AI 说得对不对」和「AI 做了没有」是两件事，现在页面只回答前者的一半**：P79 已经
  把「没做成的理由」落库了，但没人读；于是「AI 意图 67% 仓位、账户 0% 现金」这种事故
  （P79 §0.1 的真实故障）**在页面上依然看不到**。可观测性是本站的全部目的。
- **页面的 AI 段读错了臂（已实测）**：`agent_block` 写死 `arm-agent`，而那条臂真库 0 条决策。
  「AI 操盘手」段长期展示一条空臂 —— 这不是显示问题，是**读错了对象**。
- **「小面额」需要一把尺子**：`min_tradable_weight_pct`（这个账户上最小的一笔可成交建仓占
  总资产几个点）是「用最少的钱铺开最多只」的唯一刻度；没有它，「小面额多成交」不可验证。

## 0.5 锁定口径（按顺序执行；要改先回来说，不要自作主张）

- **D1｜`tradability` 增「可下手」结论，只增键**。`by_code[c]` 增两个键：
  ```json
  {"tradable": true, "untradable_reason": null}
  ```
  - 判据**唯一**：`tradable = (affordable_lots >= 1)`（不另写一套「买不买得起」的算法）。
  - `tradable == false` 时 `untradable_reason` **必须点名两个数**，两种成因分开：
    - 一手成本 > 总资产 ⇒ `"一手 ¥123794.03 已超过总资产 ¥49553.68"`；
    - 否则（总资产够、现金不够）⇒ `"现金 ¥49553.68 不足一手 ¥123794.03（先卖出其他标的可释放现金）"`。
  - `tradable == true` 时 `untradable_reason` 写 `null`（**不是**空串、**不是**省略键）。
  - 顶层增：`n_tradable`、`n_untradable`、`min_tradable_weight_pct`
    （= 可下手子集里 `min_weight_pct` 的最小值；子集为空 ⇒ `null`，**不猜数**）、
    `cheapest`（`{"code":..,"one_lot_cost":..}`，取可下手子集里一手最便宜的；空 ⇒ `null`）。
  - ⚠️ **`tradable` 是「现金口径的今天」**，不预测「卖掉别的标的是否能凑够」——
    reason 文案里写清这一点（见上）。**不许**把它读成「这标的不许交易」，
    更**不许**拿它做硬拒绝（D2 的 D1 条款沿用 P79：写入口不因可成交性拒载荷）。
  - `tradability` 已在 `DECISION_HASHED_KEYS` 里 ⇒ 指纹自然变化。**旧台账行的 sha 一律不改写**
    （append-only）；新增/变化的键集要在 §7 点名。
- **D2｜未成交腿台账必须有读出口（CLI）**。新增只读命令
  `paper agent evals --arm <臂> [--asof <日>] [--json]`：
  - 数据源只有 `store.load_agent_evals`（**不重算**任何理由）；
  - `--asof` 缺省 = 该臂 `MAX(asof)`（台账里最后一个有 evals 的日子）；该臂一行都没有 ⇒ 空列表 ＋
    `note` 明说「这台账里还没有任何未成交腿（P79 之后执行的 run 才会有）」，**exit 0**；
  - 账户不存在 ⇒ 沿用 `paper account` 的口径 **exit 2**（点名），不静默返回空；
  - `--json` 不加时打人读摘要（逐行 code/action/reason 截断），加了打完整 JSON。
- **D3｜「意图 vs 落地」对账表（报告 ＋ 页面同源）**。
  `engine.agent_block` 增 `reconciliation` 段，**逐臂**给：
  ```json
  {"arm": "arm-agent-ds-v2", "asof": "2026-09-24",
   "n_legs_planned": 6, "n_legs_filled": 6, "n_legs_unfilled": 0, "n_evals": 0,
   "unfilled": [{"code": "600900", "action": "hold", "reason": "…（截断 120 字）"}]}
  ```
  - **口径**：`n_legs_planned` = `paper_agent_decisions.payload.decisions` 的条数（最新一条 ≤ asof
    的 `portfolio` 决策）；`n_legs_filled` = 该臂该日 `paper_trades` 的行数；
    `n_legs_unfilled` = 该臂该日 `paper_agent_evals` 的行数；
    `n_evals` 与 `n_legs_unfilled` 同值（**故意重复**：一个是「台账行数」一个是「腿数」，
    两者不等时差额本身是信号 —— 不等就如实报，不要用 `min()` 抹平）。
  - **覆盖面**：`reconciliation` 是**列表**，覆盖「`paper_accounts` 里 `arm` 以 `agent` 开头
    **且**在 `paper_agent_decisions` 里有行」的每一条臂，各取自己最新的决策日；
    一条都没有 ⇒ 空列表 ＋ `note`。**不许**再写死 `ARM_AGENT`。
  - `agent_block` 的既有键**只增不减**（`arm` / `spec` / `spec_sha256` / `delta_vs_random*` …
    一字不动）—— 老读者不能因为本站而崩。
- **D4｜可下手域读数进报告与页面**。`build_report` 的每条 AI 臂补一个
  `tradable_domain` 块（数据来自 `engine.account_view(conn, arm, asof).buying_power` ，
  **同一个函数**、不另算）：
  ```json
  {"n_pool_codes": 11, "n_priced": 11, "n_tradable": 10, "n_untradable": 1,
   "min_tradable_weight_pct": 1.6516, "one_lot_cost_p50": 3856.97,
   "one_lot_cost_min": 818.42, "cheapest_code": "601398"}
  ```
  - `buying_power.by_code[c]` 增 `tradable` / `untradable_reason`（**与 D1 同一个判据**，
    两处各写一份就会对不上 —— 这正是 D-37 那类事故的形状）。
    为此允许把 D1 的判据抽成一个小函数供两处调用（`engine` 或 `agent_context` 各一处，
    **只能一处实现**），并在 §7 点名它落在哪个模块。
  - `render_report` 第四节的 AI 臂段落补一行：
    `池内可下手 10/11 只；最小可成交权重 1.65%；一手成本中位数 ¥3,856.97`；
    买不起的那只**点名**（`600519 一手 ¥123,794.03 > 现金 ¥49,553.68`）。
  - `/lab/paper` 的 AI 段落渲染 D3 的表 ＋ D4 的这一行；缺数据就写「无决策 / 取不到」，
    **不编数**（页面既有纪律）。
- **D5｜零行为改动**。`rules.plan_target_weight` / `plan_orders` / `_settle` / `_gate_cash` /
  `execute_decision` / 随机臂 `random_payload` 的**算法一字不改**（本站**只加键、只加读数**）。
  既有测试若因新键而失败 ⇒ **改期望、不改算法**，并在 §7 点名哪几个 golden 变了、为什么。
- **D6｜真库只读**：一切写实测只在 `/tmp` 副本；红线三目标**不 regen**，必须逐位 == 基线。
- **D7｜不动**：`stocklab/predict/`、`verify/`、`candidate/`、`research/`、`ops/`、`m2/`、`data/`、
  `config/`、`MODEL_VERSION`、`CLOSE_STEPS`、`MONITOR_STEPS`、`paper/config.py` 的常量。
- **D8｜站不写真库**：真库迁移 / rollout / 新臂 enroll 由 nanobot 做（含备份）。本站**不需要**迁移
  （表都已存在）。

### 7.6 与任务书不一致之处

① **判据函数落在 `engine`**（任务书允许 `engine` 或 `agent_context`，**只能一处**）：
`stocklab/paper/engine.py::tradable_verdict`。理由是 `agent_context` 已经模块级 import `engine`
（取 `max_lots_affordable` / `pit_close`），放 `engine` 不需要反向懒 import。
**并且**顺手把「一手成本占总资产几个点」这条**占比公式**也收敛成一处
（`engine.min_weight_pct`，AI 输入侧的 `min_weight_pct` 与 D4 的 `min_tradable_weight_pct` 都调它）——
任务书只点名了「判据」要一处，这条是我加的：两个读数若各写一份 round(`cost/total*100`,4)，
迟早读出两个「最小可成交权重」，与本站在防的是同一类事故（ERROR_DIARY #70）。

② **`D4` 的块比示例多三个键**：`cheapest`、`untradable[]`（code ＋ 一手成本 ＋ 理由原文）。
示例只给了标量，但 D4 同段要求「买不起的那只**点名**」—— 点名要能拿到 code 与理由，
所以它们在块里（渲染层不重算）。另：`one_lot_cost_p50` / `one_lot_cost_min` 按 **池内可定价**
（`by_code` 全部行）取，`cheapest_code` 按 **可下手子集**取 —— 前者是「池内成本分布」，
后者是「真能下手的里面最便宜的」（与 D1 的 `cheapest` 同义）。真库上两者同指 `601398`。

③ **块里是精确值、显示才舍入**：`one_lot_cost_p50 = 3856.965`（示例写 `3856.97`），
渲染出来的那一行是 `¥3,856.97`（`one_lot_cost_min = 818.4165` → `818.42`）。
不在块里先舍到分，是因为 Python 的 round 在半分点上向偶（3856.965 可能印成 3,856.96），
那会让报告与示例差一分钱。**数字的口径一律取精确值，格式化只发生在渲染层**（本项目既有做法）。

④ **对账表按 `asof` 过滤（PIT）**：D3 只说「各取自己最新的决策日」，未说历史视图怎么办。
实现取「`asof <=` 本块 asof 的最新一条决策」—— 页面/`paper show` 会拿历史 asof 出图，
把未来的决策读进来等于在历史截图里显示未来（与各臂净值同一条纪律），
`test_t3_a_historical_asof_does_not_show_a_later_decision` 钉住。

⑤ **`paper agent evals` 多了一个 note 分支**：D2 只规定了「该臂一行都没有」的文案；
本站在「显式问了**没有腿**的那一天」时另写一句点名「台账里最后一个有腿的日子是 X」——
否则用户会以为整张台账是空的（这是 D2 想挡的同一个误读的另一种形状）。

⑥ **测试文件是 5 个不是 3 个**：T1–T4 各自点名了一个文件（4 个），加上 T3 要求的
「页面出现这张表」另开 `tests/test_labweb_paper_p81.py`。用例总数 23。

⑦ **`engine.missing_account_error`**：D2 要求「账户不存在 ⇒ 沿用 `paper account` 的口径」。
为了不在第三处手抄那句话（`account_view` / `capital add` / 新命令），把它抽成一个函数
（`PaperError` 工厂），`account_view` 与该命令共用同一句文案。

⑧ **一处在实现里加宽了降级分支（本站唯一的自我修正）**：`tradable_domain_block` 最初只接
`PaperError` / `DecisionPayloadError`。全量测试立刻暴露 9 例红（`test_p49_selfeval` /
`test_p50_config_charts`）：那些夹具里的账户 `params_json` 没有 `initial_capital`
⇒ `net_deposits_at` 抛 `KeyError` ⇒ **报告整个打崩**（`/lab/paper` 会 500）。
修法是把 `KeyError` / `ValueError` 一起接住并**点名类型**（`type` 字段），
而不是去改那 9 例的期望（它们测的是别的口径）。判据：
`test_t4_an_unreadable_account_degrades_instead_of_crashing_the_report`。

⑨ **§7.3 ④ 的读数是 2 万口径**（见该行脚注）：任务书示例写的是 5 万口径的
「可下手 10/11 只 / 最小可成交权重 1.65%」。真库的 5 万入金事件生效日是 **2026-09-28**，
而所有 AI 臂最近一行净值是 **09-24** ⇒ `build_report`（只收当日有净值行的账户）在 09-24 报的是
2 万口径的 4.18%；5 万口径的 1.6516 出现在 `account_view @ 09-28`（该函数不要求净值行）。
**不是实现差异，是数据时点差异**：09-28 的净值行一落，报告那一行就会是 10/11 与 1.65%。
