## 0.5 锁定口径（D1–D9；要改先回来说）

**D1 新表（append-only）** —— 落在 `stocklab/store/schema.sql`：

```sql
-- ---------- 候选池标的状态（P91，B7；append-only） ----------
-- 需求：01 §候选池标的状态枚举 / 07 任务1-6「更新候选池标的状态」。
-- 为什么是**事件表**而不是给 candidate_members 加列：
--   ① candidate_members 挂在 (asof, run_kind) 的快照上，写它就会改写已封存的快照；
--   ② 状态变更的时刻与快照的 asof **无关**（人可以周三改、快照是上周的）；
--   ③ 本仓 append-only 纪律：变更一律「追加一行」，不 UPDATE。
CREATE TABLE IF NOT EXISTS candidate_status_events (
    event_id   INTEGER PRIMARY KEY AUTOINCREMENT,
    code       TEXT NOT NULL,
    asof_date  TEXT NOT NULL,   -- PIT 锚：该状态**从这一天起**生效（YYYY-MM-DD）
    status     TEXT NOT NULL
               CHECK (status IN ('观察中','等待买点','已建仓','逻辑证伪移出')),
    reason     TEXT NOT NULL,
    actor      TEXT NOT NULL,
    created_at TEXT NOT NULL,
    UNIQUE (code, asof_date, status)   -- 同一天同一状态**只许一行**（可重跑）
);
CREATE INDEX IF NOT EXISTS idx_cand_status_code_asof
    ON candidate_status_events (code, asof_date, event_id);
```

＋ `docs/errors` 同款的**两条 append-only 触发器**（`trg_cand_status_no_update` /
`trg_cand_status_no_delete`，写法逐字照抄 `schema.sql` 里既有触发器），
放在文件末尾的 append-only 触发器区。

⚠️ `status` 的 CHECK 枚举**必须**与 `candidate/snapshot.py::STATUSES` 同一份值 ——
schema.sql 是文本、常量在 Python，靠**一条新用例**钉住（见 G7），不靠人记。

**D2 读侧 overlay（纯函数）** —— 新增 `stocklab/candidate/status.py`：

- `latest_status(conn, code, asof) -> tuple[str, dict | None]`：
  取 `asof_date <= asof` 里 `(asof_date, event_id)` 最大的那一行的 `status`；
  **无事件 ⇒ 返回 `("观察中", None)`**（与既有默认逐位相同）。
- `status_map(conn, codes, asof) -> dict[str, str]`：批量版（页面用，一次查完，不做 N+1）。
- `history(conn, *, code=None, limit=10, asof=None) -> list[dict]`：按
  `(asof_date, event_id)` 降序。
- **只读**：本模块不许有 INSERT/UPDATE/DELETE。

**D3 新 CLI `candidate status set|show`**（`stocklab/cli/candidate.py` ＋ `cli/main.py`）：

```
candidate status set --code <6位> --status <四选一> --asof <YYYY-MM-DD>
                     [--reason <文本>] [--actor <文本>] [--now <ISO>] [--db <path>]
candidate status show [--code <6位>] [--asof <YYYY-MM-DD>] [--limit N] [--db <path>]
```

- `--status` 用 `argparse choices=STATUSES` ⇒ 非法值由 argparse 拒（**exit 2**）。
- `--reason` 缺省 `"人工设置"`（**不许空串**）；`--actor` 缺省 `"nanobot"`。
- **幂等**：同 `(code, asof_date, status)` 已有行 ⇒ 打印 `already`（含 `event_id`）、
  **exit 0**、**零写入**（可脚本重跑）。
- **同日换状态** ⇒ **新行**（UNIQUE 只管三元组）；读侧按 `(asof_date, event_id)`
  取最后一行 ⇒ 「后写覆盖读侧」。
- **不提供** `delete` / `update` 子命令（append-only；写错了只能再追加一行）。
- 与既有命令一致：`--db` 缺省 `paths.DB_PATH`，写前 `ensure_schema(db_path)`；
  用法错误（如 `--code` 不是 6 位数字）**必须先于 `ensure_schema` 拒掉**（exit 2、零写入）。

### 7.5 坑

1. **`main()` 把 argparse 的 `SystemExit` 吞成返回码**（`cli/main.py:5792-5797`）。
   用例里 `pytest.raises(SystemExit)` **永远抓不到** —— D3 要的「exit 2」在
   **CLI 进程**上确实是 2，但在 `main([...])` 这一层是 `return 2`。改成断言
   `rc == 2` 后一次通过（这是本档唯一一次「用例写错方向」）。
2. **`--code` 可为空的读命令要单独校验**：`show` 的三个过滤参数都可选，
   复用 `set` 的必填校验会让 `show --limit 1` 直接 exit 2
   （实测：`❌ --code 必须是 6 位数字，实际是 None`）。⇒ `_code_error(required=)`。
3. **「用法错误零写入」必须用 ghost 库路径取证**：用例若先 `connect(tmp_db)`
   再去读表，会因为 argparse 在 `ensure_schema` **之前**就退出而
   `sqlite3.OperationalError: no such table` —— 那正是判据要的行为，
   但断言写成了「表里 0 行」就会红。改成断言 `not ghost.exists()`（更强的判据）。
4. **只读扫描用例会撞上自己的 docstring**：`status.py` 的 docstring 里写了
   「不许有 INSERT/UPDATE/DELETE」，被自己的正则扫到。⇒ 用例改成 AST 取
   **字符串字面量并剔除 docstring** —— 注释里提一句不算违规，真的拼写 SQL 才算。
5. **`lab serve` 默认端口 8791 被 nanobot 占着**（`Address already in use`）：
   本档改用 8799 + 副本库，用完 `kill`；**没有**碰那个进程与真库。
6. **`cp -c` 只拷主库文件**：真库没在 `-wal` 里留未 checkpoint 的数据（跑前 sha
   与基线逐位相同），所以副本一致；但这是**本站的条件**，不是普遍保证。
