## 0. 一句话

把 P49 留下的两个「判定层」口子补上：**越界入参必须在任何分支之前被拒**，
且**幂等返回不许把「没使用你的入参」读成「你的请求被接受」**。

## 1. 两个口子的实测事实（P49 §10.3 原文，nanobot 未复跑）

1. **F1 · 冻结天数越界在「证据不足」路径上不校验**
   全新 `(cycle, asof)` ＋ `--fix-kind none --freeze-days 91` ＋ 门禁未过 ⇒ **exit 0**，
   且 `evidence.freeze_days = 91` **落进 append-only 台账**（该行 `branch=insufficient` / `conclusion=false` / `actions=[]`）。
   `FREEZE_MAX_DAYS` 只在真要走 `freeze` 分支时校验 ⇒ 「越界即拒」只在门禁达标那一种场景成立。
2. **F2 · 幂等优先 ⇒ 越界入参静默 exit 0**
   同一 `(cycle, asof)` 已有判定行时，后来的 `judge`（哪怕 `--freeze-days 999`）返回 `status=already` ＋ **exit 0**，
   **不校验本次入参**。

两条都**没有执行路径**（`actions=[]`，执行仍要人工 `approve`）⇒ 不是安全漏洞，但是**读起来矛盾**的记录层口子。

## 2. 口径与判据

1. **`--freeze-days` 的边界校验前移到入口**：与 `--fix-kind` 无关、与「是否已有判定行」无关。
   越界（`< 1` 或 `> FREEZE_MAX_DAYS`）⇒ **exit 2 ＋ 零写入**（不落台账行、不改任何表）。
   `FREEZE_MAX_DAYS` 的**数值一个字不改**（它是主干常量）；改的是**校验位置**。
2. **`insufficient` 分支不许把越界值写进依据**：即使校验已前移，也要把「依据里出现的 `freeze_days` 只可能来自合法区间」
   写成测试断言（防将来有人把校验挪回去）。
3. **`already` 返回要自证**：返回里加一个键（候选 `input_used: false` ＋ 一句 `input_note`），
   说明「本次入参未被使用，返回的是**已存行**」。
   **键名只增不减**（既有消费者不许被破坏）：`status` / 既有字段逐字不变，只加新键。
4. **两条都要有测试**（先红后绿）：F1 两条（门禁达标 / 未达标）、F2 一条，另加「合法区间仍照旧工作」的回归一条。
5. **不动别的**：不改 `judge()` 的三分支语义、不改台账 schema、不改熔断阈值、不碰模块1 与 `paper/`。

### 11.4 自行定死、需要拍板的口径

1. **合法区间的**下界**取 `0`，不是任务书 §2.1 写的 `1`。**
   §2.1 把越界写成「`< 1` 或 `> FREEZE_MAX_DAYS`」，但 §4 反目标同时要求「**只改校验位置**」、
   不许动边界常量；主干真源 `config/limits.py::check_freeze_days` 的区间是**闭区间 `[0, 90]`**
   （P49 §9.2 记录的报错原文也是「不在 `[0, 90]` 内」）。我选择**原样复用那个函数**（不重写、
   不改区间）⇒ 入口判据 = `[0, 90]`，`--freeze-days 0` **仍被接受**。
   要落成 `< 1` 就得改 `limits.py` 的区间，那是改主干常量，**需要拍板**。
   测试里 `0` 被**显式参数化**（`test_the_stored_evidence_never_carries_an_out_of_range_freeze_days[0]`
   断言 `exit 0`）：口径若拍板改成 `< 1`，那条会立刻判红、逼人同步改，而不是让两处口径各自漂移。
2. **校验位置 = `judge()` 函数体的第一件事**（在 `_load_cycle` **之前**）。§2.1 只说「前移到入口」，
   没说它和「周期不存在」谁先报。取最前有两个理由：与 `start_cycle` 的既有次序一致
   （`check_validation_plan` 先于读周期/日期），以及最贴合「越界入参必须在**任何分支**之前被拒」。
   **副作用**：`judge --cycle 99 --freeze-days 999` 现在报「冻结天数越界」而不是「没有 cycle_id=99」。
   两者都是 exit 2、都是「输入不合法」，且没有既有用例覆盖这个组合（已核 `tests/`）。
3. **新键名就用候选的 `input_used` / `input_note`**（§2.3 的候选，未另起名字）。
   `already` 的**两处**返回都加了：同一个 `status=already` 不该有两种形状。
4. **没给 `end_cycle` / `fuse_check` 的 `already` 加同类键**：§2.3 只点名 `judge`，且这两条的
   入参不含会被边界校验的数值（`reason` / `asof`），不属于本站两个口子。若以后要求「所有幂等
   返回统一自证」，那是一次**跨命令的口径统一**，不该塞进本站。

### 11.5 未做到 / 存疑（点名）

1. **§2.1 的 `< 1` 与常量 `[0, 90]` 的口径冲突没有替 nanobot 拍板**（见 §11.4.1）。
2. **§5 的复跑用的是 P49 夹具库，不是真库的字节副本**（理由见 §11.1 的警示框）——
   「在库副本上复跑」这句没有字面落实，如实记下。
3. **没有单独写「变异注入」脚本**（把校验挪回分支里 → 判红）。这半边的证据由 §11.3 的
   **先红**提供：修复前的实现**正是**「校验在分支里」，那 6 条红就是「挪回去会判红」的实测。
   所以 T5 的防回归力有实测支撑，但**不是**用独立的注入步骤证明的 —— 与 P49 §9.3 那种
   专门的变异测试**不是一回事**，不要读成同一强度。
4. **`already` 的新键没有端到端消费者**：`/lab/m2` 页面不展示 `input_used` / `input_note`，
   CLI 也只是照原样打印 JSON。加键是为了**让调用方能自证**（§2.3 的原文目的），未做任何
   界面接线 —— 任务书没要求，但点出来免得被读成「页面已经会解释了」。
5. **并发重放那条路径（`sqlite3.IntegrityError` 分支）的新键没有用例覆盖**：它要靠真并发
   才能触发。形状与主路径共用同一份 `ALREADY_INPUT_KEYS`，但**只有主路径有实测**。
6. **`--freeze-days 0` 的语义仍未定义**：`0` 天冻结在 `freeze` 分支上意味着什么（立即解冻？
   空操作？）没有任何判据回答。本站不动它 —— 它落在合法区间内、行为与改动前逐字相同。
