## 1. 事实：口径不对称的实测证据

**代码层面**（两条臂的分母不同）：

| 臂 | 目标市值 | 上界 |
|---|---|---|
| AI 臂 `m2_a1` v1.0.3 | 组合口径 `total_assets × w` | `Σw ≤ (100 − CASH_FLOOR) − reserved`，`reserved` ＝ **不在 picks 里**的存量持仓占比 |
| 随机臂 `random_payload` | 组合口径 `total_assets × w` | **没有**：`exposure = uniform(0, 100)`，只看「Σw + cash_pct == 100」这条载荷自洽 |

**后果**（执行层 P65 的闸门会整轮拒绝）：随机臂抽到高敞口 ⇒ 目标市值合计 > 可用现金 ⇒
`CashShortfall` ⇒ 整日事务回滚 ⇒ **该臂那天没有净值行**，且 `paper agent run` 返回 2。

**真库状态下的实测读数**（nanobot 2026-09-24 只读探针，`mode=ro`、零写入；账户
`arm-agent-random` / asof 2026-09-23：现金 ¥11,320、存量 `000333`×100 ＝ 总资产的 **42.15%**、
可用现金占比 **57.85%**）：

```

被拒者的目标敞口：62.87% / 65.44% / 68.45% / 70.02% / …（全部 > 57.85% 可用现金）
通过者的目标敞口：0.12% / 0.44% / 1.36% / 1.57% / 4.31% / …
```

> P65 §7.7-1 写的「200 个种子里 91 个」是**更粗的判据**（只看「目标市值合计 > 可用现金」，
> 没算「被抽中的存量票卖出会释放现金」）；31/200 是走完真实路径
> （`rebase_payload` → `execute_decision`）的拒绝率。**本站的判据以 31/200 这条路为准。**

**为什么这是缺陷而不只是「运气差」**（三条，缺一条就不用修）：

1. 种子是 `(arm, asof, seed)` 决定的 ⇒ **哪一天被拒是确定的**，不是随机缺失；
2. 被拒的都是**高敞口日** ⇒ 留存下来的随机臂样本**系统性地低敞口、低波动**；
3. ⇒ 用这种对照臂算 `delta_vs_random`，等于拿「被修剪过运气的对照组」比 AI 臂，
   **D-19 的结论（AI 是选对了，还是同预算下多试了几次）从根上不成立**。

**存量确认**（2026-09-24 核）：`paper_accounts` 里 `arm-agent-random` 的
`params.executor = agent_decision` ⇒ 它**在飞**、每天都该有读数；`paper_agent_decisions`
现有 2 行（`decision_id=1` 随机臂 / asof 2026-09-23；`decision_id=2` ds-v1 / 同日）
—— **这两行是 append-only，本站一个字都不许改**。

## 2. 口径（本站唯一的算法，实现必须逐条对上）

**新口径（口径 v2）**：随机臂的**敞口上界**先扣掉「不在本轮 picks 里的存量持仓当前占比」。

```
reserved = Σ weight_pct(holdings whose code ∉ picks)        # 单位：%
cap      = round((100 − RANDOM_CASH_FLOOR) − reserved, 2)    # RANDOM_CASH_FLOOR = 10.0
exposure = round(rng.uniform(0.0, max(0.0, cap)), 2)         # ← 唯一改动的抽取区间
```

其余**一个字不改**：`k` 只数仍取 `rng.randint(*RANDOM_N_CODES)`、
`picks = sorted(rng.sample(usable, k))`、权重仍 `round(exposure × rand/Σrand, 2)`、
余项仍进 `cash_pct`、种子材料仍 `sha256(f"{arm}|{asof}|{seed}")` ⇒ **逐字节可复现**。

`weight_pct` 的来源与 A1 完全一样：`hold_qty[code] × mark / total_assets × 100`
（**不许**新增契约字段、不许改 `agent_context`）。

**退化口径**（必须与旧版**逐位相同**）：
- `total_assets is None` 或 `<= 0` ⇒ `reserved = 0.0`、`exposure = uniform(0, 90)`；
- 无持仓（`held_qty` 为空） ⇒ `reserved = 0.0`；
- 池内没有可定价标的 ⇒ 仍走既有的「全现金 `cash_pct = 100`」早退分支。

**为什么这么选（写进 docstring，不要只写在任务书里）**：
- 它**逐字复刻** A1 v1.0.3 的上界公式 ⇒ 「同护栏」可验证，而不是靠形容词；
- 它保证 **成交后现金 ≥ 10% × 总资产**（`cash_after ≥ 10 + net_consumed − Σw 取整残差`，
  取整残差 < 0.005n ≤ 0.02%，被 10% 的下限吃掉）⇒ 手续费有地方出，不会踩 `CASH_TOL = 0.005`；
- 与 A1 的差别只有一处、且是**故意**的：A1 是等权 `w = cap/n`，随机臂是随机权重 —— 随机性保留。

**口径切换的可见性（硬要求）**：
- `random_payload` 的 `rationale` 里必须出现口径标识（如 `"口径 v2（P66）"`）与
  `reserved`/`cap` 的**实际取值**；
- **不重写历史**：`decision_id=1`（2026-09-23，旧口径）原样留在台账里，一个字不删不改；
- 生效时点 ＝ 本站合入日；实施记录必须写「**上一版口径的最后一天**」是 2026-09-23。
