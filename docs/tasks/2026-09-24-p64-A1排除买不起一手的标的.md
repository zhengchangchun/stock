## 2. 目标与非目标

**目标**：`m2_a1` 只把**在这个账户上真买得起的**标的放进 `picks`：按最终等权权重算出的目标市值
< 一手市值时不选它，沿排序继续往下取（去重后的序列），直到凑满 `LIMIT_N` 或用尽；入选只数 `n`
与权重 `w = min(CAP_PCT, (100 − CASH_FLOOR) / n)` **自洽**。于是 `cash_pct` 回到 10%（除非名单里
买得起的只数不足，那时如实按 `min(25, 90/n)` 给足）。

**非目标**：不改去重规则（P63 的成果）；不改 `LIMIT_N=5` / `CAP_PCT=25.0` / `CASH_FLOOR=10.0`
三个常量的数值；不改 `plugin/contract.py` 的 `picks` 形状（**加不了新字段** ⇒ 被排除的标的
在载荷里没有位置，见 §9 存疑项 1）；不动执行层（`channel_a._weights_items` 的重复拒绝留着）；
不碰模块1、`paper_trades`、`CLOSE_STEPS`。

**WAL checkpoint**（逻辑内容不变、字节变了）。本站第一份副本（11:14 取）已含全部 39 条 audit
⇒ 那条写入在取副本前就已在主库里。
③ 收工时的 sha 变化对应 `plugin_audit` 从 39 → **41**（id 40/41，11:17:54，actor
`zhengchangchun`），同一时段 nanobot 还提交了 `98aab8b docs(p63): …` —— 是**多 actor 并发**，
不是本站。真库 `m2_channel_runs` / `paper_trades` / `paper_nav_daily` 计数本站前后**完全相同**

### 7.（nanobot 补）**任务书 spec 自身的洞** —— 四道，全是口径缺口，不是实现缺陷

本站 T1–T8 的实现按判据原文无误（我独立复现过），失败的是**判据自己**：

① **「买得起」被写成了单维判据（§1 目标 / T2）。** 判据只问
`total_assets × w / 100 ≥ close × LOT` —— 可比的是「这笔目标市值在一份**全是现金**的账户里
买不买得起」，而这个账户只有 ¥11,320 现金（`total_assets` 的 58%）、另 42% 锁在**不在 picks 里**
的 `000333` 上。「按总资产买得起」与「账上拿得出」被当成了同一件事。
**spec 缺的一维＝「可用（可部署）资金」**，它必须在任务书里被显式写成判据的一部分，
而不是默认「总资产 = 现金」。

② **没写「Picks 之外的存量持仓怎么办」—— spec 缺了第三维（谁负责释放那 ¥8,247）。**
`000333` 既不在 picks、A2 也不卖它（还在池内、无止损止盈）⇒ 它既不重算也不释放。
「目标敞口 5×18%」与「存量 42% + 可用现金 58%」是两个从未对齐的口径。
修 A1 的选股规则**不可能**解决这个问题（它只能选择「不买」，不能选择「卖旧」）。

③ **T9 第四条判据写反了方向、且不具区分度。** 「`cash` 回到总资产的 ~10%」
在 1.0.1 上**本来就成立**（5.5%→实测 10.5%，见存疑项 5）、在 1.0.2 上是 −23%
—— 一条「旧版已成立、新版反面」的判据看起来像「新版退步」，但真正变的是
**旧版的偶然闸门被拆了**（ERROR_DIARY #73）。任务书里的读数类判据，
写之前必须先在两个版本上各算一遍；否则判据会把「暴露出隐藏缺陷」读成「改坏了」。

④ **契约不肯扩展 ⇒ 「为什么跳过这只」在载荷里没有位置（§9 存疑项 1 保留）。**
`picks` 每条只能 `{code, weight_pct, reason}`，被排除的标的只能从「只数 < LIMIT_N」反推。
这不是本站能修的（改 contract 是另一条口径决策），但它是「报告与计划长得一样」
这个病根的组成部分，必须和 ①② 一起决策。
