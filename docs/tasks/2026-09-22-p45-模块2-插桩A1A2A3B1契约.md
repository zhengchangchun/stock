## 1. 命名与位置（D-33，先落死再实现）

- 四支插桩以 **`m2_a1` / `m2_a2` / `m2_a3` / `m2_b1`** 登记，**不占用既有「插桩 0–5」编号**
  （那是模块1 的排雷/池评分钩子，编号语义已被需求 01 与实现钉住，混用会让审计对不上号）。
- 契约形状落在既有 `stocklab/plugin/contract.py::SHAPES` **同一张表**里（唯一真源），
  走既有 plugin 生命周期（草稿 → 沙盒 → 人工审核 → 上线）与人工 `approve` 闸门（D-24）。

## 2. 四支契约（输入/输出形状；字段名可微调，**语义与 fail-closed 规则不许改**）

| 插桩 | 作用 | 输入（PIT，只用 ≤ asof） | 输出 |
|---|---|---|---|
| `m2_a1` | AI 模拟选股：候选池内二次选股 + 仓位权重 | 候选池成员（短/中/长三池）、行情/复权、财报特征（`candidate/indicators.py`）、行业（`ctx["sector"]`）、当前模拟账户持仓与现金 | `{picks: [{code, weight_pct, reason}], cash_pct, schema_version}`；**权重合计 + 现金 = 100%**（越界拒绝） |
| `m2_a2` | AI 模拟卖出条件：止盈止损、调仓退出 | 当前持仓 + 成本 + 现价 + 主干纪律线 + 时间 | `{orders: [{code, side, reason}], schema_version}`；`side ∈ {sell}`（卖出侧） |
| `m2_a3` | AI 持仓收益预测 | 当前模拟持仓 + 特征 | 沿用**既有预测载荷形状**（`range_lo/hi` + `p_up/p_flat/p_down` + `invalidate_if`），**不许另造一套概率口径** |
| `m2_b1` | 人工持仓收益预测 | 人工镜像持仓 | 同 `m2_a3` 的形状（同口径才可比） |

**fail-closed 规则（四支共同，必须有测试）**：
1. 形状缺字段 / 类型错 / 越界 → **拒绝并把原因写回**，**绝不 clamp、绝不补默认值**；
2. 输出引用了**候选池外**或**账户里不存在**的标的 → 拒绝（不许静默丢弃，丢弃会让报告显示"有效"而实际少了腿）；
3. 概率不归一 / 区间 `lo > hi` → 拒绝；
4. 不可算的特征给 `None` + `na_reasons`，**不许给 0.0**（「不知道」≠「最差」，见 §6.3 既有口径）。

## 3. 必须新增的测试

1. **契约往返**：四支各一份合法输入 → 输出通过校验；`SHAPES` 里四支都存在且与 A1 同风格。
2. **越界不 clamp**：权重合计 110% / 概率不归一 / 区间倒挂 / 引用池外标的 → 各一条拒绝用例
   （断言**报错**，且断言**没有被改写后的输出**）。
3. **人工闸门未放宽**：`approve` 仍只能人工 CLI（复用既有源码扫描测试，若有则加对四支的断言）。
4. **沙盒探针**：四支脚本能被沙盒真实执行（`plugin/sandbox.py` 既有机制），
   且不可算特征走 `None` + `na_reasons` 路径不炸。
5. **PIT**：插桩拿不到 `> asof` 的数据（复用既有 PIT 守卫机制，别新写一套）。

### 口径偏离（任务书原文 vs 实现，**已报告后再改**）

任务书 §2 把 `m2_a3`/`m2_b1` 的输出写成 `range_lo/hi` + `p_up/p_flat/p_down`，
而代码里的真源 `predict/model.py::CONTRACT_FIELDS` 用的是 `range_80` +
`direction{up,flat,down}` + `invalidate_if`（`range_lo/range_hi` 只是
`predict/store.py::payload_to_row` 落库时的**列名**）。按 §2 自带的
「字段名可微调」取真源名，并用
`test_forecast_field_names_come_from_the_canonical_payload` 钉住
「不许出现真源之外的字段名」。另：`na_reasons`（「不知道」的落点）与
`schema_version`（形状版本）不在真源里，是模块2 新增的**非概率**字段。
