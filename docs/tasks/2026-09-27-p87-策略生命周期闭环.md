### 0.3 为什么**不能**按「加只增列」做

审计 §6 的初稿写「`validation_cycles` 前滚加只增列」。**现场核对后否证**：该表有 append-only 触发器
⇒ `UPDATE` 会被 `RAISE(ABORT)` 拒 ⇒ 一个「累计失败次数」列根本**没法维护**（每次判定都得改写行）。
所以本任务改走**派生**路线（见 D1），与项目既有纪律一致（`financial_reports` 的派生指标不落库，
ADR-016 同款）：**需求里那句「加字段」按「有可核对的读出口」满足**。

## 0.5 锁定口径（D1–D9；要改先回来说）

- **D1 零结构变更**：不新增列、不新增表、不写迁移。`连续优化失败次数` 与 `冻结到期时间`
  **一律从 append-only 的既有台账 fold 出来**（`m2_judgements` 的 `branch` / `asof_date` /
  `evidence_json.freeze_days` 是唯一真源）。真库**本次零写入**。
- **D2 失败定义**：一条判定行 `branch == 'optimize'`（＝优化后仍不达标）计一次失败；
  `branch == 'freeze'` / `'tune'` **终止连胜**（计数归零）；`branch == 'insufficient'`
  **既不递增也不归零**（它只表示读数不足，不是「这一版失败了」）。
- **D3 连胜是「尾部连续」**：从该 `script_id` **最新**一条判定往回数，`insufficient` **穿透**
  （跳过它继续往回看），遇到 `freeze`/`tune` 停止。即：`[freeze, optimize, insufficient, optimize]`
  ⇒ streak = 2。
- **D4 冻结到期日**：取该 `script_id` 最新一条 `branch == 'freeze'` 的判定，
  `due = asof_date + freeze_days` 天（**自然日**，`freeze_days` 来自该行
  `evidence_json.freeze_days`）。该行没有 `freeze_days`（或为 `null`）⇒ 无到期日（读出口给 `null`，
  **不是** 0、不是空串）。`due <= asof` 即「已到点」。
- **D5 阈值常量**：`3`，落 `stocklab/config/limits.py::STRATEGY_FAIL_STREAK_LIMIT = 3`（**新**常量；
  `FREEZE_MAX_DAYS` / `VALIDATION_ROUNDS_*` 等既有常量**一个字不改**），并在
  `stocklab/config/__init__.py` 导出。
- **D6 触发行为（只提示、不执行）**：`fail_streak >= 3` ⇒ `judge()` 结论的
  `evidence.lifecycle.force_archive = true` ＋ `archive_reason` 一句（带 streak 与阈值原文）；
  **`branch` 取值域与 D-44 规则表一个字不改**（`archive` 不是新分支），
  **`conclusion` 也按原规则算**，**绝不自动归档** —— 归档仍走人工 `plugin approve`（D-1 / D-24）。
- **D7 只读出口（新增命令）**：
  `m2 lifecycle show --script <id> [--asof <day>]` ⇒ `fail_streak` / `limit` /
  `tail`（尾部判定摘要） / `freeze_due` / `overdue`；
  `m2 lifecycle due --asof <day>` ⇒ 「到期或已过期的冻结版本」清单（按 `script_id` 去重、只列有效冻结）。
  两条命令**只读、零写入、零联网**（不得出现任何 `INSERT/UPDATE/DELETE`、不得 `ensure_schema`）。
  输出形状与既有只读命令（`m2 cycle status`）同风格：`--json` 打完整载荷、无 `--json` 打人话摘要。
- **D8 `judge()` 是扩展不是改判**：既有 `branch` / `conclusion` / `reason` / `actions` 的元素与顺序
  **逐位不变**（`actions` 允许**追加**一句归档建议）；`evidence` 既有键**一个不动**，只多一个
  `lifecycle` 子对象；`m2_judgements` 的幂等键 `(cycle_id, asof_date)` 与 append-only 语义不动。
- **D9 站内纪律**：写实测（灌判定行、构造 freeze 到期）一律在 `/tmp` 副本上做
  （`cp -c data/stocklab.db /tmp/<站>/copy.db`）；真库只读（`file:…?mode=ro`）。不 `approve`、不迁移。

3. `m2_judgements` 里 `branch='optimize'` 是否就等于需求说的「优化验证**失败**」——本任务按
   `optimize`（＝声明要改逻辑、且不达标）理解。若用户口径不同，改 D2 一处即可（派生口径，
   不涉及数据重写）。
4. `freeze_days` 用自然日而不是交易日（D4）：真源写的是「冻结 ≤ 90 天」，07 任务4-2 说的是「到期」；
   若以后要与交易日对齐，同样只改这一处。（**本任务不做**，先在 ADR 里记账。）

### 7.6 遇到的坑与处置

1. **`def summarize` 撞既有结构扫描（改了名，任务书 §7 点名）**。
   首轮全量 3606 里 1 个红：`tests/test_m2_scores.py::test_t2_no_second_metric_implementation_in_m2_or_labweb`
   —— `FORBIDDEN_DEFS` 保留 `def summarize` 给指标算法，我的载荷入口正好叫这个名。
   `git stash` 前后对比确认**是我引入的**（不是既有失败）。那条用例的语义不许改，
   故把入口改名 `snapshot`（键序与行为不变），并在 ADR-037 与模块 docstring 里写明原因。
   两笔已提交的提交用 `git reset --soft HEAD~2` 重写（**未 push 的本地提交**），
   保持任务书要求的三笔结构。
2. **`tests/test_m2_cycle*.py` 这个 glob 在仓库里不存在**（见 §2 G6 的 ⚠）：
   等价物 `tests/test_p49_selfeval.py` 未被修改而全绿（`git diff --stat` 里它没出现）。
3. **`--json` 的键序**：CLI 统一 `sort_keys=True`，所以「键名与顺序固定」这条只能在
   `snapshot()` 的 dict 字面量处钉（`test_snapshot_has_the_fixed_key_order`），
   CLI 层钉键集合 —— 两处分工写在用例注释里，免得后人以为漏钉。
4. **只读出口的「三件事」**：只拦写语句挡不住 `ensure_schema` 的整包 DDL，也挡不住
   「不小心用了读写连接」。所以 `_run_readonly` 同时钉：写语句抛 + 断言 URI 是
   `file:/绝对路径?mode=ro`（`uri=True`）+ `ensure_schema` 被换成抛错。
5. **`_evidence` 对坏 JSON 不炸**：读出口不该因为一行坏 `evidence_json` 整个不可用；
   要不到 `freeze_days` 就是 `None`（不猜 0、不猜 90）。

### 7.7 偏离与未决（按纪律逐条点名）

1. **偏离 T1 的命名**：`summarize` → `snapshot`（理由见 7.6.1）。其余签名与
   T1 一致（`judgement_tail` 多一个可选 `asof=` 关键字 —— PIT 守卫要求，见 T1 的 PIT 条目）。
2. **D4 的自然日**：`freeze_days` 按自然日加，不按交易日（ADR-037 已记账，本站不改）。
3. **`due_freezes` 的「有效冻结」取法**：按 `script_id` 取**最新一条** `branch='freeze'`；
   若该 script 之后又出过 `tune`（同 script_id 解冻），历史冻结行不会进清单。
   「解冻」当前没有独立事件行，所以这是**近似**（ADR-037「沉没成本与已知代价」里如实记下）。
   D4 只定义了「到期日」的取法，没定义「冻结算不算还生效」—— 这里按最小解释实现，
   若派单方口径不同，改 `due_freezes` 一处即可。
4. **未实现**（任务书 §4 已记账，本站不做）：自动归档（需动 `plugin` 写入口 + 用户拍板）；
   07 任务4-2 的「到期强制开启新一轮验证周期」（自动建 cycle，留 B3/B4）。
5. **真库零写入**：本站没有对真库执行任何迁移/写入；`m2 lifecycle` 两条命令在真库本体上
   只读跑过一次（sha/mtime 未变，见 §7.3）。
