日期：2026-09-26 ｜ 提出：nanobot（用户 2026-09-24 授权「只要能提高 ai 模拟的准确率，就都按照你想的优化」）

## 0. 背景

### 0.1 一句话

系统现在**只能**回答「**持有集合换一个定义**，组合收益差多少」（`research xsec-topn`），
**不能**回答「**打分本身**对前向收益有没有横截面排序能力」。本任务建这条度量闭环：
**逐调仓日算 rank IC ＋ 分 5 层看前向收益**，只读、离线、不写库、不碰任何策略参数。

### 0.2 为什么这是「所有选股优化的前置」

2026-09-25 扩池实验（`docs/experiments/2026-09-25-xsec-topn-csi300-500.md`，Δ = **+0.3132%/期**、
95% CI `[−0.4887%, +1.1584%]` **跨 0** ⇒ 「无可测的选股增量」）在 §5 自己写下了下一步：

> 瓶颈不在 N，也不在宇宙大小，而在选股信号本身 …… 要提高 AI 模拟的盈利能力，下一步不是调 N /
> 调宇宙，而是**先能量化「打分变量对前向收益的横截面排序能力」（IC / 分层回测）**，再据证据改打分函数。

`xsec-topn` 的问题不是跑错了，而是**它测的东西与「选股准不准」不同构**：

- 它比较两个**组合**的收益序列 ⇒ 只对「取前 N 相对持全部」有分辨率，
  而短池 topn 只有 6 只、`|topn|/|all|` ≈ 1/60 ⇒ 区分度**结构性地小**（报告 §3 自己写了这是固有上限）；
- 它**看不到**分数的中间段：第 7 名与第 300 名对 Δ 毫无贡献，但对「这个分数有没有信息」贡献巨大；
- 它一次只出**一个**数（Δ），无法回答「打分函数里哪一项有用」——而那正是改造打分函数的输入。

⇒ **在没有任何「信号有效性」读数之前，改打分函数就是盲改**（改完只能再跑一次 96 分钟的组合级实验、
而且大概率还是 CI 跨 0）。本任务把「盲改」变成「先量尺、再改」。

### 0.3 本任务是**度量基建**，不是策略（口径红线）

- 它**不出任何信号**：交叉截面的分数**全部**来自既有 `score_pipeline`（现算、只读）；
- 它**不改任何阈值/公式/参数**：`screen.py`、`candidate/builtin/p1_short.py`、`score.py`、
  `risk_adjust.py`、`config/` 全部零改动（§0.5 D10）；
- 它**只加一条只读命令**（`research rank-ic`），产物只落 `reports/research/`（gitignore）。
- 一旦它自己出信号，就会与通路 A 的 A1 形成第二套选股口径、A1 的归因立刻失效 ——
  与 `research/xsec.py` 开头那段自述同一个理由。

### 0.4 站点顺带发现的一条**既有口径缺口**（**不在本站修**，只记录）

`candidate/replay.py::period_returns` 算组合收益用的是 `_close_on` ⇒ 直读
`bars_daily.close`，而 `bars_daily` 全表 `adj_mode='none'` ⇒ **未复权价**
（P77 §0.3 列「所有其它价格路径都走 `load_bars_adjusted`」时**漏了 `replay.py` 这一条**）。
除权日的缺口会被算成组合亏损。

- **本站不改它**：改 `replay.py` 就动了 `xsec-topn` 的臂定义、也动了 `plugin/sandbox.py` 经注入
  调用的那条回放路径 = **第二个变量**，会与 P77 的口径切换混在一起。
- **本站要做的事**：把这条写进 ADR-030「已知遗留」与报告正文；本任务的 IC **目标收益一律走 PIT 复权价**
  （§0.5 D3）⇒ **本报告的 IC 绝对水平与 `xsec-topn` 的组合收益绝对水平不同源、不可直接比**。
- **后续**：另立任务书评估（先在库副本上量化影响，不改口径）。

## 0.5 锁定口径（按顺序执行；要改先回来说，不要自作主张）

- **D1（度量对象）**：跑 `pool="short"`，主读数 = 每只的 **`adj_score`**（`select_top` 实际排序用的那个，
  即 `risk_adjust` 之后的最终分），次读数 = **`raw_score`**（插桩1 的原始输出）并列报出。
  **只跑 short**：`mid` 需 32.6 年、`long` 需 97.9 年才够 `MIN_VALID_PERIODS`=120 个验证周期
  （纯算术，同 `xsec.ONLY_POOL` 的理由）；别的池 exit 2。
- **D2（交叉截面来源）**：每个调仓日跑一次 `score_pipeline(conn, asof=<mark>, universe=<members>)`，
  取**该池全部已打分的合格标的**（不是只有 top-N）。为做到这点给
  `candidate/run.py::PipelineResult` **只增**一个字段 `scored: dict[str, list[dict]]`
  （内容就是 `score_pipeline` 内部**已经构造好的**那个 `scored`，含 `code/raw_score/adj_score`）。
  `score_pipeline` 的**打分口径/顺序/公式一字不动**；`members`/`rejects`/`params`/`eligible`
  的取值与顺序逐位不变（`eligible` 仍由 `scored` 派生）。**不许**在 `signal.py` 里重写一遍打分循环。
- **D3（前向收益口径 = PIT 复权价）**：`fwd(c; d0, d1) = adj_close(c, d1) / adj_close(c, d0) − 1`，
  其中复权序列由 `data/adjust.py::load_bars_adjusted(conn, code, as_of=FWD_ASOF)` 提供，
  `d0`/`d1` 是两个**相邻调仓日**（`rebalance_marks` 的输出）。
  `FWD_ASOF = marks[-1]`（最后**一个**调仓日，不是 `end`；`end` 可能不是交易日）。
  - **为什么可以用一个 `as_of` 覆盖全部周期**：比值 `adj(d1)/adj(d0)` 只取决于
    `(d0, d1]` 区间内的除权事件 —— `d1` 之后的事件因子在分子分母上同时出现、**相消**。
    所以取任意 `as_of ≥ d1` 得到的前向收益**逐位相同**，且 `d0/d1 ≤ as_of` ⇒ **无未来数据**。
  - 这条**只是理由**：必须在 §7 用**只读探针**核过（≥3 个 `(code, 周期)` 样本，比
    `as_of=d1` 与 `as_of=FWD_ASOF` 两个比值；不等就把站停下来报我）。
  - **不许**自己实现一份复权、也**不许**改 `data/adjust.py`。
- **D4（复权不可用的处置：fail-open ＋ 可见）**：
  - 复权层拒绝服务（ETF `EtfChainUnsupported` / `MissingFactor` / `StaleFactorTable`，同 `run.py`
    的 `_ADJ_UNAVAILABLE` 三类）⇒ 该只**回退到未复权价**算前向收益（因子恒 1 ⇒ 数值等价），
    计入 `n_fwd_fallback`；
  - 该只**复权链为空**（无 `corp_actions`）⇒ 同样等价回退、同样计数；
  - `d0` 或 `d1` 任一取不到价 ⇒ 该 `(日期, code)` 从**该日截面**里剔除，计入 `n_no_fwd_ret`；
  - 裸 `AdjustError`（`k>1` / `pre_close<=0`，属**代码/数据缺陷**）**不在此列，原样抛**
    —— 数据脏与代码坏要分档（ERROR_DIARY #81）。
  - **fail-open 的理由与 P77 D3 同**：这是度量路径不是下单路径，一只标的的因子不可用不该让整轮死掉；
    但**必须可见**（报告计数）。**不许**把回退当静默。
- **D5（IC 定义）**：主 = **Spearman 秩相关**（并列取平均名次，`cross_section._pct_of` 那套排名法），
  次 = Pearson（并列报出）。**只用 stdlib**（`statistics` / `math` / `random`）；
  ⛔ **不许 import numpy / scipy / pandas**（本项目零 ML 依赖，既有口径见 `docs/architecture/`）。
  某日截面里同时有分数与有效前向收益的标的数 `< MIN_XSEC_N = 30` ⇒ 该日 IC 记为 `None`、
  计入 `n_dates_skipped`（**不许**用 0 顶替 —— 那是把「不知道」伪装成「没相关」）。
- **D6（分层）**：`n_layers = 5`（预注册字段，改要新预注册）。按分数**降序**、等量分桶
  （rank-based；并列按 `code` 升序定序 ⇒ 确定性），**第 1 层 = 最高分**。
  报每层的平均前向收益（先按日算层均值、再对日平均）＋ `spread = layer1 − layer5` 的日序列
  （均值 ＋ bootstrap CI）。单调性另报：`n_ascending_steps`（相邻层之间「上一层均值 > 下一层」的个数，满值 4）。
- **D7（判据：预注册 + fail-closed，复用既有门槛）**：
  - 验证段有效日期数 `< sandbox.MIN_VALID_PERIODS`（=120）⇒ verdict = **`INCONCLUSIVE`**（「测不出」，不是「没效果」）；
  - 否则：验证段 IC 序列的 `sandbox._BOOTSTRAP_N` 次按日期重采样 95% CI **不含 0** ⇒ **`IC_SIGNIFICANT`**；
    含 0 ⇒ **`IC_NOT_SIGNIFICANT`**。
  - **复用的常量/函数**：`sandbox.MIN_VALID_PERIODS` / `_BOOTSTRAP_N` / `_BOOTSTRAP_SEED` /
    `_bootstrap_ci` / `overfit_flag`（import，一个数字都不许手抄）；训练/验证切分复用
    `replay.split_train_validate`（按周期序号 70/30）。
  - **注意**：verdict **词汇**是度量专用的（IC 为负也叫 significant，叫 `WIN` 会读歪）。
    这是**预注册的**判据，不是「第二套阈值」——门槛数字全部复用，理由写进 ADR-030。
  - **不许**为了得到显著而不改门槛、不换窗口、不换宇宙（`CLAUDE.md` 度量纪律 6）。
- **D8（窗口与宇宙）**：`--start` **必填**且 `≥ 2015-01-01`（`MIN_START`，窗口即结论）。
  `--universe <id>`（默认 `None` ⇒ `seed21` 主干常量），走 `config/universes.py::resolve_universe`
  （**fail-closed**，文件缺失即抛，不回退）。**换宇宙必须新预注册**（与 `xsec` 同语义：
  预注册缺 `universe` 字段 ⇒ 语义 = `seed21`，命令行不一致即 exit 2，零输出）。
  **本站首次跑 = `--universe csi300-500`，窗 `2015-01-01 → 2026-09-24`**（与 09-25 扩池实验同窗，
  便于并列读），但**全窗由 nanobot 事后后台跑，不在站内跑**（≈100 min，见 §1 T6）。
- **D9（只读与产物）**：连库一律走 `stocklab/cli/research.py::open_read_only`（`file:…?mode=ro`），
  **不写任何表**、不进 `ops close`、不进红线基线。产物落 `reports/research/`，
  文件名**必须带宇宙 id**：`<end>-rank-ic-<universe_id>.{json,md}`（P77 T7 的教训：不带 id 会静默覆盖历史产物）。
- **D10（不许动的 —— 要动先回来说）**：`candidate/screen.py`、
  `candidate/builtin/p1_short.py`（已上线的插桩源文本）、`candidate/score.py`、`candidate/risk_adjust.py`、
  `candidate/replay.py`（见 §0.4）、`predict/` `verify/` `paper/` `m2/` `ops/`、`data/adjust.py`、
  `config/`（含 `config/costs.py` `config/replay.py`）；`research/xsec.py` 的**既有行为**也要逐位不变
  （允许给它加**只增**关键字参数，默认值必须让老调用逐位不变）。
  `candidate/run.py` **只许**做 D2 那一个只增字段。

## 2. 风险点（先读 ERROR_DIARY）

- **#47**：`ingest` 类命令不接受 `--db`。本任务**不写真库**（只读 ＋ 冒烟也只读），别顺手改采集路径。
- **#55 / #56**：CLI 用例必须注入假 runner；本任务不碰 `ops/chain.py`，别顺手改。
- **#59 / #72 / #74 / #77**：口径类改动最容易「顺手改到别处」⇒ T1 与 D10 都要求 **diff 自证**。
- **#81**：只读探针必须 `conn.row_factory = sqlite3.Row`（裸 tuple 会误报 TypeError）；
  「数据侧不可用」与「代码缺陷」要分档（D4）。
- **#66**：站若在最后一跳 HTTP 失联，代码会在、§7 会空 ⇒ 逐条勾 §7，别只提交代码。
- **性能**：`score_pipeline` 在 800 只上 ≈15–22 s/日 × 571 日 ≈ 96 min（09-25 实测 5776 s）。
  前向收益的 `load_bars_adjusted` **一次/只**（D3），别写成一次/（只·日）——那会把耗时乘上 571。
  **不要**为了跑快而缩窗/抽样（读数要逐位可复现）；全窗本来就不在站内跑（T5）。
- **幂等/写库**：本命令**零写库**；`open_read_only` 不调 `ensure_schema`、不开 WAL。
- **`PipelineResult` 是 frozen dataclass**：加字段要给默认值（`field(default_factory=dict)`），
  否则既有构造点（`_hydrate` 路径、测试夹具）会 TypeError。
- **测试目录卫生**：产物一律落 `tmp_path`，**不许**往仓库 `reports/` 写（ERROR_DIARY #51）。
- **别混引**：`xsec-topn` 的 Δ 与本站的 IC **不同源**（§0.4）；旧（未复权）口径的实验读数照 P77 §7.8 的纪律。
