### 3.3 **四支的拒绝用例**（任务书 §3.2 要求逐条）

命令：`scripts/` 无此脚本，直接调契约层（下面这段就是实际执行的内容，
`.venv/bin/python - <<'PY' … PY`，逐字可复现）：

```
[REJECTED]  m2_a1 权重80+现金30=110%
            插桩 m2_a1 的权重合计 + 现金 = 110.0，必须等于 100.0。拒绝而非缩放 ——
            缩放会把一个算错的仓位方案伪装成合规的，而下游按权重下单时不会有人发现
            原地未改写: {'picks': [{'code': '000333', 'weight_pct': 80.0, 'reason': 'r'}],
                        'cash_pct': 30.0, 'schema_version': '1'}
[REJECTED]  m2_a3 概率合计 1.5
            插桩 m2_a3 的字段 'direction' 三个概率之和应为 1，实际 1.5
            （{'up': 0.5, 'flat': 0.5, 'down': 0.5}）。拒绝而非归一化 ——
            归一化会把脚本算错的概率救成一份看起来合法的载荷
[REJECTED]  m2_a3 区间倒挂 lo>hi
            插桩 m2_a3 的字段 'range_80' 区间倒挂：lo=92.0 > hi=80.0。
            拒绝而非交换两端 —— 交换会把脚本的方向错误伪装成一个合法区间
[REJECTED]  m2_a1 引用池外 600690
            插桩 m2_a1 引用了允许集合外的标的 ['600690']。拒绝而非丢弃 ——
            丢弃会让报告显示「有效」而实际少了腿
[REJECTED]  m2_a2 引用账户外 000333
            插桩 m2_a2 引用了允许集合外的标的 ['000333']。拒绝而非丢弃 ——
            丢弃会让报告显示「有效」而实际少了腿
[REJECTED]  m2_a2 空允许集合
            插桩 m2_a2 引用了允许集合外的标的 ['000333']。拒绝而非丢弃 ——
            丢弃会让报告显示「有效」而实际少了腿
[REJECTED]  m2_b1 半真半假
            插桩 m2_b1 报了 na_reasons=['sector_unknown'] 却仍给出部分数值 ——
            「不知道」与「知道」不许混在一份载荷里（半真半假等于编数）
[REJECTED]  m2_a3 全 None 无理由
            插桩 m2_a3 有字段是 None 却没有 na_reasons —— 缺数必须逐条说明为什么
            （「不知道」≠ 0，也≠ 沉默）

[ACCEPTED] m2_a1 空仓 100% 现金 -> {'picks': [], 'cash_pct': 100.0, 'schema_version': '1'}
[ACCEPTED] m2_a2 无指令        -> {'orders': [], 'schema_version': '1'}
[ACCEPTED] m2_b1 不知道+理由   -> {'range_80': None, 'direction': None, 'invalidate_if': None,
                                 'na_reasons': ['bars_n=0'], 'schema_version': '1'}
```

对账（规则 → 用例）：

| 规则 | 拒绝用例 |
|---|---|
| 1 形状/类型/越界不 clamp | 权重+现金 110%（`test_weights_plus_cash_over_100_is_rejected_not_clamped`）、不足 100%、`cash_pct=150`、`weight_pct=True`、四支逐个缺字段、非 dict |
| 2 引用池外 / 账户里没有 | 池外 `600690`、账户外 `000333`、空允许集合（fail-closed） |
| 3 概率不归一 / 区间倒挂 | 概率合计 1.5、单概率越界、`lo > hi` |
| 4 不知道 ≠ 最差 | 半真半假、全 None 不说理由、`PROBE_CTX` 的特征是 `None` 而非 `0.0` |

**「没有被改写后的输出」**：上面第一条同时实测了 `原地未改写` ——
`validate_return` 抛错后输入对象逐字段未变（`test_rejection_does_not_rewrite_the_input`）。
