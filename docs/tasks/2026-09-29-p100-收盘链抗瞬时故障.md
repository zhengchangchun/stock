```

  ingest_index            exit=1   ← 根因
  ingest_index_500        exit=1   ← 同一根因
  ingest_bars             exit=0
```

`ingest_index` 的报错原文（`close.err.log`）：

```
09-28,2000, (Caused by NameResolutionError("HTTPSConnection(host='proxy.finance.qq.com', port=443):
Failed to resolve 'proxy.finance.qq.com' ([Errno 8] nodename nor servname provided, or not known)"))
```

**因果链（一条都不许简化）**：

1. 15:30 那一刻 DNS 挂了（三台 K 线 host 全解析失败 —— 报错点名的是 P74a 回退链的最后一台
   `proxy.finance.qq.com`）。这是**瞬时**故障：2026-09-29 复核 `web.ifzq.gtimg.cn` / `ifzq.gtimg.cn` /
   `proxy.finance.qq.com` 三台 DNS **全部正常**（116.130.229.114 / 116.130.223.103 / 116.130.223.103）。
2. `ingest index` 失败 ⇒ **`trading_calendar` 没有前滚**（它是日历的**唯一**来源，见 `CLOSE_STEPS` 里
   `ingest_index` 的 `why`）。日历 max 停在 `2026-09-24`。
3. ⇒ `predict run --asof 2026-09-28` 被 `predict/service.py::assert_session` 判「非交易日」拒绝（fail-closed 设计**是对的**，不许改）。
4. ⇒ 下班链整体停在 9/14 步：**09-28 没有 live 预测、没有验证行、没有 `reports/2026-09-28-review.md`、
   `paper step` 没跑**。
5. **二次伤害**：18:30 的 AI 操盘手日更 cron 第 1 步判「今天是不是交易日」拿到 `unknown`
   （日历未覆盖 09-28）⇒ 该轮 **7.6 s 就结束、一条决策没写、一条消息没发**（`cron/jobs.json` 的
   `runHistory`: `runAtMs 1790594910897, durationMs 7627, status ok`）。⇒ 那天三条 AI 臂**零决策、零净值**。
   （这一步的修法**不在本站范围** —— nanobot 已改 cron prompt：只有 `is_trading_day=False` 且原因是休市才静默结束，
   `unknown` 必须先 `ingest index` 补日历再重判、仍不行要发消息。）
6. 次日 09:00 巡检 `--fix` 把日历补到 09-29（**自愈是有的，但只在下一个交易日早上**）⇒ 那一天的数据**回不来**。

**本站要修的不是「DNS 会挂」（那修不了），而是「一次瞬时失败就判死一整天、整条链一次重试都没有」。**

## §0.5 拍板点（已由 nanobot 锁定，站不逐项问）

| # | 锁定项 | 内容 |
|---|---|---|
| L1 | 只加重试，不改判据 | **不碰** `predict/service.py::assert_session`（fail-closed 是对的）、**不碰** `bars_finalized_on`、**不碰** `worst_code` 的三条停止线语义、**不碰** `cross_db_refusal` |
| L2 | 默认零行为变化 | `run_steps` 新增的重试入口必须是**可选参数**，缺省 `None` ⇒ **调用方（含巡检与全部既有测试）逐字节不变**：同一步骤仍只被调用一次 |
| L3 | 重试对象 | 只重试**幂等**且**联网络**的采购步：收盘链的 6 条 `ingest *`（`ingest_index` / `ingest_index_500` / `ingest_bars` / `ingest_actions` / `ingest_valuation` / `ingest_moneyflow`）＋ 月度链的 `ingest_*`。`session_*` / `predict_run` / `verify_pending` / `review_daily` / `paper_step` / `m2_daily` / `doctor` **一律不重试**（重试它们只会掩盖真问题；且它们不是网络故障的形状） |
| L4 | 重试预算 | 每步最多 **3 次尝试**（首次 + 2 次重试），两次重试之间 `sleep` **15 s**；**重试必须落在整轮 deadline（900 s）之内** —— `remaining <= 0` 时不再重试，按既有 `budget_exhausted` 路径收尾 |
| L5 | 计数不许丢 | 每一步的结果里**只增**键：`attempts`（实际尝试次数）、`retried`（bool）、`exit_codes`（每次尝试的退出码列表）。**`exit_code` 仍是最后一次尝试的值**（下游 `worst_code` / 回执摘要 / `bad=` 的全部既有语义因此不变） |
| L6 | 不静默 | 重试过就在该步结果里如实留痕，并在 `anomalies` 里新增一条**只增**的条目（`kind="step_retried"`，文案含 step 名与每次的退出码）；重试后成功 ⇒ 该步 `exit_code=0`，整链**不该**因为它变红，但必须能看出「它重试过」 |
| L7 | 真库与子进程纪律 | 测试一律注入 **FakeRunner**（`runner=` 参数），**绝不起真子进程**；`ingest *` / `ops close` / `--fix` **不许**在真库上跑；写实测只在 `/tmp` 副本 |
| L8 | 只增不改 | 回执 JSON 既有键（`steps`/`bad`/`anomalies`/`aborted`/`exit_code`/`ok`…）的**语义与取值规则**不变；新增键只增不改 |
| L9 | 不改计划本身 | `CLOSE_STEPS` / `MONTHLY_STEPS` / `WEEKLY_STEPS` / `QUARTERLY_STEPS` 的**步骤清单与顺序**一个都不许动；只给步骤挂「可重试」标记 |

## §1 T1 执行器支持可选重试（`stocklab/ops/runner.py`）

1. `run_steps(...)` 新增关键字（名字站自定，建议 `retry_plan: Mapping[str, int] | None = None`、
   `retry_delay_s: float = RETRY_DELAY_S`），语义：

   - `retry_plan is None`（缺省）⇒ **完全走现在的代码路径**：每步一次、无 sleep、结果无新键。
   - `retry_plan` 里出现的 step 名 ⇒ 该步最多尝试 `retry_plan[name]` 次（`1` 与缺省等价）。
   - 只在「本次尝试有**失败形状**」且「还有剩余尝试」且「deadline 还够」时重试。
     失败形状 = `exit_code` 非 0 或 `exit_code is None`（子进程没起来）；**`timeout` 不重试**
     （超时说明预算/挂死，重试只会更糟）。
   - 每次尝试的耗时都要计入 `deadline` 判定；两次尝试之间 `time.sleep(retry_delay_s)`
     必须**也要**检查 deadline（sleep 不能把整轮拖过预算）。
2. 新增模块常量 `RETRY_DELAY_S = 15.0` 与 `RETRY_ATTEMPTS = 3`（放在 `runner.py`，写清为什么是这两个数）。
3. 结果 dict 的新键按 L5；`duration_s` 语义 = **全部尝试的累计耗时**（写进注释，别让人误读成最后一次）。

## §4 T4 测试（新增 `tests/test_ops_chain_retry.py`；旧用例不改）

必须用 FakeRunner（记录调用序列），至少覆盖：

1. `retry_plan=None` ⇒ 每步**恰好一次**调用（对既有行为的护栏）；既有 `tests/test_ops_*` 全绿。
2. 第 1 次 exit 1、第 2 次 exit 0 ⇒ 该步 `exit_code=0`、`attempts=2`、`retried=True`、
   `exit_codes=[1,0]`；整链 `worst_code` **不**因它升到 1（其余步全 0 时）。
3. 三次全失败 ⇒ `exit_code` = 最后一次的值、`attempts=3`、`exit_codes=[1,1,1]`，且
   `blocking=True` 时按既有停止线收尾（`step_fatal`/`worst_code`）。
4. `retry_plan` 里**没有**的步骤（如 `session_tick`）失败 ⇒ **不重试**（调用次数 1）。
5. deadline 不够 ⇒ **不再重试**（构造 `timeout_s` 很小的场景，断言 `budget_exhausted` 与调用次数）。
6. 子进程没起来（`exit_code=None`）⇒ 按 L1/L2 的既有语义收尾（`step_error`），并断言**不触发**重试
   （除非站能给出更强的理由；若选择重试，必须在 §7 写明并说明为什么不违反「一次失败就判死」的初衷）。
7. `sleep` 被 FakeRunner 场景下的 `time.sleep` 打桩隔离（测试不许真睡 15 s；用 monkeypatch 记调用次数与秒数）。
8. `ops close` 的假 runner 端到端：一条 ingest 步 1→0 ⇒ 回执里 `retried_steps` 有它、
   `anomalies` 有 `step_retried`，且**不写库**（`--report-dir` / `--backup-dir` 指向 `tmp_path`）。

### 7.5 偏离与理由（六条，逐条点名）

**① 任务书内部冲突：`exit_code is None` 算不算「失败形状」**
§1.1 的规范定义是「失败形状 = `exit_code` 非 0 **或** `exit_code is None`（子进程没起来）」，
而 §4.6 的缺省倾向是「断言**不触发**重试（除非站能给出更强的理由）」。二者在可观测断言上
互斥。取 **§1.1 的字面**（`None` ⇒ 会重试），理由：起不来在 15:30 那种并发压力下
（fork / FD 耗尽）同样是**可能瞬时**的，而重试的代价被 deadline 与尝试上限双重封顶；
真要一直起不来，三次后照旧如实报 `step_error` 断链。§4.6 明确给了「选择重试并写明理由」
的出口，本条即为那处说明；用例是
`test_a_child_that_never_starts_is_retried_then_ends_as_step_error`（断言 3 次尝试 ＋ `step_error`）。

**② 任务书内部冲突：L3 与「旧用例不改」不能同时成立 ⇒ 改了 1 条旧用例**
`tests/test_ops_close.py::test_monthly_a_blocking_step_failure_is_still_fatal` 断言
「失败的那一步**只被调用一次**」，而 L3（锁定项）要求月度链的 `ingest_*` 步重试
⇒ 该断言必然失败，且会真睡 30 s。硬约束（L3）优先于措辞（§4 的「旧用例不改」）。
改法是**保住牙齿**：仍断言「链停在这一步、退出码 2、后面的步一步没跑」，只把
「一步 = 一次调用」换成「一步 = `RETRY_ATTEMPTS` 次调用」，并把重试间隔打桩成 0。
除这一条外，旧用例**一行未改**（改后该文件 32 passed in 2.68s，此前因真睡需 37s）。

**③ 超出 §5 字面的两处文档（只增不改行为）**
`docs/README.md`（文档索引 +2 行）与 `docs/errors/ERROR_DIARY.md`（追加 #86）：前者是
「新文档要进索引」的仓库惯例（索引陈旧＝新 runbook 没人找得到），后者是 `CLAUDE.md`
的 DoD 明列项「有新教训已写入错误日记」。两者都只增、不碰任何判据。

**④ `retried_steps` 同时给月度链（任务书只写了收盘链的口径）**
T3.3 说的是「回执新增顶层键」。月度链也有重试计划，若只给收盘链，就会出现「月度链真的
重试了、而它的回执里没有这个键」的口径不一致。⇒ 收盘链与月度链都给；`weekly`/`quarterly`
**没有**重试计划 ⇒ 不加该键，它们的回执逐字节不变。

**⑤ 摘要行的 `retried=N` 只在真的重试过时出现**
L2 要求缺省路径逐字节不变，L6 要求「不静默」。两者同时满足的落点：**条件追加** ——
没重试时那一行与今天一模一样，重试过才多一段（`test_a_close_run_without_retries_says_nothing_extra`
钉住这一点）。

**⑥ 发现但**未改**的既有小错（越权，仅记录）**
`stocklab/cli/main.py` 里 `ops close` 的 `help` 与 `cmd_ops_close` docstring 写「13 步」，
而 `CLOSE_STEPS` 实际是 **14** 步（本档 L9 禁止动步骤清单，且那句 help 不在授权面内）
⇒ 记录在此，不做修改。
