## 0. 背景

### 0.1 一句话

**两个真实故障，都源于同一件事：全链路没人对「一手（100 股）够不够」负责。**

1. **AI 臂的买入腿全部落空**：2026-09-23 `arm-agent-ds-v1` 的决策要买 4 只
   （目标市值 ¥2,807.86 / ¥3,126.81 / ¥3,310.74 / ¥3,837.09），**四笔全部因
   「目标市值 < 一手含滑点成本」被判 `hold`** ⇒ 那天只成交了卖出 1 笔，该臂
   **09-24 整天 100% 现金**（`paper_nav_daily` 19553.68 平盘）—— AI 的意图
   （约 67% 仓位）与账户实际状态（0%）完全脱钩。
2. **随机对照臂两天 0 成交**：`arm-agent-random` 09-23 抽到 16.43% 敞口分 4 只
   （每只目标 ¥317 / ¥1,323 / ¥988 / ¥587，全部 < 一手）、09-24 抽到 **0.17% 敞口
   2 只（¥19.59 / ¥13.71）** ⇒ **两天零成交、净值恒等于 `arm-hold`**。
   ⇒ D-36 要求的「归因必需的对照臂」**实际是空的**：「AI 跑赢随机」这句话现在
   没有可比的对手。

### 0.2 证据（2026-09-26，真库只读）

| 读数 | 值 |
|---|---|
| `paper_trades` / `arm-agent-ds-v1` | **1 笔**（只有卖出 000333） |
| `arm-agent-ds-v1` 09-24 净值行 | `cash 19553.68 / mv 0.0 / positions []` |
| `paper_trades` / `arm-agent-random` | **0 笔**（净值行 `cum_cost 0.0`、持仓恒为种子 000333×100） |
| `paper_agent_decisions` / 随机臂 09-24 | `sum_weight_pct 0.17`、`cash_pct 99.83` |
| 09-24 ds-v2（对照） | 6 笔成交、`cum_cost 34.36` —— 因为那条决策的 reason 已逐条写明「≈1 手（含滑点）」 |

**代码事实**（不是猜测）：

- `rules.py:508-519`：`fill = costs.fill_price(side, price)`（**含滑点**），
  `qty = floor_lot(abs(delta)/fill, lot)`；`qty <= 0` ⇒ 返回 `_hold(...)`
  并写明「差 < 1 手 → 不动；目标未达成，如实上报」。**这是有意的口径，不改。**
  实测 09-23 的 4 笔：603868（目标 ¥3126.81 vs 一手 ¥3126.00）、000651
  （¥3837.09 vs ¥3836.00）**在不含滑点价上刚好够、加上滑点就翻负** ⇒ 4 笔全 hold。
- `engine.py:959`：`cash, positions, orders, _evals = agent_decide.execute_decision(...)`
  —— **`_evals` 被下划线丢弃**，`plan_orders` 算出来的「不动的理由」在 agent 路径上
  **一个字都不落库** ⇒ 页面/报告上只看到「这条臂没动」，看不到「为什么没动」。
- `agent_decide.random_payload`（v3）：`exposure = rng.uniform(0, cap)`、
  权重 = `exposure × rand/Σrand` —— **抽样完全不管整手**，抽到低敞口就必然 0 成交。
- `agent_context.build_decision_context`：喂给 AI 的上下文里**没有任何一手价 /
  最小可成交权重的信息** ⇒ 模型只能靠猜（09-24 的 ds-v2 猜对了，09-23 的 ds-v1 没猜对）。

### 0.3 为什么这值得单独立站（而不是「AI 再聪明点就行」）

- **不是 AI 的问题，是接口的问题**：一手成本在 A 股跨标差 10 倍以上
  （`601398` 一手 ¥813 vs `600519` 一手 ¥14 万+），2 万本金的账户上
  「目标权重 < 1.6%」就等于「不许买」。这条约束**必须写在输入侧**，
  不能靠模型自己悟；否则每次换模型/换提示词都要重新踩一遍。
- **对照臂是可执行性的直接受害者**：低敞口 + 分散 = 每只都不到一手 ⇒
  「随机臂」在实际账本上退化成「什么都不做」= `arm-hold` 的第二份拷贝，
  而 D-36 的 `delta_vs_random` 就是拿它做分母的。
- **不可见 = 不可审计**：`_evals` 丢弃让「AI 的意图 vs 落地」这件事在页面上
  完全不可见（本项目的一贯纪律：**不动的理由要能读**，见静态臂的 `evaluate`）。

### 0.4 与已有口径的边界（不许回退）

| 口径 | 谁修的 | 本站 |
|---|---|---|
| 敞口**上界** / 存量持仓不释放 | P64/P65/Q1-A、P66、P68（随机臂 v2→v3） | **一字不动** |
| 资金闸门 `_gate_cash` / `CASH_TOL` / `EXPOSURE_TOL` | P65 | **一字不动** |
| 整手向下取整、不足一手不凑 | `rules.plan_target_weight`（既有） | **算法一字不改**（本站只加「知情」与「留痕」） |
| 敞口**下界 / 可成交粒度** | —— | **本站修** |

## 0.5 锁定口径（按顺序执行；要改先回来说，不要自作主张）

- **D1｜不加硬拒绝**：`paper agent decide` **不因**「目标市值 < 一手」拒绝写入。
  那会把「AI 的意图」与「执行的可行性」混成一条闸门，把可观测的意图也一起杀掉。
  本站只做两件事：**输入侧把眼睛给足**、**执行侧把结果留痕**。
- **D2｜输入侧 `tradability` 块**：`build_decision_context` 新增**顶层**键
  `tradability`，形状锁定为
  ```json
  {"lot": 100,
   "min_weight_pct": 2.3104,
   "by_code": {"601398": {"one_lot_cost": 813.41, "min_weight_pct": 4.1534}, ...}}
  ```
  - `one_lot_cost = costs.fill_price("buy", price) * lot + _fee_parts(costs,"buy",fill,lot)["total"]`
    —— **必须复用** `CostModel.fill_price` 与 `_fee_parts`（一行费用公式都不许另写）。
  - `min_weight_pct = round(one_lot_cost / total_assets * 100, 4)`；`total_assets` 取
    与 `account.total_assets` **同一个数**（不许各算一份）。
  - 只含「当日有价」的池内标的（与 `marks` 的键集一致）。
  - `tradability` **加入 `DECISION_HASHED_KEYS`**（它是 AI 看得见的输入，必须进指纹）。
  - ⚠️ **必须写进文档并通报**：同一输入在 P79 前后 `decision_context_sha256`
    **不同**。台账里**已有的**两条决策（09-23 / 09-24）的 sha **一律不改写**
    （append-only）；`paper agent decide` 的 D-49 复核只对新写入生效。
- **D3｜执行侧留痕**：新表 `paper_agent_evals`（append-only），列
  `eval_id, arm, asof, code, action, reason, constraints_json, raw, created_at`；
  `UNIQUE(arm, asof, code)`；两个触发器（`UPDATE` / `DELETE` 一律 `RAISE(ABORT)`，
  **形状逐字抄 `paper_agent_decisions` 的既有触发器**，含 `PRAGMA recursive_triggers` 那条注意事项）。
  落库点＝`engine` 的 agent 执行路径（现在的 `_evals` 那一行）：**`_evals` 不许再丢**。
  迁移函数名 `migrate_p79_agent_evals`（放 `stocklab/store/migrate.py`，幂等、可重入）。
- **D4｜随机臂口径 v4（可成交抽样）**：在 v3 的抽取序列**之后**追加一步「可成交化」，
  且**所有随机都走同一个 `rng`**（逐字节可复现不许破）：
  1. 先按 v3 抽 `k` 只、`exposure`、`raw` 权重（**这些数只用于筛选，不进载荷**）；
  2. 每只算 `target = total_assets × w`，折算 `q_c = floor(target / one_lot_cost_c)`；
  3. 令 `S = {c : q_c ≥ 1}`：若 `S ≠ ∅`，权重改按**整手数**归一
     （`w'_c = q_c / Σ_{S} q × exposure_eff`），并保证每只在 `S` 里的至少 1 手；
  4. 若 `S = ∅` ⇒ **重抽**（`exposure` 重抽、其余不变），最多 `RANDOM_RETRY_MAX = 8` 次，
     用**同一个 rng 序列**继续；仍为 ∅ ⇒ 取「`one_lot_cost` 最小的池内标的」给 1 手
     （仅当 `现金 − 一手含费 ≥ 0`），否则全现金并在 `rationale` 里点名。
  5. `rationale` 必须自述「口径 v4」＋ 抽出几只/取整后几只/是否触发重抽；
     台账里 v1/v2/v3 的行**一个字不改**，代号写进 `rationale` 就是为了这个。
  - 约束：`cap` 的算法**不改**（仍是 P68 的 `100 − RANDOM_CASH_FLOOR − reserved`）；
    随机臂的**上界/现金底仓**语义不变，本口径只把「抽出来的敞口」映射到可成交的整手。
- **D5｜规则层零行为改动**：`rules.plan_target_weight`、`plan_orders`、
  `agent_decide._settle`、`_gate_cash`、`execute_decision` 的**订单/结算算法一字不改**
  （只允许把 `evaluations` 交出去、落库）。既有测试若因「evals 落库」而失败，
  **改测试的期望、不改算法**。
- **D6｜真库只读**：一切写实测只在 `/tmp` 副本；红线三目标**不 regen**，必须逐位 == 基线。
- **D7｜不动**：`stocklab/predict/`、`verify/`、`candidate/`、`ops/`、`m2/`、`data/`、`config/`、
  `MODEL_VERSION`、`CLOSE_STEPS`、`MONITOR_STEPS`。
- **D8｜站不写真库**：真库迁移与 rollout 由 nanobot 做（含备份）。

### 7.6 与任务书不一致之处（理由优先，不静默绕过）

1. **D2 的公式与 D2 的示例 JSON 互相矛盾**。公式
   `one_lot_cost = fill_price×lot + _fee_parts(...)["total"]` **含费**，而示例给的
   `601398 → 813.41` 是 `fill×lot`（**不含**费）。本站照**公式**实现
   （601398@8.13 → **818.4165**，示例的 2.3104 也必然不同）。
   理由：任务书原文说「必须复用 …，一行费用公式都不许另写」，且含费那一侧**更严**
   —— 目标 ≥ `one_lot_cost` 推得出执行层必定成交 ≥1 手（`plan_target_weight`
   判据用的是不含费的 `fill×lot`）。方向是「门槛只会更高」，与「风险规则错的方向
   必须是少投」同一条纪律。**示例里的数字不当作判据**（已写进 ADR-031）。
2. **D4 的归一式单遍跑不保证它自己声明的「S 里每只至少 1 手」**。反例：两只票
   `q = (1, 4)`、`rand` 占比 `(0.9, 0.1)` ⇒ 单遍重分后第一只掉到一手以下。
   本站把这一步收敛到**不定点**（每轮剔除又掉下去的，直到 `S` 不变）；`S` 一轮
   就没变时，权重与 D4 的公式**逐位相同**。
3. **D4 的「一手最便宜的池内标的」加了一条优先序**：候选**优先取未持有的**
   （`held_qty == 0`）。理由：已持有该票一手时，目标（1 手）与现市值（也是 1 手）
   之差 ≈ 滑点＋费（几元钱）⇒ `plan_target_weight` 判「差 < 1 手 → 不动」⇒
   **退路完全落空**，而那正是本站要修的失效。池内全持有才退回「最便宜的」（并在
   `rationale` 里如实说明可能不动）。
4. **`random_payload` 的 `asset_classes` / `cash` 是可选参数**：缺省时口径按
   **股票费率**（买入口径下股票 ≥ ETF —— 股票有过户费、ETF 没有 ⇒ 一手成本只会被
   算**高** ⇒ 门槛更严，少投方向）；`cash=None` 时退路走「全现金并在 rationale
   点名」。生产路径（`paper agent random`）**总是**传真值：口径走
   `asset_classes_for`（`instruments.type` 唯一真相、未登记即报错）。
   这偏离了「口径未知即报错」的严格读法，理由是**纯函数面**（T3 的 200 种子探针、
   既有夹具）没有库可查，而错的方向是保守的。已写进 ADR-031。
5. **`tradability` 的键集取 `marks ∩ pool`**（不是 `marks` 全集）：任务书原文
   「只含当日有价的**池内**标的」与括注「与 marks 的键集一致」在账户持有池外标的
   / marks 里出现指数时互相矛盾。取交集是唯一同时成立、且正好等于**决策空间**的
   读法（`validate_payload` 同时要求 `code ∈ pool` 且 `code ∈ marks`）。
6. **T4 的重放必须删当日成交**（不只净值行）：picks 的「现市值」由
   `_ledger_arm_state` 重放成交得出，只删净值行会让 sell 腿变成「0 与 0 相同 → 不动」
   （① 会多出第 5 行）、并让 ② 撞上 `side` 矛盾。删的是**副本**上的行（D6/D8：
   真库一个字节没动）。
7. **既有测试的 v3 断言按 v4 更新**（§7.5-B）——口径变了就是「同一输入、新口径」，
   不是绕过。三条读数（v3 的 8077.37 / 44.55 / picks 名单）**原样留档**在测试
   docstring 里，append-only 的精神照旧。
