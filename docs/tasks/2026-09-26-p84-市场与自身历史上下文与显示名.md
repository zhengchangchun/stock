### 0.6 两个块的字段表（逐字实现；键名不得改写）

`market`：

```python
{"asof": <asof>,                      # 决策日（不是数据日）
 "index": {                            # 键为 symbol；取不到就整条省略该 symbol
   "sh000300": {"level": float, "price_asof": str,
                "ret_5_pct": float|None, "ret_20_pct": float|None, "ret_60_pct": float|None},
   "sh000905": {...}},
 "breadth": {"asof": str|None,         # bars_daily 中 <= asof 的最近一个交易日
             "n_total": int, "n_up": int, "n_down": int, "n_flat": int,
             "up_ratio": float|None,   # n_up / (n_up + n_down + n_flat)，分母 0 ⇒ None
             "median_change_pct": float|None},   # 用 close/pre_close - 1 的中位数
 "valuation": {"asof": str|None, "n_total": int,
               "pe_ttm_median": float|None, "pe_ttm_p25": float|None, "pe_ttm_p75": float|None,
               "pb_median": float|None,
               "pe_ttm_median_250d_ago": float|None,
               "pe_ttm_median_change_pct": float|None},   # (今 - 250交易日前)/前，前为 0/None ⇒ None
 "money_flow": {"asof": str|None, "n_total": int,
                "main_net_sum_yi": float|None,      # SUM(main_net)/1e8，round 2
                "net_inflow_ratio": float|None},    # main_net > 0 的只数占比
 "notes": [...]}                       # 固定 1–3 条，说明「这是状态描述、不是信号」与口径
```

`own_history`（**只含 `arm` 自己**）：

```python
{"arm": <arm>,
 "nav_series": [{"date": str, "nav": float, "cum_return": float, "cum_cost": float,
                 "net_deposits": float, "drawdown": float|None,
                 "index_300_level": float|None}],     # 最近 ≤20 行，升序（最后一行 = asof 或之前最近一行）
 "n_nav_days": int,                                   # 该臂累计净值日数（全量 count，不是切片长度）
 "trades": [{"trade_id": int, "date": str, "code": str, "name": str|None,
             "side": str, "fill_price": float, "qty": int, "fee_total": float,
             "slippage_cost": float, "rule_citation": str, "reason": str}],   # 最近 ≤10 笔，升序
 "n_trades": int, "n_buy": int, "n_sell": int,
 "realized_fees_total": float,                        # 最新一行 cum_cost；无净值行 ⇒ 由 trades 求和
 "decisions": [{"decision_id": int, "asof": str, "decision_kind": str,
                "n_orders": int, "context_sha256": str,   # 全 64 位，别截断（对账要用）
                "n_trials": int, "n_rejected": int}],      # 最近 ≤5 条，升序
 "n_decisions": int,
 "notes": [...]}
```

`name` 取 `instruments.name`；`n_orders` 从该决策行的 `payload_json` 里数（`decisions` 数组长度，
解析失败 ⇒ `0` 并在 `notes` 里点名，**不抛异常**）。

### 0.7 派单方修订（2026-09-27，nanobot 追加；只覆盖 §0.6 里 `own_history.decisions` 的窗口口径）

**修订内容（只此一条）**：`own_history.decisions` 与 `n_decisions` 的取数窗口由
`arm = <arm> AND asof <= <决策日>` 改为 **`arm = <arm> AND asof < <决策日>`（严格早于决策日）**。
§0.6 字段表里的键名、字段、条数上限（≤5）、升序、`n_decisions` 是**全量计数**这些语义**一字不动**；
`nav_series` / `trades` 仍走 `store.load_nav` / `store.load_trades` 的 `date <= asof`（**禁改**）。

**为什么改（第一轮 §7.10 偏离 9 / §7.11 第 9 条上报的阻塞）**：`paper agent decide` 与
`paper agent random` 的 D-49 幂等判据是「重算 `context_sha256` 与载荷里的比对」。窗口含当天时，
写下一行就改变了**同一天**的上下文 ⇒ 重放同一天必然 sha 不等 ⇒ 走冲突分支 exit 1，而不是
「已存在且一致」exit 0。两条既有用例因此保持红：
`tests/test_paper_agent_decide.py::test_t2_replaying_the_same_decision_writes_nothing` 与
`::test_random_arm_is_deterministic_and_obeys_every_guardrail`（第一轮如实停手上报，不是漏做）。

选 `asof < 决策日` 而**不**选另外两条路的理由：① D-49 的判据面**不许动**（放宽重放 = 放行任何重放）；
② 对模型而言「当天那条**自己还没生成**的决策」不构成历史，写进上下文既无用又自指；
③ 改完之后，上下文只依赖**严格早于决策日、且已落定**（append-only）的行 ⇒ 每个决策日的上下文
**可复算** —— 幂等与可复现是同一件事。
