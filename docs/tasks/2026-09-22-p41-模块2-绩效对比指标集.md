## 0. 一句话

模块2 的「绩效对比」目前只做到 `NAV 曲线 + 指数点位`（`/lab/paper`），**没有需求 02 §4 点名的指标集**
（总收益 / 年化 / 最大回撤 / 盈亏比 / 胜率），也没有任何「样本够不够」的门禁标注 ——
于是现在**无法诚实回答「AI 模拟调整有没有跑赢大盘」**（只有 6 个交易日的曲线，看图会说谎）。
本任务＝把 §4 的指标集补齐，并且**每个数字都自带样本量与非显著性标注**。

## 1. 目标行为

### T1 绩效指标（**复用既有实现，不新造公式**）
- 新增 CLI：`stocklab paper metrics [--db] [--as-of] [--json|--out]`，对**每个模拟盘账户**（`paper_accounts`
  全部 arm）与 **基准 `sh000300`** 输出需求 02 §4 的五个指标：
  **总收益 / 年化 / 最大回撤 / 盈亏比 / 胜率**。
- 口径来源（**逐字复用**，不许另写一份）：
  `stocklab/backtest/metrics.py`（收益/年化/MDD/Sharpe 等既有实现），以及 `paper/` 里既有 NAV 口径；
  「盈亏比 / 胜率」若既有模块没有现成实现，**在 `backtest/metrics.py` 里加**（唯一真源），
  并同时被 `backtest` 与 `paper` 两侧复用 —— 不许在 `paper/` 里平行实现一份。
- **基准对齐**：`sh000300` 的同一区间、同一交易日轴；缺数据 → 该指标 `None` + 原因，**不许**用相邻日顶替。
- 期初口径：`initial_nav`（`paper_accounts`）与实盘镜像账户的**同一起跑日**；`arm-hold` 是冻结快照，
  报告里必须**显式标注它是「不动」臂**，不得当成 AI 表现。

### T2 样本量与显著性门禁（**这是本任务的重点，不是附属**）
- 输出必须带：`n_sessions`（交易日数）、`n_folds`（若有）、`threshold=120`、
  `gate_status ∈ {ok, insufficient}`（`n_sessions < 120` → `insufficient`）。
- `insufficient` 时：**所有绩效数字旁边打印「样本不足，仅供观察；不得据此选策略或改口径」**，
  且**不得**给出任何「跑赢/跑输」的结论性措辞（只给数字）。这是 `CLAUDE.md` 度量纪律第 3 条的结构化落地。
- 超额（相对 `sh000300`）与相对 `arm-hold` 的差值都要出，但同样受门禁约束。

### T3 页面（`/lab/paper` 新增一节，或复用既有块）
- 一节「绩效对比（模块2 §4）」：每 arm 一行 × 五指标 + 基准一行；表头显示 `n_sessions` 与门禁状态。
- 既有 blocks 与键名**只增不减**；`render.glance_html()` 的转义约定照旧（ERROR_DIARY #50）。
- 无数据/未 init 的账户 → 显式显示「未 init / 无净值行」，**不许**显示 0 或空白。

### T4 一致性自检
- CLI 的 JSON 与页面渲染必须来自**同一份数据函数**（同 `paper_data.py` 内），
  页面不许自己算一遍（两处必然走样）。

## 2. 必须新增的测试
1. **指标正确性**：构造已知 NAV 序列（含一次回撤）→ 手算 总收益/年化/MDD/盈亏比/胜率 → 逐位一致。
2. **门禁**：`n_sessions = 6` → `gate_status == "insufficient"` 且输出里出现「样本不足」提示；
   `n_sessions = 130` → `ok`。
3. **基准缺失**：删掉 `sh000300` 行 → 超额为 `None` + 原因，不抛异常、不用相邻日顶替。
4. **页面契约**：既有 `/lab/paper` 断言不变（键名只增不减），新增节的字段存在且无 `None`/`NaN` 裸值。
5. ⚠️ **ERROR_DIARY #55**：CLI 用例**必须**注入假 runner，绝不真起子进程（采集类命令不接受 `--db`，会写真库）。
