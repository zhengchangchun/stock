## 0. 一句话

把 `arm-agent` 从「改纪律数字的臂」重构成「**每交易日独立做一次决策的操盘手**」：
**方向 ＋ 仓位 ＋ 池内自由选标的**，每次决策全字段落 append-only 台账，
与 **5 条对照臂**（D-36）同口径、同成本、同页面并列。

## 1. 决策口径（三条，写死）

1. **决策空间**（D-34）：`每交易日一条决策` ＝
   `{asof, decisions:[{code, side, target_weight_pct, reason}], cash_pct, rationale}`。
   - `code` **必须落在当日候选池**（短/中/长三池并集，`candidate` 快照；池外 ⇒ 拒绝）；
   - `target_weight_pct ∈ [0, 100]`，全部 `target_weight_pct` 之和 ＋ `cash_pct` = **100（不许杠杆、不许负权重）**；
   - **A 股无做空**：「看空」只能表达为**降低总仓位 / 清仓**。这一条要写进文档与报错文案 ——
     否则「AI 想卖空」会被读成静默失败。
2. **频率**：每交易日一次，按「最新已收盘交易日」判定（复用 `session.tick` 的口径，**不看墙上时钟**）；
   非交易日不出决策（留痕，不补造）。
3. **护栏（不许的）**：杠杆/负权重、池外标的、接券商下单、用 `> asof` 的数据、参数搜索、
   改主干常量（熔断阈值 / 自评估边界 / `approve` 闸门）。这些**进护栏**，不再进「白名单」。

**决策由谁来产生**：**在项目外**。项目内只做「校验 → 落库 → 执行 → 计账」四件事，
由 `paper agent decide --asof <day> --file <decision.json> [--model-id … --prompt-sha256 … --seed …]` 写入。
理由：① 与 D-1「系统内不实现自动生成」同精神；② 项目保持**离线可测、零 API key**；
③ 台账里 `model_id / prompt_sha256 / context_sha256 / seed` 足以复现与追责。
（若你日后要改成项目内直连模型，代价是：离线测试失效、密钥进环境、`paper/` 引入网络依赖 —— 三条都要另立 ADR。）

## 2. 对照臂（D-36，5 条并列）

## 4. 反目标

- ❌ 不删/不改阶段 1 的台账与历史行（`paper_agent_decisions` 只增；新列用 `ALTER TABLE ADD COLUMN`）。
- ❌ 不引入杠杆/做空/融券；不做参数搜索；不做「AI 自动生成脚本」（D-1/D-24 不变）。
- ❌ 不改主干常量、不放宽 `approve` 闸门、不动 `predict/verify` 与 `MODEL_VERSION`。
- ❌ 不碰模块2 的 P47/P48/P49/P50 任务书涉及的文件（`m2_*` 插桩、绩效指标集）。
- ❌ 不把「基金等权臂」写成指数（它是**持仓未知的基金组合**，不是指数）。
- ❌ 不 `git commit`、不建分支/worktree。
