### 4.3 反向自检（扫描本身有区分力）

`test_scanners_flag_a_planted_violation` 用 `tmp_path` 造一个假源码树，
里面同时含 ①裸名重绑定 ②`limits.X = ...` 属性重绑定 ③`setattr(limits, ...)`，
外加 `labweb/` 里的一处引用 —— 三条扫描函数**必须各自判红**；
`test_scan_is_not_vacuous_on_the_real_tree` 另外断言真实源码树上扫到的文件数 > 50
且 `config/limits.py` 在扫描集合内（防「扫描零个文件也全绿」，ERROR_DIARY #50）。

### 4.4 写这条测试时的一次实测推翻（留痕）

`test_corrupted_audit_row_makes_folding_raise` 初版想用
`UPDATE plugin_audit SET action='bogus'` 造一条坏行，实测被**更上一层**挡下：

```
sqlite3.IntegrityError: CHECK constraint failed: action IN
   ('submit','sandbox_pass','sandbox_fail','approve','reject','archive',
    'start_validation','finish_validation','freeze','unfreeze')
```

即真实的坏行在本 schema 下**造不出来**（这正是纵深的第一层）。于是该测试改为
monkeypatch `store.list_audit` 喂**桩行**，直接打折叠那一层 ——
否则「折叠会拒绝未知事件」这句话就没有任何可失败的证据。

## 5. 未验证口子 / 剩余不确定性（A7 点名）

1. **`active_script_id` 只认 `active`**：脚本进入 `validating` 后不再被解析为在役版本。
   P44 **无生产调用者**（只有测试触发这些事件），故主干链不受影响；
   「验证期算不算在役」留给 **P48** 显式决策。当前行为由
   `test_validating_version_is_not_resolved_as_active` 钉住。
2. **常量扫描只覆盖 `stocklab/`**：`scripts/` 与 `docs/` 里写死的数字扫不到。
3. **真库尚未前滚**（§3.1 实测）。下一次任一写库入口会自动触发（会先备份）。
   本次**不手工迁移真库** —— 遵循 ADR-015 的单一入口原则。
4. **`CIRCUIT_BREAKER_DRAWDOWN` 尚无消费者**：本任务只落常量，熔断判定逻辑是 P48；
   该值目前**没有任何代码路径读它**（除了测试）。这不是缺陷，但**不得**被读成
   「熔断已实现」。
5. **两个白名单的真源一致性**：`store.ALLOWED_ACTIONS` ↔ `plugin_audit` 的 CHECK、
   `validation.EVENT_KINDS` ↔ `validation_events` 的 CHECK，各由一条测试断言**逐字相等**
   （`test_action_whitelist_matches_schema_check` /
   `test_event_kinds_match_schema_check`）。**仍存在的弱点**：两处白名单本身
   仍是两份手写清单，测试只能保证「此刻一致」，加新事件时要记得同时改两处。
6. **`/tmp/backups/` 残留**：§3.2 的副本前滚在 `/tmp/backups/` 留了一份备份
   （仓库外，不影响打包与 `git status`），未清理是因为清理命令被拒。
