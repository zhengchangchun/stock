## 0. 一句话

资金流的源站（新浪 MoneyFlow）是 **T-1 发布**：当天收盘后拿不到当天数据。
现在这条链路为此付了两笔**不必要的代价**，本站各修一处：

1. **采集**：`fetch_money_flow_daily` 为了拿最后 1 行，**每天把 21 只标的 2010 年至今的整段历史翻一遍**
   （≈882 次请求 / **269 s** / 写入 0 行）；改成「翻到 `start` 边界即停」目标 ≈21 次请求 / ~5 s。
2. **判据**：⑦ 把「第三方发布节奏」当成自己的 SLA ⇒ **每天 15:35 固定挂一条 stale**，
   整轮 `ops close` 常年 exit 1。改成三档 `ok / lag / stale`，其中 `lag`（恰好差一个交易日、
   且有「该行是收盘后才拿到的」证据）**不计异常、但仍排补步**。

**这一条也不许放松**：`lag` 只容许**恰好一个交易日**；差 ≥2 个交易日、或证据显示源站当天发布过
却拿不到 ⇒ 仍判 `stale`（真缺口照旧报红）。**不许**把 ⑦ 改成「永远 ok」。

## 1. 实测证据（nanobot 2026-09-24 自跑，真库只读或纯网络、零写入）

**① 源站是 T-1（`money_flow_daily` 的「日期 vs 写入时刻」实测）**

| `date` | 行数 | 首次写入 `fetched_at` |
|---|---|---|
| 2026-09-22 | 21 | **2026-09-23T09:01:02** |
| 2026-09-23 | 21 | **2026-09-24T09:00:57** |

⇒ 每天的资金流行都在**次日早间**才入账；15:30 收盘链跑时当天数据**尚未发布**。
补它的是**早间 patrol 的 `--fix`**（`job_runs` run_id=119 / 09:00:04：
`fixed=ingest_actions,ingest_valuation,ingest_moneyflow,session_tick,session_backfill_close`，exit=0）。
**这条自愈路径必须保持可用**（见 §2 T2 的排步要求）。

**② 采集成本（纯网络探针，单页请求）**

```
page=1 用时 0.27s 行数=100 日期 2026-05-06 … 2026-09-23
page=2 用时 0.17s 行数=100 日期 2025-12-01 … 2026-04-30
page=3 用时 0.33s 行数=100 日期 2025-07-04 … 2025-11-28
PAGE_SIZE = 100
```

**③ 今天的实际开销**：`ops close` 的 `ingest_moneyflow` 步 **duration_s = 269.647**（其余 13 步合计 ≈60s）。
按 ① 的口径，它**一行都没写**（`money_flow_daily` 当日 0 行）。数据侧：每只标的 **4019 行**
（2010-03-01→2026-09-23）⇒ 41 满页 + 1 短页 ≈ **42 请求/只 × 21 只 = 882 请求**
—— 与 269s / 单请求 0.17–0.33s 对得上。而 `--days 30` 只需要**第 1 页**（覆盖 4.7 个月）。

**④ 假警**：15:30 那轮 `reports/ops/latest-close.json` 的 `after.anomalies` 只有一条
（⑦ `money_flow_daily max=2026-09-23`），整轮 `exit_code=1`；而 14 步本身**全 exit 0**。

## 2. 口径（实现必须逐条对上）

### T1 采集：翻页到 `start` 边界即停

- `stocklab/data/fetch.py::fetch_money_flow_daily`：页按 `opendate` **降序**（`asc=0`）⇒
  某页的**最老一行 `<= start`** 时，再往后翻只会拿到 `< start` 的行 ⇒ **立即停止翻页**。
- 其余一个字不改：`len(rows) > page_size` 的源站口径拒绝、`len(rows) < page_size` 的到头判定、
  `[start, end]` 过滤、按日期升序返回、`MAX_PAGES` 安全阀、raw cache 的 key 形状。
- **输出必须逐条不变**：同 `(code, start, end)` 下，新旧两版返回的行**逐条相同**（用对拍用例钉住，
  不是「看着一样」）。
- 边界：`min(page dates) == start` **可以停**（该页已含 `start` 那天的行，更老的必然 `< start`）。

### T2 判据：⑦ 拆子项，`lag` 不计异常但照旧排补步

- ⑦ 现在把 `valuation_daily` / `money_flow_daily` / `adj_factors` 三件事压成一个 `status`。
  改成**子项各自有状态**（键只增不减，旧键保留：`valuation_max` / `money_flow_max` /
  `adj_factors_rows` / `required` / `reason` 照旧）：
  - `valuation`：`ok` / `stale`（照旧，当日已能拿到——实测 2026-09-24 已入库）；
  - `money_flow`：**三档**
    - `ok`：`max >= required`；
    - `lag`：`max` 恰好等于 `required` 的**前一个交易日**，
      **且**该行的首次写入时刻 `> max` 那天的收盘（15:00）—— 这条是**从数据里读出来的证据**，
      不是「假设源站 T-1」（样本：`max=2026-09-23` 的 `fetched_at=2026-09-24T09:00:57`）；
    - `stale`：其它全部情形（差 ≥2 个交易日；**或**恰好差 1 天但证据显示源站当天就发布过
      —— 那是我们**采集中断**，不许读成 `lag`）；
  - `adj_factors`：`ok` / `stale`（照旧）。
  - ⑦ 汇总 `status`：任一子项 `stale` ⇒ `stale`；否则任一为 `lag` ⇒ `lag`；否则 `ok`。
  - 另给两个**只增**的键：`required_money_flow`（`lag` 时＝`max`，即「按源站节奏该有的那一行」）、
    `lag_sessions`（`required` 与 `max` 差几个交易日）。
- **`lag` 不进 `ANOMALY_STATUSES`**（⇒ 不影响 `verdict` / 整轮 exit code），
  与 ② 的 `unknown`「不计异常但补步仍然会去采一次」同款（`verdict()` 的 docstring 已把这个先例写死）。
- **但 `plan()` 仍要排补步**，且**按子项排**：`money_flow` 落后 ⇒ 排 `ingest_moneyflow`；
  `valuation` 落后 ⇒ 排 `ingest_valuation`；`adj_factors` 空 ⇒ 排 `ingest_actions`。
  （今天是一条 stale 就三样全排；按子项排更准，也少白跑。）
- 报告/页面：`lag` 的 `reason` 必须**人话点名**，例如
  「资金流源站 T-1 发布：最近一行 2026-09-23（2026-09-24T09:00:57 写入），
  2026-09-24 的行按同一节奏在下一交易日早间补落 —— **不算缺口，但要补**」。

### T3 `job_runs` 的时长不再恒为 0（顺带，A6「文件在说谎」）

- 实测：`ingest_moneyflow` 的 `started_at == finished_at`（如 `2026-09-24T15:31:03`），
  因为整条命令共用一个启动时刻 `now` 传给 `finish_job`。
- 修：`stocklab/data/ingest.py`（bars）、`stocklab/cli/main.py`（actions＋valuation/moneyflow 两处）
  在**收尾时取一个新的时刻**写 `finished_at`（`datetime.now(TZ)`），`started_at` 不动。
- 判据：一条**慢**的假采集（注入假 client，人为 sleep 或用假时钟）在 `job_runs` 里
  `finished_at > started_at`，差值反映真实耗时；并**实测一次真库外的对照**（副本或纯 fetch）。
- 注意：`job_runs` 里 49/52/72 三条永久 `running` 是 2026-09-22 的历史残留，**不要动**。

## 5. ERROR_DIARY 要加的一条（本站必须写）

> 题目自拟，但必须覆盖两句教训：
> ① **「为了拿最后一行，把整段历史翻一遍」**——分页方向与过滤时机不一致（先翻到底再按 `start` 过滤）
>    会让「增量窗口」在请求数上完全失效；实测 882 请求/269s 换 0 行新数据。
> ② **判据把第三方的发布节奏当成了自己的 SLA**——于是每天都稳定地报一条假警，
>    而「每天都有、每天都一样」的告警会被读成背景噪音（与 #53「调度器 ok ≠ 数据链 ok」同族，
>    但方向相反：这次是**数据链正常而调度判据说谎**）。修法是让判据**从数据里读出**滞后证据。
