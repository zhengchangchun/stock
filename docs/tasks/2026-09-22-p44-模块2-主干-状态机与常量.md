## 1. 目标（三件，工期只做这三件）

### T1 模块2 状态枚举（D-29）
- 在既有 `plugin_audit` 事件流折叠里新增两态：**`validating`（验证中）**、**`frozen`（策略冻结）**；
  主干 5 态（`draft/pending_review/rejected/active/archived`）语义**一个字节不改**。
- 新增事件类型（举例，命名以既有事件风格为准）：`start_validation` / `finish_validation` /
  `freeze` / `unfreeze`；**未知事件一律拒绝**（不许静默忽略 —— 静默忽略会让状态与事件流不一致）。
- **「已回滚」不设独立态**：回滚 = 对 `archived` 版本 `approve`，状态回 `active`（D-3/D-29）。
- `approve` **仍然只能人工 CLI**（源码扫描测试已有，不许放宽）。

### T2 主干常量（D-27/D-28）——单一真源 + 「AI 改不了」的结构保证
- 新增集中常量（放 `stocklab/config/`，与既有成本/口径常量同处）：
  | 常量 | 值 | 来源 |
  |---|---|---|
  | `CIRCUIT_BREAKER_DRAWDOWN` | `0.10` | D-4（验证期内自峰值回撤 ≥10% → 策略失效） |
  | `VALIDATION_ROUNDS_MIN` / `_MAX` | `2` / `3` | 需求 02 §5 |
  | `VALIDATION_MAX_DAYS` | `30` | 需求 02 §5 |
  | `FREEZE_MAX_DAYS` | `90` | 需求 02 §5 |
- **必须有三条结构保证 + 对应测试**（不是注释纪律）：
  1. **单一真源**：这些数字在整个仓库只出现一次（源码扫描测试：别处出现字面量 0.10/30/90 的
     相关用法要红）；
  2. **无外部覆盖路径**：AST/源码扫描证明没有「从脚本 / 请求 / spec 赋值给这些常量」的代码路径；
  3. **无写入口**：Web 层不存在能修改它们的路由（本任务只要求扫描 `labweb/` 路由表与 handler）。
- **越界一律拒绝，不许 clamp**：例如 AI 给的验证周期不满足边界 → 报错并要求重新生成（D-28）。

### T3 验证周期台账（append-only）
- 新表（命名以既有风格为准，示例）：`validation_cycles`（周期：策略 + 插件版本 + 计划轮次/天数 +
  起止 + 终态 + 原因）、`validation_rounds`（每轮：周期 id + 轮序 + 观测窗口 + 结果指标 + 备注）、
  `validation_events`（熔断/冻结/解冻等事件，含触发时数值与判据原文）。
- **append-only 触发器**（`RAISE(ABORT)` 拦 UPDATE/DELETE），与既有表同款；
  状态变化**只能靠追加事件**，不许 UPDATE 状态列。
- schema 前滚走既有 `store/migrate.py::ensure_schema` 单一入口（ADR-015）+ 幂等（跑两次 `count(*)` 不变）。
- 台账写入必须能回答「**这一轮用的是哪个策略版本、哪组参数、判据原文是什么**」。
