## §0 背景（要解决的三个具体问题）

1. **新因子进不了 harness**。`research factor-ic`（P83）只评两组因子：`MAIN_FACTORS = ("mom20","vr15")`（出 verdict）
   与 `SECONDARY_FACTORS = FACTOR_FEATURE_KEYS`（5 个财务因子，**只报不判**）。二者都从 `ctx["features"]` 取值
   （`candidate/run.py::_factor_payload`）。P95 §5 盘出的 4 类新候选（资金流 / 估值 / 公告 / 财务升格）**全部不在 `ctx` 里**，
   按 ADR-038 决定五也**不该进 `ctx`**（进 `ctx` = 进打分路径 = 改生产 + 多变量）。
   ⇒ 现在没有任何合法路径让 `gm_yoy_pp` 出 verdict，或让 `mf_ratio_5d` 这类新量进同一套 IC/分层/bootstrap 判据。
2. **`gm_yoy_pp` 卡在「不足以采纳、也不足以忽略」**（P95 §3.4）：唯一正读数（+0.013433、CI [+0.0013,+0.0254]、t 2.111）
   与多重比较族大小（22.6%）＋ 有效样本折扣（`t_eff≈0.63`，抄自实测「每只 P50 = 15 条公告」）同时成立。
   唯一合法出口 = **把它升格成主读数，再跑一次单变量预注册实验**（P95 §9 拍板点 1）。**本任务是那条出口的前置**。
3. **产物同名静默覆盖**：`write_report` 落 `f"{end}-factor-ic-{universe_id}.{json,md}"`（`factor.py:788`）。
   换一个因子、同一个 `--end` / `--universe` ⇒ **覆盖上一份产物、读数直接丢**（P60 已有同类前科，见 `docs/experiments/README.md` 2026-09-25 那条）。
   **这是本次唯一「不做就会丢数据」的点**（P95 §6.4 原话）。

## §1 T1 研究侧因子注册表 ＋ 取值器层（`stocklab/research/factor.py`）

1. 新增常量：

   ```python
   RESEARCH_FACTORS: tuple[str, ...] = ("mf_ratio_5d",)   # 只有需要新取值器的才在这里
   PROMOTABLE_FACTORS: tuple[str, ...] = ("gm_yoy_pp",)   # ctx 里已有、可升格为主读数
   ```

   - 两个常量都要有注释写明「为什么它在这、为什么不塞进 `FACTOR_FEATURE_KEYS`」。
   - `gm_yoy_pp` 放 `PROMOTABLE_FACTORS`（值已随 `PipelineResult.factor_inputs` 暴露，取值器零新增）；
     `mf_ratio_5d` 放 `RESEARCH_FACTORS`（走新取值器）。**不许**两边都放（同一条路只留一个入口）。
   - 新增 `FACTOR_SOURCES: dict[str, str]`（`name -> "ctx" | "research"`）作为唯一真源，
     `--factor` 校验、「缺省逐位不变」的自证、报告里的 `source` 键都从它取。

2. 新增研究侧取值器：

   ```python
   def _research_value(conn, code: str, asof: str, name: str) -> float | None
   def mf_ratio_5d(conn, code: str, asof: str) -> float | None
   ```

   - **逐字公式（P95 §5.1 MF-A，不许改写）**：
     `mean( money_flow_daily.ratio_amount for date in 最近 5 个交易日, date <= asof )`。
     「最近 5 个交易日」= `trading_calendar` 里 `date <= asof` 的最后 5 个日期（**不是** `asof-5 自然日`）。
   - **PIT 锚 = `money_flow_daily.date`**，一律 `date <= asof`。
   - **缺失一律 `None`，不补 0**：5 日中**任一**为 `NULL`（或行缺失）⇒ `None`。
   - **不做横截面 winsorize**（rank IC 对单调变换不变；winsorize 只制造并列）。
   - 取值器必须**批量友好**：同一个 `asof` 下对 800 只标的取值，**不许**每只一条全表扫描的 SQL
     （要么一次查该 `asof` 窗的行、要么按 `asof` 缓存）；实现里要写明复杂度。
   - 报告里登记的 `source` / PIT 锚 / 缺失语义要有注释出处（指向 P95 §5.1）。

3. **取值来源参数化**（L6）：`one_factor(...)` 新增可选关键字（名字站自定，如 `values_by_mark=None`）：

   - `None` ⇒ **当前行为逐位不变**（走 `factor_values(payloads_by_mark[d0], value_of)`）；
   - 给了 ⇒ 该因子的逐调仓日 `{code: value}` 从外部来源取（研究侧取值器预计算），
     `None` 的标的不进截面（与 `factor_values` 同规）。
   - 既有 7 个因子的调用点**语义不变**（`MAIN_FACTORS` 2 个 + `SECONDARY_FACTORS` 5 个）。

### 7.7 偏离 / 与任务书不一致处（逐条点名）

1. **§3.2「报告新增键（只增）：`factor_tag`（缺省 None）…」vs §6 第一判据「缺省 ⇒ 报告 JSON 逐字节相同」** ——
   两条**不可同时满足**（新增键必然改 JSON）。按硬约束优先：**缺省路径一个新键都不出现**，四个新键 ＋ `research` 段
   **只在给了 `--factor` 时出现**（`write_report` 里 `factor_tag` 也只在非空时挂后缀）。同族前科 ＃48/＃66/＃84
   （判据互斥 ⇒ 硬约束优先＋逐条点名，不改口径）。
2. **`validate_prereg` 的期望主名单在 `--factor` 下扩成 `MAIN_FACTORS ＋ 被选因子`**（缺省时一字不变）——
   不这么做，L7「被选因子名必须已在预注册里」＋ L11「`PREREG_FIELDS` 一字不动」会把 `RESEARCH_FACTORS`
   变成**永远跑不到的死代码**（新因子写进 `factors` 就撞 `factors == MAIN_FACTORS`）。P95 §8 已把 P98 写成
   「零代码（纯跑 ＋ 预注册 ＋ 产物）」，这条扩法正是让 P98 成立的那一步。
3. **研究侧取值结果按宇宙成员裁剪**（任务书未写）—— 冒烟实测裁剪前 `value_coverage_p50 = 805 > 800`、裁剪后 **800**（== 宇宙只数），不裁剪会与 `ctx`
   那一路不同规并放松 `LOW_COVERAGE` 闸门；已补钉用例 ＋ 写进 ADR-045。
4. **冒烟窗口取 3 个月**（≤ 6 个月上限内），非 6 个月 —— 真库单 mark ≈ 24 s（P83 外推），6 个月 ≈ 14 min；
   3 个月（14 marks）已够证明「新取值器在真数据上跑得通」。**不作任何结论**：13 周期 << `MIN_VALID_PERIODS`=120，
   `verdict = INCONCLUSIVE`，且报告 `rule` 字段写明「[冒烟] 不构成判据」。
5. **冒烟的 `gm_yoy_pp` 双读数逐位相同**（`secondary` 与 `research` 两份 `mean_validate` 都是 `+0.033548`）——
   这是「升格 = 换 kind，不是换值」在**真数据**上的直接证据（两份 `n_dates = 13/4` 也一致）。
6. `mf_ratio_5d` 单 mark 是 **2 条 SQL**（日历 ＋ 窗口行），但 `money_flow_daily.date` **无独立索引**
   （PK 是 `(code,date)`）⇒ 单次窗口查询是**全表扫描**（真库 2.4 M 行）。本档不跑全窗（L9），只记边界：
   P98 的 570-mark 长跑会多 ≈2 min 量级的扫描开销（已写进 ADR-045「后果」）。
