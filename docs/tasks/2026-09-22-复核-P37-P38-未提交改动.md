## 1. 复核维度（每条结论都要能指到「文件:行 + 复现方式」）

1. **兑现度**：设计/澄清项（D-16–D-22、ADR-019/020 的可验证条款）逐条对代码 —— 同时**反向检查**：
   有没有代码做了设计里没写、也没人拍板的事（偷偷扩范围比没做完更危险）。
2. **纪律防线**（本项目最容易出「假绿灯」的地方）：
   - append-only：`paper_agent_decisions` 的触发器、`UNIQUE(arm, asof)`、`spec_before` 用 `<`、
     `current_spec` 用 `<=` —— 语义对吗？有没有 UPDATE 路径能绕过？
   - 红线：`reproducibility == None` 会不会被下游读成绿灯？`--regen` 的保留语义对吗？
   - 预算/退出码：`worst_code` 把 `budget_exhausted` 并入致命这一条，有没有漏掉的终态？
3. **测试是不是真防线**：挑 **2 处**关键不变量，亲手做「改坏 → 应变红」的反证（改完**必须还原**，
   用 `git diff` 自证还原干净）；只跑测试看绿灯不算复核。
4. **并发与时序**（本轮已实测踩到一个：`patrol` 的 15:30 槽与 `close` 的 15:30 撞同一分钟、
   两个写者对同一 SQLite 并发写 → 已止血并立 P42）—— **请系统性地把三条任务的触发时刻与写库行为
   排一遍时间线**，把同类撞点/竞态一次找全（含 `RunAtLoad`、`status` 的真源、日志与回执路径）。
5. **「文件在说谎」**：文档/注释/`why`/`window` 文案里写的窗口、条数、时点、路径，与
   **生成出来的 plist / 实际代码常量**逐条对账（P37 已有一条先例：任务书 T3 的「逐字节相同」判据
   根本不可能成立，实际判据是「5 条静态臂逐字段一致」）。
6. **未验证的口子**：明确列出「哪些断言是**没有**被机械验证的」（例如 `arm-agent-random` 阶段 3 前
   只记净值不下单、`agent.delta_vs_random` 恒 `null`、`render_report` 的 Markdown 不含 agent 小节）
