# P72 日更口径与采集范围解耦（`universe sync` 落 `active=0` ＋ 四条 ingest 支持 `--universe`）

- 立项人：nanobot（2026-09-25 00:5x，P71 独立复核时发现）
- 上游：P71 宇宙扩容实现站（`d9a0828` feat ＋ `c90cda4` docs）＋ nanobot 对 P71 的独立复核（本档 §0.1）
- 下游：真库 `universe sync csi300-500` 与 B1–B5 分批采集（nanobot 跑）

## 0. 一句话

`universe sync` 往 `instruments` 新增成员时**落 `active=0`**（研究池不进日更口径），并给
`ingest bars / valuation / moneyflow / actions` 加 `--universe <id>`（显式指定 ⇒ 采该宇宙
**全部成员、不受 `active` 过滤**）；**不传新参数的默认路径逐位不变**。

## 0.1 为什么：P71 复核发现的缺口（**本站唯一的存在理由**）

`instruments.active=1` 在本仓是**全局「日更口径」开关**，不是装饰位。实测读它的地方：

| 位置 | 含义 |
|---|---|
| `stocklab/predict/service.py:79,402` | **预测标的集合** = 库内 active 股票（现在 17 只） |
| `stocklab/verify/replay.py:73` | 回放/验证的标的集合 |
| `stocklab/experiments/runner.py:70` | 实验的标的集合 |
| `stocklab/session/review.py:255` | 复盘 / 滚动准确率的标的集合 |
| `stocklab/cli/main.py:114,189` | `_bars_universe` / `_stock_universe`（`ingest bars`/`actions` 的默认集合） |
| `stocklab/cli/main.py:554,1502` | 其它默认集合 |
| `stocklab/cli/main.py:1674` | `_tick_universe`（`session tick` 的标的集合） |
| `stocklab/ops/chain.py:87-93`、`ops/patrol.py:95-101` | `ops close` / `ops patrol` 的 `ingest *` 步骤**不带任何范围参数** |

而 P71 的 `_sync`（`stocklab/cli/universe.py:118-122`）对新成员**硬写 `active=1`**：

```python
"INSERT INTO instruments (code, name, market, board, type, sector,"
" active, added_at) VALUES (?,?,?,?,?,?,1,?)",
```

⇒ 一旦在**真库**跑 `universe sync csi300-500`，**当天立刻**：

1. 预测集合 **17 → 817 条/日**；`verify pending`、`review daily`、`session tick`、
   `experiments` 的标的集合同步放大；
2. `ops close` / `ops patrol` 的 `ingest bars/valuation/moneyflow/actions --days 30`
   从 **21 只 → 821 只**（`CLOSE_STEPS` 整轮预算 **900 s**，`ops/chain.py:70`；
   仅 `ingest moneyflow --days 30` 一项 ≈ 821 × ~0.5 s ≈ 7 min）⇒ **日链天天 exit 2**；
3. 月度链的 `ingest_financials`（不带参数）同样放大到 817 只。

**P70 设计稿与 P71 任务书都没覆盖这一项**：设计稿全文**零次**出现 `active`；P71 §6 判据 5 只在
`/tmp` 副本上跑 sync，**看不见日更口径**（副本不跑 close/predict）。⇒ 这是「真源文件 → 投影」
这条链上唯一漏掉的消费方，必须在**真库 sync 之前**补。

## 0.5 拍板点（nanobot 定，站不许另选；有异议写 §7.7 偏离）

| # | 锁定值 | 依据 |
|---|---|---|
| **F1** | `universe sync` 新成员落 **`active=0`**；既有行**一字不动**；**不加** `--activate` 开关 | 日更口径要显式；把 800 只塞进日更口径＝「隐式换宇宙」，与 D2 冲突 |
| **F2** | 四条 `ingest`（bars/valuation/moneyflow/actions）加 `--universe <id>`：**显式指定 ⇒ 采集集合＝该宇宙全部成员（含 `active=0`）**；**不带 ⇒ 逐位维持现状**（`_bars_universe` 等一个字不改） | 采集要能把研究池的行情灌进库，但不能顺手改日更口径 |
| **F3** | `--universe` 一律 **fail-closed**（文件缺失/坏 ⇒ exit 2），**不得回退** | 与 P71 `load_universe` 同一条线 |
| **F4** | `ops/chain.py` / `ops/patrol.py` / `CLOSE_STEPS` / `patrol` 的步骤参数**一字不动** | 本站目标就是「日链零变化」，改它反而引风险 |
| **F5** | 红线**不 regen**；**真库不许写**（sync/`--universe` 实测只在 `/tmp` 副本） | 同 P71 §2 |
| **F6** | `universe doctor` 的「instruments 覆盖」判据＝「成员**存在于 `instruments` 表**」（**不看 `active`**），输出里**逐条报 active 计数** | sync 之后 `active=0` 是**预期**，doctor 不能因此报红；但两边分布要可见 |

## 1. 任务

### T1 `universe sync` 落 `active=0`

- `stocklab/cli/universe.py::_sync` 的 INSERT 由 `…,1,…` 改 `…,0,…`。
- 既有行的 `UPDATE`（补空 `sector`）**不许**碰 `active`。
- 重新 sync 同一个 id 必须**幂等**：第二次跑 `added=0`、`instruments` 行数不变。
- `repo.log_event` 的 context 里加一个可查字段（如 `instruments_added_inactive: true`），
  让「新增的是非 active 成员」在事件流里一眼可见。

### T2 四条 `ingest` 支持 `--universe <id>`

- `cli/main.py`：`ingest bars` / `ingest valuation` / `ingest moneyflow` / `ingest actions`
  各加 `--universe`（与 P71 已加的 `ingest financials` **同一形状与文案**）。
- 取集合处：显式给了 `--universe` ⇒ 用 `load_universe(id).members`；不带 ⇒ 走既有函数
  （`_bars_universe` / `_stock_universe` …），**逐位不变**。
- **`--code` 既有语义不变**：`--code` 与最终集合仍走 `_reject_unknown_codes`；不在集合内的代码
  **报错退出**（不静默跳过，ERROR_DIARY #44）。
- `ingest bars` 的「ETF 也采」、`ingest actions` 的「ETF 不进复权链」（ADR-008）两条既有事实
  **不许被 `--universe` 路径破坏**。
- `ingest financials`（P71 已加）若与本站形状不一致 ⇒ 对齐到同一 helper。

### T3 `universe doctor` 口径

- 「instruments 覆盖」= 成员在表里存在（`SELECT code FROM instruments`），**不看 `active`**。
- 输出加一行：active 成员数 / 非 active 成员数（只报数，不改判据）。
- `--universe seed21`（21 只全 active）与 `--universe csi300-500`（21 active ＋ 780 inactive）都 exit 0。

### T4 测试

- 改：`tests/test_universe_cli.py` —— sync 后断言 `active` 分布（新增成员全 0、既有 21 只仍 1）。
- 新增：`tests/test_ingest_universe_scope.py` —— 四条命令的 `--universe` 路径（**假 fetcher 注入**，
  照抄 `tests/test_ingest_financials.py` 的做法）：
  - 不带 `--universe` 时采集集合与改前**逐位相同**；
  - 带 `--universe` 时集合 = 宇宙成员（**含 `active=0` 成员**）；
  - 文件缺失 ⇒ exit 2；
  - `--code` 不在集合内 ⇒ 报错。
- 一条**逐位对账判据**：`/tmp` 副本上 sync `csi300-500` 后
  `SELECT count(*) FROM instruments` = **821** 且 `WHERE active=1` = **21**。
