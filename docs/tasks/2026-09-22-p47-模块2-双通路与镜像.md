## 0. 一句话

把「候选池」接到**两条并行通路**上，用**既有模拟盘引擎**跑出两个可比较的账户 ——
通路 A（AI 插桩选股 → 模拟执行 → A3 预测）与通路 B（人工真实操作 → 镜像复刻 → B1 预测），
两条通路**资金隔离**、**同一套成交与净值口径**、**可幂等重放**。

**用户 2026-09-22 晚拍板「合成一条」→ 写成澄清 [`D-35`](../plans/2026-09-21-需求澄清录.md)（已落档）。**

| 模块2 通路 A | **就用 `arm-agent` 家族账户**，命名 `arm-agent-<策略版本>`；A1/A2/A3 三支插桩＝它的策略实现；**不新开第三套命名** |

## 2. 通路 A（纯模拟，无实盘）

固定顺序（02 §主流程「AI 不可修改流转逻辑」⇒ 步骤顺序写在**主干代码**里，插桩只能填内容）：

1. **A1**（`m2_a1`）从候选池（短/中/长三池）二次选股 → `{picks:[{code, weight_pct, reason}], cash_pct}`；
2. **模拟买入**：按权重与**T 日收盘/次日可成交口径**（沿用既有 `paper` 引擎的成交口径，不新造）；
3. **A2**（`m2_a2`）卖出/调仓/止盈止损 → `{orders:[{code, side:'sell', reason}]}`；
4. **更新账户**：现金 / 持仓 / 净值 / 交易日志（`paper_trades` / `paper_nav_daily`）；
5. **A3**（`m2_a3`）持仓收益预测落库（**append-only，不可篡改**）。

**每周一个决策？不**：决策频率按「每交易日一次」（与 P37 对齐；需求 02 没写频率 ⇒ 这是要落成常量的口径，
见 §6 待澄清）。

## 3. 通路 B（人工 → 镜像）

1. 人工录入真实操作（date/code/side/price/qty/fee）——数据源＝既有 `portfolio/` + `real_trades`
   （⚠️ 既有口径是「实盘账本重放」，不是「人工录入操作的复刻」，见 02 顶部现状注）；
2. **镜像账户**＝按 F 流水**逐笔复刻**（D-25），**复用既有 `arm-now` 实现**，不新建第二套镜像代码；
3. **B1**（`m2_b1`）对人工持仓做收益概率预测，落库；
4. 保存人工交易日志 + 镜像账户快照。

### 4. 没做到 / 存疑（**未验证的口子点名**）

1. **T7 的「缺复权因子」判据没有实现**：通路 A/B 的成交与净值口径只用**不复权**收盘
   （`adj_mode='none'`，与既有 `paper` 引擎一致），复权序列不参与，故没有为它造一条
   不会生效的判据。实现的判据是「非交易日 / 缺当日 K 线」——**两者都落在同一条**：
   该标的在 `asof` 当日有没有不复权 K 线（非交易日必然没有）。
2. **`paper report` / 对照表对通路 A 账户的措辞仍是 `arm-agent` 家族的旧文案**
   （`arm_target_label` 只认 `arm_kind`，而 `comparison.py` 是 P52 范围的禁改文件）。
   口径上它由 A1/A2/A3 插桩驱动、**不写** `paper_agent_decisions`，所以那句
   「台账在 paper_agent_decisions」对它是错的。**属 P48 展示层的事**，本轮只留接口位。
3. **A2 只能卖「已经持有」的标的**（fail-closed）。若 A1 从未买入某只池外持仓，
   通路没有「清掉它」的表达路径 —— 当前账户的初始持仓只有 000333（已入池）。
4. **`paper step` 与通路 A 的排班顺序**：`executor` 让出认领权使两者互不干扰，
   但**没有任何东西检查「通路 A 是否在收盘链里被调用」**（调度侧是 P51/D-23 的
   launchd 任务书范围）。本轮只保证「被调用就正确」。
5. **真实库未做端到端跑**（`data/stocklab.db` 只读，`m2_*` 表要等下次写库入口前滚）——
   全部实测在 `/tmp` 副本/夹具库上完成。真库首跑前需 `db init` 前滚 + 为
   `m2_a1/a2/a3/b1` 各上线一版 active 脚本（否则一律 `rejected: NoActivePlugin`）。
