## 0. 一句话

把 P52 的地基接成**能日更跑的操盘手**：AI 臂的**日终认领权**从 `paper step` 划给「决策循环」
（沿用既有 `params.executor` 显式字段），并补齐三样缺的东西 ——
① 项目外生成器的**唯一 PIT 输入源**（`paper agent context`）；
② **预注册的机械执行**（模型 / 提示词指纹写进账户行，不匹配即拒，换模型 = 开新版本账户）；
③ **「今天没决策」看得见**（台账 / 页面 / 回执三处）。
本站**不产生任何决策内容**（那是项目外的生成器），只保证「产出决策 ⇒ 可落库、可执行、可归因、可复算」。

## 1. 口径与判据

1. **谁落 AI 臂的日终**（D-50）：`arm-agent` / `arm-agent-random` / `arm-agent-<版本>` 三种账户在
   `params_json` 里带 `executor='agent_decision'` ⇒ `ops close` 的 `paper step` 按既有
   `engine.external_executor` **让出**它们（**不改让出逻辑**，只改「谁写这个键」）；日终改由新命令
   `paper agent run --asof <交易日>` 落：先要决策在台账里，再按当日收盘价成交并写净值。
   **理由（必须写进代码注释与 runbook）**：`paper step` 的幂等判据是「当日净值行存在」，
   收盘链 15:30 先跑完 ⇒ 之后写进去的决策**永远不会被执行**（同 P47 `external_executor`
   docstring 里那条坑：症状出现在净值表上，排查方向会跑到订单生成上去）。
2. **记账约定与其它臂一致**（AI 不特殊化）：全项目的约定是「**当日收盘价成交 ＋ 当日收盘数据可用**」
   （`check_no_lookahead(asof, marks)` 允 `<= asof`）。AI 臂不例外 ——
   既不许喂未来数据，也不许为它单开「次日成交」这种第二套口径。
3. **PIT 约束输入、不约束模型**（D-49）：生成器只能从 `paper agent context --asof <交易日> --arm <臂>`
   拿输入（`agent_context.build_decision_context` 的**只读投影**，只含 `<= asof` 的行）；
   决策载荷里带 `context_sha256`，`paper agent decide` 落库前**重算比对**，不一致即拒。
   ⇒ 「PIT 能不能和别的模型结合」的答案是：**能**，PIT 管的是输入与留痕，不管谁产出决策。
4. **预注册是机械的**（D-48）：`paper agent enroll --arm-name arm-agent-<版本> --model-id <m>
   --prompt-sha256 <s>` 建账户时把 `(model_id, prompt_sha256)` 写进 `params_json`；此后
   `paper agent decide --arm <该臂>` 的 `--model-id / --prompt-sha256` **不匹配即拒**（不 warn、
   不静默改写）。**换模型 / 换提示词 = 开新版本账户**，旧账户保留。这条纪律要挡的只有一件事：
   「换到好看为止」。`--prompt-sha256` 的值用新命令 `paper agent sha256 --file <提示词文件>` 算
   （对文件字节的 sha256，纯 stdlib，避免手算各算各的）。
5. **缺决策看得见**：`engine._decision_entry` 已有 `present: False` + note（**别推翻**，本站把它提到台面）：
   - `paper agent show` 加 `missing_decision` 块：`is_trading_day` / `account_in_flight` / `expected`（三个字段都要有）；
   - `/lab/paper` 的 AI 行显式写「今日无决策」——与「有决策但不动手」**不同形**；
   - `paper agent run` 的回执带 `anomaly.missing_decision`（交易日缺决策 ⇒ 退出码 1；非交易日 ⇒ 不算异常，退出码 0）。
6. **随机对照臂同日一条**：`paper agent random --asof <交易日>` 由**项目内**跑（种子固定 ⇒ 逐字节可复现），
   否则 `delta_vs_random` 恒 `null`、结论一律「不可归因」（P52 的原文纪律）。本站只把它排进循环。
7. **认领关系 fail-closed**：`params.executor` 的值必须**有对应执行者**
   （`m2_channel_a` ↔ 通路 A、`agent_decision` ↔ `paper agent run`）；出现未知值 ⇒ **点名报错**。
   静默跳过 = 那条策略悄悄不下单，而症状只会在净值表上出现。

## 4. 反目标

- ❌ 不在项目内**产生**决策：没有模型调用、没有 API key、没有「自动生成脚本」（D-1）；
- ❌ 不改主干常量（成本口径 / PIT 判据 / 整手 / 护栏 / 熔断阈值）；不做参数搜索；
- ❌ 不碰通路 A（`m2_channel_a` 的账户照旧让出，插桩路径留给后续站）；不动 `m2 daily`（P54 的地盘）；
- ❌ **不把 `paper agent run` 塞进 `CLOSE_STEPS`**（决策在项目外产出 ⇒ 链条里没有它可读的东西），
  也不在 `ops patrol` 里补跑它；
- ❌ 不给「缺决策」补造一条默认决策（不许新增「按纪律办」的替代路径 —— 那会把「没决定」
  显示成「决定按默认纪律办」）；
- ❌ 不 `git commit`、不建分支/worktree；`ops/chain.py` 一律不碰（P54/P55 同改该文件 ⇒ 必须串行）。
