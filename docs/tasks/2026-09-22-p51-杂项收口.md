## T1 · `cmd_paper_spec_set` 的两条早退路径没关连接（读码确认）

`stocklab/cli/main.py::cmd_paper_spec_set`：

- `2441` 冲突分支：`return _spec_conflict(...)` —— **没有** `conn.close()`；
- `2449` 幂等分支：`return 0` —— **同样没有** `conn.close()`；
- 同一函数的另外三条出口（`DecisionConflict` / `SpecViolation` / 成功）**都**显式 close。

**影响**：CLI 进程随即退出 ⇒ 现实伤害≈0；但它与本文件其他出口风格不一致，
一旦将来在同进程里复用（例如 labweb 走子进程之前先调一次）、或 `paper spec set` 被别处 import 调用，
就是真的写锁/句柄泄漏。**判据**：改成 `try/finally`（首选，一处收口）或给两条早退补 close；
新增一条**机械护栏**（源码扫描或调用计数），不许只靠人看。

- 反目标：不动退出码语义（1 冲突 / 2 输入不合法）、不动 `_spec_conflict` 的 JSON 字段。
- 证据口径：本条是**静态读码**结论（`stocklab/cli/main.py:2395-2475`），没有运行时句柄计数证据；
  实现时若拿不到可观测的泄漏（例如 `sqlite3` 直接 GC），**如实写「无法机械观测」**，不要编一个数字。
