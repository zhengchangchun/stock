## 二、三个硬要求的落实

### ① 只许在复权价上算收益 —— 结构性禁止，不靠自觉
三条独立防线，任何一条单独生效即可拦住：
1. 写入口：`repo.insert_bars` 拒绝 `adj_mode != "none"`（复权价**物理上进不了** `bars_daily`）；
2. 读入口：CLI 只走 `adjust.load_bars_adjusted(...)`，返回的 `Bar.adj_mode == "qfq"`；
3. 引擎入口：`run_backtest` 扫描全部输入，见非 `qfq` 即 `raise UnadjustedBars`。
测试 `test_engine_rejects_unadjusted_bars` 用不复权 K 线喂引擎，断言抛错。

### ② 不可用因子区间必须被拒绝，不许静默通过
**存储**：新增 `adj_factor_blackout(code, cqr, reason, source, fetched_at)`，视图
`v_adj_usable(code, usable_from, n_unusable)`。

**为什么存「事件」而不是给每行打 `usable` 标记**：一根 bar 可不可用取决于**读取窗口的起点**——
`2001-01-15` 之前的窗口不可用，从 `2001-01-15` 起的窗口完全可用。逐行布尔量表达不了
「窗口相关谓词」，只能表达「这一天不可用」，下游会用它把**可用的历史一起丢掉**。
这一类「看着对、语义错」正是错误日记里最贵的错，所以选事件表。

**读取层**：`adjust.load_bars_adjusted` 在返回前调 `assert_blackout_current(conn, code, chain)`：
- 窗口跨过任何不可定价事件 → `MissingFactor`（消息给出 `usable_from` 与修复命令）；
- 库里的缺口记录与本次重算的链不一致（多/少/错位） → `StaleFactorTable`（陈旧标记 = 谎报可用）。

真实数据验证：`600690` 全历史请求被拒绝（下方证据）；`600690 --start 2001-01-15` 通过。
测试 `tests/test_adjust_blackout.py`：假跌幅证明（-5% vs 还原后 0.0%）、跨缺口拒绝、
陈旧表拒绝、多余记录拒绝、多事件 `usable_from`、端到端拒绝穿透到 CLI。

### ③ 成本 / T+1 / 板别
- 成本 `CostModel`：佣金 0.025% **最低 5 元**、印花税 0.05%（仅卖出）、过户费 0.001%、滑点 5bp。
- T+1：`Portfolio._locked_today` 记当日买入量，`sellable_qty = qty - locked`，`settle(date)` 解锁。
- 板别：`LIMIT_BY_BOARD = {main:0.10, gem:0.20, star:0.20, bse:0.30}`，
  `can_trade(code, bar, *, board, ...)` 的 `board` 是**必填参数**，未知板别抛 `BoardUnknown`——
  **没有** `board = board or "main"` 这种默认值；引擎侧 `universe` 用 `Instrument` 而非裸字符串，
  `board_by_code` 缺失即抛错。计划点名的坑用类型系统堵死。

## 三、与计划的偏离（按「意图更强」取舍）

| 偏离 | 计划原样 | 本实现 | 理由 |
|------|----------|--------|------|
| 信号有效期 | 未明确，暗示顺延至成交 | **一天有效，未成交即作废**（记入 `metrics["rejected"]`） | 「顺延到能成交为止」是隐性前视：它假设信号发出后还能用未来价格决策，并把「买不到」美化成一笔更划算的成交 |
| 涨跌停判定 | 计划示例中有 `"main"` 默认 | 未知板别抛 `BoardUnknown` | 硬编码默认会把创业板当主板（少一半涨跌停空间），错误是静默的 |
| 缺价估值 | 隐式按 0 | **按上一有效收盘价前推** + `n_missing_price_days` 计数 | 按 0 估值 = 停牌日假爆仓 + 净值上一条假 −100% 回撤 |
| 缺口表达 | 字段/区间（未指定形态） | 事件表 + 视图 | 见上文「窗口相关谓词」 |
| `Session` 窗口 | 无 | CLI 输出 `session_start/session_end` | 请求区间与实际可回测区间可能不同（见遗留问题），必须披露 |
| 下单量 | 直接按比例 | `max_buy_qty`（费用感知，逐手回退） | 否则「恰好满仓」的单因费用差一分钱而不成交，回测静默变成空仓 |

