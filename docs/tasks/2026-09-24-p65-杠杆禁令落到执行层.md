## 1. 现象（P64 独立复现，真库副本、`asof=2026-09-23`）

账户 `arm-agent-v1`：`total_assets = 19,567`，其中 **`000333 ×100 @ ¥82.47 = ¥8,247`（42%）是存量持仓**、
可用现金 ¥11,320（58%）。A1 `1.0.2` 产出 5 只等权 18%（Σ=90%、`cash_pct=10`），全部成交，随后：

```
paper_nav_daily(arm-agent-v1, 2026-09-23):
    cash = -4490.01   market_value = 24024.00   nav = 19533.99
    持仓 6 只 = 000333(存量) + 603868/600900/002415/601398/002508(本次)
```

- **总敞口 = 24,024 / 19,567 = 122.8%**（透支 ¥4,490，= 总资产的 −23%）；
- 结构原因：目标敞口按 **`total_assets × 18% × 5 = ¥17,610`** 算，而**真正能动的钱只有 ¥11,320**；
  那 42% 的 `000333` **不在 5 条 pick 里**（排名不够前）、**A2 也不卖它**（它还在池内、无止损止盈）
  ⇒ 既不被重算、也不被释放。
- 执行层**没有资金闸门**：`paper/agent_decide.py` 的成交-结算处直接 `cash += gross - fee`（卖）
  / `cash -= (gross + fee)`（买，第 619 行），**允许为负**；
  `agent_decide` 只校验「收到的 `Σ target_weight_pct + cash_pct == 100`」（第 185 行，「多出来的
  部分就是杠杆（借钱买入）」），管不到「与存量持仓叠加后的总敞口」。
- **这个透支一直被上一个 bug 遮蔽**：`1.0.1` 的「按目标市值算股数、整手向下取整 ⇒ 0 股」**意外**当了闸门
  （只成交 3 笔 ⇒ 现金仍 +¥2,055）。P64 修掉「买不起一手」，净结果是把一个此前看不见的杠杆缺陷
  变成了当日的真实持仓。⇒ **不能只回退 1.0.2 了事**：那条偶然闸门迟早还会被别的改动拆掉。

## 2. 三个待决策口径（**都要用户一句话**）

### Q1 执行层要不要资金闸门？（`channel_a` / `paper` 执行层）

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | **fail-closed 具名拒绝**：`execute_decision` 在结算前校验「本轮成交后的现金 ≥ 0」与「总敞口 ≤ 100%」，不满足即 `ChannelReject(code="cash")`，整轮拒绝、零写入，读数和 P63 的重复拒绝同款 | 上游口径有洞时会**整轮不执行**（宁可空仓，不宁可透支）——这正是想要的读数 |
| B | **夹紧**（按可用现金等比缩小目标市值） | 会把「账户只有 58% 的钱」伪装成「策略本来就想买这么多」，机制**不可见**；且与 P63 的教训（执行层不许兜底合并）同型 |
| C | 不动执行层，只修上游口径 | 上游任何一次口径错误都会直接变成真实透支。P64 就是这个反例 |

### Q2 A1 的权重分母用「可用现金」还是「总资产」？

| 选项 | 内容 | 评价 |
|---|---|---|
| **A（推荐）** | 分母仍是 **`total_assets`**（组合口径），但 **Σw 的上限先扣掉「不在 picks 里的存量持仓当前占比」**：`Σw ≤ (100 − CASH_FLOOR) − 未在库占比`。`ctx.holdings` 每项**已经带** `qty`/`close`/`market_value`/**`weight_pct`**（`m2/context.py::holdings_ctx` 第 206–227 行）⇒ A1 **直接求和就行**，不需要新增契约字段。本账户即 `Σw ≤ 90 − 42 = 48%`（5 只各 9.6%） | 语义最干净：「A1 只能部署**真正空闲的**钱」，且**总敞口自然回到 ≤100%**；同时保住组合视角（存量持仓仍计入总仓位） |
| B | 分母改成**可用现金**：`Σw ≤ 100 − CASH_FLOOR`（相对现金），等权即 5 只各 18% 现金 − 现金下限 | 立刻不透支，但**存量持仓永远不被重算**（策略退化成「只在增量上加仓」），小账户会被存量越压越重；且 `cash_pct` 的语义会与 `picks` 的基数脱钩 |
| C | 现状（`total_assets`，不看存量） | 必然透支 ⇒ 必须配 Q3，否则不可用 |

### Q3 不在 picks 里的存量持仓归谁管？

| 选项 | 内容 |
|---|---|
| **A（推荐，最小改动）** | **本批不动**（谁买的谁管：`arm-agent-v1` 的 `000333` 是人工种子，A2 只做止盈止损），但**必须在报告里可见**：`m2_channel_runs.reason` 一行点名「未在库存量 ¥8,247（42%）未参与本轮目标」 |
| B | 让 A2 把「不在 picks 且无止损止盈」的持仓按目标权重减持（把总敞口拉回 ≤ 100 − cash_floor） | 语义最完整，但等于给 A2 加一条**卖出策略**（现在它只做止盈止损/调仓退出）——那是一次策略变更，要单独任务书 |
| C | 存量持仓按「保留原权重」正式写进 ctx 口径（A1 看到的就是完整组合） | 与 Q2-A 是同一条路的两种表述；选 Q2-A 就不必单列 |

**我的推荐组合＝ Q1-A ＋ Q2-A ＋ Q3-A**（一次只换一个变量：Q1 是兜底、Q2 是主修、Q3 只加可见性）。
**依赖关系**：Q1 与 Q2 **必须同批上线** —— 否则 09-23 那天会在「5 只全部买不起/被拒 ⇒ 空仓」与
「5 只全成交 ⇒ 透支 23%」之间二选一，两个都不是想要的。
