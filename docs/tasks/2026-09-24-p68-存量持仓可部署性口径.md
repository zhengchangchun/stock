## 0. 一句话

**同一条错口径**在随机臂与 A1 各写了一份：**把「存量持仓的市值」当成可部署资金**。

P66 只把**「不在 picks 里的存量」**扣了出来（那是对的一半）；**「在 picks 里、但目标市值低于现市值」的存量**
照样被当成「一减仓就变成现金」，而执行层是**整手**的：

> `plan_target_weight`：差额 < 1 手 ⇒ **不动**（`rules.py` 的 `C_LOT` 分支）。

于是「计划里那 42% 现金会释放出来」这件事**在执行层不成立**，计划总额超出现金 ⇒ `_gate_cash` fail-closed
整轮拒绝（**没有一笔透支落地**，闸门是对的；错在生成器的口径）。

**修法（两臂同款、一句话）：`reserved` 一律 = 全部存量持仓占比之和，不因 picks 而减免。**
= 生成器**不依赖任何一笔减仓**也能成交 —— 这正是 A1 自己 docstring 写的那句话
（「A1 **只能部署真正空闲的钱**」，v1.0.3 的 step 3 恰好违背了它）。

## 1. 实测证据（nanobot 2026-09-24，真库只读 ＋ 代码走链）

### ① 随机臂 seed 97：目标敞口 83.79%、`reserved=0.0`、`cap=90.0` ⇒ 被拒 `cash=-¥657.06`

真库只读探针（账本状态＝`arm-agent-random` @ 2026-09-23；现金 ¥11,320.00、存量 `000333` 100 股）：

```
seed=97  exposure=83.79  reserved=0.0  cap=90.0  verdict=cash_reject
arm-agent-random 在 2026-09-23：账上可用现金 ¥11,320.00，本轮需要 ¥11,977.06，
成交后现金 ¥-657.06（越界 ¥657.06）—— … **整轮拒绝、零写入**。code=cash
```

seed 97 的 picks ＝ `000333(10.6%) / 000651(23.72%) / 002508(12.38%) / 601398(37.09%)`：
`000333` 现市值 ¥8,247.00、目标 ¥2,074.10、差 ¥6,172.90 **< 一手 ¥8,242.88** ⇒ 执行层「不动」
⇒ 那 42.15% 的存量市值**一分钱都不会变成现金**，而 cap 公式把它当成了可部署的钱。
**P66 的 200 种子整体读数＝被拒 1/200**（旧口径 v1 是 11/40）；本站判据要求 **0/200**。

### ② 机制链（为什么闸门是对的、生成器是错的）

| 环节 | 位置 | 行为 |
|---|---|---|
| 逐笔规划 | `paper/rules.py::plan_target_weight` | 卖出：`floor_lot(差额/成交价)`；`qty<=0` ⇒ **hold「差 < 1 手 → 不动」** |
| 组计划 | `paper/agent_decide.py::plan_orders` | 每笔都用**同一份初始 `cash`** 规划（各自不超现金，**合计可以超**）【纯函数，不结算】 |
| 结算 | `paper/agent_decide.py::_settle` | 先卖后买逐笔结算到状态上 |
| 闸门 | `paper/agent_decide.py::_gate_cash` | `cash_after < -CASH_TOL` ⇒ `CashShortfall`，**整轮拒绝、零写入**（Q1-A / P65） |

⇒ 「生成器算得乐观 → 闸门拒」这条链**是设计如此**（P64/#73 的结论：偶然的副产物不能当闸门，
但闸门也不许替上游兜底）。**所以要在生成器侧把口径改对，不是放松闸门。**

### ③ A1 v1.0.3 的 step 3 ＝ 同一个假设（源码原文）

`stocklab/m2/builtin/a1_pick.py`（`SOURCE` 字符串常量）：

```
3. **一次细化**：`reserved1 = Σ over holdings whose code ∉ picks`（picks 里的
   存量**本来就持有**，不该再占它的额度）；`w1 = round(min(CAP_PCT,
   ((100 − CASH_FLOOR) − reserved1) / n), 2)`。若 `w1 > w0` ⇒ 用 `w1` 重跑
   一次 affordability 并取最终 `(S, w1)`；否则取 `(S, w0)`。**最多两轮，不迭代到不动点**。
```

`w1 > w0` 只在「picks 含存量票」时发生 ⇒ **A1 与随机臂同型**（同一账户上实测：
`000333` 100 股占 42.15%，一手 ¥8,242.88，任何 `0 < 目标 < ¥8,247.00` 都是「减不动」）。
09-24 生产那轮 `m2_a1(1.0.3)` 恰好没有选中存量票（`held_out_pct 42.2007`、3 只 15.93%），
所以**这一枪还没响**；响的那天 = 计划越界 ⇒ `m2_daily` exit 4 ⇒ `ops close` exit 2（G 级红）。

## 5. ERROR_DIARY 要加的一条（本站必须写）

> 题目自拟，必须覆盖三句教训：
> ① **修一处 ≠ 修一类**：P66 扣掉了「不在 picks 里的存量」，却把「在 picks 里但**减不动**的存量」
>    留在了公式里 —— 同一条错假设换了个分支继续存在（旧账：P64 的「偶然副产物当闸门」同族）。
> ② **生成器里的数必须由执行层能兑现的粒度决定**：写入口按**连续值**算钱，执行层按**整手**动手，
>    两边的粒度差就是一个稳定的透支缺口（本仓还有第二个同型处：`plan_orders` 用同一份初始现金
>    逐笔规划，各自不超、合计可超）。
> ③ **判据要拿「反例种子」钉，而不是拿「平均表现」看**：1/200 的概率在 120 个交易日里足够上演一次，
>    而它上演的那天整条收盘链会红、AI 臂会白白少一天。
