## 1. 计划文件与实测不符之处（实测优先，逐条留痕）

> 依据 `docs/errors/ERROR_DIARY.md`「计划不是可执行真源 / 测试必须真跑」。

### 1.1 腾讯快照 fixture 是**合成的、字段数不足**（Task 9）

计划里 `RAW_QUOTE` 用 `~` 分隔后只有 **35** 个字段，而解析器的守卫是
`len(parts) < 47: continue`（索引最大用到 46）→ 该行会被**整体跳过**，
`test_parse_single_quote` 断言 `len(quotes) == 1` **必然失败**。

**实测**（2026-09-14 真实响应 `qt.gtimg.cn/q=sz000333,sh600690`，GBK，1013 字节）：
实际 **88** 个字段。逐字段核对后确认**计划里的 14 个索引全部正确**：

| 字段 | 索引 | 实测样例 | 单位 |
|---|---|---|---|
| name | 1 | 美的集团 | — |
| code | 2 | 000333 | — |
| price | 3 | 86.80 | 元 |
| pre_close | 4 | 86.26 | 元 |
| open | 5 | 86.29 | 元 |
| volume | 36 | 180951 | **手** |
| amount | 37 | 157236 | **万元** |
| turnover | 38 | 0.26 | % |
| pe_ttm | 39 | 14.92 | — |
| high / low | 33 / 34 | 87.40 / 86.26 | 元 |
| float_mv / total_mv | 44 / 45 | 5976.53 / 6622.27 | **亿元** |
| pb | 46 | 3.13 | — |
| ts | 30 | 20260914161421 | YYYYMMDDHHMMSS |

→ **结论：改的是测试数据，不是解析逻辑。** 测试改为回放真实 fixture，
不再使用合成字符串。

### 1.2 `HttpClient` 接口声明了缓存，实现里没有（Task 8）

计划 `Interfaces` 写了 `HttpClient(..., cache=None)`、`get_text(..., cache_key="")`，
行为契约⑤「缓存命中直接返回，不发请求」，但 Step 3 的实现**完全没有 cache**。
→ 按接口与行为契约实现缓存（并补测）。

### 1.3 `ConnectionError` 抓不住（Task 8）

计划测试抛内置 `ConnectionError`，实现只 `except requests.RequestException`。
内置 `ConnectionError` 不是 `requests` 的异常子类 → 会**裸抛**，`pytest.raises(FetchError)` 失败。
→ 实现改为 `except (requests.RequestException, OSError)`（内置 `ConnectionError`/`TimeoutError` 均为 `OSError` 子类），
覆盖真实传输层（urllib3/socket）错误。

### 1.4 缓存文件数断言与实际不符（Task 11）

计划测试 `test_cache_key_is_filesystem_safe` 断言目录下 `len(files) == 1`，
但 `store()` 会同时写 `.bin`（正文）与 `.json`（元数据）→ 实际 2 个。
→ 断言改为「按 key 恰好 1 个 `.bin` + 1 个 `.json`」。

### 1.5 缓存缺 SHA256 校验、缺损坏报错（Task 11）

用户验收要求「raw cache 的 SHA256 校验与重放命中、缓存损坏时报错」，
计划的 `load()` 是裸 `read_bytes()`，不校验。
→ `load()` 默认校验元数据里的 `sha256`，不匹配抛新增的 `CacheCorrupt`（失败留痕）。

### 1.6 东财 `adjust` 默认值自相矛盾（Task 10）

`kline_url(..., adjust=0)` 与 `parse_kline(..., adjust=1)` 默认值不一致，
且 `parse_kline` 的 `adjust` 参数**在函数体内未被使用**（死参数）。
→ 统一为 `adjust=0`（不复权），并删掉 `parse_kline` 的无用参数。
依据铁律①：抓取层不下发复权价。

### 1.7 除权事件：计划的 Task 9 未覆盖，但铁律①要求

实测 `fqkline` 的除权事件是 **kline 行上的第 7 个元素（dict）**：

```json
["2024-05-15","60.809","62.069","62.409","60.419","301895.000",
 {"nd":"2023","fh_sh":"30","djr":"2024-05-14","cqr":"2024-05-15","FHcontent":"10派30元"}]
```

→ 新增 `tencent.parse_corp_actions()`（纯函数），为 ADR-001 D-01 的
PIT 复权因子链提供输入；**qfq 价格序列只用于交叉校验，禁止落 bars_raw**。

## 2. 铁律落地对照

| 铁律 | 落地方式 | 可执行证据 |
|---|---|---|
| ① point-in-time，不下发复权价 | `kline_url` 默认不复权；`parse_kline` 默认 `adj_mode="none"`；qfq 仅用于取除权事件/交叉校验 | `test_kline_url_defaults_to_unadjusted`、`test_parse_kline_defaults_to_unadjusted` |
| ② 可复现，测试禁联网 | 真实响应落 `raw_fetch_cache`；全测试套 autouse 屏蔽 socket | `tests/conftest.py::no_network` |
| ③ 失败留痕 | 坏行跳过由调用方记录；缓存哈希不匹配抛 `CacheCorrupt`；`store` 冲突写 `conflicts` | `test_cache_corruption_raises`、`test_cache_conflict_recorded` |
| ④ 单位「股/元」，禁 cron | 手→股 ×100，万元→元 ×1e4，亿→元 ×1e8；录制器为手工一次性脚本 | `test_quote_volume_*`、`test_quote_amount_*` |
| ⑤ 白名单 + 限速 | `assert_host_allowed` 每次请求前调用；`min_interval` 限流；指数退避 + 上限 | `test_host_whitelist_enforced`、`test_backoff_is_exponential`、`test_min_interval_between_requests` |
| ⑥ TDD | 每个 Task 先写测试 → 跑出失败 → 再实现 | 各 Task 的 Step 2 输出 |
