## 1. 口径与判据

1. **调用点**（文档 01 明写它在「AI优化子流程内部」）：
   ① `candidate run` 的 12 步主干 **一个字不动**；② `CLOSE_STEPS` **一个字不动**；
   ③ `candidate review` 独立可跑，并作为**非阻断步骤**加进 `MONTHLY_STEPS`（月度链）——
   它失败不许把整链拖红（照该元组里非阻断步骤的既有语义写）。
2. **active 脚本缺席必须显式**：只认 `plugin/lifecycle.py` 的 active 版本（plugin_id=`5`）；
   **没有 active 版本 ⇒ exit 2** 且点名「插桩5 没有 active 版本」，不静默跑空。
   现役 v1.0.0 是**桩**（返回 `{"analysis_result": {"status": "not_implemented"}, "bad_case_list": []}`）
   ⇒ 命令 **exit 0**、台账照记，但**报告第 1 行就写**「复盘脚本尚未实现（script_id=6 / v1.0.0 桩），本报告只有输入侧事实」。
   **不许把桩的输出包装成结论**，也不许为让报告好看而造假数据。
3. **输入必须是事实，PIT 只读**（T0 先只读探测形状，把探测到的列名写进实施记录）：
   - 历史快照：`candidate_snapshots` / `candidate_members`（只取 `asof <= 目标日`）；
   - 回测台账：`plugin_backtests`（各脚本版本已落库的回放读数；**不自己重跑回放**）；
   - 模块2 回流：`labweb/m2_data.py` 的**错判案例只读汇总**（P49 / D-31：「回流是『看』，不写表」）——
     若它现在只在页面层可用，就抽成**可复用的只读函数**（放 `m2/` 或新模块皆可），
     **不许复制第二份口径**（模块2 需求书 §5 A5 的判据）。
4. **因子胜率的定义**（写死、写进报告抬头）：以历史快照里的候选为样本（带池别与 `adj_score`），
   对照其在**其后 N 个交易日**的方向/收益（N 用**常量**写死，改它要改代码）；只用 `<= asof` 的数据。
   样本不足 ⇒ `None` ＋ `na_reasons`（**不许给 0.0 冒充「胜率 0%」**，照 `m2` 既有做法）。
5. **落库**：新增 **append-only** 表（候选名 `plugin_reviews`；CC 可换名但要写进实现记录），
   幂等键 `(asof, script_id)`；触发器拦 `UPDATE`/`DELETE`；迁移登记进 `_KNOWN_MARKERS` / `_pending_column_migrations`，
   **可重入**、**对老库是空动作**。真库迁移由 nanobot 做（§3）。
6. **报告落点**：`reports/plugin-review/<asof>.md`（新目录）。
   ⚠️ **禁止**叫 `reports/<asof>-review.md` —— 那是 `session review` 的地盘，`ops patrol` §⑤ 按这个名字判存亡，
   撞名会让 patrol 读到错的文件。**加测试钉住 patrol 的判据不受影响**，并遵守 `conftest` 的报告目录夹具（错误日记 #51）。
7. **闸门零放松**：脚本走 `plugin/runtime.py` 的受限执行；**不改** `plugin/` 下的
   `contract.py` / `guard.py` / `lifecycle.py` / `sandbox.py`（一个字都不许松）。
8. **v1.1.0 源文本**（`stocklab/candidate/builtin/review.py`，形状照 `stocklab/candidate/builtin/`）：
   `SOURCE: str` ＋ `BUILTIN_PLUGINS` 风格映射；纯函数、不 import、不做 IO、不取时间、不用随机；
   真算 ①因子胜率（按池别与分数分桶）②回测指标读数（从 `ctx` 里已有的台账条目算）③`bad_case_list`（来自 `ctx`）。
   最少样本数等上限**写死在源码里**，**不许做成可配置**；契约形状就是
   `analysis_result: dict` ＋ `bad_case_list: list`（`SHAPES["5"]`）。
   真库 `submit` 由 nanobot 做 ⇒ 本站产物停在 `pending_review`（D-24 人工闸门）。

## 3. 真库动作（nanobot 在验收后做，写进回执）

1. `data/backups/` 先备份（`store/migrate.py::backup_db`）；
2. 真库迁移（新表）＋ `candidate review --asof <上月末交易日>` 走**现役桩** ⇒ 看 exit 0 与报告抬头；
3. `plugin submit` v1.1.0 源文本 ⇒ 核对 `pending_review` 并记 `script_id`；
4. **`approve` 由用户点头后执行**（人工闸门）；
5. approve 后再跑一次 `candidate review` ⇒ 看真读数（因子胜率/回测指标原文照贴）＋ 报告交付。
