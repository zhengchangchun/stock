# P62 AI 臂净值行写错：`execute_decision` 未结算状态（**生产实测 bug，修 + 修数据**）

创建：2026-09-23（nanobot 在生产实跑中发现）｜ 实现：Claude Code（superpowers 全流程）
来源：P56 首次循环实跑（asof `2026-09-23`）之后的净值复核。**这是 P56 的验收阻断项**：
AI 臂当日的净值行与它自己的成交重放**对不上**，读数凭空少了 ¥8,233.68。

---

## 0. 一句话（症状）

`paper agent run --asof 2026-09-23` 给 `arm-agent-ds-v1` 写下的净值行是**执行前**的状态：
现金没记卖出所得、持仓却已被改动 ⇒ 净值 `11320.0`（**−43.4%**），而按它自己的成交行重放应当是
`19553.68`（**−2.23%**）。

## 1. 硬证据（nanobot 2026-09-23 23:4x 实测，真库只读 + 库副本）

决策（台账 `decision_id=2`）：`arm=arm-agent-ds-v1`、`asof=2026-09-23`、`model_id=deepseek/deepseek-v4-pro`、
`context_sha256=3aa30255d19b…`；载荷＝卖 `000333`→0%、买 `600900` 14.35% / `603868` 15.98% /
`002415` 16.92% / `000651` 19.61%、`cash_pct=33.14`。

成交行（`paper_trades`，当天**只有 1 笔**）：

```
trade_id=12  arm-agent-ds-v1  000333  sell  100 股  ref 82.47  fill 82.4288
             fee_total 9.2（commission 5.0 / stamp 4.12 / transfer 0.08）
```

写下的净值行（`paper_nav_daily`）：

```
cash=11320.0  market_value=0.0  nav=11320.0  cum_cost=9.2  cum_return=-0.434
positions_json=[{"code": "000333", "qty": 0}]      ← 零股条目（不该存在）
```

同一副本上按成交重放得到的状态（`engine._ledger_arm_state` + `mark_to_market`）：

```
cash=19553.68  positions={}  →  nav 应为 19553.68（cum_return -0.0223）
```

⇒ **差额 = ¥8,233.68**（卖出所得 8,242.88 − 手续费 9.2）。**AI 臂这条读数作废**，
且它会被 `paper show` / `/lab/paper` / 报告当作当天事实读走（`cum_return` 差 41 个百分点）。

## 2. 根因（已定位到函数与行）

`stocklab/paper/agent_decide.py::execute_decision`（约 593–616 行）的 docstring 写着
「**在给定状态上原地结算**（现金 / 持仓）」，但实现只做了 `plan_orders(...)`，
**原样返回入参**：

```python
orders, evals = plan_orders(decision=decision, cash=cash, positions=positions, ...)
...
return cash, positions, [replace(d, reason=...) for d in orders], evals   # ← 入参，不是结算后的状态
```

`engine._step_all` 拿到这个返回值后**直接**用它写净值（`cash` / `positions` / `nav = cash + mv`），
所以净值行记的是**执行前**的现金。而 `positions` 被 `plan_orders` 路径**原地改过**
（`000333` 被置 0 而不是 pop），于是出现「现金是旧的、持仓是新的」的混合状态 —— 正是上面那行。

对照：纪律臂走的是 `_plan_steps`，它返回的是**结算后**的状态 ⇒ 五条静态臂的净值行与重放一致
（nanobot 在副本上逐条核过 `arm-discipline-05/10/15` / `arm-hold` / `arm-now`，全部一致）。
**所以这是决策驱动路径独有的缺陷。**

## 3. 修法要求（口径）

1. **`execute_decision` 必须结算**：把 `orders` 逐笔应用到 `cash` / `positions` 上再返回，
   语义与 `_ledger_arm_state` 的成交重放**逐字段相同**（买：`cash -= fill*qty + fee`、卖：`cash += fill*qty - fee`；
   持仓 `qty==0` 的键**pop 掉**，不留零股条目）。
   **不许**为实现它而复制第二份费用公式：复用既有 `CostModel` / `_fee_parts` / `store.insert_trade` 的口径 ——
   目标是「重放 = 写入」这一条不变量，不是再写一遍算术。
2. **不变量必须被测试钉住**（这是本站最重要的判据）：
   对**任一** AI 臂、任一天，`paper_nav_daily` 的行必须等于
   「`initial_cash` + 当日及之前全部成交按上面口径重放（+ 当日收盘价 mark-to-market）」，
   即已有的 `engine._ledger_arm_state` + `mark_to_market`。
   写成**属性测试**：造 3–4 天、含买/卖/部分成交的日子，逐日断言 `nav == replay_nav`（容差 1e-6）。
3. **零股条目不许出现**：净值行 `positions_json` 里不得有 `qty <= 0` 的键（加断言；`mark_to_market` 也会因此更干净）。
4. **P52 那条判据为什么没拦住（写进实施记录）**：T4 当时写的是「与 `paper step` 同口径算出的值一致」，
   而 AI 臂根本不走 `paper step` 的路径 ⇒ 那条判据是空转的。本站要把它替换成 §3.2 的不变量。
   **不要**把「测试是绿的」当理由反驳 —— 绿是因为期望值是从实现反推的。
5. **修历史行（append-only 纪律下的修复）**：`paper_nav_daily` 有 `no_update`/`no_delete` 触发器
   ⇒ 不许直接 UPDATE/DELETE。走**迁移式修复**（照 `store/migrate.py` 里
   `migrate_p56_agent_arms_executor` 的既有先例：事务内摘触发器 → 只删/重写**点名的那一行**
   → 重新挂回触发器 → 核对行数与其余行逐字节不变），并：
   - 修的是 **`(arm-agent-ds-v1, 2026-09-23)` 这一行**（先探测有几行属于这类缺陷，
     把清单打印出来；**超出该清单的行一行都不许动**）；
   - `paper_trades` **一行都不删**（成交是真的，赎回来的只是净值行）；
   - 重跑 `paper agent run --asof 2026-09-23` 让它按修好的代码重写（跑之前先删掉错行）；
   - 在 `system_events`（或项目既有的同类台账）留一条可查的修复记录：日期、账户、旧值、新值、原因、依据文件名。
   - **真库执行由 nanobot 做**（§5）。
6. **验证口径**：修完后重跑本站属性测试；对真库同日重新核一遍「净值行 == 重放」（nanobot 复核）。

## 8. 顺带点名（**不属于本站**，留给用户拍板）

那四笔买入**一笔都没成交**：AI 给的权重恰好每笔≈1 手（含滑点后 99.9 股 → 向下取整 0 手），
执行层如实写了「目标未达成」。这不是 bug（整手向下取整是设计），但会让「AI 的意图」与
「实际组合」差很远。两条可选口径（**推荐 A**）：
**A** 提示词 v2 明确要求「每个目标权重至少 1 手（含滑点），给出 `手数 = floor(权重% × 总资产 / (价 × 1.0009) / 100)`」，
并作为 `arm-agent-ds-v2` 重新预注册（换提示词 = 换版本账户，D-48）；
**B** 执行层对「未达成」回执再加一个显式计数（现在只在 `evaluation` 里）。
