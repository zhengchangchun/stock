## 2. 根因

1. **模块1 的三池不是互斥划分**：真库 2026-09-23 的池成员（`agent_pool.pool_snapshot`，快照 2026-09-18）
   长 5 / 中 8 / 短 6 = 19 个槽，**并集只有 11 只**；5 只长期池成员**全部**同时在中池里。跨池重复是**常态**，
   不是偶发数据事故（2026-09-22 与 09-23 两天的重复集合逐字相同）。
2. **`m2_a1` v1.0.0 跨池排序取前 `LIMIT_N` 时不去重**（`stocklab/m2/builtin/a1_pick.py` 的 `run()`：
   「三池各自排序 → 打平成 rows → `rows.sort` → `rows[:LIMIT_N]`」）。同一个 code 在两只池里各占一个槽
   就产出两条 pick。
3. **`plugin/contract.py` 拦不住它**：`_check_cross` 只校验 `sum(weight_pct)+cash_pct == 100`，
   `_check_picks` 不查 code 唯一性 ⇒ 5 条 18% 合计 90%、现金 10%，**校验全过**。
4. **下游把它当两条独立订单**：`m2/channel_a.py::_weights_items` 逐条生成目标市值条目，`rule_citation`
   对买入侧是**同一个常量串** ⇒ 两条 `(code, side, qty)` 相同的单子撞 `paper_trades` 的唯一键。
