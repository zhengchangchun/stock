## §0 背景（要解决的一个具体问题）

1. **候选 #3 进不了 harness**。`research factor-ic --factor ep_ttm` **当前会 exit 2**：
   `P97` 建的 `RESEARCH_FACTORS = ("mf_ratio_5d",)` 里**没有** `ep_ttm`，
   而 `selected_factors()` 对未登记名字是 fail-closed 拒跑（`factor.py:451-466`）。
   P95 §8 的顺序（`gm_yoy_pp` → `mf_ratio_5d` → **`ep_ttm`**）前两项已跑完、判「不足以采纳」
   ⇒ 现在缺的**只剩一个研究侧取值器**，其余（`--factor` / 产物命名带 tag / fail-closed 预注册链）
   P97 已交付 ⇒ **本任务零架构改动，只补一个取数分支**。
2. **为什么不复用 `mf_ratio_5d` 的路径**：两者数据源不同（`money_flow_daily` vs `valuation_daily`）、
   PIT 锚不同（`date <= asof` 的 5 日窗 vs `date == asof` 的单日）、缺失语义不同
   （窗内任一 NULL ⇒ `None` vs `pe_ttm <= 0` **判为缺失**）⇒ 必须各自一个取值器，**不许**用一个泛化函数糊住两种口径。
3. **本站不跑实验**：全窗 `factor-ic` ≈3.2–3.3 h、纯本地 CPU、零 token（P98 实测 11,615.5 s / 11,883.3 s）
   ⇒ **由 nanobot 在 `/tmp` 副本上自己跑**，站只交付「取值器 ＋ 用例 ＋ 一条口径披露」。

## §1 T1 取值器（`stocklab/research/factor.py`）

新增（放在 `mf_ratio_5d` 一族之后、`_research_map` 之前，保持「机制层 → 具体因子」的现有阅读顺序）：

```python
def _ep_ttm_map(conn: sqlite3.Connection, asof: str) -> dict[str, float]:
    """`{code: 1 / pe_ttm}`（P95 §5.2 VAL-A）。

    逐字公式：`ep_ttm = 1 / pe_ttm`，**仅当 `pe_ttm > 0`**；`pe_ttm <= 0` 或 `NULL`
    ⇒ 该标的**不进结果集**（= `None`，**不补 0**）。
    PIT 锚 = `valuation_daily.date == asof`（**等式**；估值表按日，P95 §5.2 明写）。
    负 PE（亏损）**判为缺失**：不截断、不取绝对值（取绝对值 = 把亏损公司排成
    「极便宜」，方向错）。**不做横截面 winsorize**（rank IC 对单调变换不变）。
    复杂度：每个 `asof` 只发 1 条 SQL ⇒ `O(该日行数)`。
    """

def ep_ttm(conn: sqlite3.Connection, code: str, asof: str) -> float | None:
    """单只标的的 `ep_ttm`（`None` = 算不出）。批量请用 `_ep_ttm_map`。"""
```

要点：
- `float(pe_ttm) > 0` 判定，`1.0 / float(pe_ttm)` 返回；**不许**先做 `round`/格式化。
- 注释里给出出处（`docs/plans/2026-09-27-p95-新信号源-设计稿.md` §5.2 VAL-A）。
- 已知事实（写进 docstring 或注释即可，**不要**在代码里硬编码任何覆盖数字做断言）：
  实测宇宙内 `pe_ttm` 取值域 **[−114,501.7, +27,816.5]** ⇒ 不处理必然被极端值主导；
  宇宙内 2018+ 800/800 只、1,530,952 行、100% 非空，但 **2018-01-02 之前零行**。

## §3 T3 用例（`tests/test_research_factor_p97.py` 追加，或新文件 `tests/test_research_factor_ep_ttm.py`）

至少覆盖（每条一个用例，命名自解释）：
1. `pe_ttm > 0` ⇒ 值 = `1/pe_ttm`（用 1–2 个手算得出的夹具值，**不许**只断言「不是 None」）。
2. `pe_ttm = 0` / `pe_ttm < 0` / `pe_ttm IS NULL` ⇒ **不在** `_ep_ttm_map` 的键里（`ep_ttm(...)` 返 `None`）。
3. **PIT 锚是等式**：夹具里同一只标的在 `asof` 前一天与后一天各有行 ⇒ 取到的是 `date == asof` 那行（用一个「昨天故意给个不同值」的夹具把它钉死）。
4. **批量 vs 单只一致**：同一 `asof` 下 `_ep_ttm_map` 的结果与逐只调 `ep_ttm` 的结果逐键相同（防「单只入口偷偷走另一条口径」）。
5. **SQL 条数不随标的数增长**：用 `sqlite3` 的 `set_trace_callback` 计数（或等价的连接级计数器）证明 `_ep_ttm_map` 只发 1 条业务 SQL（不许用「读代码看着像」代替）。
6. **未登记名字仍 fail-closed**：`selected_factors(["pe_pct_756"])` ⇒ `PreregError`（本档**没有**登记它）。
7. **登记完整性**：`RESEARCH_FACTORS` 里每个名字在 `_research_map` 都有分支 —— 用「把某个假名字临时塞进常量后调 `_research_map` 必抛」的**反向自检**（P97 的既有手法）。
8. **缺省逐位不变**（L7）：不传 `factors` 时 `validate_prereg` / 产物键集合与 P97 交付后的期望逐字段相同（若 `p97` 用例里已有同形用例，**复用其夹具与断言手法**，不要另造一套）。
