## 关键实现决策

1. **CSS/JS 外置到静态路由**，不再内联。收益是重复导航不再重下 15KB 样式表
   （配合 `ETag`，命中即 304）。首屏仍是 3 个请求（HTML+CSS+JS），在预算内。
   代价：必须调整 P15 那条**标签级**的"无外部引用"断言（见 ERROR_DIARY #28）——
   改成按 URL 判定，比原来更严。
2. **局部更新走同源渲染函数**：`trades_pane()` / `cash_pane()` 同时供整页与 `fetch` 片段使用。
   两套模板是"局部更新后和刷新后长得不一样"的经典来源，用同一个函数从结构上排除。
3. **不猜字段**：服务端只在错误消息开头的 token 命中字段白名单时才标红那一格；
   「买入数量必须是 100 股整数倍」这种认不出的，只出横幅。标错格子比不标更糟。
4. **非 303 一律交回浏览器**：403（令牌）/409（疑似重复）本来就有整页语义，
   硬塞进 DOM 只会更差。fetch 失败/网络断开也走原生提交，并靠 `_form_id` 保证幂等。
5. **冲正不做局部更新**：它是不可逆动作，走原生 `<dialog>` 确认 + 整页跳转，简单且安全。
6. **`pnl_excl_fee` 不是新口径**：`cost_policy` 里写死"差额即累计费用"，
   所以 `不含费 = 含费 + Σ fees_paid`，两个分量都来自组合视图。

## 已知缺陷与未做

- **无深色模式**。多一套色板 = 多一套对比度证据，本任务预算内不划算，故明确不做。
- **净值曲线无交互**（无 hover 读值、无缩放）。首屏曲线的活是"相对本金线的位置"。
- **`type="date"` 的占位文案是 `mm/dd/yyyy`**：headless Chrome 是 en-US 区域。
  用户浏览器按系统语言显示，非代码问题。
- **大盘指数基线未在首屏**：`index_300` 对照在 `/data` 的验证统计里，总览页没有并列。
  这是 P15 就有的信息布局，本任务不改口径，只记下来。
- **本机原本没有任何 CJK 字体**，中文在 headless 截图里是豆腐块；
  已 `apt-get install fonts-noto-cjk` 并在字体栈里补上 `Noto Sans CJK SC`（见 ERROR_DIARY #27）。
  这是**环境**改动，不是仓库改动。
