## 1. 路由表（`--base-path /lab`，即真实路径都带 `/lab` 前缀）

| 方法 | 路径 | 行为 |
|------|------|------|
| GET | `/`（无前缀） | 303 → `/lab/` |
| GET | `/lab/` | 总览：资产卡片、持仓表、净值曲线（inline SVG）、纪律、风险摘要、趋势、数据新鲜度、LIVE/REPLAY 分开的验证统计 |
| GET | `/lab/trades` | 成交流水 + 录入表单 + 写入回执 |
| GET | `/lab/trades/<id>` | 单笔详情 + 冲正表单（带 `onsubmit=confirm`） |
| GET | `/lab/cash` | 本金/现金流 + 录入表单 |
| GET | `/lab/risk` | 凯利面板（两道门 + NO_BET 原因）、风险指标、止损位并列 |
| GET | `/lab/data` | 数据新鲜度、准确率、最近 20 条 `system_events` |
| GET | `/lab/health` | JSON 自检（degraded 时不抛 500） |
| POST | `/lab/trades` | 录入成交 |
| POST | `/lab/trades/<id>/reverse` | 冲正（append-only） |
| POST | `/lab/cash` | 录入本金/现金流 |

`PUT`/`DELETE` → 405 + `Allow: GET, POST`。前缀外的路径一律 404（不做静默兜底）。

## 2. 为什么新开 `stocklab/labweb/` 而不是扩 `stocklab/dashboard/`

1. dashboard 的「只读」是被测试钉住的契约（`test_post_is_method_not_allowed`），
   而这里必须能写；混在一起等于把那条契约悄悄放宽。
2. dashboard 还要产出离线单文件产物（`dashboard build`），生命周期与常驻服务不同。
3. 复用发生在**函数层**：组合视图调 `portfolio/`、风险调 `risk/panel.py`、
   写入调 `portfolio/ledger.py`，Web 层不含任何口径 —— 因此新包不会产生第二个真相来源。

## 3. 写安全

- **`_token`**：`HMAC-SHA256(服务端密钥, session|日期)` 取前 32 hex；密钥
  `secrets.token_bytes(32)`，只在进程内存里，**不落盘**。校验接受**今天与昨天**
  （`ACCEPT_DAYS=2`）：23:59:59 渲染的页面 00:00:01 提交是正常操作，
  在那里返 403 会让人以为系统坏了。缺失/错误 → **403 且库零改动**（有测试钉住）。
- **303 PRG**：写成功后重定向回列表页，刷新不会重发 POST。
- **两层防重**：
  - 同一 `_form_id`（渲染表单时给出）第二次提交 = 重试 → 幂等命中，不写第二行；
  - **重新敲**一笔完全相同的 6 元组 → 409「疑似重复」确认页，勾选
    「我确认这是另一笔真实成交」才写入。
  这两件事必须分开：同一天分两笔各买 100 股 @86.80 是完全正常的真单。
- **校验失败回显具体哪一条**：`TradeValidationError`/`CashFlowValidationError`
  原文直接渲染（HTTP 400），并保留用户填过的值。
- **未知就显示未知**：`missing_price` 的持仓市值与总资产渲染为「未知」，
  **不拿成本价冒充**；净值曲线在缺价处**断开**，不插值、不平滑。

## 4. 启动与 nginx 反代

```bash
.venv/bin/python -m stocklab.cli.main lab serve --port 8791 --db data/stocklab.db
# → http://127.0.0.1:8791/lab/
```

- 只绑回环：`--host` 非 `127.0.0.1/::1/localhost` **直接报错退出**（bind 之前就拒绝，一个 socket 都不建）。
- `--base-path` 默认 `/lab`；非法值（不以 `/` 开头、含 `?`/`#`/空格/`..`）启动即失败。
- 对外访问走 nanobot 的 nginx：

```nginx
location /lab/ {
    proxy_pass http://127.0.0.1:8791;   # ← 注意：**不要**带尾斜杠
    proxy_set_header Host $host;
}
```

> ⚠️ `proxy_pass http://127.0.0.1:8791/;`（带尾斜杠）会把 `/lab/` 剥掉再转发，
> 后端只认带 `/lab` 前缀的路径 → 全部 404。这一条与 `--base-path` 是一对，
> 改一个必须改另一个。

## 6. 未做 / 已知缺陷

- **未做认证**：服务只绑回环，认证交给 nginx（Basic Auth）。单机自用场景够，
  但「谁能访问 nginx 谁就能下单」—— 外网暴露前必须先加认证。
- `latest_closed_trading_day` 依赖 `trading_calendar` 覆盖到今天；日历未滚动时
  当日成交录不进去（报错文案已指向日历，不是静默拒绝）。
- 净值曲线是逐日 mark-to-market，**不是**逐笔成交曲线；分红/送转未做复权处理
  （账本记的是现金流，不是份额）。
- `/lab/health` 的 `risk_verdict` 目前是 `null`（面板挂在「按市值最大的持仓」上，
  health 未接同一份面板）—— 页面 `/lab/risk` 的结论是准的，health 少一个字段。
