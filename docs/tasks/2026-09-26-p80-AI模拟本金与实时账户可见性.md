## 0. 背景

### 0.1 一句话

**AI 操盘手这条臂现在是「2 万本金 + 看不清自己能买多少」**：本金太小 ⇒ 绝大多数目标权重
落在一手以下（P79 实测 09-23 四笔买入腿全灭）；账户状态只能靠 `paper show` 事后看，
AI 在**决策那一刻**看不到「我手上实际有多少钱、每只最多能买几手」。本站做三件事：

1. **本金改成 5 万**（AI 家族），且**不重写历史** —— 用一条 append-only 的**入金事件**落地；
2. **把账户与购买力变成一等公民**：新增只读实时查询命令 `paper account`，并把同一份口径
   喂进 AI 的 PIT 上下文（`tradability` 扩 `affordable_lots`、顶层 `cash`／`net_deposits`）；
3. **把目标写清楚**：上下文里加 `objective` 块（**目标＝扣除全部成本后的净收益**，
   预测准确度只是手段），读数面把「**净收益（元）**」与「累计收益率」并列展示。

### 0.2 证据（2026-09-26，真库只读）

| 读数 | 值 |
|---|---|
| `paper_accounts`（AI 家族 5 条） | `initial_cash 11320.0` / `initial_nav 20043.0` / `params_json.initial_capital 20000.0` |
| `paper_nav_daily` / AI 臂 | 每条 **2 行**（09-23、09-24；`arm-agent-v1` 1 行） |
| `arm-agent-ds-v2` 09-24 | `cash 4838.16 / mv 14701.0 / nav 19539.16 / cum_cost 34.36`（6 笔成交、0.176% 成本） |
| 全臂 `net_deposits` | 恒 `20000.0`（= `params_json.initial_capital`，**无入金通道**） |
| 真实约束 | 沪市最低佣金 ¥5 ⇒ 单笔 ¥1,000 以下全是「最低佣金税」；一手成本跨标的差 10 倍以上（`601398` ¥813 vs `600519` ¥14 万+） |

### 0.3 为什么这值得单独立站

- **本金是口径，口径要靠事件改，不能靠改行**：`paper_accounts` 与 `paper_nav_daily`
  **都有 `BEFORE UPDATE/DELETE` 触发器**（append-only）。就地改 5 条账户行的
  `initial_cash` 会让 09-23/09-24 那 5×2 行净值**当场变成假账**（P62 的不变量
  `nav == initial_cash + 重放成交 + mark-to-market` 立刻不成立）。所以本金变更必须
  走**事件**：这正是真实账户的做法，也顺手给以后所有「加钱/取钱」留了通道。
- **「实时查询」现在没有入口**：`paper show` 是**全臂快照**、只给最新一行净值；
  想看「这条臂此刻的现金 / 每只最多能买几手 / 今天花了多少」只能自己去算。
  P79 把「一手多少钱」喂进去了，**没喂「能买几手」** —— 半个眼睛。
- **目标是盈利，得写进输入**：`non_goals` 写了「不许做什么」，`objective` 没写
  「为了什么」。准确度是手段这件事如果不落在输入侧，模型就会去优化它看得见的那个数。

### 0.4 与已有口径的边界（不许回退）

| 口径 | 谁定的 | 本站 |
|---|---|---|
| 起跑状态（`_initial_state` / `_declared_seed`：100 股 000333@86.80、2 万本金、入场费 5.09） | P19 | **一字不改** |
| `INITIAL_CAPITAL = 20000.0` 的**值**与静态臂／`arm-now`（实盘镜像）口径 | P19 | **一字不改**（新增独立常量给 AI 家族，见 D1/D3） |
| 整手向下取整、不足一手不凑（`rules.plan_target_weight`） | P19 | **算法一字不改** |
| 资金闸门 `_gate_cash` / `CASH_TOL` / `EXPOSURE_TOL` | P65 | **一字不动** |
| 随机臂敞口上界 v3＋可成交化 v4 | P66/P68/P79 | **逐位不动**（种子材料与抽取序列都不许变） |
| `paper_nav_daily` / `paper_accounts` 的 append-only 触发器 | P6/P19 | **不删、不改写任何既有行** |
| 一手成本公式 `rules.one_lot_cost` | P79 | 复用，不另写 |

## 0.5 锁定口径（按顺序执行；要改先回来说，不要自作主张）

- **D1｜本金分家，靠事件不靠改行**：AI 家族（`account_id` 以 `arm-agent` 开头）
  的目标本金 = **50,000**；`INITIAL_CAPITAL`（20,000）仍是所有臂的**起跑口径**。
  两者之间的 3 万用 **`paper_capital_events` 的一条入金事件**表示 ——
  `paper_accounts` / `paper_nav_daily` 的既有行**一个字节都不改**。
  ⇒ 09-15→09-24 那两天**保持 2 万口径的历史原样**（那段是既成事实），5 万从
  **2026-09-28（下一个交易日）**起生效。
- **D2｜新表 `paper_capital_events`（append-only）**：
  ```sql
  CREATE TABLE IF NOT EXISTS paper_capital_events (
      event_id    INTEGER PRIMARY KEY AUTOINCREMENT,
      account_id  TEXT NOT NULL,
      date        TEXT NOT NULL,          -- 生效日（PIT：只计入 date <= asof）
      kind        TEXT NOT NULL CHECK (kind IN ('deposit','withdraw')),
      amount      REAL NOT NULL CHECK (amount > 0),
      note        TEXT NOT NULL,
      idem        TEXT NOT NULL UNIQUE,   -- 幂等键（重跑不产生第二行）
      created_at  TEXT NOT NULL
  );
  ```
  ＋ 两个 `BEFORE UPDATE/DELETE` 触发器（**形状逐字抄** `paper_agent_evals`／
  `paper_capital_events` 同族写法，见 `store/schema.sql` 与 P79 的迁移）。
  **`kind` 带符号**：`deposit` 计 `+amount`、`withdraw` 计 `-amount`；`amount` 恒正。
- **D3｜标准入金常量与「自动挂上」**（`paper/config.py`，一处定义）：
  ```python
  AGENT_CAPITAL_TOPUP_DATE: str = "2026-09-28"
  AGENT_CAPITAL_TOPUP_AMOUNT: float = 30_000.0
  AGENT_EFFECTIVE_CAPITAL: float = 50_000.0   # == INITIAL_CAPITAL + TOPUP，模块里断言
  AGENT_CAPITAL_TOPUP_IDEM: str = "p80-agent-capital-topup-30000-2026-09-28"
  ```
  三条**建账路径**都要自动挂上这条事件（幂等，同 `idem` 二次插入不新增）：
  ① `paper init` 的 agent 分支（`engine.init_accounts` 里的 `ARM_AGENT` / `ARM_AGENT_RANDOM`）；
  ② `paper agent enroll`（`engine.enroll_agent_arm`）；
  ③ 模块2 通路 A 建账（`m2/channel_a.create_account` → `arm-agent-<策略版本>`）。
  新增一个共用 helper（如 `engine.agent_capital_events_for(account_id)` 返回
  `[(date, kind, amount, note, idem)]`），**三处都调它**，不许各写一遍。
- **D4｜`_ledger_arm_state` 计入事件**：`date <= asof` 的 `deposit` 加现金、`withdraw` 减现金；
  `net_deposits = params_json.initial_capital + Σ(带符号金额 ≤ asof)`；
  **`cum_cost` 不因入金变化**（入金不是成本 —— 与 P19 对入场费的处置同一条理由）。
  `arm-now`（`ledger_state`，读实盘账本）与 `arm-hold`（冻结快照）路径**不受影响**。
- **D5｜实时账户查询（只读，新命令）**：
  `paper account --arm <臂> [--asof <日>] [--json]`，默认 `--asof` = 库里有 PIT 收盘价的
  **最近交易日**（「随时可查」不必等收盘链）。输出三块：
  - `account`：`date` / `cash` / `market_value` / `total_assets` / `net_deposits` /
    `cum_return` / `cum_cost` / `drawdown` / `nav` / **`profit_cny`（= nav − net_deposits）**；
  - `positions_detail`（逐持仓）：`qty` / `price` / `price_asof` / `source` /
    `market_value` / `one_lot_cost`（复用 `rules.one_lot_cost`）/ `sellable_qty`；
  - `buying_power`：顶层 `cash` ＋ 逐池内合格标的 `max_lots_affordable =
    floor(cash / one_lot_cost)`（**含费含滑点**，与执行层同一个成本口径）；
    另加 `fills_on_asof`（该臂当日成交笔数 / 金额 / 费用）。
  缺价、缺账户、池内标的缺 `instruments.type` ⇒ **点名报错或进 `errors`，不猜数**。
- **D6｜把同一份口径喂进 AI 的输入侧**（`agent_context.build_decision_context`）：
  - `tradability.by_code[code]` 增 `affordable_lots`（现金口径整手数）与 `sellable_qty`；
    `tradability` 顶层增 `cash` 与 `net_deposits`；
  - 金额一律**由 `cash`/`total_assets` 现算**，不许写死、不许另写费用公式（复用
    `rules.one_lot_cost` 与 `CostModel.fill_price`）。
- **D7｜`objective` 块（用户第三条）**：`build_decision_context` 新增顶层键
  ```json
  {"objective": {"goal": "扣除全部成本（佣金/印花税/过户费/滑点）后的净收益最大化",
                 "note": "预测准确度只是手段，不是考核目标 —— 本期读数以 paper_nav_daily 的 cum_return 与净收益(元) 为准",
                 "accounting": "net_deposits 含全部入金；cost 累计在 cum_cost"}}
  ```
  文案照抄，别自由发挥；`DECISION_HASHED_KEYS` 加 `"objective"`。**旧台账行的
  `context_sha256` / `payload_sha256` 一律不改写**（append-only）—— 新口径只对新写入生效。
- **D8｜读数面把「钱」摆出来**：`paper agent show` 加 `account` 块（含 `profit_cny`）；
  `/lab/paper` 每个 AI 臂一行加「净收益(元)」；顺便修
  `labweb/paper_data.py:429-430` 的**重复定义**（它自己从 `params_json.initial_capital`
  算净入金 ⇒ 入金事件落地后它会与引擎分叉）—— 改成读引擎/净值行的那一份。
- **D9｜真库只读（站）**：站一律在 `/tmp` 的**真库 APFS 副本**（`cp -c`）上跑写实测；
  建表迁移与 5 条入金事件的**根前滚由 nanobot 做**（备份 + marker + doctor）。
- **D10｜禁改清单**（diff 必须为空）：`stocklab/{predict,verify,candidate,ops,data}/`、
  `config/`、`MODEL_VERSION`、`CLOSE_STEPS`、`MONITOR_STEPS`、`rules.py` 里
  `plan_target_weight`/`plan_orders`/`_settle`/`_gate_cash`/`execute_decision` 的**算法**、
  `agent_decide.random_payload` 的抽取序列与种子材料、`engine._initial_state` /
  `_declared_seed`。

## 2. 风险点（先读 ERROR_DIARY）

- **#48 / #60（append-only 与半截数据）**：新表必须 append-only；触发器写法抄既有表，
  别忘了 `PRAGMA recursive_triggers` 那条测试注意事项。**绝不允许**为了改本金去
  `DROP TRIGGER` 或 `UPDATE paper_accounts`。
- **#62 型（净值行与重放对不上）**：T6①② 就是拿 P62 的不变量当回归判据 ——
  入金事件**只许**影响 `date >= 入金日` 的读数。
- **#73 / #77（「只修了一半」同型）**：本站**不碰**上界/下界公式与随机臂抽样；
  顺手改一下就等于把 P66/P68/P79 的读数作废。
- **重复定义**：`labweb/paper_data.py:429-430` 自己算净入金 ⇒ 必须收口到引擎那一份
  （本项目的既有教训：同一个数两个实现，迟早分叉）。
- **指纹变化**：`DECISION_HASHED_KEYS` 变更会让既有 golden 测试失效 ⇒ 按「同一输入、
  新口径」更新期望，并在 §7 点名「哪几个 golden 变了、为什么」。
- **#55（测试真起子进程）**：一律在 `/tmp` 副本；真库只读

### 7.6 与任务书不一致之处（理由优先，不静默绕过）

1. **标准入金的 `idem` 必须带账户后缀**。任务书 D3 给的是单个字面量
   `p80-agent-capital-topup-30000-2026-09-28`，而 `paper_capital_events.idem` 是
   **全表 UNIQUE**（D2 的表结构）而 5 条 AI 账户各要挂**自己**那条入金：
   用裸字面量会让第一条之后的所有账户被 `INSERT OR IGNORE` **静默吃掉**
   （症状是「4 条账户净入金还是 2 万」，看起来像迁移漏跑，不像键冲突 ——
   实测已撞上：19 例里最初 4 例红）。故新增
   `config.agent_capital_topup_idem(account_id)` 返回
   `AGENT_CAPITAL_TOPUP_IDEM + "-" + account_id`：既满足 D2 的 UNIQUE 形状，
   又保 D3「常量一处定义」（裸字面量仍是那条常量的值，后缀由 helper 推）。
   这正是任务书 §3 预置的处置：硬约束（UNIQUE）优先，偏离逐条点名。
2. **D3 的常量多了一个**：`AGENT_CAPITAL_TOPUP_NOTE`（入金理由原文）。
   `paper_capital_events.note` 是 NOT NULL，而「理由」必须**一处定义**
   （数据库与报告读同一句话）；写成两处字面量迟早漂。四常量仍是四个，
   这是第五个**文案**常量。
3. **`agent_capital_events_for` 之上多了一层 `attach_agent_capital_events`**。
   任务书说「三处都调它」，而「展开 5 元组 → 调 `insert_capital_event`」的循环
   本身才是会被抄三遍的东西；故三处调 `attach_*`，`attach_*` 是
   `agent_capital_events_for` 的**唯一**调用者。事件的定义仍只有一处。
4. **`build_decision_context` 的 `net_deposits` 缺省写 `None`** 而不是 `0` 或
   `total_assets`：净入金是「净收益」的分母，算不出时**不猜一个数**
   （与 `min_weight_pct` 同一处置）。实盘路径一律由 `decision_context_for`
   显式传入，只有测试直调时才是 `None`。
5. **`paper account` / `paper capital list` 收下但不使用 `--now`**：与其余
   `paper` 子命令同形（测试脚本统一拼这个参数）。默认 asof 是**数据**决定的
   （库里有 PIT 收盘价的最近交易日），不是「今天」—— D5 的「随时可查」正是此意。
