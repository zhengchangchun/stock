# ADR-017 沙盒回放口径（调仓周期为观测单元 + 70/30 切分 + 120 周期门槛）

日期：2026-09-20 ｜ 状态：已采纳 ｜ 前置：ADR-016（财报采集口径）、ADR-012（跌破线规则化）、ADR-001 D-05（无 cron）

证据：`docs/plans/2026-09-20-沙盒真回放-验收记录.md`（真实回放实测）
代码：`stocklab/candidate/replay.py`（回放引擎）、`stocklab/plugin/sandbox.py`（判定逻辑）、`stocklab/cli/plugin.py`（CLI 接入）

> **编号说明**：任务书指定 017；`docs/decisions/` 现有最大号为 016（财报采集口径），按「编号顺延不回收」取 **ADR-017**。

## 背景

候选池打分系统（模块1）已有三个池：短期（5日调仓）、中期（20日调仓）、长期（60日调仓）。每个池对应一套插桩脚本（`p1_short`/`p2_mid`/`p3_long`）。沙盒对比回测（`plugin sandbox`）的任务是：对比候选版本与基线版本，判断新版本的因子是否带来了可统计区分的改进。

要定的是**回放口径**：

1. **观测单元**：用交易日还是调仓周期？
2. **切分比例**：训练段与验证段各占多少？
3. **判定门槛**：多少个有效观测才算够？
4. **下游规则**：权重怎么分、空池怎么处理、成本怎么扣、涨跌停怎么处理？
5. **过拟合标记**：何时认为训练段过于乐观？
6. **基准对照**：用什么基准？
7. **无法出结论的池**：如何处理？

## 备选方案

### 1. 观测单元：交易日 vs 调仓周期

- **方案 A：以交易日为观测单元** —— 一个 20 日调仓周期里的 20 个日度收益，来自**同一持仓**，高度自相关。把它们当 20 个独立样本做 bootstrap，CI 会**过窄**，导致实际上没有优势的策略看起来通过显著性检验。是典型的「统计膨胀」错误。
- **方案 B：以调仓周期为观测单元** —— 同一持仓只产生**一个**观测（该周期的净收益）。代价：有效样本量骤降（120 个周期 >> 120 个交易日），但统计正确。

### 2. 训练/验证切分比例

- **方案 C：随机打乱后切分** —— 时间序列打乱会让训练段「看到未来」，等于泄露信息，是典型未来函数。
- **方案 D：按时间序号切分（前 70% 训练，后 30% 验证）** —— 保持时序，训练段不看到验证段的数据。唯一合理选择。

### 3. 判定门槛

- **方案 E：以交易日计（120 交易日）** —— 与 CLAUDE.md 的「样本量门槛 120 个交易日」同量纲，但在调仓周期口径下**过于宽松**：短期池 5 日调仓，120 交易日 = 24 个周期，远不足以做统计推断。
- **方案 F：以调仓周期计（120 周期）** —— 与方案 B 的观测单元一致，严格得多：短期池需 ~600 个交易日（约 2.4 年），中期池需 ~2400 个交易日（约 9.5 年），长期池需 ~7200 个交易日（约 28.5 年）。

### 4. 下游规则

- **方案 G：按因子/择时决策自适应调整下游** —— 「下游也可以改」意味着「改下游」成为另一条提分路径，Δ 的归因立刻失效（CLAUDE.md 单变量原则）。
- **方案 H：下游规则写死（等权 / 空池持现金但计成本 / 扣成本 / 涨跌停不可成交）** —— 只有「被测插桩」是变量，其余全部固定，保证单变量。

### 5. 过拟合标记阈值

- **方案 I：不标记** —— 训练段过于乐观是常见的过拟合形态，不标记就不知道。
- **方案 J：`OVERFIT_TRAIN_GAP = 0.005`（训练段均值超出验证段均值 0.5 个百分点即标「suspected」）** —— 直觉来源：「两段差距到了半个百分点，多半不是噪声」的数值化。**这个数是自创的，没有外部来源**，与 ADR-012 的跌破线阈值、ADR-016 的断更阈值同属项目自创取值。

### 6. 基准对照

- **方案 K：报绝对收益** —— CLAUDE.md 铁律：「任何策略必须与 index_300 / buy_and_hold 比较，跑不赢就明说」。只报绝对收益违反铁律。
- **方案 L：并列报告两版相对 `index_300` 的超额** —— 铁律要求的格式：与 Δ 并列，不替代。两版超额相同 ≠ 有 edge，只是说明候选与基线持仓相近。

## 决策

**1B / 2D / 3F / 4H / 5J / 6L。**

### D-01 观测单元：调仓周期

`period_returns` 返回的是**周期序列**，每个调仓周期一个值。`_bootstrap_ci` 对周期序列重采样，不是对交易日重采样。

### D-02 切分：按时间序号，前 70% 训练，后 30% 验证

`split_train_validate` 实现：`n_train = int(n * 0.7)`，验证段 = 后 `n - n_train` 个。两段**不打乱**，不使用跨段的任何信息。

**Verdict 只看验证段**，训练段均值只用于过拟合标记（D-05）。

### D-03 门槛：120 个调仓周期（验证段）

```python
MIN_VALID_PERIODS: int = 120
```

**⚠️ 这比「120 个交易日」严格得多**：

| 池 | 调仓周期 | 120 个周期对应的交易日 | 对应约多少年 |
|---|---|---|---|
| short（5日） | 5 | ~600 | ~2.4 年 |
| mid（20日） | 20 | ~2400 | ~9.5 年 |
| long（60日） | 60 | ~7200 | ~28.5 年 |

验证段是总周期数的 30%，即需要约 400 个总周期才能让验证段 ≥ 120。长期池（60日）要凑足 400 个总周期，需 24000 个交易日 ≈ **95年历史**——**在可预见的历史长度内，长期池永远出不了结论**（见 D-07）。

### D-04 下游规则写死

固定规则（不可通过插桩参数覆盖）：

| 规则 | 内容 |
|---|---|
| 权重 | **等权**：持仓内所有标的权重相同 |
| 空池 | **持现金**，但计入当期的清仓成本（`EMPTY_POOL_IS_CASH = True`） |
| 成本 | `CostModel` 扣：A 股最低佣金 5 元/笔 + 印花税 + 滑点，按期初价格 × 100 股名义市值比例扣 |
| 涨跌停 | 涨停日**不可买入**（新进仓标的），跌停日**不可卖出**（离场标的）；跳过该笔操作，不计入该期收益 |
| 调仓频率 | `REBALANCE_DAYS`：short=5、mid=20、long=60（常量，不是参数） |

### D-05 过拟合标记（`OVERFIT_TRAIN_GAP = 0.005`）

```python
OVERFIT_TRAIN_GAP: float = 0.005
```

`train_gap = train_mean − validate_mean`：

- `> 0.005`（训练段比验证段好看超过 0.5 个百分点）→ `overfit_flag = "suspected"`
- 其余（含训练段比验证段差、差距不超阈值）→ `overfit_flag = None`

**⚠️ 这个阈值是自创的**，来源是「半个百分点的差距多半不是噪声」这个直觉的数值化，没有外部文献依据。已列为项目自创取值，不掩盖。

### D-06 基准对照：两版各自相对 `sh000300` 的超额并列报告

`benchmark_excess` 对候选版本和基线版本分别计算同调仓日的平均周期超额收益，**并列打印**（不合并）。两版超额相同不意味着有 edge —— 仅说明两版的持仓组合在此窗口内相近。

CLAUDE.md 铁律要求：「任何策略必须与 index_300 / buy_and_hold 比较，跑不赢就明说」。本口径在 verdict 显示前打印，不允许绕过。

### D-07 长期池：已接受的后果

**长期池（60日调仓）在可预见历史长度内无结论**，原因是算术：

- 本库可用窗口：2015-10-08 → 2026-09-14，约 2665 个交易日
- 60日调仓总周期：44 个；验证段（后 30%）：14 个
- 门槛 120 个验证段周期要求约 400 个总周期 ≈ 24000 个交易日

**这是已接受的后果，不是缺陷。** 不许通过以下方式「修复」：

- ❌ 降低 `MIN_VALID_PERIODS`（改口径迁就结果）
- ❌ 把观测单元改回交易日（统计膨胀，得到的是假 WIN）
- ❌ 缩短调仓周期来配合门槛（那就不是长期池了）

接受路径：长期池 verdict 一律 INCONCLUSIVE，进入 `plugin audit` 时记为「首版，样本不足，暂无对照」。

### D-08 单变量原则

`plugin sandbox` 只改**被测插桩**（`plugin_id` 固定），其余插桩一律取当前 active 版本。`replay_period_deltas` 通过 `plugin_overrides` 注入确保：candidate 版本只换目标插桩，baseline 同理。`detail["scripts"]` 字段留痕所有插桩的 script_id，供复查。

### D-09 失败口径 fail-closed

未注入 `deps.replay` → 空序列 → INCONCLUSIVE（不假装「没有回放」等于「没有差异」）。任何异常不静默吞，`detail` 字段留痕原因。

### D-10 首版无 baseline

`baseline_script_id is None`（首版，还没有 active 版本）时，verdict 直接是 INCONCLUSIVE，理由「首版没有 baseline，只能看绝对表现」。**不调用 replay**（没有对比就没有 Δ）。

## 后果

**好处**

- 短期池在 2015–2026 窗口内可产出真实 verdict（实测 n=160 > 120）；沙盒的「一律 INCONCLUSIVE」行为已被替换
- 统计口径正确（调仓周期为观测单元），bootstrap CI 不会虚胖
- 下游规则写死 + 单变量原则，「改下游提分」路径被堵死
- 过拟合标记可见，不会静默接受训练段过于乐观的版本

**代价 / 已知限制（显式记账，不掩盖）**

1. **中期池样本不足**：20日调仓在 2015-2026 窗口内只有 133 个总周期，验证段 40 个，低于门槛 120。不是回放缺陷，是算术限制。要出结论需约 9.5 年以上的验证段数据（≥ 24 年总窗口）。
2. **长期池永久 INCONCLUSIVE**：见 D-07。
3. **`OVERFIT_TRAIN_GAP = 0.005` 是自创取值**：没有外部文献依据，可能与实际过拟合的统计阈值不符。作为提示使用，不作为拒绝版本的充分条件。
4. **候选=基线时 Δ 恒为 0**：本轮所有内置插桩（1.0.0 版）首次跑 `plugin sandbox`，candidate=baseline，Δ=0，短期池 verdict=LOSE 是已知的必然结果，**不是策略负超额的证据**。（Fix Round 2 更新：plugin_id=1 已注册 v1.1.0（script_id=7），全窗口对比产出真实 LOSE，n_periods=160——此条在 plugin_id=1 上已不适用；其余插桩仍处于首版 self_comparison 状态，此条对它们仍成立。）
5. **等权假设**：实盘持仓可能不等权（当前持有 000333 约 50%），等权回放与实盘有结构性偏差。
