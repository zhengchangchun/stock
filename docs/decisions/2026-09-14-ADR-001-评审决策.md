## 2. 阻塞项决策（对应评审 E 节）

### D-01【B1 复权方案】→ 采用**方案 1：自建 PIT 复权因子链**
- 数据构成：
  - `bars_raw`：腾讯**不复权** OHLCV（主源，≤900 根）
  - `corp_actions`：除权除息事件表（腾讯 fqkline 的事件行：`cqr` 除权日、`fh_sh` 每 10 股派息、`FHcontent` 原文）
  - `adj_factor`：**自建**，规则为 `factor(t) = Π (1 - 现金分红/除权前收盘)` 逐事件累乘；**回测/特征在日期 T 只允许使用 `cqr <= T` 的事件**（这是 PIT 的关键）
- 禁止：直接把腾讯 qfq 序列当"前复权"使用（它是用最新因子重算的，违反 R3）。qfq 序列**仅用于交叉校验**（自建因子链 vs 官方 qfq 的累计差异 < 0.5%）。
- 无事件时 `adj_factor = 1`，必须以显式默认值入库，禁止 NULL。
- 依据：探针已证明不复权 + 事件两个输入都拿得到，成本可控且正确。

### D-02【B2 长历史】→ 接受 **900 根（≈3.7 年）** 作为 v1 数据窗口
- 主源腾讯，单次请求上限按 900 根；需要更长历史时**分页拉取 + 本地拼接**（P2 实现，不作为 P1–P4 阻塞）。
- walk-forward 可跑折数：(900 − 310) / 60 ≈ **9 折**，满足 P4/P8 需要。
- 若未来需要更长：优先试东财分段 `beg/end`；仍不行则把"样本量不足"写入 ADR，**不允许假装能跑**。

### D-03【A5 归因】→ 接受**两级归因**
- `attribution_auto`：v1 只自动判 `DATA`（有客观判据）；其余落 `UNDETERMINED`。
- `attribution_manual`：`SIGNAL` / `STRATEGY` / `MODEL` / `NOISE` 作为**人工标注假设标签**，独立字段。
- **禁止**用 if-else 假装归因。如实记录"未归因"优于伪造归因。
- `NOISE` 是合法且重要的结论，必须能落库。

### D-04【D3 策略数量】→ v1 做 **4 个**（在评审建议的 3 个上 +1）
`buy_and_hold`、`index_300`（两个基准）+ `trend_ma` + **`dividend_hold`**。
- 加 `dividend_hold` 的理由：参数极少（PE 分位 + 股息率），且**与用户真实持仓（美的，股息率 4.4%）直接对应**，验证结果对用户有直接价值。
- `breakout` / `range_grid` / `pullback` → **闭环跑通且样本量达标后再加**。

### D-05【C8 调度归属】→ **项目只产出报告，不实现 cron**
- stocklab 产出 `reports/YYYY-MM-DD.json` + `.md`，退出码语义化。
- **推送与调度全部由 nanobot 侧 cron 负责**。项目内禁止实现任何定时/守护进程。

### D-06【A2 实盘账本】→ **只录成交流水**
- `real_trades(date, code, side, price, qty, fee, note)` 为唯一录入接口；持仓与净值一律**由流水推导**。
- 禁止每日持仓快照表。用户只在**发生交易时**录入一条。

## 3. 硬伤修正（对应评审 A/B 节，全部接受）

| 编号 | 决策 |
|---|---|
| A1 | `features_daily` 主键 = 自增 `snapshot_id`，加 `UNIQUE(code, date, feature_version)`；下游只经 `predictions.feature_snapshot_id` 引用 |
| A3 | R7 由"系统级"降为"**单策略级**"（单策略参数个数 ≤ 该策略样本外样本数/10），并**实现为自动测试**（策略注册时断言）；另设**冻结参数集**（评分权重、集成半衰期、flat 阈值）v1 不进优化循环 |
| A4 | 高频特征落**宽表列**（≥10 个），长尾特征才进 `json_payload` |
| A6 | 预测**一旦落库永远计入分母**；触发 `invalidate_if` 的额外打 `invalidated` 标记并**单独统计该子集**；禁止事后剔除 |
| B3 | 新增 `raw_fetch_cache(source, code, date_range, fetched_at, content_sha256, body)`；**复现模式一律读缓存不联网**；同时作为测试 fixture 来源 |
| B4 | 交易日历 = **沪深300 指数日线日期集合**（落 `trading_calendar` 表），零额外数据源 |
| B5 | v1 **冻结"每周参数再优化"**，只做周度回测报告 + 策略权重按规则调整 |
| C1 | R6 门槛改为 **≥120 个交易日**的样本外观测，统计**按日聚类**（对每日截面取均值后再算统计量 / block bootstrap）；禁止用"140 个组合 = 140 个样本"自欺 |
| C2 | 成本模型加 `min_commission = 5.0 元`，并单测"小额成交按 5 元计"分支 |
| C3 | schema 层单位固定为「**股 / 元**」；加断言 `amount ≈ close × volume`（容差 1%） |
| C4 | 采集失败的标的必须落 `predictions` 缺失记录（或 `status='failed'`）**计入分母**；报告给出「本日成功 N/M」 |
| C5 | 实现 `record_fixture` CLI：真实抓一次 → 存原始响应 + 元数据（URL/headers/时间/hash），测试回放走同一解析路径 |
| C6 | 采集器 = **适配器接口 + 字段映射表**（`raw -> list[Bar]` 纯函数）；**双源交叉校验**，同日收盘偏差 > 0.5% 告警 |
| C7 | 新增 `job_runs(job_name, scheduled_at, started_at, finished_at, status)`；启动时检测"上次成功距今超阈值"→ 写 `system_events` 并告警 |

## 7. 复权地基验收补充（新增，必须测）

因为 D-01 是自建因子链，必须补两条测试：
1. **PIT 性测试**：用 `cqr > T` 的事件构造反例，断言 T 日因子不受其影响。
2. **交叉校验测试**：自建因子链累计收益 vs 腾讯官方 qfq 序列累计收益，偏差 < 0.5%；超阈值告警而非静默通过。
