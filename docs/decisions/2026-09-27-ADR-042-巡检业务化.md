# ADR-042 巡检业务化：只读的边界与「唯一可写的那一格」

- 日期：2026-09-27
- 状态：已采纳
- 上游：`docs/plans/2026-09-26-需求对照全量审计.md` §2 B5；`docs/tasks/2026-09-27-p92-巡检业务化.md`
- 相关：ADR-019（巡检本体在项目里）、ADR-041（候选池状态事件表）、ADR-038（公告与北向数据层）

## 背景

07 §任务1 的「轻量巡检｜每 30 分钟」列了 7 件事，P38 只把其中**数据链体检**那部分
搬进了 `ops/patrol.py`（7 项 + 缺步补跑 + 退出码）。剩下的业务面一直没有落点：
插桩0 重校验风险（②）、熔断检测（⑤）、更新候选池标的状态（⑥）、简报（⑦），
以及北向/公告的**新鲜度**（①里属于读的那一半）。本档把它们并进 `ops patrol`。

## 决策

### D1 业务块挂在 `check_chain()` 快照的新顶层键 `business` 下，形状固定

四个子块 `risk_screen` / `fuse` / `candidate_status` / `freshness`，键**只增不减**
（页面与简报按它读）。每个子块必须有 `reason`（人话、含关键数字）——
只给 `status` 会逼读者去翻实现才知道「为什么是这个状态」。

子块的 `status` **复用** `patrol.py` 已有的状态词汇表，不新造第二套；
只为业务块加了两个词：`TRIPPED`（熔断已触发）与 `RISKY`（排雷命中）。
两个都**刻意不在** `ANOMALY_STATUSES` 里 —— 业务块不进 `checks`，它的异常由
`_anomalies()` 显式露面，而不是搭通用状态机那趟车。

### D2 熔断是**唯一**进退出码的业务读数（`EXIT_ANOMALY = 1`）

- 只读路径：未收尾的 `validation_cycles` ＋ `paper_nav_daily`（`date >= start_date`）
  ⇒ `m2.selfeval.fuse_verdict`（**复用**，不重写回撤算法）；
- **绝不调 `m2 cycle fuse-check`**：那条命令在一个事务里往 append-only 的
  `validation_events` 追加 `circuit_breaker` + `validation_end` 两行。30 分钟一轮
  会把它写花，而且「触发即终止验证周期」是个**动作**，不该由闹钟按下；
- `validation_cycles` 为空 ⇒ `skipped` + 「没有进行中的验证周期」，**不计异常**；
- 其余三块（排雷 / 状态 / 新鲜度）**只展示**。盘中每 30 分钟报一次假警会把巡检
  变成噪音 —— 这与 `verdict()` 里「② `unknown` 不计异常」是同一条理由。

熔断异常排在 `_anomalies()` 的**最前**：断链（`EXIT_BLOCKED`）那条早退不能把它
吞掉，两件事都要看得见。

### D3 候选池状态：默认**只算不写**，写路径走子进程

- 推导规则的**白名单只有一条**：池内成员被**任一 live 账户实际持有** ⇒ `已建仓`。
  其余三个状态（观察中 / 等待买点 / 逻辑证伪移出）**不可自动推导** ——
  机器判不出「逻辑证伪」，写死一条规则比不写更糟；
- 「live」走 `paper.engine.live_of`（同一把尺子，`params.live` 缺省 true）；
  持仓取每账户**最新净值行**的 `positions_json` 里 `qty > 0` 的标的；
- 默认 `would_set` 只列出「打开开关会写哪几条」，`applied` 恒空、**一行不写**；
- `--update-status` 打开后用**子进程**逐字调 P91 的 `candidate status set`
  （本仓 `ops` 纪律：补步一律子进程复用现成 CLI，不 import 业务函数）。
  幂等由 P91 的表保证：同 `(code, asof, status)` ⇒ 打印 `already`、exit 0、零写入。
  子进程的失败照实记进 `applied[*].exit_code`／`detail`，**不改退出码**。

### D4 简报：产物不阻断

`<report_dir>/ops/brief/<YYYY-MM-DD>.md` **追加**（同日第二轮不许覆盖第一轮）＋
`<report_dir>/ops/latest-patrol-brief.md` **覆盖**。内容**只由本轮 payload 生成**
（不现场再查库、不引入新判定）。写失败 ⇒ 只记 `payload["brief_error"]`，
退出码一个字不改（同 P58 的非阻断步纪律）。

### D5 命令载荷与调度面不动

`--update-status` **默认关** ⇒ launchd 里那条 `ops patrol --fix` 逐字节不变：
`ops schedule generate` 的 `patrol` 载荷 sha 仍是 `73649b8a0bd6b25b…`、槽数仍 60，
`close` / `monthly` / `weekly` / `quarterly` 也逐位不变。`ops/chain.py`、
`CLOSE_STEPS` / `MONTHLY_STEPS` / `WEEKLY_STEPS`、`ops/schedule.py` **零改动**。

### D6 不做 A3/B1 高频刷新（明确不做）

盘中 `bars` 未定型（`ops close` 的 P46 口径＝当天 `fetched_at ≥ 15:00` 才算定型），
30 分钟重复跑 A3/B1 会拿半天数据反复写 append-only 台账，并与 `m2_daily` 的收盘
口径打架。**要做的话前置**：先有一个「当日 bar 已定型」的判据（`fetched_at ≥ 15:00`
＋ `amount` 非 NULL 的覆盖率门槛）＋ A3/B1 改成「同日同 asof 幂等覆盖」而不是追加
⇒ 那是一次口径变更，得另立任务书。本档零改动。

## 「只读 / 可写」分界（一句话）

| 动作 | 落点 | 是否写库 |
|---|---|---|
| 排雷、熔断、新鲜度、状态**推导** | `ops/business.py`（只读连接） | 否 |
| 状态**写入** | 子进程 `candidate status set`（`--update-status` 才起） | 追加 `candidate_status_events` |
| 回执 + `job_runs` | `journal.seal`（巡检本来就有） | 每轮 1 行 |
| 简报 | `reports/ops/brief|latest-patrol-brief.md` | 文件，非库 |

副本实测：跑一轮 `ops patrol` 后**除 `job_runs` 一行外零新增行**；
加 `--update-status` 才多出 `candidate_status_events` 行，重跑 ⇒ `already`、零新增。

## 偏离与代价

1. **`risk_screen` 复用 `candidate/run.py` 的私有助手**
   （`_load_bars_adjusted` / `_cross_section_map` / `_load_bars`）。
   口径必须与 `candidate run` 第 4 步逐位相同，而那份口径就写在那三个函数里；
   在 `ops/` 再抄一份 = 迟早分叉（后果是「巡检说干净、主流程却拦下了」）。
   代价：跨模块引用下划线名，`candidate/run.py` 改签名会连带打到本模块。
2. **排雷的横截面用默认宇宙（`SEED_UNIVERSE`）**。若最新快照是用别的宇宙
   （如 `csi300-500`）跑的，池内某些代码不在 `xsec` 里 ⇒ `build_ctx` 跳过
   横截面因子（`if cross_section and inst.code in cross_section`），
   这一块的排雷输入比 `candidate run` **少几个因子**。如实记：
   本档不改「跟着快照的 params 还原宇宙」（那是另一次口径变更）。
3. **业务块只在**第一趟**体检时算**。`--fix` 之后的复检传 `with_business=False`
   （业务读数与「补步有没有修好」无关，重跑只是白烧插桩0 的沙盒）。
   于是 `payload["business"]` 永远是第一趟的读数；熔断不会被补步修好，
   所以它的异常与退出码在 `run_patrol` 里**单独带进**最终结果。
4. **`payload["brief_error"]` 只在失败时出现**（成功不新增键）。这是为了满足
   G3 的「只多 business 键」；代价是成功路径在载荷里看不出简报写过 ——
   文件路径是确定可导出的，回执的 `journal.report` 也指得着。
5. **`check_db` 默认算业务块**，而 `ops/chain.py` 每次运行要调它 3 次
   （D10 规定 `chain.py` 一字不动）⇒ 收盘链/月链每轮多付约 3×0.5s
   （副本实测业务块整块 0.51s，12 只成员、真插桩0）。如实记，不改。

## 未做 / 留给后续

- 自动推导「等待买点」「逻辑证伪移出」：需要一条**说得清**的判据，本档没有。
- 页面（`/lab/ops`）消费 `business` 键：本档只保证多出来的键**不破页面**
  （HTTP 200、不缺字段、不抛异常），展示留给后续。
- 简报的保留策略（按日文件会一直堆）：本档不做清理。
