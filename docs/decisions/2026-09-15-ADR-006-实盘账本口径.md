# ADR-006：实盘账本的口径（成本含费 / 现金与总资产定义 / 无保证金 / 冲正而非修改）

- 日期：2026-09-15
- 状态：**已采纳**（P12 落地）
- 相关：`docs/plans/2026-09-15-p12-实盘账本与组合视图.md`、ADR-001 §5（append-only）、ADR-005（幂等键取语义）

## 背景

P12 之前 `real_trades` 表建好了但**零写入入口**（实测 `count(*) = 0`），也没有本金/现金表。
「实盘现在什么状态、纪律破没破」在系统里无法回答。

要让账本可用，必须先定死四个口径问题。它们每一个都能让同一份数据算出**不同**的数字，
而且**都看不出来**——所以必须在写代码前定，并写在这里，而不是散在代码注释里。

用户背景事实（原样入库，不许改数）：本金 20,000 元（2026-09-14 到账）；
2026-09-14 买入 000333 100 股 @86.80，费用 5.09 元；用户口述「成本 8,680」= **不含费**。

## 决策

### D-01 成本默认**含费**，同时输出不含费

| 字段 | 定义 |
|---|---|
| `cost_basis_incl_fee` / `avg_cost_incl_fee` | 价×量 **+** 费用。账户里真正花掉的钱 |
| `cost_basis_excl_fee` / `avg_cost_excl_fee` | 只有价×量。对用户口述的「成本 8,680」 |

**含费是默认口径**。理由：与《准确率优先·扣成本》同源（「回测不扣成本的成绩视为无效」），
实盘对比也必须同口径，否则模拟盘与实盘的收益差里混着一个手续费，无法归因。

不含费数字**照样输出**，因为用户报数时用的是它：用户说现金 11,320，账本说 11,314.91，
差 5.09。两个口径并列，差额一眼可见 —— 而不是让人怀疑账算错了，或者（更坏）
为了让数字对上而**悄悄不算费**。

实测：`avg_cost_incl_fee = 86.8509`，`avg_cost_excl_fee = 86.80`。

### D-02 现金 = Σ现金流 − Σ买入(价×量+费) + Σ卖出(价×量−费)

这是唯一能对上**券商流水**的算法。现金不单独存一张表、不存余额字段：
存余额就要在每次写成交时同步更新它，那就有了第二个真相来源，
两者不一致时无法判断谁对。**现金永远是推导量。**

现金流三分解（`cash_breakdown`）：

| 项 | 定义 |
|---|---|
| `net_deposits` | Σdeposit + Σwithdraw（withdraw 记负数）——「本金净投入」 |
| `trade_cash` | Σ成交净额（买入为负、卖出为正，均含费） |
| `other_cash` | 分红/税费等 |

### D-03 累计净投入 = Σdeposit + Σwithdraw；累计收益 = 总资产 − 累计净投入

分红**不进**净投入 —— 它是投资收益，不是本金。把分红算进投入会让收益率凭空变小。

### D-04 总资产 = 现金 + Σ**有现价**的持仓市值

拿不到现价的标的**排除出合计**，置 `missing_price`，并把该标的的
`price` / `market_value` / `weight` 全部置 `null`（不是 0，不是成本价）。

**不许用成本价冒充现价、不许插值。** 用成本价冒充会让浮亏恒显示为 0 ——
所有"看起来正常"的错误里最坏的一种，因为它让人以为没事。

### D-05 **没有保证金**

A 股现货全额交易，无杠杆、无维持担保比。账本不需要保证金字段，
也不做任何强平/追保判定。将来若接入融资融券，**另开 ADR**，不要往本账本里塞字段。

### D-06 改错**只能冲正**，不许 UPDATE

`real_trades` / `cash_flows` / `ledger_idem` 三表 append-only（触发器钉住 UPDATE 与 DELETE）。
改错的唯一合法路径是**追加一笔反向记录 + `note` 说明原因**（`trade reverse --reason`）。

理由：账本是「我真做过什么」的唯一记录。事后改写会让**所有归因失效**，
且失效时没有任何痕迹。冲正会让错误作为一行**留在历史里**，
连同「为什么冲」一起 —— 历史仍然可读，而不是被抹掉。

### D-07 重复录入**不用唯一约束**，用幂等键 + 显式二次确认

❌ **不加** `UNIQUE(date, code, side, price, qty, fee)`。

理由：真实成交**可能同价同量同费**。同一天分两笔各买 100 股 @86.80、佣金都是 5.09，
是完全正常的真单。唯一约束会**静默吃掉真单**，吞的时候一声不响 ——
这比重复录入危险得多（重复录入手滑能被看见，被吃掉的单永远不会被发现）。

✅ 两层机制，**都不阻止真单**：

1. `--idempotency-key KEY`：键落 `ledger_idem` 表。同键第二次 → `state="identical"`，
   不写第二行，退出码 0（"幂等命中"在调度链口径里算成功）。
   解决「命令重试 / 补跑」。
2. 无 key 且元组完全相同 → **硬拒**（退出码 2），提示要么给 `--idempotency-key`、
   要么给 `--allow-duplicate` 确认这是另一笔真单。解决「手滑敲两遍」。

**为什么键必须由调用方给**：只有调用方知道自己是不是在重试。
业务元组相同既可能是重试也可能是真单，从数据本身**无法区分**。

`ledger_idem` 主键是 `(idem_key, scope)`：同一个 key 字符串用在成交与用在现金流上是两回事。

## 后果

- 现金 11,314.91 ≠ 用户口述 11,320：**这是对的**，差的就是手续费。已在组合视图里并排输出两个口径。
- 买入当天必然显示浮亏一个手续费（`float_pnl_incl_fee = -5.09`）：**这是对的**，
  不含费口径同时给出 0.00。若哪天含费浮亏不等于 −费用，说明账本有问题。
- 冲正会留下两行；查「实际持仓」永远走 `replay_trades()`（按 `(date, trade_id)` 回放），
  不要用 `SELECT` 直接数行。
- 纪律线（85.00 / 83.25 / 87.00）是**按标的**的（`PER_CODE_LINES`），由**入场价**推出。
  拿它们去量别的标的是错的口径，系统对未配线的标的判 `UNDETERMINED` 而不是套用。
