# 018. 单一 Web 服务（合并 `dashboard serve` 进 `lab serve`）

- 日期：2026-09-21
- 状态：已接受
- 触发：用户「改造后就一个服务，不要其他那些，都合并到一起」

## 背景

本机曾同时存在**两个网页服务**，而它们的**默认端口都是 8791**：

| 服务 | 来源 | 性质 | 端口 |
|---|---|---|---|
| `dashboard serve` | P14 | 只读快照（`/`、`/lab/`、`/health`、`/api/summary`） | 8791 |
| `lab serve` | P15 | 应用（八个页面 + 表单写路径） | 8791 |

后果不是「浪费一个端口」，而是三件具体的事：

1. **本机此刻跑着哪一个只能靠记忆回答** —— 两者都能在 `/lab/` 返回 200，
   但一个只读、一个带写路径，页面上看起来还都是同一套壳。
   ERROR_DIARY（`scripts/ui_shot.sh` 写死 `--port 8791` 那一条）已经踩过一次：
   脚本连上的不是它以为的那个服务。
2. `labweb/__init__.py` 里为此写了一整段「为什么不扩 dashboard」的取舍记录，
   还有一条契约（`test_post_is_method_not_allowed`）在维护「只读」这个词 ——
   属于**为区分而付出的持续成本**。
3. 导航与入口分裂：`dashboard` 有 `/api/summary`，`labweb` 有 `/health`，
   想用 JSON 观测的人得先知道该敲哪个端口。

## 备选方案

1. **合并进 `lab serve`，`dashboard` 只留离线产物**（选中）
   - 优点：一个入口、一套导航、一份回环白名单；写路径享受已有的 CSRF + 幂等纪律；
     `dashboard build` 的单文件 HTML 本来就是「可双击、可转发」的离线物，不是服务。
   - 缺点：`/api/summary` 这个稳定 JSON 接口随服务一起消失（无消费者，仅自有测试）。
2. **合并进 `dashboard serve`**（反向）
   - 优点：只读服务的攻击面更小。
   - 缺点：要给它加写路径，等于把「只读」这条被测钉住的契约亲手拆掉；
     而 `labweb` 的八个页面与表单逻辑远多于看板。
3. **保留两个服务，把端口错开**（`8791` / `8792`）
   - 优点：不动代码。
   - 缺点：**没有解决「哪个是哪个」**，只是让它更难记；用户明确说了「不要其他那些」。

## 决策

方案 1。落地为：

- `stocklab/dashboard/server.py` 只保留**回环守卫**（`LOOPBACK_HOSTS` /
  `NonLoopbackHost` / `assert_loopback`）—— 它是 `labweb` 复用的那一份，
  留在原处避免第二份白名单。HTTP 层（`route` / `make_server` / `make_handler` /
  `summary_health` / `bound_url` / `Context` / `Response`）整体删除。
- CLI：删掉 `dashboard serve`（argparse 里 `dashboard` 只剩 `build`）；
  `lab serve` 是**唯一**的网页服务，端口 8791。
- `dashboard build` 与 `dashboard/summary.py` 的 JSON 契约**保留不动**：
  离线产物仍然按同一份摘要渲染，摘要结构版本仍是 `SCHEMA_VERSION = 1`。
- `/api/summary` **不迁移**：合并后 `/lab/health`（JSON）已覆盖「服务活着 + 库在不在 +
  摘要算不算得出来」。要一次性快照用 `dashboard build`。

## 后果

- 好处：一个地址（`http://127.0.0.1:8791/lab/`）、一套导航、一份白名单；
  以后加页面不用再决定「放哪个服务」。
- 代价：`/api/summary` 这条只读 JSON 接口消失；若要恢复，应在 `labweb` 里重新开
  `/lab/api/summary` 并作为**一个**新契约（而不是把旧服务请回来）。
- 护栏（可执行，防止无声回退）：
  - `tests/test_dashboard_server.py::test_module_public_surface_is_just_the_guard`
    —— `dashboard.server` 的公开面就是三个名字，`make_server` / `route` 等一旦回来即判红；
  - `tests/test_cli_dashboard.py::test_dashboard_serve_is_gone` ——
    `dashboard serve` 必须是 `invalid choice`（退出码 2），且 `lab serve` 仍可用。
- 后续注意：nginx 反代只需指向 **8791 一个**上游（`proxy_pass http://127.0.0.1:8791;`
  不带尾斜杠，见 `docs/tasks/2026-09-15-p15-task66-70.md`）。
