# ADR-011 估值 / 资金流采集口径（PIT 硬口径 + 首写保留 + 非 PIT 风险披露）

## 背景

`regime_label` / `main_net_5d` / `pe_pct_3y` 三个特征此前**没有数据来源**。
P28 建了采集路径：源 A 东财 `datacenter-web`（估值）、源 B 新浪 `vip.stock.finance.sina.com.cn`（资金流），
落 `valuation_daily` / `money_flow_daily` 两张 PIT 表。

要定的是**口径**，不是「怎么抓」—— 具体说：这两张表的 PIT 语义到底有多硬、
源站改写历史怎么办、拿不到数据写什么、以及**采完的数据能不能直接喂策略**。

## 备选方案

### 1. PIT 语义的三种做法

- **方案 A：严格 PIT（只用 `fetched_at <= asof` 的行）** —— 语义最强，但首日采集的历史全是
  「今天才抓到」的，下游 `date <= asof` 会一行都读不到，采集等于白做。
- **方案 B：`date <= asof` 就认（采信 `date` 为 PIT 键）** —— 可用，但**默认源站不会改写历史**。
  这个假设对东财 `RPT_VALUEANALYSIS_DET` **不成立**（它是重算报表，见下）。
- **方案 C：`date <= asof` + 首写保留 + 源站改写留痕 + 非 PIT 风险显式披露** —— B 的可用性 + A 的诚实。

### 2. 源站改写历史的对策

- **方案 D：覆盖（`ON CONFLICT DO UPDATE`）** —— 总是拿最新值。等于让最新股本**反复洗历史**，
  回测里会出现「2018 年的 PE 用的是 2026 年的股本」这种**未来函数**。
- **方案 E：首写保留（`ON CONFLICT DO NOTHING`）+ 值变了记 `restated` 留痕** ——
  第一次观测离那天最近，比让源站反复重算可信；改写**不静默**。

### 3. 拿不到数据写什么

- **方案 F：填 0 / 用前值填充 / 估算** —— 下游分不清「真的是 0」和「没有数据」。
- **方案 G：写 `NULL`** —— 下游必须显式处理缺失。

### 4. 采完立刻上策略？

- **方案 H：本轮就接进特征/策略** —— 数据没验证过就上，等于用未验证输入做准确率结论。
- **方案 I：本轮只采集，不接策略** —— 采集与消费解耦，P29 再单独预注册评测。

## 决策

**全部取后者：1C / 2E / 3G / 4I。**

### D-01 PIT 硬口径：下游只允许读 `date <= asof`

`valuation_daily.date`（东财 `TRADE_DATE` 裁剪到 `YYYY-MM-DD`）与 `money_flow_daily.date`
（新浪 `opendate` 原生即 `YYYY-MM-DD`）就是 **PIT 键**。

- `fetched_at`（入库审计时刻）与 `created_at` **不是** PIT 键，只用于溯源；
- 本轮**不写下游读层**，但表语义先钉死：任何消费方**只允许** `WHERE date <= :asof`。
  `asof` 之后的 `date` 行在回测/预测里一律不可见（`date` 是交易日，不是入库日）。

### D-02 append-only + 首写保留

- 两表各挂 `trg_valuation_daily_no_update/delete`、`trg_money_flow_daily_no_update/delete`，
  `RAISE(ABORT, …)`；`connect()` 已开 `recursive_triggers=ON`，连 `INSERT OR REPLACE` 的隐式 DELETE 也拦得住。
- 幂等键 `PRIMARY KEY (code, date)` + `ON CONFLICT(code, date) DO NOTHING` →
  同一区间重跑**新增 0 行**（实测：`{"rows":0,"restated":0,"fetched":4}`，前后行数不变）。
- 「重采但值变了」不覆盖、只留痕：计入 `restated` 并写 `system_events` warn
  （与 `insert_corp_actions` 同款语义）。**历史行一次写入后永不改写。**

### D-03 非 PIT 风险（**必须显式披露**）及其对策

**风险**：`RPT_VALUEANALYSIS_DET` 是**重算报表**。东财可能按**最新股本**重算整条历史 PE/PB。
即「今天抓到的 2018 年 PE」**不一定等于**「2018 年当时能看到的 PE」。
这是估值序列的**结构性局限**，不是 bug，本 ADR 也不假装它不存在。

**对策（三层）**：
1. **首写保留**（D-02）—— 第一次观测离那天最近，比让最新股本反复洗历史更可信；
2. **改写留痕** —— `restated` 计数 + `system_events` warn，**不许静默**；
3. **下游披露义务** —— 任何引用估值序列的报告**必须**写明「估值序列可能被源站整体重算」。
   这是「非 PIT 里最接近 PIT 的选择」，不是「已经 PIT 了」。

> 用户级判断：**本 ADR 明确不把 `valuation_daily` 称作 PIT-安全数据**，只称「PIT 键已钉死、
> 但有已知的非 PIT 残余风险且已披露」。下游若把它当严格 PIT 用，是**误用**。

### D-04 NULL 语义：拿不到写 NULL，不填 0、不估算

- 源拿不到（`"-"` / 空串）→ `to_float` 返回 `None` → 写 `NULL`。
- **不许填 0**（0 是合法值，会与「没有数据」混淆）、**不许用前值填充**、**不许估算**。
- 唯一例外是**显式覆盖记录**：某个标的在某个源结构性拿不到数据 → 写 `system_events`
  一条 warn（谁、哪个源、为什么），**不是**写假行、**也不是**静默缺失。

### D-05 ETF / 缺数据的显式覆盖（实测修正了原假设）

实测（证据 f）把原计划的一个假设**否证**了：

| 源 | 510300 / 510880 / 512890 / 518880 | 处置 |
|---|---|---|
| 估值（东财 datacenter） | **4 只全部 `rows=0`** | 已落 4 条 `system_events` warn 显式覆盖（`event_id` 24–27）。原因：`RPT_VALUEANALYSIS_DET` 是**个股估值报表**，ETF 无 PE/PB 概念，源站返回空集 —— **不是抓取失败**（`failed=[]`、退出码 0） |
| 资金流（新浪 MoneyFlow） | **4 只全部有数据**（各 43 行，字段零 NULL 零 0） | **不再适用「无数据」覆盖**。代码 `if not rows and inst.is_etf` 使其正确地**不写** warn |

**决策**：覆盖记录按 `(code, source)` **逐对**判定，**不按标的一刀切**。
「ETF 没有估值/资金流」是**半个错误假设** —— 只有估值那一半成立。
`asset_type='etf'` 不是「一定没数据」的同义词，任何「按类型跳过」的优化都是错的。

### D-06 溯源三件套（实为四件）

每行都带：`source`（如 `eastmoney-datacenter` / `sina`）、`fetched_at`（入库审计时刻）、
`resp_sha256`（该行来源响应体的 sha256）、`cache_key`（raw_cache 的 `params_key`，
可直接定位 `data/raw_cache/` 下的原始响应体）。**能复现、能对拍、能查账。**

缓存键遵 ADR-009：估值 `valuation:{code}:{end}:{page}:{pageSize}`、
资金流 `moneyflow:{code}:{end}:{page}:{num}` —— 第 3 段是锚点 `end` 日，
故 `is_intraday_snapshot` 自动生效：**盘中抓的快照不进正式缓存、读侧视为未命中**。

### D-07 失败口径 fail-closed

解析失败 / 非合法 JSON / 空页异常 → 抛 `FetchError`，**整批不落库**
（不许把半截数据当完整）。分页走到底（东财按 `result.pages`，新浪翻到空页 + 翻页上限防死循环）；
单标的失败记 `system_events` error 并计入 `failed`，**不拖垮其它标的**。

### D-08 **采完不直接上策略**（本 ADR 最重要的一条）

本轮只建**采集路径**、落**原始数据**。**不接任何策略、不跑任何评测、不写 `docs/experiments/`**。

- 高股息类与资金流类策略**继续搁置**；
- 要走策略必须先过 P29 的**预注册样本外评测**（walk-forward + 按日聚类 + 扣成本 + 基准对照），
  且**先问用户测不测**；
- **数据存在 ≠ 数据可用 ≠ 有 edge。** 把「表里有 7000 行」当成「有信号」，
  正是本项目 CLAUDE.md 里最贵的那类错。

### D-09 白名单：精确匹配，无子域通配

两个新 host（`datacenter-web.eastmoney.com`、`vip.stock.finance.sina.com.cn`）进
`ALLOWED_HOSTS`，`assert_host_allowed` 仍是**精确匹配**（`host not in ALLOWED_HOSTS`），
**没有**任何「以子域通配」的松动。

已加回归测试 `test_p28_hosts_do_not_open_subdomain_wildcard` 钉住：同域其它子域
（`other.eastmoney.com`、`datacenter.eastmoney.com`、`stock.finance.sina.com.cn`）与
后缀伪装域（`vip.stock.finance.sina.com.cn.evil.com`）**仍须被拒**。
`test_whitelist_is_exact` 保持**集合精确相等**（未放松成子集/包含）。

### D-10 表结构：空表重定义，有数据即拒绝

两表在 P28 前**已存在但 0 行、无触发器**，且老 shape 与真实源字段对不上
（`money_flow` 无 `small/mid/big_net` 来源；`valuation` 缺 `ps_ttm`/`total_shares`/`close_price`）。
趁空重定义：

- `schema.sql` 保持 `CREATE TABLE IF NOT EXISTS`（新 shape）→ 新库/测试库直接得新结构；
- 老库迁移（`migrate_p28_valuation_moneyflow`）：**表为空时** `DROP TABLE` + 重建（零损失）；
  **表非空则抛错拒绝**，绝不静默删历史。

## 后果

**好处**
- 「源站改写历史」从**静默污染**变成**结构性拦不住但每次留痕**（`restated` + warn）+ 下游披露义务；
- 历史行不可改（append-only + 首写保留），回测可复现；
- 缺失数据有显式账（`NULL` + `system_events`），**没有静默缺失**；
- 采集与消费解耦，P29 之前**不可能**拿未验证数据做出准确率结论；
- 白名单仍是精确匹配，新增两个源**没有**顺带开大出网口子。

**代价 / 已知限制（显式记账，不掩盖）**
1. **非 PIT 残余风险**：估值序列可能被源站整体重算，且我们**无法检测**「整体重算」
   （只能检测同一 `(code,date)` 的值是否变过）。下游引用时必须披露。
2. **turnover 精确倍数未确证**：两源**同口径（流通股换手率）确证**、**量纲差 100 确证**，
   但实测比值 **97.15–101.08**（n=6，仅 3 个交易日两侧同时有值）。残余 1–3% **判定不了成因**。
   → **故不做 `bars_daily.turnover` 回填**（见下）。
3. **ETF 资金流历史深度未测**：本轮只跑了 60 天窗口，`--days 8000` 未测。
4. **`main_net`/`xl_net`/`ratio_amount` 单位未独立确证**：源站未给对照量，无第二证据源，
   按源原值入库（`docs/diagnostics/…` §e-4 已标「未确证」）。

**明确不做：turnover 回填**

P28 计划里它是「可选加分项」。P28b 实测后**决定不做**，理由三条：
1. 两源换算倍数**不是精确 100**（97.15–101.08，残余 1–3% 未归因）→ 回填会引入不可归因误差；
2. `bars_daily.turnover` **全库仅 4 行非空**（腾讯历史日 K 接口不返回换手率，
   只有 `backfill-close` 的实时快照才有）→ 回填等于用**单源覆盖** 3000+ 天历史，
   **无从交叉校验**，一旦口径错就是静默污染；
3. 「为了做而做」正是 CLAUDE.md 里点名的反过拟合红线旁边的坑 —— **没有确证可比就不回填**。
