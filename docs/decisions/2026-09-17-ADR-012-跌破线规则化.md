# ADR-012. 000333 跌破线从拍数 85.00 换成规则值 MA60 − 1×ATR14

- 日期：2026-09-17
- 状态：已接受

## 背景

`discipline.PER_CODE_LINES['000333']['stop_loss_close']` 一直是 **85.00**，
但仓库里只有这个值、**没有任何公式或推导**。唯一的关联注释
（`discipline.py:34`「围绕 86.80 建仓价定的」）只是对「−2.07%」的**事后再描述**，
不是生成规则 —— 85.00 是**拍脑袋**的数。用户 2026-09-16 晚直接要求换成
**有依据的规则值**，并给出理由。

## 备选方案

1. **MA60 − 1×ATR14**（采纳）—— 用行情本身的趋势均值与真实波幅生成，
   规则可复现、有公式、每根 bar 都能重算。
2. 固定百分比（如成本 −N%）—— 仍是拍数，只是换了形式。
3. MA60 直接当线 —— 无波动缓冲，单日穿越太频繁。

## 决策

`stop_loss_close = MA60 − 1×ATR14`，全部用 `bars_daily` 的**不复权**
（`adj_mode='none'`）日 K（铁律①：抓取层只存不复权价，这也是库里唯一的口径）：

- `MA60` = 近 60 根不复权收盘价的**简单均值**；
- `ATR14` = 近 14 根 **True Range** 的**简单均值**（**不是 Wilder 平滑**；
  `TR = max(H−L, |H−C₋₁|, |L−C₋₁|)`，首根退化为 H−L，与 `stocklab/risk/stops.py`
  同一口径，简单可复核）；
- asof = `bars_daily` 里 000333 的**最新 bar 日期**。

### asof 复现值（真实库，可复现命令见末尾）

- asof（最新 bar） = **2026-09-16**
- MA60  = **83.7893**
- ATR14 = **1.6521**
- 目标线 = 83.7893 − 1.6521 = **82.1372 → 82.14**

> 与 nanobot 参考值「82.10 = MA60 83.79 − 1×ATR14 1.65」**不一致**：
> 83.79 − 1.65 = **82.14**，参考值自身算术不自洽（少了 0.04）。以复算的 82.14 为准。

## 误触证据（规则灵敏度，**不是**准确率/收益结论）

用**固定线 82.14** 去量不复权历史收盘价的「单日频率」：

- 全历史：2932 / 3097 = **94.67%**
- 近 250 交易日：193 / 250 = **77.20%**

**这个固定线频率无意义**，必须写在前头：不复权序列有除权除息造成的历史价格水平
跳变（000333 不复权收盘区间 16.57–107.11；2016-05-06 有一次 32.99→20.35 的送转等），
早期股价天然低于 82，「close < 82.14」测的是「当时股价更便宜」，**不是**「跟踪止损会触发」。

有意义的**规则灵敏度**是每天用 asof 当时可见的 MA60−ATR14 **重算线**（trailing）：

- 全历史（n≥61 天）：929 / 3037 = **30.59%** —— 同样被历史除权跳变污染，仅作参考；
- 近 250 交易日：28 / 250 = **11.20%** —— 该窗口内无除权除息，数字干净，
  这才是「MA60−1×ATR14 这条规则近一年会触发多少次」的诚实读数。

## 异常与取舍（如实指出）

1. 当前收盘 85.00，新线 82.14，距现价 **−2.86 元 / −3.36%** —— 没在今天就跌破，缓冲合理。
2. **日线/周线顺序倒挂**：原设计里日线（85.00，相对成本 −2.07%）比周线
   （83.25，−4.09%）**更紧**（先触发）；新日线 82.14（−5.37%）比未动的周线 83.25
   **更松**，顺序反转。周线线**本轮不动**（口径变更需用户点头），建议值见下。

## 不重算历史的理由

`paper_nav_daily` / 历史 `reports/` 是 append-only 的已落盘产物。本变更只改
**未来行为**（从下一个 `paper step` 起用 82.14 判止损），已记录的净值/历史报告
**一律不回改、不重跑** —— 重算会让「当时用的就是 85.00」这个历史事实消失。

## check id `stop_loss_close_85` 不变的理由

`stop_loss_close_85` 是**已落盘 run 记录里的稳定 id**（`reports/`、`portfolio` JSON
的 `check` 字段、台账、测试都按它索引）。改数值不等于改判据身份：这仍是同一条
「收盘止损」检查，只是阈值变了。改 id 会让历史记录与未来记录对不上、让按 id 聚合
的台账断链 —— 所以 id 保留，**只改数值与文案**。

## 周线线未动的说明

`stop_loss_weekly`（现 83.25）仍是用户建仓价推的**硬约定**，本轮**不动**。
若希望它同步规则化（恢复「日紧周松」的顺序），建议值：

**`MA60 − 2×ATR14 = 83.7893 − 2×1.6521 = 80.49`**

理由：与 `risk/stops.py` 已有的 `ATR_MULT=2.0`（ATR×2 技术止损）同一口径，
且保持「日线 −1×ATR（更紧）< 周线 −2×ATR（更松）」的原始层级。**这只是建议，
是否采纳由用户定** —— 它属于口径变更，不擅自改。

## 后果

- 好：止损线从无据拍数变成可复现规则，每根 bar 都能重算、可审计。
- 代价：日线（82.14）现在比周线（83.25）松，层级倒挂（未改周线的直接后果）；
  固定线误触频率在不复权序列上无意义，必须用 trailing 灵敏度替代理解。
- 后续注意：下次 `paper step` 起，模拟盘止损行为从 85.00 切换到 82.14；
  近 250 日 trailing 触发率 11.20% 是**规则属性**，不是准确率、不是收益结论。

## 复现命令

```bash
.venv/bin/python - <<'PY'
import sqlite3
from stocklab.risk.stops import ma, atr
conn = sqlite3.connect("data/stocklab.db")
rows = conn.execute("SELECT date, high, low, close FROM bars_daily "
                    "WHERE code='000333' AND adj_mode='none' ORDER BY date").fetchall()
class B:
    def __init__(s, h, l, c): s.high, s.low, s.close = h, l, c
bars = [B(r[1], r[2], r[3]) for r in rows]
closes = [r[3] for r in rows]
ma60 = ma(closes, window=60)
atr14 = atr(bars, window=14)
print(rows[-1][0], round(ma60, 4), round(atr14, 4), round(ma60 - atr14, 2))
PY
# 2026-09-16 83.7893 1.6521 82.14
```
