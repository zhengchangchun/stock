# ADR-045 研究侧因子注册表与 `--factor`（口径扩增：因子值首次不来自 `ctx`）（P97）

日期：2026-09-29 ｜ 状态：已实施 ｜ 上游：ADR-038 决定五、P95 设计稿
（[`docs/plans/2026-09-27-p95-新信号源-设计稿.md`](../plans/2026-09-27-p95-新信号源-设计稿.md)）
§5.1 / §6.4 / §9 拍板点 2、P97 任务书（[`docs/tasks/2026-09-29-p97-因子度量扩展.md`](../tasks/2026-09-29-p97-因子度量扩展.md)）

> 本 ADR 选择**新增一篇**（而不是给 ADR-038 追加「更新」段）。理由：ADR-038 决定的是
> **数据层**口径（公告/北向怎么落库、为什么不进 `ctx`），本 ADR 决定的是**度量层**口径
> —— 新因子怎么进 IC harness。两者的边界不同：前者管「数据长什么样」，后者管「怎么量」。

## 背景

P83 的 `research factor-ic` 只评两组因子：`MAIN_FACTORS = ("mom20","vr15")`（出 verdict）
与 `SECONDARY_FACTORS = FACTOR_FEATURE_KEYS`（5 个财务因子，**只报不判**）。二者的因子值
**都来自打分用的同一个 `ctx`**（`candidate/run.py::_factor_payload` ⇒ `ctx["features"]`），
这是 P83 的核心设计原则：「不另建价格口径，只是把打分内核已经抠出来的输入换个形状读」。

P95 §5 盘出的 4 类新候选（资金流 / 估值 / 公告 / 财务升格）**全部不在 `ctx` 里**，而且按
ADR-038 决定五**也不该进 `ctx`**（进 `ctx` = 进打分路径 = 改生产 ＋ 多变量）。
⇒ 任何把新因子接进 harness 的方案都**必须新增一个「研究侧取值器」** —— 这是 P83 之后
**第一次「因子值不来自 `ctx`」**，必须显式披露为口径扩增，不能假装是「只加名字」。

## 决定

### 1. 只扩研究侧，生产路径零改（ADR-038 决定五继续成立）

新增/改动的文件**只有**：`stocklab/research/factor.py`、`stocklab/cli/main.py`、
`stocklab/cli/research.py`、`tests/`、`docs/`。`candidate/` / `plugin/` / `predict/` /
`paper/` / `m2/` / `data/` / `ops/` / `config/` / `store/schema.sql` **零 diff**。
研究侧取值器**只读库**（`mode=ro` 由调用方保证）、**只被 `research/` 调用**。
**不新增表、不跑迁移、不新增预注册字段**（`PREREG_FIELDS` 一字不动）。

### 2. 三个并列而不重叠的注册表 ＋ 唯一真源 `FACTOR_SOURCES`

| 常量 | 内容 | 走哪条取值路 |
|---|---|---|
| `MAIN_FACTORS`（P83，不动） | `mom20` / `vr15` | `ctx`（`payloads_by_mark` ＋ 专用 accessor） |
| `SECONDARY_FACTORS`（P83，不动） | `= FACTOR_FEATURE_KEYS`（5 个财务因子） | `ctx`（`secondary_value`） |
| `PROMOTABLE_FACTORS`（**新增**） | `gm_yoy_pp` | `ctx`（复用 `secondary_value`，**取值器零新增**） |
| `RESEARCH_FACTORS`（**新增**；P101 起两个） | `mf_ratio_5d` ＋ `ep_ttm`（见文末追加段） | **研究侧取值器** `_research_value(conn, code, asof, name)` |

`FACTOR_SOURCES: name -> "ctx" | "research"` 是**唯一真源**：`--factor` 的合法性校验、
报告里的 `source` 键、缺省逐位不变的自证都从它取，不许另抄名单。

研究侧取值器的结果在 `run_factor_ic` 里**按宇宙成员裁剪一次**（`code ∈ members`）：
`value_coverage_p50` 的口径是「当日在**短池**截面上取到值的标的数」，不裁剪就会算进
宇宙外的标的（真数据冒烟实测 **805 > 800**），既与 `ctx` 那一路（打分载荷本来就只有
宇宙成员）不同规，又会放松 `LOW_COVERAGE` 闸门（其口径是「该因子在**短池上**基本取不到
值」）。截面读数（IC / 分层）本来就只取 `因子值 ∩ 前向收益` ⇒ 不受影响，但覆盖度必须同规。

**为什么 `gm_yoy_pp` 在 `PROMOTABLE_FACTORS` 而不在 `RESEARCH_FACTORS`**：它的值**已经**
在 `ctx` 里、已经随 `PipelineResult.factor_inputs` 暴露出来 ⇒ 升格 = 换 `kind`
（`secondary` → `main`），不是复制代码。同一个因子**只留一个取值入口**（两边都放 = 两条路
可能给出不同的数）。**为什么两个新常量都不塞进 `FACTOR_FEATURE_KEYS`**：那个常量是
**打分载荷**（`ctx["features"]`）的形状真源，往里加名字 = 改生产载荷形状
（`tests/test_research_factor.py:233-234` 钉死，且该文件不许改）。

### 3. `--factor` 的语义：升格 ＋ 只增键

`--factor NAME`（`action="append"`）缺省 `None` ⇒ **逐位不变**（`MAIN_FACTORS` 出 verdict、
`SECONDARY_FACTORS` 只报不判）。给了 ⇒ 被选因子走 `FACTOR_SOURCES[name]` 那条路、
**以 `kind="main"` 评**（这就是「升格」），并**只增键**：顶层 `verdict`、
`selected_factors`、`factor_tag`、`factor_sources`、`research` 段。
`MAIN_FACTORS` 的既有读数、`clip_diag` / `coverage` / `rank_ic_reference` 等既有键
**值一个都不许变**。被选因子若同时是 `SECONDARY_FACTORS` 成员，**不从次读数段删掉**
（删了就破坏「既有键只增不改」）—— 同一条取值路两种 kind 各出一份读数，报告里显式解释。

### 4. 预注册链**复用**（fail-closed 不放松）

被选因子名必须**已经**出现在预注册的 `factors` / `secondary_factors` 里；
未登记的名字（不在 `FACTOR_SOURCES`）⇒ `PreregError` ⇒ exit 2、**零输出**。
`validate_prereg` 的期望主因子名单在 `--factor` 缺省时**仍是 `MAIN_FACTORS`**（P83 逐位相同）；
给了就扩成 `MAIN_FACTORS ＋ 被选因子` —— 于是 P98 那类「一次一个因子」的预注册
（`factors` 里多写一个被选因子）能走**同一条** fail-closed 链，P98 只需写预注册、零代码。

### 5. 产物名防静默覆盖（P95 §6.4 的「不做就会丢数据」点）

`write_report` 的产物名：缺省 `<end>-factor-ic-<universe_id>`（**一个字不改**）；
给了 `--factor` ⇒ 再挂 `-<tag>`，`tag = "_".join(sorted(selected))` 且
`[^A-Za-z0-9._-] → _`。**不新增**「文件已存在即 exit 2」这类 fail-closed（那会改缺省行为）。
命名规则写进报告（`factor_tag` 键）并有用例钉住。

### 6. 只加「怎么量」，不改「判什么」

门槛 / 切分 / CI / `MIN_XSEC_N` / `MIN_VALID_PERIODS` / 分层数 / verdict 词汇表
**一个都不许动**；不做参数搜索；不在同窗上调参。

## 判据（可证伪）

1. **缺省逐位不变**（第一判据）：`--factor` 缺省跑出的 report JSON（除耗时键与 tmp 绝对路径
   `prereg_path`）、`render_md`、`summary_line` 与改动前**逐字节相同**；缺省路径**一个新键
   都不出现**。用例：`tests/test_research_factor_p97.py` 的三条黄金 digest。
2. `tests/test_research_factor.py:233-234` 继续绿（`SECONDARY_FACTORS == FACTOR_FEATURE_KEYS`），
   且该文件**未被修改**。
3. `mf_ratio_5d` 的取值正确性：5 日均值 / 任一 `NULL` ⇒ `None` / 不足 5 个交易日 ⇒ `None` /
   `date > asof` 的行读不到（PIT）。
4. `--factor` 未登记名 / 未进预注册名 ⇒ exit 2、零产物。
5. 反目标：`candidate/` 等八个目录零 diff；真库零写入；`reports/research/` 清单不变；
   未跑任何全窗实验。

## 后果 / 已知边界

- **研究侧因子的读数不能说「这就是插桩用的因子」**（`mom20`/`vr15` 才能说）——它只能说
  「这个定义在这段历史上与收益的关系是这样」。取数口径、PIT 锚、缺失语义由取值器自己负责，
  与打分路径**无关**。
- `mf_ratio_5d` 的批量取数是**每个 `asof` 两条 SQL**（日历 ＋ 该 5 个交易日的窗口行），
  `O(窗口行数)`；`money_flow_daily` 的 `date` 列**无独立索引**（PK 是 `(code,date)`）
  ⇒ 单次窗口查询是全表扫描。全窗（570 marks）会有约 2 分钟量级的额外扫描开销 ——
  本档**不跑全窗**（L9），这只影响 P98 的长跑时长，不影响正确性。
- `family_size` / `family_note` 只**报**族大小与未校正事实，**不做**多重比较校正
  （类内校正由预注册的 `rule` 写死，P95 §9 拍板点 7）。
- `RESEARCH_FACTORS` 当前 `mf_ratio_5d` ＋ `ep_ttm`（后者见文末 P101 追加段）；
  `mf_net_surprise_20d` / `pe_pct_756` / `ann_count_5d` 等候选**一律未登记**
  （避免死代码），各自随其 P99+ 实验站落地。

## 追加（P101）：候选 #3 VAL-A `ep_ttm` 进注册表

**同一决定、同一入口的第二次扩增** —— `--factor` / `FACTOR_SOURCES` / 研究侧取值器
`_research_value` 的**机制层一字未动**，只补一个取数分支 ⇒ **不新开 ADR 编号**
（避免编号通胀）。P95 §8 的顺序（`gm_yoy_pp` → `mf_ratio_5d` → `ep_ttm`）前两项已跑完
且判「不足以采纳」，本档补上第 3 项的研究侧取值器：`RESEARCH_FACTORS` 扩为
`("mf_ratio_5d", "ep_ttm")`，`_research_map` 增一条 `elif name == "ep_ttm"` 分支
（末尾 `PreregError` 兜底一字不改 ⇒ 登记了但没分支仍 fail-closed）。

改动面**只有** `stocklab/research/factor.py` ＋ `tests/test_research_factor_ep_ttm.py`
（＋本 ADR 追加段与 `ai-pipeline.md` 一句）；`candidate/` / `plugin/` / `predict/` /
`paper/` / `m2/` / `ops/` / `data/` / `config/` / `store/` **零 diff**（决定 1 继续成立）。

### 逐字公式（P95 §5.2 VAL-A）

    ep_ttm = 1 / pe_ttm          # 仅当 pe_ttm > 0

- **PIT 锚 = `valuation_daily.date == asof`（等式）**，与 `mf_ratio_5d` 的 `date <= asof`
  **不同**：估值表按日（P95 §5.2 明写「对齐时刻 = `date == asof`」），
  日历／窗口一律不参与本因子。
- **缺失语义**：`pe_ttm <= 0`（含 `0` 与负 PE）或 `NULL` ⇒ 该标的**不进结果集**
  （= `None`，**不补 0**）。
- **负 PE 不取绝对值**（关键）：取绝对值会把亏损公司排成「极便宜」——**方向错**。
  `pe_ttm > 0` 这一条**是公式的一部分**，不是可选的清洗；也不做 winsorize / 截断
  （rank IC 对单调变换不变）。
- 复杂度：每个 `asof` **只发 1 条 SQL**（`SELECT code, pe_ttm FROM valuation_daily
  WHERE date = ?`），一次覆盖该 `asof` 下**全部**标的 ⇒ `O(该日行数)`；
  **禁止**逐标的一条 SQL（`mf_ratio_5d` 每 `asof` 两条是「日历 ＋ 窗口」，
  本因子无窗口 ⇒ 只需一条）。

### 覆盖实测（P95 §5.2 / §7.2；写进注释**不作断言**）

宇宙内 2018+ **800/800 只、1,530,952 行、`pe_ttm` 100% 非空**；`pe_ttm` 取值域
**[−114,501.7, +27,816.5]**（⇒ 不处理必然被极端值主导，故 `pe_ttm <= 0` 判缺失）；
但 `valuation_daily` 从 **2018-01-02** 起、**之前零行** ⇒ 早于该日的 `asof` 一律得到
空结果集（P95 §7.3：代价全在训练段，验证段 171/171 一个不少）。

### 判据

- 取值正确性：`pe_ttm > 0 ⇒ 1/pe_ttm`（**手算值**）／`0`、负、`NULL` ⇒ `None` 不补 0／
  **PIT 锚是等式**（`asof` 前天的诱饵行不许泄漏、`asof` 当天零行即 `None`）／
  批量与单只逐键一致／一次 `_ep_ttm_map` **只发 1 条 SQL**（`set_trace_callback` 计数）。
- **只登记 `ep_ttm` 一个**：`pe_pct_756` / `ann_count_5d` / `mf_net_surprise_20d`
  **仍未登记** ⇒ `selected_factors` 一律 `PreregError`（不做死代码）。
- **缺省逐位不变**（本 ADR 第一判据）继续成立：`RESEARCH_FACTORS` 多一个名字**不改变**
  缺省路径的任何字段／顺序 —— P97 的三条黄金 digest 在 P101 起**原样**通过。
- 用例：`tests/test_research_factor_ep_ttm.py`（八组）。

## 追加（P102）：候选 #4 EV-A `ann_count_5d` 进注册表

**同一决定、同一入口的第三次扩增** —— `--factor` / `FACTOR_SOURCES` / 研究侧取值器
`_research_value` 的**机制层一字未动**（除 `_research_map` 多一个**可选** `members`
位置参数），只补一个取数分支 ⇒ **不新开 ADR 编号**。P95 §8 的顺序
（`gm_yoy_pp` → `mf_ratio_5d` → `ep_ttm` → `ann_count_5d`）前三项已跑完且判
「不足以采纳」，本档补上第 4 项的研究侧取值器：`RESEARCH_FACTORS` 扩为
`("mf_ratio_5d", "ep_ttm", "ann_count_5d")`，`_research_map` 增一条
`if name == "ann_count_5d"` 分支（末尾 `PreregError` 兜底一字不改 ⇒ 登记了但没分支
仍 fail-closed）。这是本注册表里**第一个事件类（公告）因子** —— 前三个都属
「行情 ＋ 财务」类别（P94 方向结论：合成分数与输入因子均无 IC ⇒ 换信号源）。

改动面**只有** `stocklab/research/factor.py` ＋ `tests/`（新增
`tests/test_research_factor_p102.py`，并同步两处**既有**集合钉）＋ 本追加段 ＋
`ai-pipeline.md` 一句；`candidate/` / `plugin/` / `predict/` / `paper/` / `m2/` /
`ops/` / `data/` / `config/` / `store/` **零 diff**（决定 1 继续成立）。

### 逐字公式与窗口（P95 §5.4 EV-A）

    ann_count_5d = #{announcements : notice_date ∈ (d₋₅, d₀]}
    d₀ = asof，d₋₅ = trading_calendar 里 is_open = 1 AND date <= asof 的第 6 个交易日

- **左端开、右端闭的「日期区间」**，**不是**「最近 5 个交易日的闭集」。实测
  `announcements` 里 **19.5%（220,271 / 1,128,199）** 行的 `notice_date` 落在
  周六/周日 —— 闭集读法会让这批公告**永远落不进任何窗口**（静默丢弃），
  区间读法才等于「最近 5 个交易日**时段内**的公告密度」。
- 不足 6 个交易日 ⇒ 窗口算不出 ⇒ `_ann_count_5d_map` 返回 `{}`（不拿「有几日算几日」
  顶替，与 MF-A 同规）；单只入口同规返回 `0.0`。
- **PIT 锚 = `notice_date`**（DDL 注释即为「公告日（PIT 锚）」）。**`display_time`
  一律不参与任何时间轴筛选**（P88 D2 / P96 §7.7：它带毫秒抖动、只作留痕）。
- 本因子是**全类型**公告计数：不过 `title` / `column_name` 任何筛
  （`ev_回购` 那类事件型因子另立项）。
- 复杂度：每个 `asof` **只发 2 条 SQL**（日历 1 条 ＋ 窗口 1 条），一次覆盖全市场
  标的；**禁止**逐标的一条 SQL。计划为 `SCAN announcements USING COVERING INDEX
  idx_announcements_code_notice`（索引首列是 `code`，日期条件只能过滤）——
  covering、不回表；**不加新索引**（改 schema 的收益只有几分钟）。

### 「0 是真值」例外（**本档与前三档的语义差异，必须点名披露**）

其它研究侧因子的「算不出」是 `None`（不进截面）；`ann_count_5d` 的「这几天没有
公告」是**真 `0`**（数量确实是 0，不是算不出）。⇒ `_ann_count_5d_map(conn, asof,
members)` 对**每个成员都给值**：窗口内没公告即 `0.0`，`members` 里的库外 code 也是
`0.0`（不抛）；单只入口 `ann_count_5d(conn, code, asof) -> float` **永不返回 `None`**
（例外落在它的类型注解上，`_research_value` 那一支因此不做 `None` 过滤）。

**直接后果**：`value_coverage_p50` **恒等于宇宙成员数** ⇒ `LOW_COVERAGE` 闸门对
本因子**永不触发**。这是本因子的**固有性质，不是 bug** —— 判读读数时必须知道
「覆盖度 100%」在这里不代表「数据齐全」，它只是「0 也是值」的同义反复。

### 分辨率披露：`zero_ratio_p50` / `tie_ratio_p50`（**只增键**）

P95 §5.4 明写「零值会是多数 ⇒ 分辨率要单独报（仿 `clip_diag`）」⇒ 研究侧
（`source=research`）因子的读数块里**新增两个键**，与 `n`/`ic`/`ci` 同级：

- `zero_ratio_p50`：逐调仓日「截面内值等于 0 的标的占比」的中位数；
- `tie_ratio_p50`：逐调仓日「与 ≥1 个其它标的取值完全相同（rank 并列）的标的
  占比」的中位数。

二者**不参与任何 verdict**（判据一个都不许动），只是分辨率披露。真库只读实测的
零值占比是 **0.156–0.626**（2016-03-15 / 2020-07-01 / 2024-09-02 / 2026-09-24
四点的四点读数），比 P95 §5.4 预估的「零值占多数」**温和** ⇒ 不必预判本因子
分辨率不足（判读出读数一侧负责，本 ADR 不下结论）。

### 覆盖深度限制

`announcements` 的 `MIN(notice_date) = 2014-12-19`（P96 的 `--days 4300` cutoff）
⇒ 早于该日的 `asof` 窗口左边被截断；`trading_calendar` 覆盖 2007-01-15 起 ⇒
更早的 `asof` 连窗口都算不出（本实验窗从 2015-01-01 起，安全）。**必须在预注册里
点名**。

### 判据

- 取值正确性：窗口边界 `d₋₅` 不计 / `d₋₄` 计 / `d₀` 计 / `d₀+1` 不计；**周末公告
  计入**；「0 是真值」（3 成员只 1 只有公告 ⇒ 3 个键、另 2 个 `0.0`）；库外 code
  给 `0.0` 不抛；日历不足 6 个交易日 ⇒ `{}`；单只入口 `float` 且与批量映射逐位一致。
- `_research_map` 的 `members` 透传与 `members=None`（空成员集）路径；未登记名仍
  `PreregError`。**调用点的宇宙裁剪逻辑保留不动**（L7）：取值器按定义会把宇宙外的
  有公告标的也带出来，裁剪必须留在 `run_factor_ic`。
- **缺省逐位不变**（本 ADR 第一判据）继续成立：`RESEARCH_FACTORS` 多一个名字**不改变**
  缺省路径的任何字段／顺序，两个新键在缺省路径**一个都不出现** —— P97 的三条黄金
  digest 在 P102 起**原样**通过。
- 用例：`tests/test_research_factor_p102.py`（C1–C12）。

## 怎么改回来

删掉 `--factor` 参数与 `FACTOR_SOURCES` / `PROMOTABLE_FACTORS` / `RESEARCH_FACTORS` 三个常量、
研究侧取值器层、`research` 段与 `_report_stem` 的 tag 分支即可回到 P83 状态
（缺省路径本来就与之逐位相同 ⇒ 回退不需要动任何既有读数）。
