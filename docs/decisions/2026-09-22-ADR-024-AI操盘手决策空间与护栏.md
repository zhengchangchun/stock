# ADR-024 AI 操盘手的决策空间与护栏（覆盖 D-18）

- 日期：2026-09-22
- 状态：已采纳（用户 2026-09-22 晚间逐条拍板，见 `docs/plans/2026-09-21-需求澄清录.md` §7 D-34）

  任务书 `docs/tasks/2026-09-22-p52-AI操盘手臂重构与对照臂.md`

## 背景

P37 把 `arm-agent` 设计成「在 5 个纪律字段的白名单里改数字」的臂（D-18）。
2026-09-22 用户把这条臂重新定调为「**让 AI 当操盘手接受考核，对照真实金融操盘手**」：
自由度从「改参」扩到「**方向 ＋ 仓位 ＋ 池内自由选标的**，每交易日决策一次」。
D-34 明文**覆盖 D-18**，P37 阶段 2/3 的原设计作废（阶段 1 的代码与台账保留）。

## 决策

### ① 决策载荷的形状（唯一一种）

```
{ asof, decisions: [{code, side, target_weight_pct, reason}], cash_pct, rationale }
```

- `code` **必须落在当日候选池**（短/中/长三池并集，取自 `candidate` 快照，
  按 `snapshot.asof <= asof` 取每池最近一份）；
- `target_weight_pct ∈ [0, 100]`，`Σ target_weight_pct + cash_pct = 100`（容差 1e-6）
  —— **不许杠杆、不许负权重**；
- `reason` 不许为空。

**越界即拒（不夹紧、不静默）**：任何一条不满足 → 写入口 exit 2，**该日不下单**，
账户与净值一个字节不变。

### ② A 股无做空：「看空」只能降总仓位 / 清仓

- 结构上：目标权重 ≥ 0 ⇒ 单条决策最多卖到清仓，**卖空不可表达**；
- 显式上：`side` 是**意图的声明**，必须与「目标市值 vs 现市值」的方向一致；
  对**未持有**的标的写 `side="sell"` → 拒绝，报错文案原样带上
  `NO_SHORT_SIDE_MSG`（「A 股无做空……看空只能表达为降低总仓位 / 清仓」）。
  不这么办的话，「AI 想卖空」会被读成一个静默失败。

### ③ 决策**在项目外产生**，项目内只做四件事

`校验 → 落库 → 执行 → 计账`。写入口：

```
paper agent decide --asof <day> --file <decision.json> --model-id <id> --prompt-sha256 <sha> [--seed N]
```

理由：① 与 D-1「系统内不实现自动生成」同精神；② 项目保持**离线可测、零 API key**、
`paper/` 不引入网络依赖；③ 台账里的 `model_id / prompt_sha256 / context_sha256 / seed`
足以复现与追责。

**代价与出口**：若日后要改成项目内直连模型，代价是离线测试失效、密钥进环境、
`paper/` 引入网络依赖 —— 三条都要另立 ADR，不在本条的授权范围内。

### ④ 台账：一张表两段历史，`decision_kind` 分开

`paper_agent_decisions` 用 `UNIQUE(arm, asof)`，新增三列（`ALTER TABLE ADD COLUMN`，
**不回填历史行**）：

| 列 | 用途 |
|---|---|
| `decision_kind` | `'spec'`（P37 的改参）/ `'portfolio'`（P52 的操盘决策）；历史行默认 `'spec'` |
| `payload_json` | 操盘决策的原始载荷（canonical JSON） |
| `pool_json` | 当时那份候选池（「池外拒绝」的审计依据） |

执行侧**按 `decision_kind` 过滤**（`portfolio_decision_on`）：spec 行的载荷是 `{}`，
若被当成操盘决策读，会变成「这天决定空仓」—— 静默的空仓比报错难查得多。

**成交的溯源写在成交行自己身上**：`paper_trades.reason` 带 `decision <payload_sha256[:12]>`。
成交表 append-only，读单笔成交的人不该被迫 JOIN 台账。

### ⑤ 护栏（进「护栏」，不再进「白名单」）

不许：杠杆 / 负权重、池外标的、接券商下单、用 `> asof` 的数据、参数搜索、
改主干常量（熔断阈值 / 自评估边界 / `approve` 闸门）。

**源码扫描按臂分作用域**（`tests/test_paper_discipline_guard.py`）：

- 「操盘口径」的标识符（`target_weight_pct` / `target_value` / `plan_target_weight` /
  `portfolio_decision_on` / `random_payload`）只许出现在
  `agent_decide.py` / `agent_pool.py` / `rules.py` / `engine.py`；
  `config.py` **只许声明**键名（`target_weight_pct`），不许出现下单构造；
- 静态臂的执行函数（`_plan_steps` / `_build_etf` / `evaluate`）**一个都不许出现**；
- `paper/` 仍不 import 模型 / 验证 / 凯利 / 选股链路 —— `agent_pool.py` 用**裸 SQL**
  读候选池快照，护栏不为它开洞。

### ⑥ 随机对照臂 `arm-agent-random` 是**判据的一部分**

每交易日从同一候选池随机抽标的与权重，**护栏与成本口径完全相同**，随机性由
`sha256(arm|asof|seed)` 驱动（⇒ 逐字节可复现、幂等成立）。`model_id = random-control`。

- 没有它，`arm-agent` 的读数一律**不可归因**（D-19）；
- `delta_vs_random` 无数据时是 `null` 并写明「**不存在，不是 0**」。

运行期还有一条判据：**`arm-agent*` 的每个成交日都必须有一条决策行**
（`agent_decide.audit_decisions`）。缺行即判红 —— 那正是「编辑代执行」的形状。

### ⑦ 对照臂口径（D-36 五条 ＋ 随机臂）

| # | 臂 | 来源 | 成本 | 可交易 |
|---|---|---|---|---|
| ① | `arm-agent` | `paper_nav_daily` | 有 | 是 |
| ② | `arm-now` | `paper_nav_daily`（实盘账本镜像） | 有 | 是 |
| ③ | 真实主动权益基金等权平均 | `fund_nav_daily`（天天基金 `pingzhongdata`，**非官方**） | 无 | **否** |
| ④ | `arm-hold` | `paper_nav_daily`（冻结快照） | 无成交 | 是 |
| ⑤ | `sh000300` | `bars_daily` 指数收盘 | 无 | **否** |
| ＋ | `arm-agent-random` | `paper_nav_daily` | 有 | 是 |

- **基金臂不是指数**：公募基金持仓不公开，它与各臂的关系只有「净值曲线并列」。
  页面与报告必须标注「近似 / 非官方」＋数据源；不得改写成指数。
- **不可比就写「不可比」，不填 0**（指数不可交易、基金无持仓与成本、缺数据断线）。
  写 0 会把「不知道」显示成「那天没涨没跌」。
- **等权 = 各基金自起算日的累计收益的算术平均**；起算日之前无净值的基金不参与，
  其权重也不摊给别人（悄悄重分配 = 悄悄换了基准）。基金清单**先验选定、
  不按历史业绩挑**（按业绩挑出来的基准会让 AI 臂的成绩看起来更好）。
- 样本 < 120 交易日只给读数、不给结论（`SAMPLE_THRESHOLD`，与
  `verify.report.MIN_DAYS` 同源同值，靠测试对拍钉住 —— **不 import 验证链路**）。

## 备选与否决

| 备选 | 为什么否决 |
|---|---|
| AI 臂保留 spec 参数化执行，与操盘决策**并存** | 同一条臂两个下单来源 ⇒ 成交无法归因到单一决策；且「谁先谁后」会成为隐形的策略自由度 |
| 项目内直连模型产出决策 | 与 D-1 冲突、离线测试失效、密钥进环境、`paper/` 引入网络依赖（三条都要另立 ADR） |
| 在写入口**夹紧**越界权重（而不是拒绝） | 夹紧会把「AI 提了一个非法仓位」变成「系统批准了一个它没提过的仓位」，两件事在台账上必须分得开 |
| 用 `side="sell"` 表达看空（含未持有标的） | 那是融券；A 股无这条腿 |
| 把基金臂塞进 `paper_nav_daily` | 会让人以为它有持仓、有成交、有成本 |
| 按「不可比就填 0」简化页面 | 把「没有数据」读成「没涨没跌」，是本项目反复踩过的同型失效 |

## 后果

- `arm-agent` 在**没有任何决策的日子不下单**（起跑日与 `arm-hold` 同值）。
  这不是缺陷，是「AI 还没决定任何事」的如实显示；页面与报告用
  `agent_decision.present=false` 明说，**不给它编一个默认条文**。
- 静态臂（`arm-discipline-*`）与 `arm-now` / `arm-hold` 的行为**一字未变**
  （`has_rules` 只服务纪律臂；`replays_own_trades` 与「会不会下单」分开表达）。
- 基金净值抓取是**唯一出网点**（`stocklab fund ingest --fetch`），
  测试只用本地夹具；真源核对由 nanobot 跑一次。
- 时间戳约定（`x` 的毫秒值是当日 UTC 零点还是北京零点）**离线无法证实** ⇒
  按 `+08:00` 读（对两种约定给出同一天），并把这件事写进代码注释与测试。
