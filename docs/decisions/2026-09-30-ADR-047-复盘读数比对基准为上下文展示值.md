# ADR-047 复盘 metric 腿的比对基准＝上下文展示值（P105）

日期：2026-09-30 ｜ 状态：已实施 ｜ 上游：P105 任务书
（[`docs/tasks/2026-09-30-p105-复盘读数比对基准.md`](../tasks/2026-09-30-p105-复盘读数比对基准.md)）
｜ 同族：[ADR-036 复盘台账与教训回注](2026-09-26-ADR-036-复盘台账与教训回注.md)

## 背景

2026-09-30 18:34，v4 臂日更第二轮：`paper agent review` 被
`ReviewValidationError` 拒收 ⇒ 当日 `paper_agent_reviews` 零行、`n_lessons=0`。

现场：

- 模型回传 `{"kind":"metric","metric":"cum_return","date":"2026-09-29","value":-0.0115}`；
- 库真值 `paper_nav_daily(arm-agent-ds-v4, 2026-09-29).cum_return = -0.011548`；
- 校验容差 `TOL = 1e-6` ⇒ `abs(-0.0115 - (-0.011548)) = 4.8e-05 > 1e-6` ⇒ 拒。

**这不是模型编数，是两条口径不自洽**：

| 侧 | 口径 | 位置 |
|---|---|---|
| 写（喂给模型的上下文） | 净值/成交读数**截到 4 位小数** | `paper/own_history.py::_round4` |
| 校验（`metric` 腿） | 与**未舍入的库值**差 ≤ 1e-6 | `paper/review.py::_check_metric` |

模型**只能看到 4 位小数**，却被要求与 ≥6 位精度逐值相同。4 位小数必带 ≤5e-5 的舍入
误差，**1e-6 在数学上不可能满足** —— 凡该列读数的小数第 5 位非 0，这条复盘必被误拒
（触发概率≈天天，02 那种「修 v4 闭环」每轮都会掉一次）。

**`market` 腿早已是对的样板**：它拿的是当日 `market` 块自己的值（`market_view` 已统一
`round(x, 4)`）⇒ 模型照抄块里的值，比对**必然**通过；库里唯一成功的 `review_id=1`
的 3 条 item 全是 `market`。失败的必要条件正是「引用了 `metric` 腿」。

## 备选方案

1. **放宽容差**（`TOL` → 1e-3 / 1e-4 / 2e-3）—— 优点：一行改动。缺点：**会同时放过
   真编的读数**。展示单位是 1e-4，放到 1e-3 等于允许模型把一个读数编到十倍展示精度
   之外；「读数不许编」这条硬校验（K3 的牙齿）就名存实亡。
2. **降低上下文展示精度**（`_round4` → `_round2` 之类）—— 优点：不用碰校验。
   缺点：改了喂给模型的读数 ⇒ 改 `context_sha256` 序列、改历史决策的指纹对照，
   且损失信息；把「校验口径」的问题转嫁给「展示口径」是错的方向。
3. **校验基准改为「模型实际看到的那个读数」**＝`round(库真值, DISPLAY_DP)`，
   容差 `1e-6` 不动 —— 与 `market` 腿同构。

## 决策

采**方案 3**（D1，核心口径）：

- `paper/review.py` 新增模块级 **`DISPLAY_DP: int = 4`**（口径真源单点化）与
  `round_display(x) -> round(x, DISPLAY_DP)`；`metric` 腿的比对基准由「未舍入库值」
  改为 `round_display(库真值)`，**`TOL = 1e-6` 一字不放宽**。
- **`DISPLAY_DP` 定义在 `review.py`**（D2）：`own_history` 已 import `review`，
  反向会让 `review` import `own_history` 成环 —— 故真源放 `review`，
  `own_history._round4` 改为引用它（`round(float(x), review.DISPLAY_DP)`）。
  **数值逐位不变**（`round(x, 4)` 还是 `round(x, 4)`），靠一条用例钉住「两个模块
  用的是同一个 dp」。
- 失败文案同时打印**上下文展示值**与**库真值**（D3），「读数不许编」五字保留，例如：
  `与上下文里的读数不一致：2026-09-29 的 cum_return 展示为 -0.0115（库真值 -0.011548）（差 4.8e-05 > 1e-06）—— 读数不许编`。
- `market` 腿**一字不动**（它本来就拿块里的展示值）。

## 后果

- **好处**：`metric` 腿与 `market` 腿同构；展示精度的舍入误差不再被判成「编数」。
  口径从「与库值一致」改为「**与展示值一致**」—— 这是一句更诚实的话：校验的本来就该是
  「模型有没有老实照抄它在上下文里看到的东西」。
- **不放松鉴别力**：真编的读数（离展示值 > 1e-6）照旧被拒、零写入。把展示值当基准
  只吸收了 ≤5e-5 的**已知**舍入，不吸收任何「随手写一个数」。
- **改动面**：`paper/review.py`、`paper/own_history.py`（只 `_round4` 一处）、
  `tests/test_paper_review.py`、文档。零结构变更、`store/schema.sql` 零 diff、
  真库零写入、红线三目标不 regen。
- **不补写历史**（D5）：09-30 那条复盘由 nanobot 在修复上线后走生成器补（补写要真调
  模型）；`paper_agent_reviews` 既有行、决策行、净值行一字不动（D4）。
- **同类错**：「**写侧的表示精度**与**校验侧的基准**必须同源」。这是 ERROR_DIARY
  #66/#81/#82 同族的「同一族的三条路只修了一条」的近亲 —— 这里暴露的是**两个不同
  模块各持一份精度口径**。日后凡「展示/落库/校验」三处出现同一个数值口径，先问
  「它们用的是同一个 dp 吗」。
