# ADR-026 宇宙配置载体：repo 文件＝真源、DB 表＝投影（D1–D8 口径固化）

- 日期：2026-09-24
- 状态：**已采纳**（D1–D8 由 nanobot 在任务书 §0.5 拍板，实现站按条落地、不许另选）
- 相关：上游设计稿 `docs/plans/2026-09-24-p70-宇宙扩容-设计稿.md`、
  任务书 `docs/tasks/2026-09-24-p71-宇宙扩容实现.md`（§9 接口裁决 4 条）、
  ADR-005（幂等键取语义不取呈现）、ADR-013（休市表与 PIT 纪律）、
  ADR-015（写库入口自动前滚 schema）、ADR-016（财报采集口径）
- 代码落点：`stocklab/config/universes.py`、`stocklab/cli/universe.py`、
  `config/universes/seed21.{csv,meta.json}`、`stocklab/store/schema.sql`
  （表 `universe_memberships`）

## 背景

「候选池扫描宇宙」此前是**写死的常量**（`candidate/seeds.py::SEED_UNIVERSE`，21 只）。
要做「换一个宇宙重跑 `xsec-topn`」这件事，必须先回答：宇宙的**真源**放在哪里？
P70 设计稿 §3.3 比过 A/B/C 三个方案，D3 选了 **C**。同时 D2 明确：扩宇宙**不改**
`SEED_UNIVERSE` 的语义与取值 —— 这是设计站点名的「必须回对话」项，拍板结果＝**选不动**。

本 ADR 只记「为什么」，**不复制常量值**；生效口径的唯一真源仍在代码里。

## 决策

### ① D3＝C：`config/universes/<id>.csv`（＋`.meta.json` 的 sha）是**真源**，`universe_memberships` 表是**投影**

- 「asof=2016-06-30 时这个宇宙是哪几只、什么时候写进去的」这个问题**只有提交历史能回答**
  —— `added_at` 之类的列可以被 rewrite，`git log` 不能。所以真源必须是 repo 文件。
- 表的用途是 **SQL join**（「这个 code 属于哪些宇宙」）与下游下一站；它不是真源。
- **C 的代价是必须做对账**：`universe doctor` 只读比对「文件 `members_sha256` vs 表里该
  `universe_id` 行的 canonical sha」。不做这份对账，C 就退化成「两个都像真的、谁也不负责」。
- 表**刻意不挂 append-only 触发器**：`universe sync` 的语义是按 `universe_id`
  **整体重写**该 id 的行（幂等、可重入）。挂上触发器等于让投影无法重写 ⇒ 投影与真源的
  漂移会变成**永久性错误**。可追溯性由文件 ＋ `git log` 提供，不是这张表。
- 表里**冗余** `members_sha256`（同一 `universe_id` 的所有行必须同值）：表里没有
  `name`/`market`/`board`/`asset_type`/`org_type`，算不出完整 canonical sha，
  所以 doctor 只靠这一列判「投影还是不是文件那一版」。
- 建表走 `schema.sql` 的 `CREATE TABLE IF NOT EXISTS`（ADR-015 的前滚路径），
  **不登记进 `_pending_column_migrations`** —— 表不存在不是「待迁移」，是「等着被建出来」，
  登记会让每次写库入口都给老库做一次备份。只在 `_KNOWN_MARKERS` 里登记供 doctor 只读报告。

### ② D2：`SEED_UNIVERSE` 语义与取值**一字不动**；扩宇宙**只能**走新增 `--universe <id>`，**不得隐式回退**

- 「默认路径」= 不传 `--universe` = 主干常量 21 只。这是红线三目标、`paper/**`、`m2/**` 的
  既有行为赖以成立的基线。
- `load_universe` **fail-closed**：文件缺失 / 列不合规 / 行数与 `meta.n_members` 不符 /
  `members_sha256` 与 meta 不符 / 代码重复 / `board` 与代码前缀派生值不符 —— 任一即抛
  `UniverseError`，**绝不回退到 `SEED_UNIVERSE`**。隐式回退会让「我以为跑的是宇宙 A」
  与「实际跑的是 21 只」**不可区分**，那正是「窗口即结论」想防的那类错误。
- `SEED_UNIVERSE` **仍是 21 只的真源**；`config/universes/seed21.csv` 是它的
  **冗余副本**（冗余是有意的：让 21 只也走与扩池宇宙同一条载入/对账路径）。
  两者的一致性由 `seed21_sha256()` 对账守。
- 另一条路（把 `SEED_UNIVERSE` 降级为「历史宇宙之一」）**保持开放**，本档不碰。

### ③ D4：`m2/context.py` 的硬守卫**一字不动**

守卫把 `ctx` 里的标的限制在登记集合内。放宽到「按表」≈ **不改变被拒集合**
（表里就是那 21 只），却把防线从**常量级**降到**数据级** —— 收益为零、防线变弱。
扩池后 m2 通路 A/B 继续只认 21 只。

### ④ D5：`sector` 为空 ⇒ 名称推断的**兜底保留**

删掉它会让 15/21 只输出变化，**且任何测试都抓不到**（`pass_flag` 恒 True）。
「不被测试抓到的行为变化」不许静默发生。

### ⑤ D1：只做「现成分」；报告一律打 `non_pit=true` ＋ 设计稿 §2.2 的 N1–N4 限定句

- 历史成分与退市**名单**都拿不到（设计稿 §2.1 逐源探测）。`RPT_INDEX_CONSTITUENT`
  看着像历史成分，其实**不是**（`TRADE_DATE` 只给「今天仍在成分里的成员各自的入选日」）。
- 报告必须逐条写出 N1（**双向**生存偏差）／N2（退市股缺席）／N3（无历史成分）／
  N4（指数只到 800 只，更大的 `TYPE` 指数名未核实、不许按行数推断）。
  这四条**不与**种子宇宙那三条非 PIT 项合并、也不替换它们 —— 扩池换掉的是偏差的**类型**，
  不是「有没有偏差」。
- ⚠️ **任务书 §0.5 写的是「N1/N2/N3 限定句」，设计稿 §2.2 实际有四条**（N4 在
  「**必须写进报告的「非 PIT 项」（逐条，不许含糊）**」标题之下）。本档按**上游设计稿**取四条，
  见任务书 §7.7 偏离 1。

### ⑥ D6：采集分批顺序 `universe+sector → bars → valuation → financials → moneyflow → actions`

moneyflow 单独一批、可跨天。**该动作不在本档**：联网写库由 nanobot 执行，CC 侧一律假源。

### ⑦ D7：`PREREG_FIELDS` 新增 `universe`；兼容裁决＝老预注册**一字不改**、缺字段**视为 `seed21`**

- 不加这个字段，同一份预注册换宇宙能跑出两个结论 ⇒ **静默换宇宙**（扩池打开的新口子）。
- 老台账 `docs/experiments/2026-09-24-xsec-topn.md` 是 append-only 的台账，**一字不许改**
  ⇒ 它必然缺 `universe`。裁决：**缺席 ⇒ 语义视为 `seed21`**（写进 docstring ＋ 报告一行）。
- **这不等于放行**：`validate_prereg` 仍拿**命令行实参**去比对 ⇒
  「预注册推得 `seed21`、命令行传 `csi300-500`」照样 **exit 2**（反向亦然）。
- 换宇宙必须**新预注册**（设计稿 §7.1 硬要求 1–2）。

### ⑧ D8：红线基线**不 regen**；扩池后库指纹大量「新增」差异是**预期**

`instruments 21→821`、`bars code 23→823`。红线三目标（`predict_synthetic` /
`predict_real_2026-09-14` / `backfill_real_2013-12-23_2026-09-14`）本档逐位不变。

### ⑨ 派生与留空纪律（任务书 §9 裁决 2/3）

- `board` 是**派生量**（按代码前缀确定性推导），不查表、不猜；未知前缀 ⇒ **抛错**，
  不静默归 `main`。载入时还会拿 CSV 里写的 `board` 与派生值**对账**，不一致即抛错
  （手写覆盖 `board` 会算错涨跌停，而症状是零）。ETF 例外：场内 ETF 一律 `main`，
  沿用 `DEFAULT_UNIVERSE` 的既有口径。
- `org_type` **未知时不许猜**：扩池行的 `org_type` 在数据源里确定不了 ⇒ CSV 留空、
  载入为 `None`。`Instrument.org_type` 的 dataclass 默认值 `"通用"` 是「不破坏既有调用点」的
  兼容默认，**扩池路径不许借它兜底** —— `fetch_financial_reports(org_type=None)`
  **显式跳过整个 F10 段**，公告日退回法定披露截止日（P53 设计 §E 的口径）。
  理由：这一列决定东财 F10 报表名（`G`/`B`/`I`），把「不知道」当成「通用」会**静默拿不到财报**，
  而症状看起来像「这只标的没有财报」= 数据源问题。

### ⑩ `doctor` 的「一致」判据（任务书 §9 裁决 4）

文件 `members_sha256` == 表里该 `universe_id` 行的 canonical sha；**表缺行也是 exit 2**
（不是「跳过」）。`instruments` 覆盖不全同样 exit 2；`sector` 非空率**只报不判红**
（`seed21` 在真库上本来就是 0/21，属 P53 回填的历史欠账，不是宇宙扩容引入的）。
只读姿势 `sqlite3.connect(f"file:{abs}?mode=ro&immutable=1", uri=True)`。

## 什么条件下推翻

| 决策 | 推翻条件 |
|---|---|
| ① D3＝C（文件为真源） | 出现**必须写库才能表达**的宇宙语义（如表内逐次调仓的调入/调出流水）⇒ 那时真源要挪进表，并**同时**废弃 `doctor` 的对账（两者必须一起改，不能只留一个） |
| ② D2（`SEED_UNIVERSE` 不动） | 「把 `SEED_UNIVERSE` 降级为历史宇宙之一」这条路被重新选中 ⇒ 需要**先**证明红线三目标与 `paper`/`m2` 行为可以逐位保持（目前无此证据） |
| ③ D4（硬守卫不动） | m2 通路 A/B 真的要扫扩池宇宙 ⇒ 那时要**新造一个数据级守卫**（带 fail-closed 的登记查询），而不是把常量守卫**放宽** |
| ④ D5（`sector` 兜底保留） | `instruments.sector` 回填在生产跑过、非空率接近 100% ⇒ 兜底路径实际上不可达，那时可删（删前要先造一条能抓到输出变化的测试） |
| ⑤ D1（只做现成分） | 拿到**逐次调仓的调入/调出名单（含退市股）** ⇒ 才能反推任意 `asof` 的成分集合，那时才谈真 PIT 宇宙；`RPT_INDEX_CONSTITUENT` 的 `TRADE_DATE` **不够** |
| ⑦ D7（`universe` 进预注册） | 若未来预注册格式换成带 schema 版本的对象，`PREREG_OPTIONAL_FIELDS` 这个「缺席即默认」的兼容层要**一起撤**，否则默认值会变成永久的静默语义 |
| ⑨ `board` 派生表 | 出现派生表未收录的合法前缀 ⇒ **扩充前缀表**（不许改成「未知归 main」），并同时补 `derive_board` 的用例 |
| ⑩ doctor 判据 | 表成为真源（见①）⇒ 对账改为「文件 vs 表」之外的形态，或整个删除 |

## 后果

- **默认路径零行为变化**：不传 `--universe` 时字节级行为不变；红线三目标未 regen。
  唯一的**有意增量**是候选池快照 `params_json` 多两个键（`universe_id` / `members_sha256`），
  老键 `seed_count` / `topn` 逐位不变 —— 判据是「老键逐位不变 ＋ 成员集合逐位不变」，
  **不是**「快照行 sha 不变」。
- 扩池后的结论**不许升级口径**：报告必须同时打出「与 `seed21` 版不可直接比」这句话
  （设计稿 §7.1 硬要求 3），且 `all` 臂的定义域变了 ⇒ E1–E5 判据（设计稿 §7.3）才谈得上是否成立。
- **本档不承诺「扩池后准确率会提高」** —— 那是设计稿 §7.3 的 E1–E5 判据要回答的问题，
  不是本档能断言的。
- 本档**未做**（点名）：`csi300-500` 的**真实抓取与写库**（联网动作，由 nanobot 跑）；
  `select_top` 取前 N 的策略问题；PIT 历史成分。
