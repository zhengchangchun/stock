# ADR-036：复盘台账与教训回注（P85）

- 日期：2026-09-26 / 27（P85 站点实施）
- 状态：已实施
- 相关：ADR-024（D-34 决策空间与五字段白名单）、ADR-031/032/033（可成交性、本金口径）、
  ADR-035（`market` / `own_history` 上下文）
- 任务书：`docs/tasks/2026-09-26-p85-复盘台账与教训回注.md`

## 背景

用户 2026-09-26 晚要求 AI 操盘手具备「**不断分析市场、复盘总结自己**」的能力。
ADR-035（P84）做了**输入侧**那一半：AI 看得见「今天市场什么样」与「自己过去做过什么」。
P85 补另一半：AI 能把「对上一笔决策的复盘」**写进台账**，而**每一句都要带能在库里
核到的证据指针**；并且**反复出现、已被确认的教训**要作为「事实」回注到下一轮的
上下文里。本站**不碰提示词、不开新臂、不跑模型**（提示词 v4 与新对照臂是 P86）。

## 决定一：证据指针是**硬校验**，不是提示词礼貌（K2 / K3）

新表 `paper_agent_reviews`（append-only，幂等键 `(arm, asof, kind)`）的载荷里，
每条 `claim` 必须挂一条 `evidence`，`kind ∈ {decision, trade, metric, market}`，
写入口逐个**回库核对**：

| kind | 校验 | 落空时 |
|---|---|---|
| `decision` | `decision_id` 存在、`arm` 相符、`asof <= 复盘日` | exit 2 |
| `trade` | `trade_id` 存在、`account_id == arm`、`date <= 复盘日` | exit 2 |
| `metric` | `metric` 在七列白名单、该臂该日有净值行、**`value` 与库里读数容差 1e-6** | exit 2 |
| `market` | `field` 在**当日 `market` 块**的标量字段路径里（**动态枚举**，不手抄）、**`value` 与块里的读数一致** | exit 2 |

**为什么值得这么严**：复盘是**下一轮的输入**。一句「我这周回撤 3%」如果和
`paper_nav_daily` 对不上，它就会作为一个**假事实**进入模型自己的历史叙事 ——
而历史叙事一旦假了，后面每一轮复盘都建立在它上面。**能编的读数比没有读数更糟。**

两条附带的口径：

- **`market.field` 的白名单是「当日块里有什么」现算的**，不是手抄一份清单：
  抄的那份迟早与块漂移，而漂移的方向永远是「允许引用一个不存在的字段」。
- `market` 指针的 `date`（给了的话）必须等于**该字段所属子块自己报的数据日**
  （`breadth.asof` / `index.<code>.price_asof`），不是复盘日 —— 长假后第一天，
  块的数据日就是**早于**复盘日的，一律按复盘日算会读错。

## 决定二：`facts` 的「已确认」＝ **≥2 条不同 `asof`**（K4）

`derive_facts(conn, arm=arm, asof=)` 从该臂**全部** `kind='daily'` 且 `asof <= 复盘日`
的复盘里按 `lessons[].key` 聚合：

- 同一个 `key` 出现在 **≥2 条不同 `asof`** 的复盘里 ⇒ 进 `facts`；
- `text` 取**最新**一条，`seen_at` 列全部 `asof` 升序；
- 同一 `key` 的 `text` 不一致 ⇒ `conflict: true`，各不相同的原文**全部**列在 `texts`
  （**不取平均、不猜**）；
- `≤10` 条：超出按 `seen_at` 条数降序、再按 `key` 字典序截断，截断数进 `n_facts_truncated`。

**单次陈述是观察，反复出现才是模式** —— 这条规则就是「确认」二字的可执行定义。
只要出现一次就当成「已确认事实」，等于把模型的每一句自述都升格为事实，
`facts` 会退化成「上次我说过什么」的复读机，而这个块存在的意义恰恰是**筛掉**噪声。

`derive_facts` 是**纯函数**：输出只含 `key` / `text` / `seen_at` / `conflict`，
不含时间戳、不含自增 id ⇒ 同库两次调用逐字节相同。

## 决定三：复盘是**文字与读数**，不是参数通路（K6）

载荷 schema 是**结构白名单**（顶层只认 `asof`/`arm`/`kind`/`items`/`lessons`，
`additionalProperties: false`）：**「把参数改成 X」这种字段在结构上就写不进来**。
`facts` 只以**文本**进入上下文。

参数改动的唯一通路仍然是 `paper/spec set` 的五字段白名单（D-18 / D-34）；
`paper/rules.py`、`paper/config.py` 既有常量、`paper/engine.py` 的执行函数
**一个字都没改**。`NON_GOALS` 末尾追加一条（逐字）把这条边界写在**给模型看的输入里**：

> 复盘只写文字与读数：教训（facts）是**经验陈述**，不许当成参数改动的载体 ——
> 五字段白名单、成本口径、整手口径、熔断阈值都不在复盘的触达范围内

## 决定四：两块放进 `own_history` 的**子键**，不新开顶层键（K5 / K8）

`own_history` 末尾追加 `recent_reviews`（最近 ≤3 条复盘，升序，原样搬运
`items`/`lessons`）与 `facts`（≤10 条）。理由三条：

1. **语义上它们就是「我自己的历史」**：「我说过什么」与「我得出的结论是什么」
   和「我做过什么」是同一个读者（模型自省）、同一层 PIT 过滤、同一处有界尺寸。
   新开一个顶层键会让「自己的历史」在两个地方各说一半。
2. **`own_history` 已经在 `DECISION_HASHED_KEYS` 里** ⇒ 两块**自动进指纹**，
   不需要动那份键清单（**零改动**，判据之一）。给 `asof` 之后加一条复盘 ⇒
   `own_history` 与 `decision_context_sha256` **逐字节不变**（PIT）。
3. **`recent_reviews` 与 `facts` 是两种东西**（原话 vs 归纳），合成一块就再也分不开
   「我说过什么」与「我因此得出了什么」—— 前者可被引用，后者可被检验。

## 决定五：`context_sha256` 在**写之前**算

`paper agent review` 记录的这一列 = `decision_context_for(conn, arm, asof)` 在
**这条复盘落地之前**的指纹。K7 的「现算」＝由 `decision_context_for` 算出来、
**不信调用方**；而「写之前」是因为写完之后这条复盘自己就出现在
`own_history.recent_reviews` 里 —— 事后现算得到的是「一个含它自己的输入」，
并且会变成 `sha = f(sha)` 的不动点。台账那一列记的是**写它时所依据的上下文**。

## 后果

- **好处**：读数是可核的（四种指针回库校验）；教训是**可检验**的（≥2 条才确认）；
  参数通路没有被打开（schema 白名单 + `NON_GOALS` + 执行层零改动）。
- **代价**：`NON_GOALS` 追加第 4 条 ⇒ **同一个输入**的 `decision_context_sha256`
  与 `context_sha256` 都变了（旧台账行**一字不改写**，append-only）。
- **注意**：新表 DDL 写在 `store/migrate.py::migrate_p85_agent_reviews` 里，
  **不在** `schema.sql`（本站改动面白名单不含它）—— 于是「表不存在」**就是**待前滚，
  与 P58/P79/P80「表由 executescript 建出、不存在 ⇒ 不 pending」的判据刻意不同。
  真库前滚由 nanobot 做（站只在 `/tmp` 副本上验）。
- **未决（不属本站）**：提示词 v4 怎么用 `facts` 与 `recent_reviews`（P86）；
  `facts` 是否需要「过期/撤回」机制（现在只增不撤）。
