# ADR-028 外部行情源允许**同构镜像 host** 回退（白名单只增，不放宽 R13）

- 日期：2026-09-25
- 状态：**已采纳**（F1–F7 由 nanobot 在任务书 §0.5 拍板，实现站按条落地、不许另选）
- 相关：ADR-003（长历史数据源：腾讯 `fqkline` 翻页）、ADR-009（raw_cache 当日时效）、
  ADR-001（R13 出网白名单闸门）、ERROR_DIARY **#80**（本 ADR 的现场）、
  上游 `docs/tasks/2026-09-25-p74-真库800只采集.md`、
  任务书 `docs/tasks/2026-09-25-p74a-腾讯K线镜像回退.md`
- 代码落点：`stocklab/data/sources/tencent.py`（`KLINE_MIRROR_URLS` / `KLINE_URLS` /
  `kline_url_on`）、`stocklab/data/fetch.py`（`_kline_page`：host 级回退）、
  `stocklab/config/universe.py`（`ALLOWED_HOSTS` +2）

## 背景

日K 取数只连一个 host：`web.ifzq.gtimg.cn/appstock/app/fqkline/get`。2026-09-25
该 host 被腾讯 WAF 拦下，**所有**请求一律 `HTTP 501`（`waf.tencent.com/501page.html`
跳转脚本，326 B、非 JSON）；补 `Referer`/`Origin`/UA 等完整浏览器头**仍是 501**。
而 `http.py` 对 5xx 的语义是「退避重试 4 次」——于是每个标的先白跑 ~6–8 s 才承认失败，
800 只的批量采集大面积失败（有 bars 的只有 230 只），且**重试注定再失败**（被拦的是
host 本身）。同参数换到 `ifzq.gtimg.cn` / `proxy.finance.qq.com/ifzqgtimg/…` 均
`HTTP 200`，且两者 body **逐字节相同**（24675 B），喂进 `tencent.parse_kline`
正常解出 320 根 ⇒ 问题纯粹在「host 单点」，不在解析与口径。

## 决策

### ① F1：回退链顺序＝首选 → `ifzq.gtimg.cn` → `proxy.finance.qq.com`

- **首选保持第一**，且常量 `KLINE_URL` 的**名字与取值一字不改**。理由有两层：
  (a) WAF 拦截可能只是临时的，首选在前 ⇒ 恢复后**自动**回到原路径；
  (b) 既有断言（`tests/test_source_tencent.py` / `tests/test_data_fetch*.py`）钉的是
      「首选 URL 长什么样」，常量不动则这些断言天然保持绿 —— 回退是**增量**，不是重写。
- `KLINE_URLS = (KLINE_URL, *KLINE_MIRROR_URLS)` 是**唯一**的顺序真源；
  `fetch.py` 只迭代它，不自己拼顺序。

### ② F2：触发条件＝**该 base 抛 `FetchError`**；4xx（非 429）不换

| 情况 | 换 host？ | 理由 |
|---|---|---|
| 5xx / 连接异常 / 空响应（重试耗尽） | ✅ | 「这个源此刻不行」，同构 host 可能行 |
| 正文非 JSON（拦页以 200 返回 HTML） | ✅ | 同上：这份 body 无法解析 |
| **4xx（非 429）** | ❌ | `http.py` 对它们**不重试**就抛 —— 说的是「**我请求错了**」（参数/URL 错），换 host 只会把同一个错再犯两次 |
| **`HostNotAllowed`**（白名单） | ❌ | 白名单是本站自己的闸门（R13）。静默换 host 会让「白名单漏配」永远不可见 ⇒ 必须响亮失败 |
| 翻页到上限 | ❌（不在此层） | 那是「整段历史没取完」，与用哪个 host 无关 |
| 成功取到 JSON 但**零行** | ❌ | 「零行」＝到上市首日之前的**合法**结果。若把它当失败去换 host，就会变成「换页重放」 |

- 链上全失败 ⇒ 抛**聚合** `FetchError`，文案**点名试过的每个 host** 并挂上最后一个异常
  （`raise … from last`）。「上次是哪个域名死了」必须一眼可见，不能又变成一轮猜。
- 每个 base 内部**沿用** `HttpClient` 的既有重试/限流；本轮**只加一层「host 级」回退**。
  ⇒ 镜像回退**不写进** `HttpClient`：HTTP 层保持 host 无关，`http.py` 零改动。

### ③ F3：缓存键**分段**，首选键一字不改

- 首选：`kline:{code}:{anchor}:{page}:{adj}`（与加回退链之前**逐字节相同**）
- 镜像：`kline@{host}:{code}:{anchor}:{page}:{adj}`（除权事件同理：`actions@…`）

理由：真库 `data/raw_cache` 已 194 MB，**换键 = 已缓存页全部重取**（纯浪费）；而
**共用一个键**更糟 —— 那会变成「同一个键下混着两个 host 的字节」，正是铁律②
（可复现）最怕的样子：命中哪个 host 的响应取决于历史，事后不可还原。
分段后每一份缓存都**自行携带它来自哪个 URL**（`raw_cache.url` 列），可复现、可溯源。

### ④ F4：白名单**只增**，不放宽 R13 的匹配口径

- 只加 `ifzq.gtimg.cn`、`proxy.finance.qq.com` 两个**精确主机名**；既有条目一个不删不改；
  **不**加数字子域、**不**加代理、**不**加 IP。
- `assert_host_allowed` 的精确匹配语义不变 ⇒ `1.ifzq.gtimg.cn`、
  `ifzq.gtimg.cn.evil.com`、`stock.ifzq.gtimg.cn` **仍旧被拒**（本站钉成回归用例）。
- 白名单仍是**精确集合**断言（`test_whitelist_is_exact`）：扩白名单必须留下痕迹。

### ⑤ F5 / F6：只修日K 这一条链

- 真库 `data/stocklab.db` **只读可**，实测只在 `/tmp` 副本；真库补采由 nanobot 跑。
- 不 regen 红线；`ops/`、`paper/`、`m2/`、`predict/`、`eastmoney`、`sina`、`http.py`
  **零改动**。ETF/东财/新浪/上交所各源不碰。

### ⑥ F7：真实源实证额度 ≤12 次请求

证据要来自**真源**（假 client 只能证明「代码按我写的那样跑」），但不能借机做大规模采集：
实证只取数、**不落库**、不写任何缓存。

## 什么条件下推翻

1. **首选 host 长期不可用**（WAF 永久拦）⇒ 应**换首选**（把 `KLINE_URL` 改成可用 host），
   而不是永远靠回退链多打一次注定失败的请求。「首选在前」是为**临时**拦截设计的。
2. **镜像载荷不再同构**（字段少、口径不同、缺少事件行）⇒ 回退就变成**换源**，
   必须走新源那一套（新 fixture + 重新核对字段索引 + 口径确认），不能默默复用解析器。
3. **出现第二类「host 单点」的取数链**（如快照 / 估值）⇒ 应把回退逻辑**收敛**成可复用的
   一处，而不是每个源各写一遍；本 ADR 只裁决日K，理由是当时**只有这一条链断**
   （同轮实测 `qt.gtimg.cn`、`datacenter-web.eastmoney.com`、
   `vip.stock.finance.sina.com.cn` 均 200）。
4. **白名单需要通配/后缀语义**才能表达镜像 ⇒ 说明「同构镜像」这一档不再成立，
   R13 的口径要重新讨论（本 ADR 明确**不**走这条路）。

## 后果

- 源站换域名 / 上 WAF / CDN 抖动不再等于「取数链断了」；代价是**首选失败时每页多一次请求**
  （以及首选那 4 次注定失败的重试仍在，因为 `http.py` 的 5xx 语义没有变、也不该在这里变）。
- **首选可用时路径逐位不变**：URL、缓存键、请求序列、解析层全部与改前一致 ⇒
  既有 raw_cache 全部照旧命中，红线不需要 regen。
- 4xx 与白名单违规**仍然响亮失败**：`#80` 的教训是「源坏了」要能回退，**不是**
  「所有错都去试下一个 host」—— 那会把「我请求错了」埋掉，正是 ERROR_DIARY #44 家族。
