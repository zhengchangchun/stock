# ADR-022：模块2 四支插桩的契约口径（m2_a1/a2/a3/b1）

- 日期：2026-09-22
- 状态：已采纳（P45 落地）
- 上游：`docs/plans/2026-09-22-模块2-需求书.md` D-24 / D-30 / D-33；
  `docs/tasks/2026-09-22-p45-模块2-插桩A1A2A3B1契约.md` §2
- 关联：ADR-017（沙盒回放口径）、ERROR_DIARY #32（口径落地选择 vs 预注册原文）、
  #38（比值不是判据 / 代理指标不是事实）、#42（判据「A（B）」括号歧义）
- 实现：`stocklab/plugin/contract.py`、`tests/test_plugin_contract_m2.py`、
  `stocklab/cli/main.py`（`--plugin-id` 帮助文案）

## 背景

模块2 的「AI 模拟选股 / 卖出 / 收益预测」与「人工持仓收益预测」是四支**插桩脚本**
（D-24：走既有 plugin 契约 + 沙盒 + 人工 `approve` 闸门，不是主干硬编码逻辑）。
任务书 §2 定死了四支的语义与失败行为，但在写契约时冒出了三个**任务书没写死**的口径分叉：

1. **`m2_a3`/`m2_b1` 的字段名**：任务书括号写的是 `range_lo/hi` + `p_up/p_flat/p_down`，
   而代码里的真源 `predict/model.py::CONTRACT_FIELDS` 用的是 `range_80` +
   `direction{up,flat,down}` + `invalidate_if`。`range_lo/range_hi` 只是
   `predict/store.py::payload_to_row` 落库时的**列名** —— 两套名字并存。
2. **「不知道」怎么表达**：规则 4 说「不可算的特征给 `None` + `na_reasons`，不许给 0.0」，
   但既有预测载荷**没有**「不知道」形态（它算不出就抛 `DegenerateInput`）。
   而沙盒探针必须能拿一份**无数据**的 ctx 跑通正常脚本（`PROBE_CTX` 的既有职责）。
3. **规则 2（引用越界）放哪**：它需要候选池/账户作为入参，形状校验不需要。

## 决策

### 1. 字段名取真源：`range_80` + `direction{up,flat,down}` + `invalidate_if`

任务书自己写了「字段名可微调」，所以按真源取。`test_forecast_field_names_come_from_the_canonical_payload`
断言这三个键名 **⊆ `predict.CONTRACT_FIELDS`** —— 「另造第二套概率口径」从此是一条
读得懂的失败，而不是靠人去 diff 两份文档（需求书 §5 A5 口径唯一、D-30 口径分工）。

> 为什么不用 `range_lo/hi`/`p_up/...`：那是**库里 `predictions` 的列名**。列名是
> 存储层的事，会随 schema 变；载荷字段名是口径。拿列名当契约，等于把「口径」
> 钉在了一个随时可改的存储细节上（同型：ERROR_DIARY #33「同名的量、两把尺子」）。

### 2. `na_reasons` 用**全有或全无**，不做部分未知

`m2_a3`/`m2_b1` 的形状 = `range_80` + `direction` + `invalidate_if` + `na_reasons` + `schema_version`：

| `na_reasons` | 三个数值字段 |
|---|---|
| 非空 | **必须全为 `None`** |
| 空 | **必须全在且合规**（`lo ≤ hi`；三概率各 ∈ `[0,1]` 且合计 = 1）|

**半真半假直接拒绝**：报了 `na_reasons` 却仍给出部分数值 = 「不知道」与「知道」
混在一份载荷里。允许这种形态，脚本就可以在算不出的地方填一个「看起来还行」的数
再补一条理由把它圆过去 —— 那正是规则 4 要防的「不知道 ≠ 最差」。

`na_reasons` **不是**第二套概率口径：它的存在意味着这份载荷**一个概率都不出**。

### 3. 规则 2 单独一个函数 `validate_references`，且**没有「跳过」的默认值**

```python
validate_references(plugin_id, result, *, allowed_codes)   # allowed_codes 必填
```

- 与 `validate_return` 分开：形状校验不需要候选池/账户，混进一个签名会让人以为
  「形状过了」等于「引用也过了」。
- `allowed_codes` **是必填关键字参数，没有 `None → 跳过` 的默认**。传空集合时
  任何引用都算越界（fail-closed）。fail-open 的默认值会让「忘记传」与
  「校验通过」在返回值上长得一模一样（ERROR_DIARY #31 家族：缺席被读成「否」）。
- 对不引用标的的插桩（`m2_a3`/`m2_b1`）调用它 → `ValueError`：这是调用方的
  编程错误，不是脚本 bug。

### 4. `approve` 闸门与 `0–5` 编号一个字不改

四支走**同一道**闸门：`approve` 的合法前置状态仍是 `pending_review` / `archived`，
不因为是 `m2_*` 而开口子（D-24）。`SHAPES` 的 `"0"`–`"5"` 五项逐字未动
（`test_builtin_zero_to_five_shapes_are_untouched` 钉住）。

## 被否的备选

| 备选 | 为什么否 |
|---|---|
| 契约用 `range_lo/hi` + `p_up/p_flat/p_down`（照抄任务书字面） | A5 口径唯一：真源已是 `range_80`/`direction`，再定义一套名字 = 两处真源并存 |
| 要求**整个** `CONTRACT_FIELDS`（含 `key_levels`/`strategy_mix`/`model_version`） | 越权：会要求 AI 插件产出它未必能决定的字段（如 `model_version`），且远超任务书 §2 列出的「概率/区间」范围 |
| 把规则 2 做成 `validate_return(..., allowed_codes=None)` 的可选参数 | `None` 会变成「静默跳过」的默认值；探针路径不传它，于是「引用越界」这条规则在探针里永远不生效，而报告看不出区别 |
| 「不知道」时让脚本抛错（学 `DegenerateInput`） | 沙盒探针拿的是**无数据** ctx，抛错 = 每个正常脚本都被误拒（`PROBE_CTX` docstring 记过的既有坑） |
| 概率不归一 → 自动归一化 / 区间倒挂 → 交换两端 | 规则 1 明令「绝不 clamp」：归一化会把算错的概率救成合法载荷，交换两端会把方向错误伪装成合法区间 |

## 后果与风险

- **`PROBE_CTX` 新增 `candidates` / `holdings` / `cash`**（空形状）。`cash` 给 `None` 而非
  `0.0`（「不知道」≠「没钱」，规则 4 同款）。
  ⚠️ **未验证的口子**：这三个键名是**我按任务书 §2 的输入列猜的**，P46 定稿通路 ctx 时
  必须回来核对；键名对不上 = 探针在拿一份不存在的契约认证脚本。
  核对点写进了 `contract.py` 的 `PROBE_CTX` 注释。
- **`validate_references` 目前没有生产调用者**（只有测试）。这是刻意的：
  P45 只做契约，通路属 P46。它在 docstring 里标了 `⏳ P46 接线`，
  **不是**一句「已经接好了」的谎话（ERROR_DIARY #24 的纪律）。
- `stocklab/cli/main.py` 的 `--plugin-id` 帮助文案由「0-5（本轮）」改为点名四支 ——
  不改就是 A6「文件在说谎」（帮助串里的枚举与 `SHAPES` 的键对不上）。
- 四支的**语义正确性**（选得准不准、卖得对不对）**不在本 ADR 范围内** ——
  本 ADR 只定「形状与失败行为」。绩效与自评估是 P47 / P48。
