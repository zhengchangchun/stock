# ADR-023. 模块2 §4 绩效对比的口径：五个指标、期初基、样本量门禁

- 日期：2026-09-22
- 状态：已接受

## 背景

需求 `stock/02_模块 2_模拟人工交易闭环需求.md` §4 点名「输出：总收益、年化、最大回撤、
盈亏比、胜率」。P41 之前 `/lab/paper` 只有 `NAV 曲线 + 指数点位`，一句「AI 模拟调整有没有
跑赢大盘」都答不了 —— 而且曲线只有 5 个交易日，看图必然会**说出谎话**。

要让这五个数可用，必须先把四件事定死（事后改任何一个都等于换指标救结果，`CLAUDE.md`
度量纪律第 6 条禁）：

1. 每个指标的**算法**在哪；
2. 每条线的**期初基**取什么；
3. `n_sessions` 到底数什么（它同时决定年化与门禁）；
4. 样本不够时**说什么、不说什么**。

## 备选方案

### A. 算法放哪

1. **全部复用 `backtest/metrics.py`（采纳）** —— 该模块已有 `summarize`（总收益 /
   最大回撤）、`annualize`（几何年化）、`win_rate`。缺的 `profit_loss_ratio` 补在**同一个
   模块**里，`backtest` 与 `paper` 两侧共用。
2. 在 `labweb/paper_data.py` 里现算 —— 页面与 `backtest` 会各有一套公式，两边必然漂移
   （`paper_data` 自己的模块 docstring 就是「本模块不产生新口径」）。
3. 在 `paper/engine.py` 里再实现一份 —— 同一个公式三个实现，`#52` 那种「写了但没生效」
   会在这里重演。

### B. 期初基

1. **`paper_accounts.initial_nav`（采纳，与任务书 §1 一致）** —— 起跑日收盘
   mark-to-market 的结果。账户与基准（起跑日 `sh000300` 收盘）**同一起跑日**，
   五个指标全部由这一条序列推出 ⇒ 「总收益 == Π(1+日收益) − 1」恒成立。
2. `paper_nav_daily.cum_return` 的基（净入金 `net_deposits` = `initial_capital`）——
   好处是与既有「累计收益」列**逐位相同**；代价是那个基**不是**任何一天的净值：
   起跑日持仓已有浮盈时，它把一笔**模拟盘开始之前**的账面收益算进了每一臂。
3. 0 / 现金 —— 明显错（本金一进来就不是 0）。

**已知差异，记账不修**：实测真库 2026-09-15 `initial_nav = 20043`、`initial_capital = 20000`
⇒ 方案 1 的「总收益」比方案 2 低 **0.2155%**。这是一个**对全部臂相同**的常数因子：
排名不变、只把水平线整体平移。选 1 是因为「起跑日持仓浮盈」不是模拟臂挣来的；
**不靠改 `cum_return` 的基去对齐** —— 改口径去迎合一个新页面正是反过拟合红线。

### C. `n_sessions` 数什么

1. **日收益个数 = `paper_nav_daily` 的行数（采纳）** —— 真库当前 = 5，
   与 `paper.engine.build_report.sample_note`（「共 5 个交易日」）和
   `paper_data.track()["n_sessions"]`（5）**同值**。
2. 横轴点数 = 6（起跑日锚点 + 5 行）—— 与页面上那两张图的横轴相同。
   但年化要的是**相邻观测之间的区间数**，含锚点会多算一段。

⚠️ 这两个数在同一页上都会出现（图说「横轴 6 个点」、表说「5 个交易日」），
所以两个函数各自的 docstring 与页面文案都写明了「谁数什么」。

### D. `profit_loss_ratio` / `win_rate` 的定义域

1. **吃同一条日收益序列（采纳）** —— 与 `win_rate` 现有签名同域，两者永远不会
   一个按日收益算、另一个按别的口径算。零收益日**两边都不算**。
2. 按成交笔算 —— 需要逐笔已实现盈亏的持仓会计，`paper_trades` 里没有现成真源，
   等于新造一套口径（反目标：不新增指标口径）。

**只有赢或只有输时 `profit_loss_ratio = None`**（不是 `0`、不是 `inf`）：
「还没输过」推不出「盈亏比无穷大」，是分母那一侧还没出现观测。
实测真库的 `sh000300` 单调上涨那一路就会命中这条。

### E. 门禁与措辞

1. **`threshold = verify.report.MIN_DAYS`（120），`gate_status ∈ {ok, insufficient}`（采纳）** ——
   与 `trend/evaluate.py` 同一条做法：门槛只有一个真源，不另写一个 120。
2. 只在文档里写「样本不足」—— 那正是本任务要修的病：**每个数字旁边**都要有标注。

## 决策

- 五个指标 = `METRIC_KEYS`，**名字与顺序定死**；超出这五个的（Sharpe / Calmar / 波动率）
  一律不加 —— 需求只点名五个，多一个就是一条「事后换指标」的入口。
- 算法唯一真源 `stocklab/backtest/metrics.py`；新增 `profit_loss_ratio(returns)`。
- 期初基 = 起跑日值（账户 `initial_nav` / 基准起跑日收盘）。
- `n_sessions` = 日收益个数（= 净值行数）。
- 门禁 = `PERFORMANCE_THRESHOLD`（= `MIN_DAYS` = 120）；不够时
  `gate_status = "insufficient"`，措辞 `PERFORMANCE_INSUFFICIENT`
  =「样本不足，仅供观察；不得据此选策略或改口径」。
- `insufficient` 时**只给读数**：不出现「跑赢 / 跑输 / 优于 / 劣于 / 领先 / 胜过」
  （测试逐词钉死，页面与 CLI 文本两条渲染路径都查）。
- 回撤：**数据**保留 `backtest/metrics` 的负值；**页面**按既有「逐条对照」列的正值口径
  显示同一个数（符号是展示约定，不是第二套口径；有测试钉住两处是同一个数）。
- 基准 `sh000300` 与各臂**同一交易日轴、只按精确日期取收盘**。窗口内任一日期缺价
  → 该行五个指标全 `None` + 原因，**不用相邻日顶替**。

## 后果

- **好处**：`paper metrics`（CLI）与 `/lab/paper` 新节读**同一个函数**
  （`paper_data.performance`），两处不可能出现两个「总收益」；每个数字自带
  `n_sessions` 与门禁状态；5 个交易日的读数不再可能被当成结论。
- **代价 / 需注意**：
  1. 新节的「总收益」与既有「累计收益」列相差起跑日那 0.2155%（对全部臂相同）。
     两处都写在案；**不要**为了对齐去动 `cum_return` 的基。
  2. `n_sessions`（5）与页面横轴点数（6）不是同一个数 —— 文案已分别写明。
  3. 短窗口的**年化**是纯外推（实测真库 5 个交易日：基准 +188.5%、纪律臂 −80%）。
     它出现在表里正是为了让读者看见「这么短的窗口谈年化有多荒谬」；门禁没过时
     它就是读数、不是结论。
  4. 真库当前只有 5 个账户（`arm-now` / `arm-hold` / 三档 `arm-discipline-*`），
     **没有** `arm-agent` / `arm-agent-random` —— P37 的智能体臂没在真库 `init` 过。
     本表按库里的账户如实列，不补行、不猜。

## 修正（2026-09-22 晚，用户拍板 ⇒ 澄清 D-37）

⚠️ **上面「后果 / 需注意」第 1 条被本条修正**（历史正文不删，只标失效）：

- **期初口径改取「净入金 20000」而不是 `initial_nav`**：三者原本差一个 **0.2155%** 的常数
  （`initial_nav` 含种子买入的浮动）。同一个页面上两个数差一个常数，读者会以为是真差异，
  本就是一个坏口径 ⇒ 取净入金后，新节的「总收益」与既有「累计收益」列**逐位一致**。
- 受影响的：`paper metrics`（CLI）、`/lab/paper` 新节、以及任何写「相对净入金」的文案；
  因为**两处本来就读同一个函数**，所以改一处就够，改完要断言两列相等。
- **未变**：净值口径（`paper_nav_daily.nav`）、成本口径（ADR-008）、门禁 120 交易日、
  `insufficient` 只给读数的措辞纪律。
