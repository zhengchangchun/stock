# ADR-027 日更口径与采集范围解耦：`instruments.active` 是**全局口径开关**，新成员一律落 `active=0`

- 日期：2026-09-25
- 状态：**已采纳**（F1–F6 由 nanobot 在任务书 §0.5 拍板，实现站按条落地、不许另选）
- 相关：ADR-026（宇宙：文件＝真源、表＝投影；C 的代价是做对账）、
  上游 `docs/tasks/2026-09-24-p71-宇宙扩容实现.md`、
  任务书 `docs/tasks/2026-09-25-p72-日更口径与采集范围解耦.md`、
  ADR-008（ETF 不进复权链）、ADR-015（写库入口自动前滚 schema）
- 代码落点：`stocklab/cli/universe.py`（`_sync` / `_doctor`）、
  `stocklab/cli/main.py`（`_explicit_universe` ＋ 四条 `ingest` 的 `--universe`）

## 背景

P71 让宇宙成了**带 id 与 sha 的显式对象**（ADR-026），但它的 `_sync` 对新成员硬写
`active=1`。而 `instruments.active` 在本仓**不是装饰位，是全局「日更口径」开关**——
只读它的地方至少有八处：`predict/service.py`（预测标的集合）、`verify/replay.py`、
`experiments/runner.py`、`session/review.py`、`session tick`、`ingest bars/actions/valuation/
moneyflow` 的默认集合（`_bars_universe` / `_stock_universe`）、以及
`ops/close` / `ops/patrol` 里**不带任何范围参数**的 `ingest *` 步骤。

⇒ 一旦在真库跑 `universe sync csi300-500`，**当天**：预测集合 17 → 817 条/日；
`ops close` 的 `ingest *` 从 21 只 → 821 只（整轮预算 900 s 当场爆，日链天天 exit 2）。
这是「真源文件 → 投影」这条链上**唯一漏掉的消费方**；P70 设计稿全文**零次**出现
`active`，P71 判据只在 `/tmp` 副本上 sync —— 副本不跑 close/predict，**看不见日更口径**。

## 决策

### ① F1：`universe sync` 的新成员落 `active=0`；既有行**一字不动**；**不加** `--activate`

- **`active` 是口径，不是元数据。** 把 800 只研究池顺手写成 `active=1` ＝ **隐式换日更
  宇宙**：与 ADR-026 的 D2（扩宇宙只能走显式 id、不得隐式回退）**直接冲突** ——
  用户以为只是「把行情灌进库」，实际把预测/回放/实验/复盘/日链的标的集合全换了。
- 缺口在**写入侧**而不是读取侧：读 `active` 的八处**一处都不用改**（本站零改动）。
  错的只是「插行时的默认值」。⇒ 修 `_sync` 的 INSERT（`1` → `0`）。
- **既有行的 `active` 不许被 `sync` 改写**：与「只补空 `sector`」同一条纪律 ——
  `sync` 只负责把研究池**登记进表**，无权重写人工/既有口径。既有 21 只因此仍 `active=1`。
- **不加 `--activate` 开关**：真要进日更口径必须**显式**改这一列（人工 `UPDATE`），
  不由 `sync` 代劳。少一个能「顺手换宇宙」的入口。

### ② F2：四条 `ingest`（bars/valuation/moneyflow/actions）加 `--universe <id>`

- **显式指定 ⇒ 采集集合＝该宇宙全部成员（含 `active=0`）**；**不带 ⇒ 逐位维持现状**
  （`_bars_universe` / `_stock_universe` 一个字不改）。
- 解耦点：**「采集范围」与「日更口径」是两件事**。研究池的行情**必须能进库**
  （不然扩池无意义），但采集它**不能顺手**改预测集合。二者由两个显式入口分开控制。
- **`--universe` 一律 fail-closed**（F3）：文件缺失/坏 ⇒ exit 2，**不回退**与 ADR-026
  `load_universe` 同一条线。
- **`--universe` 路径不调 `upsert_instruments`**：`instruments.active` 的 schema 默认值是
  `1`，upsert 会把库中还没有的成员按默认值插成 `active=1` —— 正是 F1/F2 要堵的同一件事。
  成员登记是 `universe sync` 的职责（ADR-026：表＝文件投影）。这与 P71 的
  `ingest financials --universe` **同形**（它也不 upsert）。
- **既有事实不被 `--universe` 破坏**：`ingest bars` **ETF 也采**；
  `ingest actions` 显式宇宙再过一道 `is_stock` —— **ETF 不进复权链**（ADR-008）。
  `--code` 语义不变：与最终集合求交，集合外代码**报错退出**（ERROR_DIARY #44）。

### ③ F4：`ops/chain.py` / `ops/patrol.py` / `CLOSE_STEPS` **一字不动**

本站的目标就是「**日链零变化**」：改 `ops/` 反而把风险引到最不该动的地方。
`active=0` 生效后，日链的 `ingest *` 默认集合仍是那 21 只 —— 这正是红线本身。

### ④ F6：`universe doctor` 的「instruments 覆盖」判据**不看 `active`**，但逐条报数

`sync` 之后研究池成员是 `active=0` 是**预期**，doctor 不能因此报红；否则扩池后
`doctor` 恒红，红线就失效了。判据＝「成员**存在于 `instruments` 表**」，
另加一行 `成员 active N / 非 active M` —— 只报数、不改判据（两边分布要可见）。

## 什么条件下推翻

1. **`active` 不再是全局日更口径**（例如预测/回放/实验各自持有独立的标的集合，
   不再读这一列）⇒ ①②的耦合前提消失，`sync` 落什么值就不再是「换宇宙」。
2. **扩池被正式采纳为日更口径**（用户明确说「以后 800 只就是每日预测集合」）⇒
   那时应改的是**消费方的集合来源**（显式决定），而不是靠 `sync` 顺手写 `active=1`。
3. **出现第二个「范围」消费方却不读 `active`** ⇒ 说明口径已分裂，本 ADR 的
   「八处同源」前提要重核。
4. 若未来的 `universe sync` 需要**同时**支持「登记」与「激活」两种语义 ⇒ 那时再引入
   显式开关（且必须**具名**、默认不激活），不是回到隐式默认值。

## 后果

- 扩池**不再有**「sync 一下，日链当场爆」这条路：研究池先进表（`active=0`），
  要采它们的行情必须显式 `--universe`。
- 代价：研究池成员在行情的**默认**采集里**不出现** —— 这是**有意**的；
  扩池后「默认集合还是 21 只」由 §③ 的零改动保证，不是遗漏。
- `doctor` 多一行读数（active 分布），判据不变 ⇒ 既有 `exit 0` 语义不受影响。
- 红线三目标**不 regen**；默认路径（不传 `--universe`）行为**逐位不变**。
