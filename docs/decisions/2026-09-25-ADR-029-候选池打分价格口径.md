# ADR-029 候选池打分的价格口径（因子侧复权 / 判定侧未复权）

- 日期：2026-09-25
- 状态：已接受
- 上游：`docs/tasks/2026-09-25-p77-候选池打分价格口径.md`（D1–D6）、
  `docs/experiments/2026-09-25-xsec-topn-csi300-500.md` §5、ADR-004、ADR-008

## 背景

`candidate/run.py::_load_bars` 直接读 `bars_daily`（真库全表 `adj_mode='none'` = **未复权**），
`score.build_ctx` 把它原样放进 `ctx["bars"]` ⇒ **插桩 1/2/3/4 看到的是未复权价**。
而本项目其它每一条价格路径都走 ADR-004 的复权链（`predict/`、`verify/`、
`risk/rules.py`、`strategies/evaluate.py`、`plugin_review/inputs.py`、`paper`），
29 篇 ADR 里也没有一篇写过「候选池打分故意用未复权价」—— 这是一处**未记载的口径缺口**，
不是有意的口径。

后果（只读探针实测，`csi300-500` 800 只 × 6 个调仓日，见任务书 §0.2）：插桩1 的
`score = 50 + 20日动量×200 + (量比−1)×20`，而 20 日动量在**除权日当天被除权缺口污染**
—— 分红送转季每 8–10 只里就有 1 只的动量被污染，且**方向会反**（未复权大跌 / 复权大涨）。
打分是「动量×200」线性放大 ⇒ 这些标的的**排序被系统性搞错**，而排序是通路 A 选股的唯一依据。

反证口径正确的一侧：既有 `tests/test_verify_*::test_score_uses_adjusted_not_raw_prices`
表明「验证器用复权价」是本项目的既定口径。

## 备选方案

1. **保持未复权**（不动）—— 优点：零风险、零耗时；缺点：打分输入在一个已知会系统性
   翻转符号的量上做线性放大，且与项目其余价格路径口径不一致。**否**。
2. **因子侧换复权、判定侧（`screen.py`）保留未复权**（选中）—— 两处用途的口径本来就不同
   （见下），分开取数即可，不改任何策略参数、不改插桩公式。
3. **两侧都换复权** —— **否**：涨跌停按**前收**判定，除权日的未复权跳空正是「跌停」与
   「除权」的区别；把复权价喂给 `screen` 会把除权日误读成跌停（当日不复权 −16.7% 的
   送转事件会被判成连续跌停），也会漏掉真实跌停。`screen.py` 是主干，一行不许改。
4. **把复权价落库**（`bars_daily` 里存 `adj_mode='qfq'`）—— **否**：复权是**读取层**的事
   （ADR-004），落库会让 `as_of` 语义失效（复权锚点固定在某一天，历史就再也回不到当时
   看到的价格）。`adjust_bars` 输出的 `adj_mode='qfq'` 会被 `repo.insert_bars` 拒绝，
   物理上不可能被误落库。

## 决策

### D1 因子侧换价

`ctx["bars"]`（插桩 0/1/2/3/4 的输入）改为 `data/adjust.py::load_bars_adjusted` 的输出，
`as_of=asof` 与同一天 `_load_bars` 的 `asof` **同一个值**、**不缩窗**：
成功时两条路径的 `date` 序列**逐位相同**（都由 `bars_daily` 的 `date <= asof` 决定，
复权层只做乘法、不增删行）。**不自己实现复权**，一律走既有读取层。

### D2 判定侧不换价

`screen.screen` 继续吃 `_load_bars` 的未复权价。`screen.py` **一行不改**（判据/阈值/顺序
都不许动）。

### D3 回退与可见性（`n_adj_fallback`）

`load_bars_adjusted` 拿不到复权价时**回退未复权价**并**计数**，因为这是打分路径不是下单路径
—— 一条标的的复权链不可用不该让整轮 `candidate run` 死掉。回退分三类：

| 类别 | 触发 | 真库 `csi300-500` 实测 |
|---|---|---|
| `etf_chain_unsupported` | `EtfChainUnsupported`（ADR-008 白名单拒绝服务） | 宇宙内 0 只（4 只 ETF 不在成分表里） |
| `unpriceable_event_in_window` | `MissingFactor`（窗口跨过不可定价事件） | **148/800**（asof 2026-09-23） |
| `stale_blackout_table` | `StaleFactorTable`（缺口记录与链不同源） | 0 只 |
| `empty_chain` | 该 code 还没采 `ingest actions` ⇒ 因子恒 1 ⇒ 价 == 未复权价 | **226/800** |

**边界（`AdjustError` 全体不等于可回退的那一类）**：只回退上面这四类**数据侧不可用**，
裸 `AdjustError`（`k > 1` 的负现金解析 bug、`pre_close <= 0`）**原样抛** ——
「数据脏」与「代码坏」要分档（ERROR_DIARY #81 的教训：兜底要 catch 的是「这一类失败」，
不是「当前已有的那几个子类」）。

> ⚠️ **与任务书 D3 的偏差（如实记）**：任务书点名了两类（ETF / 复权链为空），而实测
> 148/800 的标的是**第三类**（窗口跨不可定价事件）。只捕获任务书点名的两类 ⇒
> `csi300-500` 上 18.5% 的标的会让整批 abort（正是 D3 自己的 fail-open 理由要避免的）。
> 本站按「D3 的理由优先、点名清单补齐」处理：多捕 `MissingFactor` / `StaleFactorTable`，
> 并把它写进本节与任务书 §7。

计数只统计**真正进入打分**的标的：`screen` 淘汰的标的从不构造 `ctx`，把它们算进来会让
这个数随排雷结果漂移，不是「这一轮有多少只没吃到复权」。

fail-open 也必须**可见** ⇒ 计数进 `PipelineResult.params` → `candidate_snapshots.params_json`。
（`candidate/report.py` 不在本任务的允许改动清单内，所以「报告里可见」由 `params_json`
承担；labweb 的候选池页读的就是快照 `params`。）

### D4 口径可追溯、历史不改写

`candidate_snapshots.params_json` **只增两个键**：`scoring_price_mode =
"adjusted_factor_side+raw_screen"`、`n_adj_fallback`（整数）。老键
（`seed_count` / `topn` / `universe_id` / `members_sha256`）名与取值一字不变；
历史快照行**一个字节都不许改**（表本身有 append-only 触发器）。

**口径切换点之后才能靠新快照区分**：同一天 `(asof, run_kind)` 已有旧口径快照时，
`run_candidate` 会幂等命中并整体跳过（连 `params` 都返回老行里的），**不许为了让它生效
去删历史行**。要拿新口径读数，只能等下一个调仓日，或走 `score_pipeline` 现算（只读，不落库）。

### D5 不许动的

`screen.py` 判据/阈值；`builtin/p1_short.py` 的公式（已上线插桩源文本，改它要走
`plugin submit`）；`predict/ verify/ paper/ m2/ ops/`；`bars_daily` 的采集口径
（不落复权价）。本任务的改动面只有 `candidate/run.py` 一个生产文件。

### D6 性能与确定性

复权读比裸读慢，扫描变慢是**可接受**的代价，记读数即可（本 ADR「后果」节的实测）。
不加缓存：任何缓存都必须只读、逐位可复现、且不得改变任何数值结果，本轮没有这个必要。

## 后果

**实测影响（真库 APFS 副本 `/tmp/p77/audit.db`，6 个调仓日 × `csi300-500` 800 只，
改前 = HEAD detached worktree、改后 = 本 ADR 的实现）：**

| 调仓日 | 单日扫描耗时 | short top-6 交集 | 共同成员中 adj_score 变化数 | `eligible[short]` | `n_adj_fallback` |
|---|---|---|---|---|---|
| 2018-06-29 | 8.5 s → 13.2 s | 5/6 | 0/18 | 324 → 324 | 106 |
| 2020-06-30 | 9.7 s → 14.8 s | 4/6 | 0/17 | 373 → 373 | 133 |
| 2022-06-22 | 11.5 s → 17.4 s | 5/6 | 0/18 | 460 → 460 | 203 |
| 2024-06-28 | 13.2 s → 19.9 s | 6/6 | 1/19（max\|Δ\|=3.23） | 518 → 518 | 248 |
| 2026-06-24 | 14.8 s → 22.6 s | 5/6 | 0/18 | 533 → 533 | 260 |
| 2026-09-23 | 15.2 s → 22.8 s | 6/6 | 0/19 | 532 → 532 | 259 |

- **中/长期池成员 6/6 天与改前逐位相同**（插桩 2/3 只读财报，不读价）——
  这是「改动只落在因子侧价格路径上」的旁证。
- 短池成员变动全部发生在**分红送转季**：进入 top-6 的标的插桩1 得分
  `51.7 / 65.2 / 5.4 / 46.6 / 57.1 → 100.0`（未复权 → 复权），
  即未复权序列里的**假跌停跌幅**被还原（例：`300604` 2018-06-29 的 20 日动量
  −37.98% → +18.13%，除权事件 `10派1.5元转9股`）。退出 top-6 的标的自身得分没变
  （100.0 → 100.0），是被进来的挤出去的。
- **耗时 +55%～+85%**（同一天同宇宙）：多一次全历史 K 线读 + 一次事件链构建。
  单日 8.5–15.2 s → 13.2–22.8 s。P60 那种 571 天的全窗扫描会从 ≈96 min 涨到 ≈2.5 h 量级。
- **`n_adj_fallback` 长期占 1/3～1/2**（2026-09-23：259/532 进入打分的标的）：
  其中 226 只是**还没采 `ingest actions`**（补采任务在跑）、其余是窗口跨不可定价事件。
  ⇒ **本次修复当前只对约一半的候选标的真正生效**，另一半仍是老口径（已计数、可见）。

**代价与后续注意：**

1. **旧读数不可与新读数混引**：`docs/experiments/2026-09-25-xsec-topn-csi300-500.md`
   （Δ=+0.3132%、CI 跨 0）与 P60 的 `2026-09-24-xsec-topn.*` 都是在**旧（未复权）口径**
   下跑的，与本 ADR 之后的读数**不可同时引用**；本 ADR 不改写它们。
2. **回退面会随补采缩小**：`ingest actions` 补齐后 `empty_chain` 那一类会消失，
   但 `unpriceable_event_in_window`（配股/脏条款）不会 —— 它由数据源的内容决定。
3. **口径切换点**：真实库同一天已有旧口径快照时不变（幂等），要等下一个调仓日。
4. **性能**：如果将来 571 天全窗扫描的时间不可接受，先考虑缩宇宙，**不许**缩窗口/抽样
   （读数要逐位可复现）。
