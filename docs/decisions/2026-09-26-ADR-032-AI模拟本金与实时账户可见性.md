# ADR-032 AI 家族本金 5 万：入金事件而非改行（实时账户投影与 objective）

- 日期：2026-09-26
- 状态：已接受
- 上游：`docs/tasks/2026-09-26-p80-AI模拟本金与实时账户可见性.md`（D1–D10）、
  ADR-024（AI 操盘手的决策空间与护栏）、ADR-025（模块2 双通路与镜像口径）、
  ADR-031（决策可成交性）、P62（AI 臂未结算净值行）、P69（模拟操盘可见性）
- 用户原话（2026-09-26，三条）：①「Ai 模拟金额改成 5w」②「完善 Ai 模拟功能，
  实际交易多钱 Ai 能够实时查询」③「预测准确性高的目的是盈利」

## 背景

用户把考核目标从「预测准不准」改成**扣成本后的净收益**，并把 AI 家族的本金从 2 万提到 5 万。
两件事撞上了同一个结构性约束：**`paper_accounts` 与 `paper_nav_daily` 都是 append-only**
（`BEFORE UPDATE/DELETE` 触发器 `RAISE(ABORT)`，`db.connect()` 还开着 `recursive_triggers`
使 `INSERT OR REPLACE` 的隐式删行也被拦）。

- 就地改 `paper_accounts.initial_cash` 看着最省事，但它会让 **09-23 / 09-24 那几行净值当场变成假账**：
  P62 的不变量（`nav == initial_cash + 重放自有成交 + 当日 mark-to-market`）立刻不成立，
  而 P62 探测器会在下一次 `doctor` / `ops patrol` 上把这几行点名。
- 单独给 AI 臂「重开一个 5 万的账户」也不对：等于把 09-15→09-24 的历史（含 4 条决策、
  21 笔成交、44 行净值）换一个身份，D-36 的对照臂同轴性直接断掉。
- 而「随时可查手上有多少现金、每只最多买几手」（用户第二条）在代码里**当时根本读不出来**：
  账户状态只在收盘链跑完 `paper step` 写下的 `paper_nav_daily` 行里有，买入力只有执行层的
  `plan_orders` 内部知道。

## 决定

1. **本金口径靠事件改，不靠改行**。新表 `paper_capital_events`（append-only、两个触发器、
   `idem` 全表 UNIQUE、`kind ∈ {deposit, withdraw}` 带符号、`amount` 恒正）。
   AI 家族（`account_id LIKE 'arm-agent%'`）各挂一条标准入金：**+30,000 于 2026-09-28 生效**
   ⇒ 目标本金 50,000 = `INITIAL_CAPITAL`(20,000) + `AGENT_CAPITAL_TOPUP_AMOUNT`(30,000)。
   `INITIAL_CAPITAL` 仍是所有臂的**起跑口径**；`arm-hold` / `arm-now`（实盘镜像）/ 三条静态纪律臂
   仍是 2 万（要一起改回来一句话的事，但那是另一个决定）。
2. **09-15→09-24 保持 2 万口径的历史原样**：事件生效日 09-28 晚于那两天 ⇒ `date <= asof` 的重放
   读法下，那 5×2 行净值**逐字段零差异**（真库副本实测，见下）。规则是 `PIT：只计入 date <= asof`。
3. **迁移两个函数，不合成一个**（抄 P62 的理由）：
   - `migrate_p80_capital_events`＝结构前滚（补触发器），幂等、挂在 `_apply_schema` 上；
   - `seed_agent_capital_topup`＝**数据前滚**，只登记 `_KNOWN_MARKERS`、**只准显式调用**。
     挂到「任一写库入口都会跑」的位置 ＝ 让某次 `paper predict` 顺手把 5 条账户的本金改成 5 万。
     配套只读探测 `agent_capital_topup_missing` 供 `doctor` 报「哪几条还没挂上」。
4. **三条建账路径共用一处定义**：`engine.agent_capital_events_for(account_id)` 返回事件元组，
   `attach_agent_capital_events` 是它唯一的调用者；`paper init` 的 agent 分支、`paper agent enroll`、
   `m2/channel_a.create_account` 三处都调后者（通路 A 的新版本账户自动带上本金口径）。
5. **实时账户 = 一个投影**：`engine.account_view(conn, arm, asof=None)` 是**唯一**实现
   （`paper account` CLI 与 AI 的输入侧都调它，两条路各拼一套必然分叉 —— D-37 那类事故）。
   默认 `asof` = 库里有 PIT 收盘价的**最近交易日**（数据决定，不是墙上时钟）⇒ 「随时可查」不必等收盘链。
   输出三块：`account`（含 `profit_cny = nav − net_deposits`）／`positions_detail`（含
   `one_lot_cost`、`sellable_qty`）／`buying_power`（`max_lots_affordable = floor(cash / one_lot_cost)`，
   与执行层同一个成本口径）；另加 `fills_on_asof`。缺价/缺账户**点名报错**，不猜数。
6. **同一份口径喂进 AI 的输入侧**：`tradability` 逐只增 `affordable_lots` / `sellable_qty`、
   顶层增 `cash` / `net_deposits`；新增顶层 `objective` 块（考核目标＝扣除全部成本后的净收益最大化，
   文案逐字照任务书 D7）并进 `DECISION_HASHED_KEYS` ⇒ **新写入**的 `context_sha256` 与 P80 前不同，
   台账里**已有的**决策行一字不改写（append-only）。
7. **读数面把「钱」摆出来**：`paper agent show` 加 `account` 块；`/lab/paper` AI 臂表加「净收益(元)」列；
   `labweb/paper_data.py` 里自己算净入金的**重复定义**收口到引擎那一份。

## 理由

- **append-only 是这类账户库的地基**：本金是可被追溯的事实，改一行就等于伪造历史账；
  「入金」本身就是真实世界里发生的事件，用事件表达既保历史又保语义。
- **一个数只能有一个实现**：净入金曾有第二处实现（labweb），入金事件一落地它必然与引擎分叉；
  购买力同理（CLI 与 AI 输入侧问的是同一个问题）。
- **净收益要能一眼读到**：`profit_cny = nav − net_deposits` 只在分母同步变大时才有意义 ——
  入金后累计收益率**不跳变**（分母一起变大），这正是「入金能被正确理解」的关键读数。

## 代价 / 风险

- 新增一条**数据前滚只在显式调用时发生**的路径 ⇒ 部署顺序有意义：先 `ensure_schema`
  （建表 + 触发器），再 `seed_agent_capital_topup`（挂事件）；两步都幂等，重跑返 `[]`。
- `cum_cost` 不因入金变化（入金不是成本），所以入金后 `cum_return` 的分母变了而成本不变 ——
  页面同时给 `cum_return` 与净收益(元)，两者不要混读。
- 静态臂 / `arm-now` / 三条纪律臂**仍是 2 万**：跨臂比较时口径不同轴，读数要按「AI 家族 5 万、
  其余 2 万」分组看。
- `paper account` / `paper capital list` 收下 `--now` 但不用（与其余 `paper` 子命令同形）；
  默认 asof 取 `MAX(bars_daily.date)`，与交易日历的「最近交易日」是否恒等**未核**（只有单测）。

## 与任务书的偏离（站记录在任务书 §7.6，此处只留结论）

1. 标准入金的 `idem` **必须带账户后缀**（`agent_capital_topup_idem(账户) = 常量 + "-" + 账户 id`）：
   `idem` 是全表 UNIQUE，裸字面量会让第一条之后的 4 条账户被 `INSERT OR IGNORE` **静默吃掉**。
2. 多一个**文案**常量 `AGENT_CAPITAL_TOPUP_NOTE`（`note` 是 NOT NULL，理由必须一处定义）。
3. `agent_capital_events_for` 之上多一层 `attach_agent_capital_events`（避免把展开循环抄三遍）。
4. `build_decision_context` 的 `net_deposits` 缺省写 `None` 而不是 `0`/`total_assets`（算不出不猜）。
5. `sellable_qty` 的 T+1 判据实现为「当前持仓 − 当日买入」（当日卖出已反映在当前持仓里）。
