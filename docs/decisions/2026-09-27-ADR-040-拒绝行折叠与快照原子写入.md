# ADR-040 拒绝行按主键折叠与快照原子写入（P90）

- 日期：2026-09-27 ｜ 状态：已采纳
- 上游：`docs/tasks/2026-09-27-p90-candidate-run拒绝行去重与快照原子化.md`（D1–D8）、
  `docs/tasks/2026-09-27-p89-每周与季度调度.md` §8.5（复核发现的阻塞级缺陷）、
  `stocklab/candidate/snapshot.py` 的幂等键设计（`(asof, run_kind)`）、
  `stocklab/store/db.py::transaction()`

## 背景

P89 给 `WEEKLY_STEPS` 的第 1 步就是 `candidate run --run-kind weekly`（阻断步），
而它在**全新 `(asof, run_kind)` 上首次执行就失败**（`rc=1`）：

```
❌ IntegrityError: UNIQUE constraint failed:
   candidate_rejects.snapshot_id, candidate_rejects.code, candidate_rejects.stage
```

两个根因（只读定位见任务书 §0.2）：

- **A｜产出侧在说谎**：打分循环对 `eligible_pools(inst)` 的**每个池**各判一次，
  拒绝时 `stage` 恒为 `'score'`、**不带池名** ⇒ 一只标的在 mid 与 long 两池都
  打分不通过就产出两行同 `(code, stage)`。而 `candidate_rejects` 的主键是
  `(snapshot_id, code, stage)`（`store/schema.sql:1004-1012`）。21 只种子里
  **永远有 3 家银行**走这条路（`600036`/`601318`/`601398`）⇒ 不是偶发。
- **B｜写快照不是原子的**：`store/db.py::connect()` 是 `isolation_level=None`
  （autocommit），`write_snapshot` 末尾的 `conn.commit()` 是**空操作**、抛错
  **无 ROLLBACK** ⇒ 留下「半截快照」（实测：快照行 + 2 行 rejects，而该轮应有
  19 members + 4 rejects）。更糟：**再跑一次**会被 `find_snapshot` 命中并**静默**
  返回这份残缺快照 —— 一条「静静地产出错数据」的路径。

## 决定

### 1. 去重口径 = 按 `(code, stage)` 唯一，保留流水线顺序第一条

依据是**主键本身就是** `(snapshot_id, code, stage)` —— schema 的意图一直是
「一个 `(code, stage)` 一行」；修的是产出侧，不是 schema。

- 顺序取 `eligible_pools` 的返回顺序（`short→mid→long`）⇒ 银行保留 **mid 池**
  那条 `reason`（实测 `mid池打分未通过：…`）。
- **不改 `reason` 文案、不把池名塞进 `stage`**：后者要连带动 schema 的 CHECK
  与报告 / labweb 口径（`stage` 只有 `pre_screen`/`industry_screen`/`score`），
  代价远大于收益。
- 策略语义不受影响：该标的在任一池不通过就不会进那一池的 `scored`；丢掉的
  第二行只丢「另一个池也拒了它」这条信息，**不丢任何买卖决策**。

### 2. 去重落在**写路径**（`run_candidate` / `_dedup_rejects`），不进内核

`score_pipeline`（回放、`research rank-ic`、`research factor-ic` 共用）保持
**无损**：同一 `(code, stage)` 有几行就是几行。折叠只发生在「映射到表结构」
这一步。

**为什么不是把去重放进 `score_pipeline`**（本档最关键的取舍）：D2 要求把丢弃数
写进快照 `params` 的新键 `n_reject_dups_dropped`，而三条**既有的**红线把内核
`params` 的键集 / digest 逐一钉死：

| 红线 | 断言 |
|---|---|
| `tests/test_research_factor.py::test_params_keys_unchanged` | `set(res.params)` 精确等于 6 个键 |
| `tests/test_research_factor.py::test_default_path_digest_is_unchanged_from_head` | 五个原字段的 digest == 常量 |
| `tests/test_research_signal.py::test_pipeline_result_exposes_scored_without_changing_derivation` | 同上（键集） |

把新键放进内核 ⇒ 这三条**必然变红**，而要让它们绿就必须改这三个文件，可它们
不在任务书 §1 的允许改动面内（「超出即停」）。把新键放在写路径上，
**三条硬约束同时满足**：内核 `params` 键集**真的**没变（红线仍然有效，不是被
放宽）、快照 `params_json` 里有计数（D2）、改动物全部落在 §1 白名单内。

代价（如实记）：内核 rejects（7 行）与落库 rejects（4 行）在有重复时**不相等**。
`PipelineResult` 的字段与 `params` 键集是 P83 用测试钉死的公开面（**不能只增**），
所以「内核无损 + 写路径折叠」是唯一不破坏那些钉子的落点。
`tests/test_candidate_run.py::test_score_pipeline_matches_run_candidate_members`
因此改为比「内核产物按主键投影后」—— 保证仍在（回测跑的就是生产逻辑），
只是把「按主键投影」这一步显式写出来。

### 3. `write_snapshot` 用 `store.db.transaction()` 包住全部写入

`isolation_level=None` 下 `with conn:` 与裸 `conn.commit()` 都是**空操作**
（同一个坑），所以显式用既有的 `transaction()`（内部 `BEGIN` / `commit()` /
异常 `rollback()` 并重抛）。`transaction()` 禁止嵌套 ⇒ `write_snapshot` 必须是
事务最外层；已核**没有**调用方先开事务（`run_candidate` 不开，
`tests/test_labweb_candidate.py::_snap` 也不开）。

保留原早退语义（同 `(asof, run_kind)` ⇒ 直接返回既有 id、零写入），
pre-flight 校验留在 `BEGIN` 之前。`store/db.py` 与 `store/schema.sql` **零改动**
（主键、CHECK、append-only 触发器一个都没动）。

## 实测（真库零写入，全部在 `/tmp/p90` 副本上）

- 副本 `candidate run --run-kind weekly --asof 2026-09-24`：**rc=0**，
  members 19 / rejects **4** / `(code, stage)` 两两不同 /
  `params_json` 含 `"n_reject_dups_dropped": 3`；3 家银行各**恰好一行**且
  `reason` 以 `mid池打分未通过` 开头；再跑一次 ⇒ `skipped`、sha 与行数逐位不变。
- 原子性：构造一次「写 members 中途」的 `IntegrityError`（member 的 `pool` 撞
  CHECK —— 刻意不用 status 非法，那会被 pre-flight 在开事务前拦掉、证不到回滚）
  ⇒ `candidate_snapshots` 无该 `(asof, run_kind)` 行、members/rejects 零残留、
  `find_snapshot` 为 None；随后正常路径再跑**成功**且读数与上面逐位相同。
- 三种 `run_kind` 互不覆盖：同 `asof` 的 `weekly`/`light`/`quarterly` =
  三个 snapshot_id（3/4/5），各 19+4，互不删改。
- `scripts/check_redlines.py` 不 regen ⇒ 三目标逐位 == 基线
  （`0acf35c9…`/175、`73ffbfb1…`/1330、`ddac0a88…`/171）；
  `data/stocklab.db` sha 跑前 == 跑后。

## 影响

- `stocklab/candidate/run.py`：新增 `_dedup_rejects`（写路径折叠 + 计数）、
  `run_candidate` 用它并补 `params` 新键；模块/docstring 里「`write_snapshot`
  内部 commit」那句**假的**描述改对（ERROR_DIARY #48 同型的「文档在说谎」）。
- `stocklab/candidate/snapshot.py`：`write_snapshot` 原子化（唯一改动）。
- 打分/分流口径一字未动（`screen.py`/`score.py`/`risk_adjust.py`/`pools.py`/
  `report.py` 零改动）；幂等语义不变；`light`/`weekly`/`quarterly` 互不覆盖。
