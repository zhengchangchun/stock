# ADR-033 小面额可下手域与意图/落地对账：输入侧结论、台账读出口、同源读数

- 日期：2026-09-26
- 状态：已接受
- 上游：`docs/tasks/2026-09-26-p81-小面额可下手域与意图落地对账.md`（D1–D8）、
  ADR-031（决策可成交性 = P79 的「一手契约」）、ADR-032（AI 家族本金 5 万 / 实时账户 /
  `objective`）、ADR-024（AI 操盘手的决策空间与护栏）
- 用户原话（2026-09-26）：「Ai 模拟股票也具备可以模拟小面额多成交的能力」；
  两问回答「不允许零股/按金额成交（保持整手 100 股）」「多次成交需要根据你的分析结果，
  有必要就需要交易的，股值小的这种也可以分析分析」；追加确认「是，如果可以盈利也是可以的」

## 背景

「小面额多成交」在执行层**早就具备**（整手向下取整、跨日不限次、每交易日一条决策），
缺的是三件**接口与读数**的事：

1. **输入侧没有「今天哪几只我根本买不起」的结论**：`affordable_lots` 是个数（P80），
   要模型自己拿去和 0 比；`pool.codes` 也不区分买得起 / 买不起。
2. **P79 落库的 `paper_agent_evals`（未成交腿的理由）一个消费者都没有**：写进了表，
   而 `paper show` / `/lab/paper` / 日报全都不读它 ⇒ 用户仍然看不到
   「AI 想买什么、为什么没买成」。
3. **「小面额能下手」没有任何读数面**：池内一手成本分布、可下手只数、最小可成交权重
   全要手工算 ⇒ 用户没法验证「小面额确实在下手」，汇报里也给不出一个可核对的数。

另有一处**实测的读错对象**：`engine.agent_block` 写死 `ARM_AGENT`（`arm-agent`），而真库里
那条臂**0 条决策**、真正在跑的 `arm-agent-ds-v1/-v2` 不在页面上 —— 页面长期展示一条空臂。

## 备选方案

1. **只改执行层（放宽整手 / 允许按金额成交）** —— 直接违背用户两条原话（不许零股；
   不允许按金额），且会把「最小可成交权重」这个唯一的刻度抹掉。**否**。
2. **同日拆单**（同一标的同一天拆 N 笔小额）—— 只多付 (N−1)×5 元最低佣金，不增信息，
   且 `agent_decide.validate_payload` 的同日去重（`UNIQUE(arm, asof)` 精神）本来就硬拒。**否**。
3. **让模型自己心算**（把 `one_lot_cost` 与 `affordable_lots` 给足就够）—— P79 §0.1 的
   事故正是这么来的（四笔腿全部落在「目标市值 < 一手」上）。把**结论**也交出去。**取**。
4. **页面直连 `paper_agent_evals`**（labweb 自己查一遍）—— 会在同一页造出第二个
   「未成交腿数」（D-37 / ADR-023 那类事故）。**否**：读出口收在 `engine`。

## 决定

1. **D1：`tradability` 只增键，判据唯一。** 逐只增 `tradable` / `untradable_reason`；
   顶层增 `n_tradable` / `n_untradable` / `min_tradable_weight_pct` / `cheapest`。
   判据 = `engine.tradable_verdict`（`tradable = affordable_lots >= 1`，`affordable_lots` 仍是
   `max_lots_affordable` 的产出）；`untradable_reason` 把两种成因**分开**写并各点名两个数：
   成本 > 总资产（无解）/ 现金不足（先卖出可释放）。可下手子集为空 ⇒ 后两个读数一律 `None`
   （**不猜数**）。它是「**现金口径的今天**」，不是「这标的不许交易」，**不许**做硬拒绝。
2. **D2：未成交腿台账有读出口。** 新只读命令 `paper agent evals --arm <臂> [--asof <日>] [--json]`：
   数据源只有 `store.load_agent_evals`（**不重算**任何理由）；`--asof` 缺省 = 该臂 `MAX(asof)`；
   一行都没有 ⇒ 空列表 ＋ `note`、**exit 0**（空列表不是「AI 没动过」）；账户不存在 ⇒
   沿用 `paper account` 的口径 **exit 2**（点名）。理由**不截断**（截断只是对账表的显示口径）。
3. **D3：意图 vs 落地逐臂对账。** `engine.agent_block` 增 `reconciliation`（列表）＋
   `reconciliation_note`，覆盖「`paper_accounts.arm` 以 `agent` 开头且在 `paper_agent_decisions`
   里有行」的每一条臂，各取自己最新（且 `<= asof`）的决策日 —— **不再写死 `arm-agent`**。
   `n_legs_planned`（载荷条数）/ `n_legs_filled`（当日 `paper_trades` 行数）/
   `n_legs_unfilled`（当日 `paper_agent_evals` 行数）/ `n_evals`（与前者同值，**故意重复**：
   「腿数」与「台账行数」不等时差额本身就是信号，**不许用 `min()` 抹平**）。既有键只增不减。
4. **D4：可下手域读数同源。** `tradability` 的**占比公式**抽成 `engine.min_weight_pct`
   （唯一实现，AI 输入侧与读数面都调它）；`account_view.buying_power.by_code` 增
   `tradable` / `untradable_reason`（与 D1 **同一个** `tradable_verdict`），并增
   `tradable_domain` 汇总块；`build_report` 给**每条 AI 臂**补同一个块，`render_report`
   第四节与 `/lab/paper` 各渲染一行 ＋ 买不起的点名。缺数据写「取不到」，**不填 0**。
5. **D5：零行为改动。** `rules.plan_target_weight` / `plan_orders` / `_settle` / `_gate_cash` /
   `execute_decision` / 随机臂 `random_payload` 的算法**一字不改**；本站只加键、只加读数。
6. **D6–D8：真库只读、不 regen 红线、不动其余模块。** 写实测只在 `/tmp` 副本；三目标
   逐位 == `docs/baselines/redlines.json`；真库迁移 / rollout / 新臂 enroll 是 nanobot 侧的事。

## 后果

**好处**

- 「买不起」从**要推理**变成**读结论**：模型与用户拿到的是同一句话、同一对数字。
- 「AI 说得对不对」和「AI 做了没有」第一次在**同一页**上对齐：意图（载荷腿数）、落地
  （成交笔数）、未成交（evals 行数与理由原文）三个数各有来源、互不顶替。
- 页面不再展示一条 0 决策的空臂；真库实测的 `arm-agent-ds-v1`「计划 5 条 / 成交 1 笔 /
  未成交 0 行」这种**缺口**第一次看得见（P79 之前那些 run 没有 evals 行）。
- 「小面额能下手」有了刻度：`min_tradable_weight_pct`（真库 5 万口径 = 1.6516%）。

**代价 / 注意**

- `tradability` 进指纹 ⇒ **同一输入在 P81 前后的 `decision_context_sha256` 不同**；
  台账里**既有**决策行的 sha 一个字节都不改（append-only），旧行读出来的是
  「它当时看到的那个输入」。跨版本指纹/决策行不可直接比。
- 判据一旦分叉就会出现「同一页两个数」：所以 `tradable_verdict` 与 `min_weight_pct`
  各只有一处实现，两边的调用点由测试对拍钉住（`tests/test_paper_tradable_domain_p81.py`）。
- 报告里多出来的这一段挂在渲染路径上：账户口径读不出来时**只许降级**（写「取不到」＋
  点名异常类型），不许把整份报告打崩 —— 回归判据在同一个测试文件里。
- 未成交腿**只对孩子** P79 之后执行的 run 才有行（真库现为 0 行）：`n_legs_planned > 0`
  而 `n_evals == 0` 不等于「全都落地了」，它可能是「那天还没有这台账」。
