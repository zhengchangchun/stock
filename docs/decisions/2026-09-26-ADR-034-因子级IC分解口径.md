# ADR-034 因子级 IC 分解的口径（把短池打分拆成输入因子逐个量）

- 日期：2026-09-26
- 状态：已接受
- 上游：`docs/tasks/2026-09-26-p83-因子级IC分解.md`（D1–D9）、
  `docs/experiments/2026-09-26-factor-ic-short-csi300-500.md`（预注册）、
  ADR-030（`rank-ic`）、ADR-029（打分价格口径）

## 背景

`research rank-ic`（P78 / ADR-030）已经量出：**合成后的分数**对前一个调仓周期的
前向收益没有可测的横截面排序能力 —— `csi300-500` 全窗验证段 IC 均值 −0.0158、
95% CI `[−0.0458, +0.0143]`、`IC_NOT_SIGNIFICANT`。

而现役短池打分插桩（`plugin_scripts.script_id=7`，`plugin_id='1'`，v1.1.0，
`source_sha256=558a6a08b62e508c…`）的分数只是**两个输入因子的线性组合 + 裁剪**：

```
score = clip(50 + 150 × mom20 + 30 × (vr15 − 1), 0, 100)
mom20 = (C[-1] − C[-20]) / C[-20]          # C = PIT 复权收盘价（ADR-029 口径）
vr15  = mean(V[-5:]) / mean(V[-20:-5])
```

于是「合成分数没 IC」有三种互斥的解释，**只有把分数拆开才能区分**：

1. 两个因子都没 IC ⇒ **这套输入没有 edge** ⇒ 方向是换信号源（新数据类别），
   不是继续在现有因子上调权重；
2. 某因子有 IC 而合成分数没有 ⇒ **组合/裁剪把信息毁了** ⇒ 下一步改合成方式；
3. 两个因子都有 IC ⇒ 与合成分数读数矛盾 ⇒ 先查实现。

在没有任何「因子级」读数之前改打分函数，就是**盲改**：改完只能再跑一次 ≈2 h 的
组合级实验，而且大概率还是 CI 跨 0。本 ADR 记录这把更细的尺子的口径。

## 备选方案

1. **直接按读数改打分函数**（换权重 / 去裁剪 / 换因子）—— 优点：一步到位；
   缺点：**没有归因**，改完不知道是哪一项起了作用；且违反「单变量原则」。**否**。
2. **在 `research/` 里自己写一遍打分循环与价格口径** —— 优点：省事；缺点：会形成
   **第二套打分口径 / 第二套复权口径**，与通路 A 的 A1 归因冲突（ADR-030 D2 的同一
   理由）。**否**。
3. **只测现役插桩真正用的两个输入因子 ＋ 管线里已有的 5 个财务因子**（选中）——
   因子值**取自打分用的同一个 `ctx`**，IC / 分层 / bootstrap **直接复用 `rank-ic`
   的既有实现**，另加一项裁剪诊断。

## 决策

### D1 只测已有输入，不扩充因子库

主读数只含 `mom20` / `vr15`（现役短池插桩真正用的两个）；次读数只含管线里**已有**
的 5 个财务因子（`candidate/indicators.py:90-91` 的 `roe` / `gross_margin` /
`gm_yoy_pp` / `inv_days` / `fcf_margin`，现役短池插桩**一个都没用**）。
**不许**加均线 / 换手 / 资金流等新因子 —— 那会把「度量」变成「因子挖掘」，
而且是多变量（CLAUDE.md 单变量原则）。

### D2 因子值取自打分用的同一个 `ctx`

`candidate/run.py::_load_bars_adjusted`（PIT 复权价，ADR-029）＋
`_cross_section_map` ＋ `score.build_ctx` 三条**原样复用**。实现方式是给
`score_pipeline` **只增**一个开关 `want_factors: bool = False`：`True` 时把短池
插桩**这一次真正看到的那个 `pool_ctx`** 里的输入搬进
`PipelineResult.factor_inputs`（只增字段）。**不在 research 侧另建价格口径、
不另算复权**。

### D3 只增字段：`want_factors` / `factor_inputs`

- `PipelineResult` **只增** `factor_inputs: dict[str, dict]`（位置在 `scored` 之后，
  `field(default_factory=dict)`）；
- 载荷形状锁定 `{code: {"closes": [≤20 个 float], "volumes": [≤20 个 float],
  "feats": {5 个财务因子键 + "period"}}}`；
- `want_factors=False`（默认）⇒ **既有调用点零改动**，`members` / `rejects` /
  `params` / `eligible` / `scored` **逐位不变**；
- `factor_inputs` 的键集合恒等于 `scored["short"]` 的 code 集合（在打分**通过之后**
  才填），这条不变量由用例钉住。

**逐位不变的自证结果**：`git archive HEAD`（`5c720eb`）导出到 `/tmp/p83/head`，
用同一段 digest 脚本（`/tmp/p83/digest.py`）在 HEAD 导出与工作区各跑一次
`score_pipeline(conn, asof=days[280])`，五个原字段的 sha256 **两边完全相同**
`02b20b5f4eb90b35fd0a1558edc31be5b7ec7cad956d11cbd791c31158a84671`；该值写死在
`tests/test_research_factor.py::FALSE_PATH_DIGEST`，从此任何对默认路径的污染都会变红。

### D4 公式复述 ＋ 一致性用例

`mom20` / `vr15` / `clip(50 + 150×mom20 + 30×(vr15−1))` 在
`stocklab/research/factor.py` 里**复述一次**（注释点名 `script_id=7` / v1.1.0 /
`source_sha256=558a6a08…`），并**必须**用用例钉住：同一 `ctx` 上重建的分数
== 插桩实际返回的 `score`。

用例夹具里的插桩1 是**现役 v1.1.0 的逐字源文本**（`source_sha256` 也在用例里钉住），
所以这不是「拿自己的实现对自己」；对不上就说明本站算的因子不是插桩的因子，
**先修再谈结论**（预注册 §2）。

### D5 裁剪诊断只报不判

逐调仓日统计「被打分插桩裁到 0 或 100 的标的本数 / 当日截面数」，出 P50 与极值。
它量化裁剪对 rank 分辨率的破坏（被裁到同一边界的标的在秩相关里**并列**，
可用名次因此变少）。**这是读数，不进任何 verdict。**

### D6 fail-closed 预注册

新实验短名 `factor-ic`；`PREREG_FIELDS`（14 个键）与预注册 md 里那段 json 的键
**逐字一致**（比 `rank-ic` 多 `factors` / `secondary_factors` / `min_xsec_n`）。
命令行实参任一不符 ⇒ exit 2、**零输出**（没开库、没建产物目录）。
与 `rank-ic` 的一处有意差异：`universe` 在本站是**必填**（P83 只跑 `csi300-500`，
宇宙写进预注册才钉得住），而不是「缺席 ⇒ seed21」。

### D7 只跑 `short` ＋ 宇宙 `csi300-500` ＋ 同窗

`mid` 需 32.6 年、`long` 需 97.9 年才够 `MIN_VALID_PERIODS=120` 个验证周期 ——
别的池跑了也只有 `INCONCLUSIVE`。窗口 `--start ≥ 2015-01-01`（窗口即结论）。

### D8 只读与产物

连库走 `stocklab/cli/research.py::open_read_only`（`file:…?mode=ro`），
**不写任何表、不进 `ops close`、不进红线基线**。产物落 `reports/research/`，
文件名带宇宙 id：`<end>-factor-ic-<universe_id>.{json,md}`。
真库只读：一切跑都在 APFS 克隆副本（`cp -c data/stocklab.db /tmp/p83/copy.db`）上。

### D9 不做采纳

本站**只出读数与量尺**。改打分函数是**另一次**决定（新预注册、单变量）。

## 复用了什么、抽了什么

IC / 分层 / bootstrap / 前向收益 / 训练-验证切分**全部 import 复用**：

| 复用对象 | 来自 | 本站 |
|---|---|---|
| `spearman_ic` / `pearson_ic` / `assign_layers` / `layer_means` / `ascending_steps` | `research/signal.py`（公开名） | 直接 import |
| `ForwardPrices` / `ic_stats` / `tail_mean` | `research/signal.py` | **P83 只改名为公开名**（原 `_ForwardPrices` / `_ic_stats` / `_tail_mean`），无一行逻辑改动 |
| `MIN_VALID_PERIODS` / `_BOOTSTRAP_N` / `_BOOTSTRAP_SEED` / `_bootstrap_ci` / `overfit_flag` | `plugin/sandbox.py` | 直接 import（一个数字都没手抄） |
| `MIN_XSEC_N` / `N_LAYERS` / `IC_TYPE` / `ONLY_POOL` / `MIN_START` / `split_train_validate` / `REBALANCE_DAYS` | `research/signal.py`、`candidate/replay.py`、`config/replay.py` | 直接 import |
| `PreregError` | `research/xsec.py`（经 `signal.PreregError` 再继承） | 子类，CLI 不用加 except 分支 |
| `NON_PIT_ITEMS` / `NON_PIT_UNIVERSE_ITEMS` | `research/xsec.py` | 报告里并列披露 |

**为什么改 `signal.py` 而不是 import 私有名**：那三个名字在修改前是下划线私有，
跨模块依赖私有名会把它们变成事实上的公共契约。任务书 T2 明写「若需抽公共 helper，
抽完必须保证 `rank-ic` 的输出**逐位不变**」，所以按「只改名、不加壳」的最小改动做：
`git diff` 是纯改名（`_ForwardPrices` → `ForwardPrices` 等），`rank-ic` 的行为与读数
一条都没动，`tests/test_research_signal.py` 39 条全绿。

## 与 `rank-ic` 的并排引用（**只引用不重跑**）

## 后果

- **好处**：从此「改打分函数」有**因子级**归因 —— 三种互斥解释里是哪一种，一次
  读数就能分开；`rank-ic` 的合成分数读数与本站的因子级读数**同一套口径**（同窗、
  同宇宙、同判据常量、同前向收益），可直接并排读。
- **代价**：`score_pipeline` 多一个默认关闭的开关（`want_factors`）与一个只增字段；
  短窗自检 ≈几分钟、全窗 ≈2 h（与 `rank-ic` 同量级），全窗由 nanobot 后台跑。
- **失败的结论也合法**：全都不显著就写「这套输入在这段历史上没有可测的横截面
  信息」，方向转「换信号源」，**不**降门槛、不换窗口、不换宇宙（CLAUDE.md 度量纪律 6）。
- **`LOW_COVERAGE` 与 `INCONCLUSIVE` 的优先级**：两者同时成立时（例：截面过薄导致
  每天都被跳过 ⇒ 覆盖度也不足）本站取 `LOW_COVERAGE`（更具体：它说出了**为什么**
  没有有效日期）。此时 `INCONCLUSIVE` 的信息没有丢失 —— `n_dates` /`n_validate`
  仍是 0 与实测点估计，读者一眼能看出样本不足。
- **次读数一律 `verdict=None`**（"只报读数、不作判据"）：结论词汇表里没有「不判」
  这一档，所以**留空**而不是硬塞一个词。覆盖度不足时只填 `coverage_flag` 这个标记。
- **`n_dates_skipped` 在报告顶层是「逐因子」的字典**（两个主因子各自少算了多少天），
  不是一个标量 —— 两个因子的非空覆盖度不同，合成一个数会掩盖差异。
- **后续可选**：若某因子显著，下一步是**新预注册的单变量实验**（改合成方式或权重，
  一次只动一处），本站不替它做决定。
