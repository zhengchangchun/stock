# ADR-031 决策可成交性（一手契约进上下文、未成交腿留痕、随机臂可成交抽样）

- 日期：2026-09-26
- 状态：已接受
- 上游：`docs/tasks/2026-09-26-p79-决策可成交性收口.md`（D1–D8）、ADR-024（AI 操盘手的
  决策空间与护栏）、ADR-025（模块2 双通路与镜像口径）、ADR-023（模块2 绩效指标口径）、
  P65（资金闸门）／P66（随机臂现金底仓）／P68（存量持仓可部署性口径 v3）

## 背景

两个真实故障，同源：**全链路没有任何一处对「一手（100 股）够不够」负责。**

1. **AI 臂的买入腿全部落空**：2026-09-23 `arm-agent-ds-v1` 的决策要买 4 只，目标市值
   ¥2,807.86 / ¥3,126.81 / ¥3,310.74 / ¥3,837.09，**四笔全部**被 `plan_target_weight`
   判 `hold`（理由「差 < 1 手 → 不动」）⇒ 那天只成交卖出 1 笔（000333×100），
   09-24 该臂净值行 `cash 19553.68 / market_value 0.0` —— **AI 的意图（约 67% 仓位）
   与账户实际（0%）完全脱钩，而这件事在页面/台账上一个字都读不到。**
2. **随机对照臂连续两天零成交**：`arm-agent-random` 09-23 抽到 16.43% 敞口分 4 只
   （每只 ¥317 / ¥1,323 / ¥988 / ¥587，全 < 一手）、09-24 抽到 **0.17% 敞口 2 只**
   （¥19.59 / ¥13.71）⇒ 两天零成交、净值恒等于 `arm-hold`。D-36 的归因分母
   （`delta_vs_random`）**实际是空的**：「AI 跑赢随机」这句话没有可比的对手。

代码事实（不是猜测）：

- `rules.py`：`fill = costs.fill_price(side, price)`（**含滑点**）、
  `qty = floor_lot(abs(delta) / fill, lot)`，`qty <= 0` ⇒ `_hold(...)` 并写明
  「差 < 1 手 → 不动；目标未达成，如实上报」。**这是有意口径，本站不改。**
  实测 603868（目标 ¥3,126.81 vs 一手 ¥3,126.00）与 000651（¥3,837.09 vs ¥3,836.00）
  **在不含滑点价上刚好够、加上滑点就翻负** ⇒ 四笔全 `hold`。
- `engine.py`：`cash, positions, orders, _evals = agent_decide.execute_decision(...)`
  —— **`_evals` 被下划线丢弃**，`plan_orders` 早就算出来的「不动的理由」在 agent
  执行路径上不落库。
- `agent_context.build_decision_context`：喂给 AI 的上下文里**没有任何一手价 / 最小
  可成交权重**的信息 ⇒ 模型只能靠猜（09-24 的 ds-v2 猜对了，09-23 的 ds-v1 没猜对）。
- `agent_decide.random_payload`（v3）：`exposure = rng.uniform(0, cap)`、
  权重 = `exposure × rand/Σrand` —— 抽样完全不管整手。

## 备选方案

1. **在执行层加硬拒绝**（目标市值 < 一手即拒绝写入决策）—— 优点：一句话就把故障挡住；
   缺点：把「AI 的**意图**」与「执行的**可行性**」混成一条闸门，把可观测的意图一起杀掉；
   且价格一跳就会在边界上来回翻转。**否**。
2. **靠模型自己悟**（提示词里叮嘱「注意整手」）—— 缺点：一手成本跨标差 10 倍以上
   （601398 一手 ¥813 vs 600519 一手 ¥14 万+），2 万本金的账户上「目标权重 < 1.6%」
   就等于「不许买」；每次换模型/换提示词都要重踩一遍，且失败时无痕。**否**。
3. **输入侧给足 ＋ 执行侧留痕 ＋ 随机臂抽样可成交化**（选中）—— 不动任何既有算法
   （订单/结算/闸门/整手取整全一字不改），只加「知情」与「留痕」；随机臂把抽出的敞口
   映射到可成交的整手。

## 决策

### D1 不加硬拒绝

`paper agent decide` **不因**「目标市值 < 一手」拒绝写入。本站只做两件事：输入侧把眼睛
给足、执行侧把结果留痕。

### D2 输入侧 `tradability` 块（`agent_context._tradability_block`，纯函数）

`build_decision_context` 新增**顶层**键 `tradability`，形状锁定：

```json
{"lot": 100,
 "min_weight_pct": 2.3104,
 "by_code": {"601398": {"one_lot_cost": 813.41, "min_weight_pct": 4.1534}}}
```

- 一手成本的**唯一公式**落 `rules.one_lot_cost`（**复用** `CostModel.fill_price`
  与 `_fee_parts`，一行费用公式都不另写）；随机臂用**同一个**函数。
- `min_weight_pct = round(one_lot_cost / total_assets * 100, 4)`，`total_assets` 与
  `account.total_assets` 同源。
- 键集 = `marks ∩ pool`（**必须同时成立**的两个条件：`validate_payload` 要求
  `code ∈ pool` 且 `code ∈ marks`）。池外/无价标的不出现。
- `tradability` **进 `DECISION_HASHED_KEYS`**：它是 AI 看得见的输入，必须进指纹。
- ⚠️ **后果**：同一输入在 P79 前后 `decision_context_sha256` **不同**。台账里
  **已有的**决策行（`decision_id=2` / `4`）的 `context_sha256` **一个字符都不改写**
  （append-only）；D-49 的复核只对**新写入**的载荷生效。

### D3 执行侧留痕：新表 `paper_agent_evals`（append-only）

列 `eval_id, arm, asof, code, action, reason, constraints_json, raw, created_at`；
`UNIQUE(arm, asof, code)`；两个触发器（`UPDATE` / `DELETE` 一律 `RAISE(ABORT)`，形状
逐字抄 `paper_agent_decisions`）。落库点＝`engine._step_all` 的 agent 分支（原来的
`_evals`）：**只落决策驱动的那条路**，静态臂与 `arm-agent-v1`（m2 通路）的 `_evals`
仍不落库 —— 它们不是「AI 说了没做到」，混进来会把两种读数变成一种。
`decision.code is None`（全现金留痕）写**空串**（`UNIQUE` 里 NULL 互不相等，用 NULL
会让同一天重复落库）；写入口用 `INSERT OR IGNORE`（幂等、不覆盖、不产生隐式 DELETE，
故不会撞 append-only 触发器）。迁移 `migrate.migrate_p79_agent_evals`（幂等、可重入）。

### D4 随机臂口径 v4（可成交抽样）

在 v3 的抽取序列**之后**追加一步「可成交化」，**所有随机都走同一个 `rng`**
（逐字节可复现不许破）：

1. 先按 v3 抽 `k` 只、`exposure`、`raw` 权重（**这些数只用于筛选，不进载荷**）；
2. 每只算 `target = total_assets × w`，折算 `q_c = floor(target / one_lot_cost_c)`；
3. 令 `S = {c : q_c ≥ 1}`：若 `S ≠ ∅`，权重改按**整手数**归一
   （`w'_c = q_c / Σ_S q × exposure_eff`），并保证 `S` 里每只至少 1 手；
4. 若 `S = ∅` ⇒ **重抽**（`exposure` 重抽、其余不变），最多 `RANDOM_RETRY_MAX = 8` 次，
   用同一个 rng 序列继续；仍为 ∅ ⇒ 取「`one_lot_cost` 最小的池内标的」给 1 手
   （仅当 `现金 − 一手含费 ≥ 0`），否则全现金并在 `rationale` 里点名。
5. `rationale` 自述「口径 v4」＋抽出几只/取整后几只/是否触发重抽；v1/v2/v3 的行
   **一个字不改**（代号写进 `rationale` 就是为了这个）。

约束：`cap` 的算法**不改**（仍是 P68 的 `100 − RANDOM_CASH_FLOOR − reserved` ⇒ `reserved`
一律 = **全部**存量持仓占比），随机臂的**上界/现金底仓**语义不变 —— 本口径只把「抽出来的
敞口」映射到可成交的整手，修的是**下界**（P68 修的是上界，ERROR_DIARY #73/#77 同型）。

### D5 规则层零行为改动

`rules.plan_target_weight`、`plan_orders`、`agent_decide._settle`、`_gate_cash`、
`execute_decision` 的订单/结算算法**一字不改**（只允许把 `evaluations` 交出去并落库）。
`rules.py` 的唯一新增是 `one_lot_cost`（新函数，不改任何既有路径）。

### D6–D8 纪律

红线三目标**不 regen**、必须逐位 == 基线；一切写实测只在真库的 APFS 副本（`cp -c`）上
做；真库迁移与 rollout **由 nanobot 做**（备份 → 前滚 → doctor），站不写真库。

### 与任务书实现层面的偏离（理由优先，不静默绕过；逐条见任务书 §7.6）

1. **D2 的公式与 D2 的示例 JSON 互相矛盾**：公式含费、示例给了不含费的 `813.41`。
   照**公式**实现（更严：目标 ≥ 含费一手价 ⇒ 执行层必定成交 ≥ 1 手，因为
   `plan_target_weight` 判据用的是不含费的 `fill × lot`）。示例里的数字不当作判据。
2. **D4 的单遍归一不保证它自己声明的「`S` 里每只至少 1 手」**（反例：`q=(1,4)`、
   `rand` 占比 `(0.9, 0.1)`）⇒ 收敛到**不定点**（每轮剔除又掉下去的，直到 `S` 不变）。
   `S` 一轮就没变时，权重与 D4 公式**逐位相同**。
3. **退路加了一条优先序**：候选**优先取未持有的**（`held_qty == 0`）—— 已持有该票
   一手时目标与现市值之差 ≈ 滑点＋费（几元钱）⇒ 执行层判「差 < 1 手 → 不动」
   ⇒ 退路完全落空，而那正是本站要修的失效。池内全持有才退回「最便宜的」。
4. **`random_payload` 的 `asset_classes` / `cash` 是可选参数**：缺省按**股票费率**
   （买入口径下股票 ≥ ETF：股票有过户费、ETF 没有 ⇒ 一手成本只会被算**高** ⇒ 门槛
   更严、方向保守）；`cash=None` 时退路走「全现金并在 `rationale` 点名」。生产路径
   （`paper agent random`）**总是**传真值，口径走 `asset_classes_for`（`instruments.type`
   唯一真相、未登记即报错）。
5. **`tradability` 的键集取 `marks ∩ pool`**：任务书「只含当日有价的池内标的」与括注
   「与 `marks` 的键集一致」在「持有池外标的 / marks 里出现指数」时互相矛盾；取交集是
   唯一同时成立、且正好等于**决策空间**的读法。
6. **T4 的重放必须删当日成交，不只删净值行**：picks 的「现市值」由重放成交得出，
   只删净值行会让 sell 腿变成「0 与 0 相同 → 不动」。
7. **既有 v3 断言按 v4 更新**（口径变了就是「同一输入、新口径」）：三条 v3 读数
   （`cash_after 8077.37` / `601398 @44.55%` / picks 名单）**原样留档**在测试 docstring 里。

## 后果

- **好处**：① 「AI 的意图 vs 落地」第一次可审计 —— 未成交腿的理由（含「差 < 1 手」、
  目标市值、一手成本）落在 `paper_agent_evals`，不再只是页面上的「没动」；
  ② 输入侧有了 `one_lot_cost` / `min_weight_pct`，模型不必再猜「这只有多贵」；
  ③ 随机对照臂从 09-23/09-24 起各至少 1 笔成交，「AI 跑赢随机」这句话终于有分母。
- **代价 / 必须知道的事**：
  - `decision_context_sha256` 对**同一输入**在 P79 前后**不同**（`tradability` 进指纹）。
    这是有意的、也是必须通报的；**旧台账行不改写**，因此跨 P79 的两行 sha
    不可直接比较 —— 比较口径时必须同版本。
  - `paper_agent_evals` 是**新表**，老库前滚只能靠任一写库入口的 `ensure_schema`／
    显式前滚；触发器缺席的库「看着有这张表，实际可以改历史行」，由 `doctor` 的
    只读 marker `p79_agent_evals` 报告。
  - 随机臂 v4 的读数与 v1/v2/v3 **不可混引**（同一 `(arm, asof, seed)` 的载荷已不同）。
- **未做 / 不在本站范围**：`tradability` 怎么被 AI 用（决策生成器侧）是 nanobot 的事；
  一手契约**不**进 `validate_payload`（不加硬拒绝，D1）；`replay.py` 组合收益的未复权价
  口径仍是 ADR-030 记录的已知遗留。
