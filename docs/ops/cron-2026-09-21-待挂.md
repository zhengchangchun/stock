| — | 季度深度复盘 | 不挂 | 07 任务4 依赖模块1 季度重打分，未开工 |

**与老备份的差异（要你认可的一点）**：老备份是 4 条（巡检 2h + 盘中 tick + 收盘 tick + 收盘链）。
本建议把「盘中 tick / 收盘 tick」**并进 30 分钟巡检**（巡检第一步就是 `session tick`），
理由是 D-7 已经把 07 的「优先级排队」改成「自查 + 补跑」，再单独挂两条 tick 会在
同一时点重复采集（幂等无害，但白跑），并且 nanobot cron 与用户会话共用一条会话，
任务越多越容易互相排队。

## 2. 可直接执行的挂载命令（`cron add`）

> 一条一条执行即可；`tz` 一律 `Asia/Shanghai`。

### A. 收盘链（15:30）

- `cron_expr`: `30 15 * * 1-5`
- `name`: `stock-lab-收盘链(daily)`
- `message`:

```
【stock-lab 收盘链】按序执行，每步看退出码（不要起 claude 任务，数据链断了才在汇报里点名）：
cd ~/Documents/Workspace/stock
LATEST="$(.venv/bin/python -c "import sqlite3;print(sqlite3.connect('data/stocklab.db').execute('select max(date) from bars_daily').fetchone()[0])")"
0) 库备份（07 D-7 新增固定步；不依赖 sqlite3 CLI，走 stdlib）:
   .venv/bin/python -c "import sqlite3,pathlib,datetime as dt; d=pathlib.Path('data/backups'); d.mkdir(parents=True,exist_ok=True); t=d/f'stocklab-{dt.date.today()}.db'; sqlite3.connect('data/stocklab.db').backup(sqlite3.connect(t)); print('backup ->', t)"
1) .venv/bin/python -m stocklab.cli.main ingest bars --days 12000 2>&1 | tail -3
2) .venv/bin/python -m stocklab.cli.main session backfill-close --date "$LATEST" 2>&1 | tail -5
3) .venv/bin/python -m stocklab.cli.main predict run --asof "$LATEST" 2>&1 | tail -8
4) .venv/bin/python -m stocklab.cli.main review daily 2>&1 | tail -20
5) .venv/bin/python -m stocklab.cli.main paper step --asof "$LATEST" 2>&1 | tail -6   # 模拟盘（ADR-010）；退出 2 多为当日 bars 未入库（ADR-009 缓存冻结），排查后补跑，幂等
6) .venv/bin/python -m stocklab.cli.main doctor 2>&1 | tail -8

前置自查（D-7）：非交易日（日历 `is_open=0` 或日历为空）→ 直接跳过，只在汇报里写一行「非交易日跳过」。
汇报（≤6 行）：最新交易日 / 当日入库根数与快照行数 / 明日预测（各标的涨·平·跌概率 + 80% 区间）/
review 报告文件名 + LIVE 与 REPLAY 两组数字（LIVE=0 就写 0，**禁止**拿 REPLAY 的 38% 当实盘表现）/
amount 非 NULL 行数 / 模拟盘三臂净值（<120 交易日标注样本不足，只并列不挑推荐）/ 异常与阻塞。全正常压到 3 行。
```

### B. 30 分钟巡检（09:00–15:30，工作日）

- `cron_expr`: `*/30 9-15 * * 1-5`
- `name`: `stock-lab-巡检(30m)`
- `message`:

```
【stock-lab 轻量巡检】执行（不要起 claude 任务）：
cd ~/Documents/Workspace/stock

A) 当天链路体检（只读，先做）：
   .venv/bin/python -m stocklab.cli.main doctor 2>&1 | tail -8
   逐项确认：① 今日 bars 是否入库 ② 今日快照/盘中 tick 是否采到 ③ 明日预测是否已落库
   ④ 当日 review 报告是否存在 ⑤ 模拟盘净值是否已记（收盘后）

B) 缺哪步补哪步（严格按收盘链顺序，幂等，只补当天）：
   1) .venv/bin/python -m stocklab.cli.main session tick 2>&1 | tail -5
   2) .venv/bin/python -m stocklab.cli.main session backfill-close --date <最新交易日> 2>&1 | tail -5
   3) .venv/bin/python -m stocklab.cli.main predict run --asof <最新交易日> 2>&1 | tail -8
   4) .venv/bin/python -m stocklab.cli.main review daily 2>&1 | tail -20
   5) .venv/bin/python -m stocklab.cli.main paper step --asof <最新交易日> 2>&1 | tail -6
   15:30 那条收盘链已跑过的步骤不要重跑（幂等，但白跑）；非交易日全部跳过。

超时：单轮别超过 8 分钟；卡住就记一行并停（07 §调度约束 2）。
汇报：exit=0 且 anomalies=0 → **只回一行**（体检 5 项各自 ✅/缺步补了哪几步）；
exit≠0 或 anomalies>0 → 贴原始错误 + `system_events` 最新一条，明写「数据链异常」+ 是否需人工介入。
禁止复述代码。
```

## 3. 挂上之后的预期副作用（先知道再决定）

1. 任务会**写真实库**：快照、预测、模拟盘净值、`system_events`；行情类可重采，快照与回测结论
   **不可重建** ⇒ 所以 A 的第 0 步是库备份（`data/backups/`）。
2. `paper step` 需要**当日 bars 已入库**，否则退出 2（ADR-009 缓存冻结）—— 这是已知坑，不是异常。
3. cron 与你的会话**共用一条会话**：会话忙时任务停在 `queued`，所以巡检自带「补步」；
   这也意味着**不要**在任务里起 claude 子任务（老消息里的「不要起 claude 任务」就是为这个）。
4. 首次挂上后建议**手动各跑一次**（不要等时点）：A 用当天日期、B 用 `--no-capture` 试一下离线路径。
