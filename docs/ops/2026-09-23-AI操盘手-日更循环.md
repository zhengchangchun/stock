## 0. 一句话与那条硬理由

AI 臂（`params.executor = agent_decision`）的**日终不在 `paper step` 里**，
而在 `paper agent run --asof <交易日>`；顺序是**先 decide，后 run**。

> **为什么顺序是硬的（必须记住这一条）**：`paper step` 的幂等判据是
> 「**当日净值行存在**」。收盘链 15:30 先跑完 ⇒ 之后写进台账的决策**永远不会被执行**
> —— 因为那一天的净值行已经被写掉了，`run` 只会回你 `already`。
> 症状出现在**净值表**上（那条臂一路平盘），而排查方向很容易跑到订单生成上去
> （同 P47 `external_executor` 里记的那条坑）。所以 `paper step` 对这类账户
> **显式让出**（账户行里写着 `executor`，`paper show` 里照旧看得见它）。

## 1. 一天一次的循环（收盘后，建议 18:30 之后）

```bash
PY=.venv/bin/python

# ① 收盘链（15:30 由 nanobot 调度；这里只是说明它做了什么）
#    它跑 paper step —— AI 臂被让出，不受影响
$PY -m stocklab.cli.main ops close            # 或 nanobot 的定时任务

# ② 随机对照臂（**项目内**跑，种子固定 ⇒ 逐字节可复现）
$PY -m stocklab.cli.main paper agent random --asof <上一交易日> --arm arm-agent-random

# ③ PIT 输入：项目外的生成器**只从这里**取输入
$PY -m stocklab.cli.main paper agent context --asof <上一交易日> --arm arm-agent-ds-v1
#   → 把输出里的 context_sha256 原样抄进决策载荷

# ④ 写决策（项目外产出载荷；写入口只校验/落库，不产生决策）
$PY -m stocklab.cli.main paper agent decide --asof <上一交易日> \
      --file /path/to/decision.json --arm arm-agent-ds-v1 \
      --model-id deepseek/deepseek-v4-pro --prompt-sha256 <enroll 时的那个>

# ⑤ 落 AI 臂的日终（先有决策，再成交并写净值）
#    ⚠️ P69 起**显式点名**在飞的那几条臂 —— 不点名 = 认领全部 `executor=agent_decision`
#    的账户，其中停飞/占位的会被记成「缺决策」⇒ 退出码恒 1（P69 §1.4 的根因）。
$PY -m stocklab.cli.main paper agent run --asof <上一交易日> \
      --arm arm-agent-ds-v2 --arm arm-agent-random
```

**判据（每一步的退出码）**

| 命令 | 0 | 1 | 2 |
|---|---|---|---|
| `paper step` | 该写的都写了 | — | 输入/状态不合法（不落半截） |
| `paper agent random` | 已写入 / 已存在且一致 | 与既有那行**撞键**（append-only） | 载荷越界 |
| `paper agent context` | 打印上下文 | — | 臂不存在 / 未知 `executor` |
| `paper agent decide` | 已写入 / 已存在且一致 | 同 `(arm,asof)` 已有**不同**载荷 | 越界 / 预注册不符 / `context_sha256` 不符 |
| `paper agent run` | 该有的都有，或**非交易日** | **交易日缺决策**（异常；点名的臂里有一条没决策就 1） | **两种成因**：① 库的状态坏了（未知 `executor` / 无认领账户）；② **某个账户被资金闸门整轮拒**（stderr 带 `code=cash`）⇒ 该臂当天**没有净值行**（P65 / Q1-A 的设计，见 §3） |

**④⑤ 之间不要插别的写库动作**：`decide` 落的是台账（append-only，可重放），
`run` 落的是成交与净值；两者之间若有人手工写了别的成交，
`run` 会按**执行时**的总资产重算目标市值（`rebase_payload`），
`side` 与目标方向矛盾时**直接报错**并回滚 —— 这是设计，不是故障。

**两臂口径同源（P66 起）**：随机对照臂与 AI 臂的**敞口上界是同一条公式** ——
`cap = (100 − 10) − Σ weight_pct(不在本轮 picks 里的存量持仓)`，落点是
`paper/agent_decide.py::random_payload`（随机臂，`RANDOM_CASH_FLOOR`）
与 `m2/builtin/a1_pick.py` v1.0.3（AI 臂，`CASH_FLOOR`）。所以「同护栏、同成本」
这句形容词现在**对得上数**：两边的现金下限都是 10%，且两边都由同一个执行层闸门
（`agent_decide._gate_cash`）兜底。随机臂的 `rationale` 里写着
`口径 v2（P66）: reserved=…, cap=…`，读台账就能知道那一行是哪条口径。

## 2. 缺决策长什么样（三处，都不静默）

| 位置 | 形态 |
|---|---|
| `paper agent show --asof <日> --arm <臂>` | `missing_decision` 块：`is_trading_day` / `account_in_flight` / `expected` + `present`（+ `preregistered`） |
| `/lab/paper` 对照表 | AI 行写「**今日无决策**」；有决策时写「**今日有决策**」——**两种形态开头就不一样** |
| `paper agent run` 回执 | `anomaly.missing_decision`（逐账户点名）+ 交易日 ⇒ **退出码 1** |

- 「还没起跑」（`account_in_flight=False`）与「日历判不出」都**不是**缺决策，
  措辞分别是「不要求决策」与 `why=calendar_not_covered`。
- **不补造默认决策**：`run` 在无决策那天写一条**平盘**净值行（成交 0 笔），
  绝不自作主张按某条纪律下单 —— 那会把「没决定」显示成「决定按默认纪律办」。

## 3. 失败处置

| 症状 | 先看什么 | 处置 |
|---|---|---|
| `run` 退出码 1 | 回执的 `anomaly.missing_decision` | 生成器那天没产出 ⇒ 补产出？**注意**：若那天的净值行已经写过，补决策也没用（见 §0）——那天就如实记为「没决定」，别改台账 |
| `run` 退出码 2 且 stderr 带 `code=cash` | stderr 里的越界金额与那条臂的载荷（`paper agent show --arm <臂> --asof <日>`） | **这是设计，不要去改执行层闸门**（P65 / Q1-A：宁可空仓，不宁可透支）。该臂当天**没有净值行**——缺得可见。处置＝检查那条臂载荷的**目标敞口**：上游口径有洞就在**上游口径**上修（P66 就是这么修的随机臂：`cap = (100 − 10) − 不在 picks 里的存量持仓占比`）。**唯一已知的残余**：抽中的存量票目标市值不足一手（如 `000333` 一手 ≈ 总资产 42%）⇒ 整手卖不出 ⇒ 那部分现金不释放；修它要动**上游口径**（A1 与随机臂同型），同样不是改闸门 |
| `run` 退出码 2 且 stderr 报「未知 executor」/「没有认领账户」 | `params.executor` / `paper_accounts` | 见下一行（库状态那两种） |
| `run` 回执全是 `already` | 那天的净值行 | 已跑过。若那天本该有决策而你没有 ⇒ 那天按 §0 记为「缺决策」，**不重写历史** |
| `decide` 退出码 2「预注册不符」 | 你的 `--model-id/--prompt-sha256` vs `paper agent show` 的 `preregistered` | 对不上就**开新版本账户**（§4），不许改旧账户 |
| `decide` 退出码 2「上下文指纹不符」 | 载荷里的 `context_sha256` vs `paper agent context --asof 同一日` | 重新跑 ③ 取新指纹（池子/持仓在两次之间变过 ⇒ 旧载荷已过期，**重做决策**，不是改指纹） |
| `decide` 退出码 2「没有预注册」 | `paper agent show` 的 `preregistered: null` | 这条臂没声明是哪一版 ⇒ `enroll` 开新版本账户 |
| 报「未知 executor」 | `params.executor` 的值 | 既不是 `m2_channel_a` 也不是 `agent_decision` ⇒ 改回已知值；**别指望它被跳过**（fail-closed） |
| `ops patrol` ⑥ 报 stale（未知 executor） | `checks.paper_nav.unknown_executors` | 同上。**注意**：被认领账户缺净值行**不算**本项缺口（`note` 里写明「由决策循环认领」） |
| `run` 回执全是 `already` | 那天的净值行 | 已跑过。若那天本该有决策而你没有 ⇒ 那天按 §0 记为「缺决策」，**不重写历史** |

## 4. 预注册纪律（D-48）与换模型流程

**规则**：`paper agent decide` 只许写在**预注册过**的账户上；载荷里的
`--model-id / --prompt-sha256` 必须与账户行里那版**逐字段相同**，否则拒绝（exit 2、零写入）。

```bash
# 提示词指纹用**同一个算法**算（纯 stdlib，不碰库、不联网）
$PY -m stocklab.cli.main paper agent sha256 --file prompts/trader-v1.txt

# 开一个版本账户：模型/提示词指纹写进 params_json（**不存任何凭据**）
$PY -m stocklab.cli.main paper agent enroll --arm-name arm-agent-ds-v1 \
      --model-id deepseek/deepseek-v4-pro --prompt-sha256 <上一步的 sha256>
```

**换模型 / 换提示词 / 换通路 = 开新版本账户**（`arm-agent-ds-v2`…），
**旧账户保留不删、不重写台账**。这条纪律只挡一件事：**「换到好看为止」**。

- 账户名形状：`arm-agent-<版本>`（小写字母数字开头，只允许 `. _ -`，≤32 字符）。
  `arm-agent` / `arm-agent-random` 是内置账户名，`enroll` **拒收**。
- 内置 `arm-agent`（P52 建的默认臂）**没有预注册** ⇒ 它不能再接收 `llm` 决策；
  要接模型请开新版本账户。它仍然照常记净值（走 `paper agent run` 的平盘分支）。
- **P69 起多一个显式停飞位**：`params_json.live = false`（缺省 `true`）。停飞臂
  **不再被 `paper agent run` 认领**（不写平盘行、不进 `anomaly.missing_decision`）、
  `paper agent show` 与 `/lab/paper` 都标「**历史版本（已停飞）**」，且**不判它缺决策**。
  台账/净值/成交行**一行不动**（D-48：旧账户保留不删）。
  真库落位：`migrate_p69_agent_arms_live`（只点名 `arm-agent` 与 `arm-agent-ds-v1`；
  逐条点名、只加一个键、可重入）。**它不挂 `_apply_schema`**（挂上去等于让任一写库
  入口顺手停飞两条臂）—— 与 P62 同款，只登记 `_KNOWN_MARKERS` 供 doctor 只读报告。
  停飞哪几条或要不要放回来，改迁移里的 `_P69_HALTED_ARMS` 并**同时**改任务书。
- ⚠️ `arm-agent-` 前缀与**通路 A** 的账户相同 —— **不是冲突**：
  两者靠 `params.executor` 区分（通路 A = `m2_channel_a`，本站 = `agent_decision`）。
- 网关无快照 id ⇒ 模型漂移靠「**新版本账户 + 逐日 `system_fingerprint` 留痕**」兜：
  一旦网关改指向，开 `v2`，不改旧账户、不重写台账（旧账户＝旧口径的历史）。
- 台账/结论里标注「**经 commandcode 网关**」，`model_id` 记**原样字面量**
  （`deepseek/deepseek-v4-pro`），不替它改写成厂商官方型号串。

## 5. 边界（本站**不做**什么）

- 项目内**零 API key、零联网、零模型调用**：决策载荷在项目外产出，
  `enroll` 只存 `model_id` 字符串；凭据只在项目外读取。
- **不把 `paper agent run` 塞进 `CLOSE_STEPS`**（决策在项目外产出 ⇒ 链条里没有它可读的东西），
  也**不在 `ops patrol` 里补跑**它。
- 不改主干常量（成本口径 / PIT 判据 / 整手 / 护栏 / 熔断阈值）；不做参数搜索。
- 随机对照臂同日一条由**项目内**跑 —— 缺它，`delta_vs_random` 恒 `null`，
  AI 的读数一律「不可归因」（P52 的原文纪律）。
