## e. turnover 单位交叉验证 —— ⚠️ 结论：**同口径、量纲差 100，但精确倍数未确证**

### e-0 先说覆盖度限制（**必须先说**）

任务书要求「≥5 个交易日」。**实测只有 3 个交易日两侧同时有值（6 个观测）**，原因不是我少取：

- `bars_daily.turnover` 全库**只有 4 行非空**（000333 / 600690 × 2026-09-15、2026-09-16），
  其余 3095 / 7807 行全为 `NULL`；
- 因为腾讯**历史日 K 接口不返回换手率**（`web.ifzq.gtimg.cn` 的 `day` 数组只有
  `[date, open, close, high, low, volume]` 6 个字段，见 raw_cache 原文），
  只有 `session backfill-close` 走的**实时快照**（`qt.gtimg.cn` 字段 38）才带换手率。
- 本轮另从 raw_cache 里找到 **1 份 2026-09-14 收盘后（23:48:28）的离线快照**
  （`data/raw_cache/tencent/q_sz000333_sh600690.f1aad750fc26.json`），补出第 3 个交易日。

**3 个交易日是现有数据能支撑的上限**，不是抽样选择。要拉到 ≥5 天必须新增数据源/改白名单 —— 本轮不扩范围。

### e-2 独立口径反推（这才是判据，不靠比值猜）

光看比值无法区分「量纲不同」和「口径不同」（分母是流通股还是总股本）。所以另做**独立反推**：
用腾讯自己给的 `amount`(万元) + `close` + `float_mv`/`total_mv`，自算换手率，看腾讯字段 38 和
新浪值分别落在哪个分母上。

```
000333  2026-09-14  close=86.8  amount=1,572,360,000 元
  成交股数(≈amount/close)      = 18,114,747
  流通股(tencent float_mv/px)  = 6,885,403,226
  总股本(tencent total_mv/px)  = 7,629,343,318
  东财 valuation.total_shares  = 7,629,346,190  → 与 tencent total 偏差 0.0000%   ★
  → 换手率(分母=流通股) = 0.2631%      换手率(分母=总股本) = 0.2374%
  → 腾讯 field38 = 0.26      新浪/100 = 0.2628

600690  2026-09-14  close=21.12  amount=485,700,000 元
  成交股数(≈amount/close)      = 22,997,159
  流通股(tencent float_mv/px)  = 6,178,503,788
  总股本(tencent total_mv/px)  = 9,303,077,652
  东财 valuation.total_shares  = 9,303,088,164  → 与 tencent total 偏差 0.0001%   ★
  → 换手率(分母=流通股) = 0.3722%      换手率(分母=总股本) = 0.2472%
  → 腾讯 field38 = 0.37      新浪/100 = 0.3730
```

两条独立证据都指向**同一结论**：

- 以**流通股**为分母算出的换手率（0.2631% / 0.3722%）与腾讯 field38（0.26 / 0.37）
  和新浪/100（0.2628 / 0.3730）**同时吻合**；
- 以**总股本**为分母（0.2374% / 0.2472%）与两者都**明显不符**（差 8–10%，远超舍入）。
- 附带确证一条跨源一致性：腾讯 `total_mv/close` 与东财 `total_shares` 偏差 **0.0000% / 0.0001%**
  —— 两个源对**总股本**的口径完全一致。

### e-3 结论（明确写「确证 / 未确证 / 对不上」）

| 判断 | 状态 | 依据 |
|---|---|---|
| 两源 turnover **同口径**（都是「流通股换手率」，单位 %） | **确证** | e-2 独立反推，两源同时吻合流通股分母、同时不符总股本分母 |
| 量纲关系是「新浪 = 腾讯 × 100」 | **确证** | 比值序列全部落在 97–101；新浪 43.346 ↔ 腾讯 0.43 同量纲换算后一致 |
| 精确倍数 = 100.0000× | **未确证** | 实测 97.15–101.08。4/6 落在腾讯 2 位小数舍入范围内（±0.005 绝对值），**2/6 超出**（-2.85%、-1.27%），说明除舍入外还有约 1–3% 的残余差 |
| 残余 1–3% 的成因（两源「流通股」定义/取数时点不同？腾讯快照股本略旧？） | **判定不了** | 现有 3 天数据 + 单侧股本快照不足以归因。**不猜、不写「约等于 100」** |
| 两源数据「本身不可比」 | **否证** | e-2 已证明口径相同，可比；差的是量纲约定与源站精度 |

**因此：原计划 §2.1「差 100 倍」的表述要修正为** ——
「同口径（流通股换手率），新浪存的是百分数值 ×100；**换算倍数实测 97.15–101.08，不是精确 100**，
残余 1–3% 未归因」。字段注释按此更新（见本轮 commit）。


ETF 没有 PE/PB 概念，源站对该 secid 返回空集 → **不是抓取失败**（`failed=[]`、退出码 0）。
