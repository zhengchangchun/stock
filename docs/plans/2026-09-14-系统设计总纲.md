# stock-lab 系统设计总纲

> 状态：需求基线（由 nanobot 起草，Claude Code 负责细化与实现）
> 日期：2026-09-14
> 本文件是**需求与设计基线**，不是最终实现计划。实现计划由 `superpowers:writing-plans` 产出，写入 `docs/plans/`。

---

## 0. 一句话

建立一套 **A股"预测 → 验证 → 归因 → 自优化"闭环系统**：每天收盘后生成可证伪的预测，次日用真实行情验证打分、归因错误，用回测/模拟盘积累最大量的样本，并让策略基于样本外表现自动迭代。

**最终目的不是"猜对涨跌"，而是积累足够多的、干净的、可复现的模拟与验证数据，从而知道：哪些策略在什么市场状态下真的有效，以及什么时候不该下注。**

---

## 1. 目标 / 非目标

### 目标
1. 每晚 19:00 自动生成次日预测，**每条预测可证伪、可打分**。
2. 次日 19:30 自动验证：方向、区间、关键位、建议动作，四项分别打分并落库。
3. 每次预测保存**当日的特征快照**，使错误可归因（数据问题/信号问题/策略问题/市场噪声）。
4. 具备**回测引擎**：含交易成本、含基准对比、walk-forward，不是"曲线拟合器"。
5. 具备**模拟盘**（全自动纸面交易）与**实盘账本**（用户手工录入），二者持续对比。
6. 策略**自动晋级/降权/淘汰**，每次改动写入决策日志（可回滚）。
7. 定时提醒：只在关键位触发/预测失效/数据异常时提醒，不制造噪音。
8. 样本量最大化：从第一天就支持**多标的池 × 多策略**并行，而不是只盯一只股票。

### 非目标（明确不做）
- ❌ 不做自动下单、不接券商接口（纯粹的分析与模拟系统）。
- ❌ 不承诺收益、不输出"必涨/必跌"结论。
- ❌ 不做日内/高频（数据源只支持日线级别的可靠抓取）。
- ❌ 不用"黑箱深度学习"作为第一阶段方案（样本量根本不够，必然过拟合）。

## 2. 核心闭环

```
        ┌──────────────── 每日 19:00 ────────────────┐
        │ 1. 采集行情/资金/估值/板块 → 落库            │
        │ 2. 数据质量校验（缺口/异常/复权）→ 告警       │
        │ 3. 计算 point-in-time 特征 → 快照落库         │
        │ 4. 多策略生成信号 → 集成 → 次日预测 → 落库     │
        └────────────────────┬─────────────────────┘
                             │
                   （次日 15:00 收盘）
                             │
        ┌──────────────── 次日 19:30 ────────────────┐
        │ 5. 采集实际行情 → 对照预测 → 四项打分         │
        │ 6. 归因：数据/信号/策略/噪声 四分类           │
        │ 7. 更新策略滚动表现 → 权重自适应             │
        │ 8. 模拟盘按策略执行（含成本）→ 记 trade       │
        │ 9. 生成验证报告 + 异常告警                   │
        └────────────────────┬─────────────────────┘
                             │
        ┌──────────────── 每周日 20:00 ───────────────┐
        │ 10. 全量回测 + walk-forward 参数再优化        │
        │ 11. 策略晋级/降权/淘汰 → 写决策日志           │
        │ 12. 周报：样本量、胜率、盈亏比、回撤、纪律违规 │
        └────────────────────────────────────────────┘
```

## 3. 铁律（违反即视为 bug，不是"取舍"）

| # | 铁律 | 为什么 |
|---|------|--------|
| R1 | **预测必须可证伪**：方向(含概率) + 价格区间 + 关键位 + 建议动作 + **失效条件**，五项缺一不可；含糊表述不计分 | 否则"我觉得可能震荡"永远正确，永远无法改进 |
| R2 | **Point-in-time**：T 日预测只能使用 T 日 15:00 前（含收盘）已知的数据 | 未来函数是回测作弊的头号来源 |
| R3 | **复权规则固定**：前复权，且复权因子必须 point-in-time（禁用会随未来除权变化的最新因子） | 否则历史价格会被未来分红"改写" |
| R4 | **成本内建**：佣金双边 0.025%、印花税卖出 0.05%、过户费、滑点按成交额分档；**任何回测/模拟收益都必须扣成本** | 不扣成本的收益全是幻觉 |
| R5 | **必须有基准**：所有策略对比 `buy_and_hold` 与 `沪深300` | 跑不赢躺平就没有存在价值 |
| R6 | **样本量纪律**：单票单策略一年仅 ~250 样本 → 必须多标的 × 多策略并行；任何"策略上线"需满足最小样本量门槛（初始 ≥ 120 个样本外观测） | 3 天赚了钱不叫策略有效 |
| R7 | **自由度限制**：可调参数个数 ≤ 样本量的 1/10；禁止在同一数据上反复调参 | 防过拟合的数学底线 |
| R8 | **预测快照不可篡改**：predictions 与 features_daily 为 append-only，落库后不得 UPDATE | 否则事后改预测 = 自我欺骗 |
| R9 | **可复现**：同一日期 + 同一数据版本重跑必须得到完全相同结果（固定随机种子、数据版本号） | 不可复现 = 不可调试 |
| R10 | **失败必须留痕**：抓取失败/预测失败/验证失败一律写入 `data_quality` 或 `system_events` 并告警，**禁止静默跳过** | 静默失败会让统计结论全部失真 |
| R11 | **交易日历**：所有"次日"判断必须走交易日历（周末/节假日/停牌） | 周五的"次日"是下周一 |
| R12 | **变更留痕**：任何策略参数/权重/上下线变更必须写入 `decisions` 表：改了什么、依据、样本外结果、可否回滚 | 「同样的错不犯第二次」的落地形式 |
| R13 | **只读公网数据源**：仅使用公开行情接口域名；**禁止**访问内网地址、IP 直连、代理（运行环境有安全策略拦截） | 环境事实，绕不过去 |
| R14 | **合规**：任何推送都带"不构成投资建议"；系统输出是概率与风险，不是买卖指令 | 底线 |

## 4. 模块架构

```
stock-lab/
├── stocklab/
│   ├── config/         # 配置（标的池、成本模型、阈值、路径）
│   ├── calendar/       # 交易日历
│   ├── data/           # 采集器 + 多源容错 + 退避重试 + 本地缓存
│   ├── store/          # SQLite 访问层（schema、迁移、append-only 约束）
│   ├── quality/        # 数据质量校验（缺口/异常值/复权一致性/停牌）
│   ├── features/       # 特征工程（技术/资金/估值/板块/市场状态）
│   ├── strategies/     # 策略库（信号+仓位+风控，统一接口）
│   ├── predict/        # 集成 → 概率/区间/关键位/动作/失效条件
│   ├── verify/         # 打分 + 四类归因
│   ├── backtest/       # 事件驱动回测（成本/基准/walk-forward）
│   ├── simulate/       # 模拟盘（纸面交易、持仓、净值曲线）
│   ├── optimize/       # 参数搜索 + 策略权重自适应 + 晋级淘汰
│   ├── portfolio/      # 实盘账本（手工录入/导入）+ 模拟盘对比
│   ├── report/         # 日报/周报/月报 + 告警载荷
│   └── cli/            # 命令入口
├── data/               # SQLite 文件、缓存（.gitignore）
├── docs/               # 见模板既有结构
├── scripts/            # verify.sh、定时任务入口
└── tests/              # pytest
```

**关键接口约定（避免模块互相穿透）**
- 所有数据写入必须经 `store/`，禁止模块直接写 SQLite。
- 策略统一接口：`Strategy.fit(history) -> State`、`Strategy.signal(state, features) -> Signal(action, size, stop, reason)`。
- 预测器只消费 `features_daily`，不直接联网。
- 验证器只消费 `predictions` + `bars_daily`。

- 时区：Asia/Shanghai。A股交易时间 09:30–11:30 / 13:00–15:00。
- 项目目录：`/root/.nanobot/workspace/projects/stock-lab`。

### 已验证可用的公开数据源
| 用途 | 接口 | 备注 |
|------|------|------|
| 快照行情 | `https://qt.gtimg.cn/q=sz000333,sh600690,...` | **GBK 编码**，需转码；字段按 `~` 分割，索引：3=现价 4=昨收 5=今开 31=涨跌 32=涨跌% 33=最高 34=最低 36=成交量(手) 37=成交额(万) 38=换手% 39=PE(TTM) 44=流通市值(亿) 45=总市值(亿) 46=PB 30=时间戳 |
| 日K线 | `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sz000333,day,,,320,qfq` | 返回 `data.<code>.qfqday`，每行 `[日期,开,收,最高,最低,成交量]`，含分红除权信息 |
| 指数/板块/个股列表 | `https://push2.eastmoney.com/api/qt/clist/get?...&fs=m:90+t:2`（行业）/`m:90+t:3`（概念） | **限流敏感**，需退避重试 |
| 海外指数 | `https://push2.eastmoney.com/api/qt/stock/get?secid=100.DJIA` | 指数代码 100.DJIA / 100.NDX / 100.SPX / 100.HSI / 100.N225 |
| 日K/历史 | `https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=0.000333&klt=101&fqt=1` | 需 `Referer: https://quote.eastmoney.com/` |
| 资金流 | `https://push2.eastmoney.com/api/qt/stock/fflow/kline/get?secid=0.000333&klt=101` | 字段 `f51..f56` = 日期/主力净额/小单/中单/大单/超大单（主力=大单+超大单，已校验自洽） |

### 已知坑（必须内建容错）
1. **东财限流**：连续快速请求会返回空响应（实测触发）。→ 必须实现：指数退避重试、请求间隔、多域名轮询、本地缓存、失败降级到腾讯源。
2. **腾讯返回 GBK**，直接按 UTF-8 解析会乱码。
3. **禁止内网/IP/代理**：`1.push2.eastmoney.com` 这类数字子域会被运行环境安全策略判定为疑似内网而拦截。只用主域名。
4. **`secid` 前缀**：`1.` = 沪市，`0.` = 深市；港股/美股/指数用 `100.`。
5. **数据落库前必须校验**：`high>=max(open,close)>=min(open,close)>=low`、成交量非负、日期递增、无重复。

## 6. 数据库 Schema（SQLite 草案）

```
instruments       标的池（code, name, market, type, sector, active, added_at）
bars_daily        日线（code, date, open, high, low, close, volume, amount,
                          turnover, adj_factor, source, fetched_at）  PK(code,date)
money_flow_daily  资金流（code, date, main_net, small_net, mid_net, big_net, xl_net）
valuation_daily   估值快照（code, date, pe_ttm, pb, total_mv, div_yield, pe_pct_3y）
sector_daily      板块（sector_code, name, date, pct_chg, main_net, rank）
market_state      市场状态（date, index_code, close, ma_state, vol_state,
                            breadth_up, breadth_down, regime_label）
features_daily    特征快照（code, date, feature_version, json_payload,
                            payload_hash, created_at）  ── append-only
predictions       预测（pred_id, code, asof_date, target_date, direction,
                          prob_up, prob_flat, prob_down, lo, hi, key_levels_json,
                          action, size_pct, invalidate_if, strategy_mix_json,
                          feature_snapshot_id, model_version, created_at）── append-only
verifications     验证（pred_id, target_date, actual_close, actual_pct,
                          hit_direction, hit_range, hit_levels, sim_pnl,
                          score_direction, score_range, score_level, score_action,
                          total_score, attribution, notes, created_at）
strategy_registry 策略（strategy_id, version, params_json, status, stage,
                        added_at, promoted_at, retired_at, retire_reason）
strategy_daily    策略日表现（strategy_id, date, signal, sim_return, benchmark_return, n_obs）
sim_portfolio     模拟盘（date, cash, positions_json, nav, drawdown）
sim_trades        模拟成交（trade_id, date, code, side, price, qty, fee, strategy_id, reason）
real_portfolio    实盘账本（date, code, qty, cost_price, note）  ── 手工/导入
real_trades       实盘成交（同上结构）
decisions         系统决策日志（dec_id, date, scope, change, evidence, oos_result, rollback_plan）
data_quality      数据质量（date, source, code, issue_type, detail, resolved）
system_events     运行事件（ts, module, level, message, context_json）
```

**约束**
- `features_daily` / `predictions` / `verifications` / `sim_trades` / `decisions` 通过触发器或代码层**禁止 UPDATE/DELETE**。
- 所有时间戳统一 ISO8601 带时区。

## 7. 策略库（初始候选，统一接口）

| strategy_id | 逻辑 | 适用市场状态 | 核心参数 |
|---|---|---|---|
| `buy_and_hold` | 基准：首日买入持有 | 全 | — |
| `index_300` | 基准：沪深300 | 全 | — |
| `dividend_hold` | 低估值+高股息（PE 分位低 + 股息率 > 4%）长期持有 | 震荡/熊市 | pe_pct_max, div_yield_min |
| `trend_ma` | MA20 上穿 MA60 买入，下穿卖出，ATR 止损 | 趋势 | fast, slow, atr_mult |
| `breakout` | 放量突破 N 日高点买入，跌回突破位卖出 | 趋势启动 | lookback, vol_ratio |
| `range_grid` | 识别箱体（ADX 低 + 区间收敛），下沿买上沿卖 | 震荡 | box_lookback, band |
| `pullback` | 上升趋势中回踩 MA20/MA60 且缩量，买入 | 趋势回调 | ma_ref, shrink_ratio |

**集成方式（初版）**：按市场状态（`regime_label`）切换策略子集 + 按各策略近期样本外表现做指数加权，得到方向概率与仓位建议。**不要一上来就上机器学习**。

## 8. 预测与评分规范

### 8.1 预测载荷（每晚 19:00 落库 + 可选推送）
```json
{
  "code": "000333",
  "asof_date": "2026-09-14",
  "target_date": "2026-09-15",
  "direction": {"up": 0.42, "flat": 0.31, "down": 0.27},
  "range_80": [85.2, 88.4],
  "key_levels": [{"price": 87.40, "role": "resistance", "p_touch": 0.45},
                 {"price": 85.00, "role": "support",    "p_touch": 0.40}],
  "action": "hold",            // hold | trim | add | exit | wait
  "size_pct": 50,
  "invalidate_if": "收盘跌破 85.00 或放量突破 88.50",
  "strategy_mix": {"trend_ma": 0.4, "range_grid": 0.35, "dividend_hold": 0.25},
  "model_version": "v0.1.0"
}
```

### 8.2 验证评分（次日 19:30）
| 维度 | 判定 | 分值 |
|------|------|------|
| 方向 | 三分类（±0.5% 为 flat）+ 使用 Brier score 校验概率校准 | 0–1 |
| 区间 | 实际收盘是否落入 `range_80`（命中率长期应 ≈ 80%，偏离即校准问题） | 0–1 |
| 关键位 | 预测"会触及"的位是否触及 / "不会触及"的是否真的没触及 | 0–1 |
| 动作 | 按 `action` 执行的模拟收益（扣成本）相对基准的超额 | 0–1 |
| **总分** | 四项加权（默认 0.3/0.2/0.2/0.3，权重本身也是可优化参数） | 0–1 |

**滚动统计**：20 / 60 / 120 日窗口的命中率、Brier、区间覆盖率、超额收益。**任何结论必须标注窗口与样本量。**

## 9. 归因规范（四分类）

每次错误必须归到以下之一，并写入 `verifications.attribution`：

| 类别 | 判据 | 后续动作 |
|------|------|----------|
| `DATA` | 数据缺口/异常/复权错误 | 修数据管道，补校验 |
| `SIGNAL` | 特征里没有覆盖到当时的关键信息 | 加特征（如板块联动、隔夜外盘） |
| `STRATEGY` | 用错了策略（市场状态判断错） | 调 regime 判定 / 策略权重 |
| `MODEL` | 过拟合（样本内好样本外差） | 简化参数、增大正则 |
| `NOISE` | 真的不可预测 | **如实记录**，用于回答"什么时候不该下注" |

> `NOISE` 是合法结论，且是系统长期最有价值的产出之一。**不允许为了好看的胜率把 NOISE 硬归成 SIGNAL。**

## 10. 优化与防过拟合

1. **Walk-forward**：滚动窗口（如训练 250 日 → 测试 60 日 → 前移 60 日）。禁止全样本调参。
2. **三段切分**：Train / Validate / Test，Test 集只在"晋级评审"时用一次。
3. **参数变更需记录**：写 `decisions`，含样本外结果与回滚方案。
4. **策略权重自适应**：按 20/60 日样本外超额收益做指数加权（半衰期可配）。
5. **淘汰规则**：连续 3 周（或 ≥60 样本）跑输基准 → 降权 50%；连续 6 周 → 下线，`retired_at` 记录原因。
6. **禁止寻优频率过高**：参数再优化每周最多一次，防止追逐噪声。
7. **随机种子固定**，任何随机过程可复现。

## 11. 模拟盘 vs 实盘对比

- **模拟盘**：每个策略独立虚拟账户（初始 100 万），按信号全自动成交（含成本/滑点/涨跌停不可成交约束）。
- **实盘账本**：用户手工录入（当前：000333 持仓占 50%，成本 86.80，剩余 50% 现金）。
- **对比维度**：
  - 同一标的、同一时段，模拟盘净值 vs 实盘净值
  - 差异归因：**执行差异**（T+1/滑点）、**情绪差异**（不按纪律加减仓）、**策略差异**（策略本身无效）
  - 输出"纪律违规清单"：实盘是否违反了系统给出的 `invalidate_if`
- **注意**：实盘账本是**只读镜像**，系统不产生任何自动交易指令。
