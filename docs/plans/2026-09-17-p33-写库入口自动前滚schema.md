# P33 —— 让所有「写库入口」自动前滚 schema（根因修复）

日期：2026-09-17
任务：P33
状态：执行中

## 背景（nanobot 实测，真数据）

P32 给 `predictions` 加了 `origin` 列，迁移 `migrate_p32_predictions_origin` 只经 `db init` 前滚。
但真实库 `data/stocklab.db` 当时**并没有**前滚（`PRAGMA table_info(predictions)` 查不到 origin）。
后果：`insert_prediction` 的 `_INSERT_SQL` 已含 `origin` → 未迁移库上写预测撞
`sqlite3.OperationalError: table predictions has no column named origin` → 15:30 收盘链
`predict run` 失败 = 当天预测永久缺失，而巡检/测试全绿看不出。

**根因**：前滚只发生在 `db init`、`_cmd_ingest_series`、`features build`、`quality/redline`；
收盘链其余写入口（`ingest bars` / `predict run` / `verify *` / `review daily` / `paper step` /
`session tick` / `session backfill-close` / lab 应用）都不调用。

## 目标与范围

1. **单一入口** `stocklab/store/migrate.py::ensure_schema(db_path)` = 「幂等前滚 + 真失败要炸」。
   写库入口全部接到它；已直接调 `init_db` 的入口改成调同一入口（不两套并存）。
2. `doctor` 增加 schema 状态输出：逐个已知迁移 marker 在位与否，缺失显式告警。
3. 新测试钉住真场景：未迁移库上跑写入口不炸（先红后绿）+ doctor 能报缺失列。
4. 文档：ERROR_DIARY + TODO 收口 + ADR-015。

## 设计决策

- `ensure_schema` 与 `init_db` **并存但分工**：`init_db` 每次显式调用都先备份（语义＝「人工要动库，
  留退路」，给 `db init` 用）；`ensure_schema` 是写前自动守护，**只在确有结构变更时备份一次**、
  没有变更零写零备份（否则每次 `predict run` 都产一份备份文件）。
- `ensure_schema` 返回变更列表；`migrate_p28` 遇到「老 shape 且有数据」仍抛 `RuntimeError`
  （append-only 不可静默丢数据）—— 这正是「真失败要炸」。
- `doctor` 是**只读**入口：只报告 schema marker 状态，**不擅自迁移**（写库入口才迁移）。
- 接入范围：`cmd_ingest_bars` / `cmd_ingest_actions` / `cmd_ingest_index` /
  `_cmd_ingest_series`（改接）/ `cmd_predict_run` / `cmd_verify_run` / `cmd_verify_backfill` /
  `cmd_verify_pending` / `cmd_review_daily` / `cmd_session_tick` / `cmd_session_backfill_close` /
  `cmd_features_build`（改接）/ `cmd_paper_init`+`cmd_paper_step`（经 `_paper_conn`）/
  `cmd_lab_serve`（lab 应用写入口）。
  - 背景里 nanobot 写「`_cmd_ingest_series`（index/valuation/moneyflow）」——实测 `ingest index`
    是**独立的** `cmd_ingest_index`，并不调 `init_db`，故本轮一并接上（同一根因的漏网之鱼）；
    `ingest actions` 同理。
  - **本轮不接**（超出收盘链、非本事故路径，留待后续统一）：P12 手工账本 `trade add/reverse`、
    `cash add`、`adj rebuild`、`calendar holidays fetch`。理由见 ADR-015 §边界。

## 硬约束

- 不回填历史行（老行 `origin` 保持 NULL）、不删改任何历史数据、不加滚动清理。
- 不改 `MODEL_VERSION`、不改任何预测数字；`scripts/check_redlines.py` 三目标逐位不变，禁 `--regen`。
- `docs/experiments/`、`docs/portfolio/` 只读。

## 验证方式

- 清 `__pycache__` 后 `.venv/bin/python -m pytest`（不加 -q）全绿且只增不减（基线 1599）。
- `bash scripts/verify.sh` → all ✅ + 红线三目标全绿。
- 实证两条命令：接线前在「缺 origin 列的副本库」上跑写入口 → `OperationalError`；
  接线后同一副本 → 自动前滚并成功写入（副本 `count(*)` 不变、老行 NULL 不变）。
- `git status --short` 为空。
