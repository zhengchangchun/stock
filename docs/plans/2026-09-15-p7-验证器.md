# P7 上半：验证器（次日评分）+ 四类归因 + 首个真实准确率数字（历史回放）

> **For agentic workers:** REQUIRED SUB-SKILL: 用 `superpowers:executing-plans` 逐任务执行。
> 步骤用 `- [ ]` 勾选跟踪。计划文件不是圣经：断言与实现冲突时，先跑，再改断言并留痕
> （ERROR_DIARY 已踩 5 次）。

**Goal:** 让每个预测在次日被**实际复权 OHLC** 打分并落库（append-only），
再用 PIT 逐日回放在全历史上量出**第一个真实准确率数字**，难看也原样上报。

**Architecture:** 新增 `stocklab/verify/`（`score` 纯函数 / `store` 落库 / `service` 取数组装 /
`report` 聚合），CLI 加 `verify run --target-date` 与 `verify backfill --from --to`。
评分**只读**库（`predictions` + `bars_daily` + `adj_factors`），不碰任何联网路径。
报告由库里的 `verifications` 行**反算**，因此「重复跑 → 同内容 → 同 sha256」。

**Spec:** `docs/plans/2026-09-14-系统设计总纲.md` §8.2（评分口径）+ §9（四类归因）；
前置 `docs/plans/2026-09-15-p6-预测器.md`（载荷契约）。

## 口径决策（写在代码 docstring 里，逐条可查）

| 项 | 口径 | 理由 |
|----|------|------|
| 实际收益 | `adj_close(target)/adj_close(asof) - 1`，复权锚定 `as_of=target_date` | 比值与锚点无关；`<= target_date` 是硬上限（PIT，无未来信息） |
| 方向分类 | `> +0.5%` up / `< -0.5%` down / 其余 flat；`FLAT_BAND` **从 `predict.model` 导入** | §8.2 规定 ±0.5%；单一真源，杜绝两处写死 |
| 预测分类 | `direction` 三概率 `argmax`，平手优先级 `flat > up > down` | 与模型 `action` 的平手判据同序（`p_flat >= p_up and p_flat >= p_down`） |
| `score_direction` | `1 - Brier/2`（Brier 为三分类，值域 0–2） | §8.2 要求 0–1 且要 Brier；该映射**可逆**，Brier 可从库反算 |
| `score_range` | 收盘落入 `[lo, hi]` 为 1，否则 0 | §8.2 原文「实际**收盘**是否落入」 |
| `score_level` | 逐位「会触及 ⇔ 真触及」兑现比例的均值；`hit_levels` = 全部兑现 | §8.2 原文；阈值 `p_touch >= 0.5` 记为「会触及」（决策边界，非拟合参数） |
| 触及判据 | resistance: `high_t >= price`；support: `low_t <= price`（复权 OHLC） | 位是「盘中能否够到」，故用 high/low，不是 close |
| `score_action` | `sim_ret > bh_ret` 为 1，否则 0；原始超额单独上报 | **参数无关**。不引入「2% 半宽」这类凭空标尺（与 `model.py` 同纪律） |
| 动作模拟 | 目标仓位 `w = size_pct/100`，`asof` 收盘买、`target` 收盘卖，整手 100 股，本金 100 万，`CostModel` 双边扣费 | 与 §11「模拟盘」同口径；本金常量只影响 5 元最低佣金，已声明 |
| 基准 | ① `buy_and_hold` 同日（**同成本、同进出**）② `index_300` 同日（**无成本**，指数不可交易） | ERROR_DIARY：跑赢必须同时给两个基准结论 |
| `invalidated` | 从 `invalidate_if` **原文**正则取「跌破 X / 站上 Y」，`close < X or close > Y`；解析失败 → `None` + UNDETERMINED | 契约是那句话本身；解析失败不猜 |
| `attribution_auto` | 不可评分 → `DATA`；可评分 → `UNDETERMINED`（`SIGNAL/STRATEGY/MODEL/NOISE` 一律不自动判） | §9 + 本任务硬约束：硬判 = 造假归因 |
| 幂等 | 同 `pred_id` 已有 verification：**内容全等** → `identical`（不写）；已可评分却不同 → `VerificationConflict`（退出码 1，**不覆盖**）；曾不可评分、现在数据到了 → `rescored_after_data_gap`（ADR-002 允许改结果列；**打印 ⚠️**，不静默） | append-only 纪律 + 日循环必须能在数据到达后补分 |

## 文件结构

| 文件 | 职责 |
|------|------|
| `stocklab/verify/__init__.py` | 空包 |
| `stocklab/verify/score.py` | **纯函数**：`(pred_payload, bars, config) -> payload`，无 IO 无时间 |
| `stocklab/verify/store.py` | `verifications` 落库：四态 + 内容 hash + 显式冲突 |
| `stocklab/verify/service.py` | PIT 取数（raw 存在性/停牌/复权可用性）→ 打分 → 归因 → 落库；`PitCache` 供批量回放 |
| `stocklab/verify/report.py` | 从 verification 行聚合：方向准确率 / Brier / 覆盖率 / 关键位 / 超额 / 按日聚类 / 基准对照 → markdown |
| `stocklab/verify/replay.py` | `verify backfill`：逐日 `predict` + 次日打分，落库，出报告 |
| `stocklab/cli/main.py` | 加 `verify run` / `verify backfill` 子命令 |
| `stocklab/store/schema.sql` | 加 `CREATE UNIQUE INDEX IF NOT EXISTS ux_verifications_pred ON verifications(pred_id)`（结构性第二道防线） |
| `stocklab/predict/service.py` | 加**可选** `cache=PitCache`（默认 None，行为不变），供回放复用因子链/日历 |

### Task 32: 打分口径（纯函数 + 单测）

**Files:** Create `stocklab/verify/__init__.py`, `stocklab/verify/score.py`;
Test `tests/test_verify_score.py`

**Interfaces:**
- `SCORABLE_FIELDS: tuple[str, ...]`（hash 覆盖的列）
- `class Unscorable(Exception)`: `.reason_code` ∈ `{NO_BAR_TARGET, NO_BAR_ASOF, SUSPENDED, NOT_ADJUSTABLE}`
- `benchmark_return(bars, asof, target, costs, capital) -> float`
- `score_prediction(pred: Mapping, *, bars: Sequence[Bar], raw_bars: Sequence[Bar], costs: CostModel, capital: float = 1_000_000.0) -> dict`

`pred` 是 `store.payload_from_row(row)` 的形状（含 `pred_id`）。
`bars` 是**复权**序列（`as_of=target_date`），`raw_bars` 是**不复权**序列
（只用于判「有没有这根 bar / 是否停牌」）。
返回 dict 含 `scorable` / `reason_code` / `reason` 与全部 `SCORABLE_FIELDS`。
