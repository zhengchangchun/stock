## 1. 目标（用户验收标准）

浏览器打开一个地址，就能：
1. **一眼看清**：总资产 / 现金 / 持仓市值 / 累计收益（含费与不含费）、持仓明细（成本、现价、来源与时间、
   市值、浮动盈亏、占比）、净值曲线（按日 mark-to-market，inline SVG）、纪律逐条 PASS/WARN/FAIL；
2. **管理真实持仓**：录入成交（买/卖/费用/备注）、**冲正**错单、录入本金/出入金 —— 全在页面上点，不用敲命令；
3. 每次写入后**立刻看到新状态**（持仓、现金、纪律、风险）与「写了什么」的回执；
4. 看到风险与仓位：凯利结论（含 **NO_BET 与理由**）、波动率目标、VaR95/CVaR95、破产风险、四路止损位；
5. 看到数据可信度：bars/快照最新时间、近日验证统计（LIVE 与 REPLAY **分开**、样本门槛标注）、
   最近异常事件（来自 `system_events`）。
6. 手机上也能看（响应式，最小可用）。

## 2. 技术形态（写死）

- **零新增依赖**：仅 stdlib（`http.server.ThreadingHTTPServer` + 手写路由 + 服务端渲染 HTML + 内嵌 CSS +
  inline SVG）。无 CDN、无外部字体、无 JS 框架；少量内联原生 JS 只用于「确认弹窗 / 自动刷新」这类锦上添花。
- **只绑回环**：`serve --host 127.0.0.1 --port 8791`；`--host` 非回环值 → **直接报错退出**（单测钉住）。
  对外一律经 nginx（`:80` → `127.0.0.1:8791`），**禁止**监听 `0.0.0.0`。
- **子路径部署**：`--base-path /lab`（默认 `/lab`）。所有链接、表单 action、静态路径都必须带该前缀；
  提供测试（正则扫生成的 HTML：不得出现不带前缀的 `href="/..."`）。
- **中文界面**，颜色语义 PASS 绿 / WARN 黄 / FAIL 红 / 未知灰（未知必须显示为未知，不许猜）。

## 3. 路由（本任务的范围，不多不少）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/lab/` | 总览：资产卡片 + 持仓表 + 净值曲线 + 纪律面板 + 风险摘要 + 趋势状态 + 数据新鲜度 |
| GET | `/lab/trades` | 成交流水（含冲正标记）+ 新增成交表单 |
| GET | `/lab/trades/<id>` | 单笔详情 + 冲正表单（note 必填） |
| GET | `/lab/cash` | 现金流列表 + 新增表单 |
| GET | `/lab/risk` | 凯利完整口径（p/b/CI/p_be/f*/分数/上限 + 约束逐条 binding）+ 波动目标 + VaR/CVaR + 破产风险 + 止损位 |
| GET | `/lab/data` | bars/快照/日历最新 + 验证统计（LIVE/REPLAY 分离 + 门槛）+ `system_events` 最近 20 条 |
| GET | `/lab/health` | JSON 健康检查（含 DB 路径、asof、服务版本） |
| POST | `/lab/trades` | 新增成交 → 校验/幂等/append-only 写入 → 303 重定向回列表 + 回执 |
| POST | `/lab/trades/<id>/reverse` | 冲正 → 追加反向记录（**不改原行**）→ 303 + 回执 |
| POST | `/lab/cash` | 新增现金流 → 303 + 回执 |

- **校验**：完全复用 P12 的校验矩阵（`qty` 买入必须 100 股整数倍、卖出允许零股残量、`price>0`、`fee>=0`、
  `code` 必须在 `instruments`、`date` 在 `trading_calendar` 内且不晚于最近已收盘交易日、卖出不得超过当时持仓）。
  失败时**回显具体原因**（哪一条没过），不写库、不吞错。
- **幂等**：完全相同的 5 元组（date/code/side/price/qty）重复提交 → 不直接写，返回「疑似重复」页面，
  需显式勾选「确认这是另一笔真实成交」才写入（沿用 P12 的机制与文案）。
- **写操作安全**：每个表单带一次性 `_token` = HMAC(服务端密钥, 会话 id + 日期)，服务端校验；
  缺失/错误 → 403 且**不写库**（防 CSRF：basic auth 下跨站表单会自动带上凭据，这层必须有）。
- **POST/Redirect/GET**：写成功后 303，避免刷新重复提交。

## 4. 安全边界

- 应用本身只监听回环；**对外由 nginx 反代 + HTTP Basic Auth**（nanobot 负责配置 `.htpasswd`）。
- 服务端**不记录**口令/凭据到日志；`/lab/health` 不泄露密钥。
- 账本写入仍受既有 append-only 触发器保护（禁 UPDATE/DELETE 已有测试，保持）。
