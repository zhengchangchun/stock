`script_id=6 / v1.0.0 / active` 的**桩**（返回 `{"analysis_result": {"status":
"not_implemented"}, "bad_case_list": []}`），而全仓库没有任何一条命令会去调它。

本轮把它接上：**一条真调用路径**（`candidate review --asof <日>`）＋ 一版**真算**的

### 1.1 包名：`plugin_review` 而不是 `review`

任务书写的是「`stocklab/review/`（新包）**或等价落点**」。这里取 `plugin_review`，
理由是本任务的红线之一就是「**别跟 session review 撞名**」（任务书 §1.6）：
一个叫 `stocklab/review/` 的包会与 `review daily`（session 复盘）在同一套命名空间里
并排出现，而两者的报告落点已经被明令分开（`reports/<asof>-review.md` vs
`reports/plugin-review/<asof>.md`）。包名与报告目录名一致，命名的歧义就不必靠记忆消除。

### 1.2 数据流

```
candidate review --asof D
  └─ ensure_schema(db)                       # 幂等前滚（新表由 schema.sql 建）
  └─ service.run_review(conn, asof=D, now=…)
       ├─ ① lifecycle.active_script_id(conn, "5", required=True)   ← 没有 ⇒ NoActivePlugin
       ├─ ② inputs.build_ctx(conn, asof=D)                         ← 全部只读、全部 <= D
       │     ├─ 历史快照：candidate_snapshots ∩ asof<=D，成员 candidate_members
       │     │   ⇒ samples[{code, pool, adj_score, asof, ret_pct, n_days}]
       │     ├─ 回测台账：plugin_backtests（**只读已落库读数，不重跑回放**）
       │     └─ 模块2 回流：`stocklab/m2/cases.py::miss_cases`（唯一口径，见 §3）
       ├─ ③ lifecycle.call_active(conn, "5", ctx)                  ← guard + 超时 + validate_return
       ├─ ④ 报告渲染 → reports/plugin-review/<D>.md
       └─ ⑤ 台账落库 plugin_reviews（幂等键 (asof, script_id)，append-only）
```

`candidate run` 的 12 步主干与 `CLOSE_STEPS` **一个字不动**。

## 2. 关键口径（任务书 §1 的落地形态）

### 2.1 active 缺席显式化

- 只认 `plugin/lifecycle.py::active_script_id(conn, "5", required=True)`；
- 抛 `NoActivePlugin` ⇒ **exit 2**、stderr 点名「插桩5 没有 active 版本」、
  **零写入**（无台账行、无报告文件）；
- 现役桩 ⇒ **exit 0**：台账照记（`analysis_result` 原样落库），报告**第 1 行**写
  「复盘脚本尚未实现（script_id=… / … 桩），本报告只有输入侧事实」。

### 2.2 退出码（任务书只定了 0 与 2，1 由本设计定）

| 码 | 含义 |
|---|---|
| 0 | 跑完（含桩） |
| 2 | **结构性拒绝**：无 active 版本 / 库不存在 / asof 不是 YYYY-MM-DD ⇒ 零写入 |
| 1 | active 版本在，但脚本**执行失败**（guard 预检 / 超时 / 契约校验不过）⇒ 不落台账、不写报告 |

`1` 的口径取自本仓库既有语义（`runner`：1 = 「跑完了但如实报了异常」不算断链；2 =
结构性失败）。脚本自身报错是「有版本、跑不了」，与「没有版本」不是同一句话，
所以两者分开。**这一条任务书未写死，由本设计定**（实施记录里点名）。

### 2.3 因子胜率的定义（写死，并写进报告抬头）

- 样本 = 历史快照里的候选，带 `(pool, adj_score, asof)`；
- 前视窗口 **N = 5 个交易日**（`inputs.FORWARD_DAYS`，**常量**，改它要改代码）；
- 方向判据：`ret_pct > 0` 记命中（0 与负都算未命中，不给 0 冒充）；
- 只用 `<= asof` 的数据：窗口必须**在 asof 当天或之前走完**，否则该样本**不进样本集**
  （不像「按已有数据算半个窗口」——那是把未来读成现在）；
- 前视收益走 `stocklab/data/adjust.py::load_bars_adjusted`（ADR-004 复权链、ADR-008
  ETF 拒绝服务）——**不拿不复权价冒充复权价**；算不出来的标的按 `na_reasons` 逐条计数剔除；
- 样本不足 ⇒ `None` ＋ `na_reasons`（**不许给 0.0 冒充「胜率 0%」**，照 `m2` 既有做法）。

分桶：按池别（short/mid/long）与 `adj_score` 五分桶（`[0,20) … [80,100]`）各出一份胜率。

### 2.4 台账与迁移

```sql
CREATE TABLE IF NOT EXISTS plugin_reviews (
    review_id      INTEGER PRIMARY KEY AUTOINCREMENT,
    asof           TEXT NOT NULL,
    plugin_id      TEXT NOT NULL,
    script_id      INTEGER NOT NULL,
    script_version TEXT NOT NULL,
    source_sha256  TEXT NOT NULL,
    status         TEXT NOT NULL CHECK (status IN ('ok','not_implemented')),
    analysis_json  TEXT NOT NULL,
    bad_case_json  TEXT NOT NULL,
    inputs_json    TEXT NOT NULL,
    report_path    TEXT NOT NULL,
    report_sha256  TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    UNIQUE (asof, script_id)              -- 幂等键
);
```

- 触发器 `trg_plugin_reviews_no_update` / `trg_plugin_reviews_no_delete`（照既有同族表
  的写法，`RAISE(ABORT, 'plugin_reviews is append-only')`）；
- 幂等：`INSERT … ON CONFLICT(asof, script_id) DO NOTHING`（**不用 `INSERT OR REPLACE`**
  —— 它走隐式 DELETE，是 P6 那个坑）；
- 迁移：新表由 `schema.sql` 的 `CREATE TABLE IF NOT EXISTS` 建出 ⇒ **对老库是空动作**；
  `_KNOWN_MARKERS` 登记 `p58_plugin_reviews`（doctor 只读报告）；
  `_pending_column_migrations` 只在「表已存在但缺 append-only 触发器」时报 pending
  （真正的结构漂移），表不存在时**不报** —— 与既有约定一致（表不存在 ⇒ executescript
  会按新 shape 建出，无需迁移、无需备份）。

### 2.5 报告落点（红线）

`reports/plugin-review/<asof>.md`，**绝不** `reports/<asof>-review.md`。
`ops patrol` ⑤ 的判据（`patrol.check_chain`：`rdir / f"{latest}-review.md"`）**一行不改**，
并加测试钉住：新目录里有文件时 patrol ⑤ 仍是 `missing`。

### 2.6 月度链的非阻断

`MONTHLY_STEPS` 追加一步 `candidate_review ("candidate","review","--asof","{asof}")`。

「非阻断」的落地：`Step` 加一个**默认 True** 的 `blocking` 字段，`run_steps` 对
`blocking=False` 的步骤**不因非 0 退出码中止整链**；`worst_code` **不把它的退出码
计入链的退出码**（异常仍逐条记在 `steps` 与回执摘要里，不静默）。

为什么这样落地：`MONTHLY_STEPS` 里并没有现成的「非阻断步骤」语义可照抄
（任务书 §1.1 ③ 说的「照该元组里非阻断步骤的既有语义写」，实测该元组 5 步全是阻断步）。
最小改动 = 给 `Step` 加一个默认 `True` 的字段：既有 5 步的行为**逐字节不变**
（`run_steps`/`worst_code` 只在 `blocking=False` 时走新分支），巡检与收盘链不受影响。
**需要拍板**：这条是本设计自定的最严落地（失败可见、但不拖红、也不中止后续步骤）。

`run_monthly` 的 `run_steps(...)` 调用补上 `asof=`（原本没传）——既有 5 步的 argv 里
没有 `{asof}` 占位符，传与不传对它们**逐字节相同**。

## 3. 模块2 回流：抽一份，不复制第二份

`stocklab/labweb/m2_data.py::miss_cases` 是错判案例集的**唯一**取数（P48 §2：没有筛选参数）。
它挂在 web 层（该模块 `import m2_charts` 等页面依赖），命令行不该反向依赖页面层。

做法：把 `miss_cases` 与它的三个常量（`CASE_LIMIT` / `ATTR_FIELD` / `ATTRIBUTION_NOTE`）
**原样搬到** `stocklab/m2/cases.py`，`labweb/m2_data.py` 改为从那里 import（页面侧
的公开名字一个不少，`_cycle_cases` / `case_summary` / `review_backlog` 继续调同一个函数）。
口径仍只有一份，页面与复盘读的是同一段代码。

## 4. v1.1.0 源文本（`stocklab/candidate/builtin/review.py`）

形状照 `stocklab/candidate/builtin/`（`SOURCE: str`），纯函数、不 import、不 IO、
不取时间、不用随机。真算：

1. **因子胜率**：按池别与 `adj_score` 五分桶聚合 `ctx["samples"]`，样本不足
   （`MIN_SAMPLES = 5`，**写死在源码里，不许可配置**）⇒ `None` + `na_reasons`；
2. **回测指标读数**：从 `ctx["backtests"]`（已落库的台账条目）聚合——按池别数
   `WIN/LOSE/INCONCLUSIVE`、算胜率、数 `overfit_flag='suspected'`、给窗口跨度；
3. **`bad_case_list`**：来自 `ctx["bad_cases"]`（模块2 回流摘要里的案例）。

`ctx` 的读法一律 `.get(...)` ＋ 缺省分支：`contract.PROBE_CTX` **不覆盖**本插桩的 ctx 键
（而 `plugin/contract.py` 是反目标里禁止改的四个闸门文件之一），所以脚本必须在
「键全缺」时也能跑完并交出合规结果 —— 那时全部字段落进 `na_reasons`。
