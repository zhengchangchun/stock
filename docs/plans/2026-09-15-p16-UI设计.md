# P16 · 前端 UI 设计计划（对账单，不是仪表盘）

- **日期**：2026-09-15
- **技能**：`frontend-design`（plugin `frontend-design@claude-plugins-official`）
- **状态**：设计定稿 → 待实现
- **上游**：`docs/plans/2026-09-15-p15-持仓管理Web应用.md`（功能与路由定稿，本任务**不改口径**）

## 0. 先定主体（技能要求：设计从题材里长出来，不是套模板）

| 问题 | 答案 |
|---|---|
| 产品 | 个人 A 股**持仓与纪律台账**（stock-lab） |
| 受众 | 机主本人：技术型投资者，**看数字比看形容词快** |
| 题材/vernacular | 券商**对账单**（statement）—— 细线分栏、表头band、数字右对齐、合计行、来源脚注 |
| 首要工作 | ① 一眼看出哪里出格 → ② 几秒录入/冲正 → ③ 相信每个数字 |

对账单的视觉语言是**已经存在的**、且完全贴合三个主任务：它天生就是给「核对」用的。
所以本设计不发明新隐喻，而是把一个真实对账单的规矩（线、栏、脚注）执行到底。

## 1. 色板（6 个命名值 + 4 个语义值）

| token | 值 | 角色 |
|---|---|---|
| `--ground` | `#EDF0F3` | 页面底。**冷灰**，不是米色/奶油色 |
| `--paper` | `#FFFFFF` | 纸面：表格、表头 band、表单 |
| `--ink` | `#12181F` | 正文与数字（近黑，微冷） |
| `--ink2` | `#5A6672` | 次要：栏标签、来源、asof 时间戳 |
| `--rule` | `#D9DFE6` | 细线（行分隔、栏分隔） |
| `--accent` | `#123E6B` | 墨蓝：链接、主按钮、净值线 |
| `--ok` | `#0F6B3B` | PASS / 盈利 |
| `--warn` | `#8A5A00` | WARN / 偏离 |
| `--fail` | `#A81C1C` | FAIL / 亏损 / 已冲正 |
| `--unknown` | `#5A6672` | 未判定（**斜体**，与 PASS/WARN/FAIL 视觉上不同类） |

**色只为纪律与盈亏服务**：页面上所有饱和色都出现在状态与盈亏上，没有一处装饰性用色。
没有渐变、没有阴影、没有插画。`--fail` 允许被用作**实底块**（纪律条上出格的那一格），
这是全页唯一的高对比元素 —— 把「醒目额度」只花在「出格」这一件事上。

## 2. 字体与角色

- **一个家族**（本地系统栈，无 CDN、无外链字体）：
  `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`
- **不引入等宽家族**。台账数字的对齐靠 `font-variant-numeric: tabular-nums` 完成 ——
  换等宽会同时把中文拉到回退字体上，得不偿失，而且是「小数据标签用等宽」的 AI 默认脸之一。
- 字阶：`28` CANONICAL 大数字 / `16` 区块标题 / `14` 正文 / `13.5` 表格正文 /
  `12.5` 栏标签与表头 / `11.5` 来源与时间戳脚注。
- 字重：`400` 正文，`600` 表头与强调数字，`700` 只给 CANONICAL 那一行。
- 行高：正文 `1.5`，表格 `1.35`（密度来自行高，不来自缩字号）。

## 3. 布局

**概念（一句话）**：左侧一条固定导航轨（`--ground` 上，无底色块），右侧一张**纸**；
纸上没有卡片，只有**线**——一条横向的通栏表头带（CANONICAL 数字）、一条纪律条、
持仓表、净值曲线，每一块由 `1px` 细线分隔，像一张打印出来的对账单。

```
≥1200px                                    ≤768px
┌──────────┬──────────────────────────┐    ┌──────────────────────┐
│ stock-lab│ 总资产   现金   持仓市值  │    │ stock-lab  asof ...  │
│ 台账 09-14│ 19,858.42 10,102.12 ...  │    ├──────────────────────┤
│          │ 累计收益(含费) -141.58    │    │ 总资产 19,858.42     │
│ 总览   ▏  ├──────────────────────────┤    │ 现金   10,102.12     │
│ 成交流水  │ 纪律 ┃单票上限┃43.53% ▲   │    │ …                    │
│ 现金流    │      ┃ 43.53% 超 40% 上限 │    ├──────────────────────┤
│ 风险      ├──────────────────────────┤    │ 纪律（逐条换行）      │
│ 数据      │ 持仓  代码 数量 均价 现价 │    ├──────────────────────┤
│ 健康      │      000333 100 86.85 …  │    │ 持仓表（横向可滑）    │
│          ├──────────────────────────┤    ├──────────────────────┤
│          │ 净值曲线（inline SVG）    │    │ 净值曲线              │
└──────────┴──────────────────────────┘    └──────────────────────┘
```

- 对齐：**一律左对齐**，只有**数字列右对齐**（对账单唯一的对齐规则）。
- 内容最大宽 `1100px`，靠左（不居中）——居中会让右侧留白吃掉表格宽度。
- 首屏顺序（写死）：CANONICAL 一行数字 → 纪律条 → 持仓表 → 净值曲线。

## 4. 设计原则

1. **数字优先于形容词**：每个数字旁边就是它的来源与时间（`--ink2` 11.5px）。
   没有「较昨日+3.2%」这类需要二次解释的话。
2. **一张纸，不是一堵卡片墙**：全站只有一个圆角 token（`4px`），只用在输入控件与按钮上；
   内容区块没有圆角、没有边框、没有阴影，只有线。
3. **色只为纪律与盈亏**：见色板。
4. **零装饰**：没有眉标、没有 01/02/03、没有入场动画、没有 emoji、没有 `→` 尾巴。
5. **未知是斜体的**：`未判定` / `未知` 用斜体 + 灰，在形态上就与「通过」不同类 ——
   避免「灰色 = 中性 = 没事」的误读。

## 5. 对照技能里的「AI 默认脸」清单自检

| # | 默认脸 | 本设计 | 处置 |
|---|---|---|---|
| 1 | 奶油底 `#F4F1EA` + 高对比衬线 + 陶土色 `#D97757` | 冷灰 `#EDF0F3` + 无衬线 + 墨蓝 `#123E6B` | **避开** |
| 2 | 近黑底 + 单一荧光绿/朱红 | 浅底，四态语义色各自成体系 | **避开** |
| 3 | 报纸式细线 + 零圆角 + 密集分栏 | 保留细线与密度 | **有意保留**（见下） |
| 4 | SaaS 卡片墙：统一圆角 + 同一团灰阴影 + 渐变 | 无卡片、无阴影、无渐变 | **避开** |
| 5 | 模板 chrome：全大写小眉标 / `A · B · C` 中点串 / `→` 尾巴 / 小数据用等宽 | 中文句式标签，无眉标，无中点串，去掉 `→`，不用等宽 | **避开** |

**第 3 条为什么保留**：设计简报**明写**「气质：台账/对账单的密度与克制，不是 SaaS 营销页。
细线分隔、紧凑而清晰的行高」。技能里「简报自身的话永远优先」。
但因为第 3 条被保留，其余自由度**必须**花在别处 —— 见下面自检后的两处修改。

### 自检后的两处修改（技能要求：说明改了什么、为什么）

**改动一：CANONICAL 数字从「卡片墙」改成「通栏表头带」。**
第一稿把 4 个大数字做成 `flex` 平铺的圆角卡片。这正是默认脸 #4。
改成一整条横向 band：每个数字「标签在上、数字在下」，数字之间用**竖细线**分隔，
像对账单的栏目头；含费/不含费两个口径**同格上下并列**（`含费 -141.58 / 不含费 -136.49`），
而不是分成两张卡。
*为什么*：简报的首要任务是「一眼看出哪里出格」。四张等权卡片把「总资产」和「累计收益」
拉到同一视觉重量，眼睛要逐个跳读；换成一条 band 后数字等距、可横向比较，
且**纪律条紧贴在它下面**，出格项成为首屏的第二个视觉落点。

**改动二：导航从「胶囊按钮」改成「左轨 + 2px 活动标记」。**
原实现是 `border-radius:14px` 的胶囊按钮组（SaaS 味），改为左侧固定轨上的一列文字 +
当前项左侧一条 `2px` 墨蓝竖线。
*为什么*：胶囊按钮把导航做成了「四个平等的可选项」，而这里导航是**一条固定的目录**，
对账单的目录不会长成按钮。同时左侧竖轨给了页面一个稳定的锚，让右侧那张纸看起来是「一张纸」。

**去掉的一处**：净值曲线图例/坐标轴原本还打算加一层网格线 + 面积填充渐变。
砍掉，只留折线 + 本金虚线参考线。
*为什么*：Chanel 那句「出门前摘掉一件配饰」。曲线的活是「比本金线高还是低」，
渐变面积和网格都不帮这个忙。

## 6. 动效政策（技能要求：非用户触发的动效要克制）

- **页面加载零动画**。没有 fade-and-slide 入场，没有逐区块 reveal。
- 只有**一处**动效，且是**响应人的动作**的：写入成功后的回执条有一次
  `background` 高亮回落（`240ms`），说明「刚才这件事发生了」。
- 按钮 pending 态（`提交中…` + 禁用）也是状态反馈，不是装饰。
- `prefers-reduced-motion: reduce` 下所有 `transition`/`animation` 归零，回执直接静态呈现。

## 7. 交互设计（简报第 2、3 条任务）

| 场景 | 设计 |
|---|---|
| 录入成交 | 表单在流水**上方**；字段错误**内联**在字段正下方（`--fail` 12px），不再只给一条横幅 |
| 提交 | 按钮进 `提交中…` 禁用态；成功后 `fetch` 局部替换回执条与流水表 —— **不整页刷新、不闪白** |
| 冲正 | `<dialog>` 原生确认框（Esc 关闭、焦点锁定）；无 `dialog` 支持时回退 `confirm()` |
| 键盘 | Tab 顺序 = 视觉顺序；Enter 提交（原生表单）；Esc 关确认框 |
| 表格 | 行 hover 有 `--ground` 底；被冲正行整行降饱和并在「状态」栏写明 |
| 无 JS | 所有交互**降级可用**：fetch 失败自动退回原生表单提交（P15 的 303 路径原样保留） |

## 8. 技术约束（写死，与简报一致）

- **资产本地化**：`stocklab/labweb/static/app.css`、`app.js`，提交进仓库，
  由应用自身的静态路由 `/lab/static/app.css`、`/lab/static/app.js` 提供。
  **零外部 URL、零外链字体、零图表库、零图标库、零 JS 框架。** 图标一律自绘内联 SVG。
- **性能预算**：CSS ≤ 25KB、JS ≤ 20KB（未压缩）；首屏 ≤ 3 个请求（HTML + CSS + JS）；无阻塞第三方。
- 曲线、进度条、占比条一律 inline SVG 或纯 CSS 手绘。
- 响应式：≥1200 桌面（左轨 + 内容 ≤1100px）；≤768 单列，表格 `overflow-x:auto` 横向滑动。

### 8.1 一处**必须**说明的既有测试调整（诚实记录）

P15 的 `test_html_has_no_external_references` 断言里有一条 `assert "<link" not in text`。
该断言的本意是「不许有 CDN / 外链字体」，但 `<link>` 这个**标签**本身不是外部引用 ——
自托管的 `<link rel="stylesheet" href="/lab/static/app.css">` 同样会被它拦下。

本任务把这条断言**改成按 URL 判定**（更强，不是更弱）：

- 原：`"<link" not in text`（标签级，误伤自托管样式表）
- 新：扫出所有 `href`/`src`，**每一个都必须是 base-path 前缀的站内相对路径**；
  同时 `http://` / `https://` / 协议相对 `//` 一律禁止。

改动在 `tests/test_labweb_app.py`，新增的断言同时覆盖 P15 原本覆盖的情况
（任何外链 URL 仍然被拦），并额外覆盖了「标签白名单式」断言漏掉的情况
（例如 `<link href="//evil.example/x.css">` 这种协议相对外链，旧断言只查 `http://` 与 `https://`，
根本查不出来）。**这是加强，不是放宽**，理由与差异写进 `docs/errors/ERROR_DIARY.md`。

## 10. 非目标（明确不做）

- 不改任何口径、不加新路由（只加静态资源路由）、不动写路径语义。
- 不做深色模式（多一套色板 = 多一套对比度证据，本任务预算内不划算；列为已知缺陷）。
- 不做图表交互（hover 读值、缩放）——首屏曲线的活是「相对本金线的位置」。
- 不做前端构建链（无 bundler、无 npm）。
