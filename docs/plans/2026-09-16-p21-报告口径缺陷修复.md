| # | 现象 | 根因 | 位置 |

| D1 | JSON `counts.test_rows` = **7**，md §4 写 test 段样本行 **1962** | 写的是 `len(splits["test"])` —— test 段**指标字典的键数**（M1/M2… 共 7 个），同层 `train_rows`/`validate_rows`/`rows_used` 都是「行数」语义 | `stocklab/trend/evaluate.py` counts 段 |

## 修复方案（一次只改一个变量，逐条闭环提交）

### T1 `counts.test_rows` 改为「test 段样本行数」

- 语义对齐：`test_rows = splits["test"]["n_rows"] if test_evaluated else 0`。
- 测试：`counts["test_rows"] == splits["test"]["n_rows"]`、`!= 7`；封存（未评估）时为 0。

### T2 判据 (a)/(b) 理由文字由 CI 实际值生成

- 新增 `_criterion_reason(seg, key)`：与 `criteria_of` 共用 `_side_holds` 判据函数
  （同源 → 结构上不可能与 verdict 分叉），文字里的下界值取 `delta_ci95[0]` 原值。
- `judge` 把两条文字放进 `verdict["criteria_reasons"]`；`render_markdown` §3 直接打印，
  **删掉硬编码的「均 > 0」**。
- 三种尾巴：均 > 0 → 「故 (a) 成立」；有侧算不出 CI → 「有侧算不出 CI，故 (a) 不成立」；
  其余 → 「两侧 CI 下界并未均 > 0，故 (a) 不成立」。
- 测试：文字里出现的下界值 = 报告里的 CI 下界值；`a=False` 时文字**不得**含「故 (a) 成立」。

### T3 §6 两套行集说明由代码算出

- `_selfcheck` 增参 `n_outside_axis`，产出 `row_sets`（本报告全样本 / 预注册 §4.1 /
  差值 / 不得互引），差值与来源行数**全部由代码算**，不手写常量。
- 口径：本报告全样本 = 按预注册 §3 交易日轴裁剪后的行（= `counts.rows_used`）；
  §4.1 = 未按日历裁剪的全量 bar 行；两者 **不得互引**。

### T4 重新生成报告

- `stocklab trend evaluate --report reports/2026-09-16-trend-state-hit-rate.md`。
- 逐位对比：除 `counts.test_rows` / `verdict.criteria_reasons` / `selfcheck.row_sets` /
  `report_sha256` 外，其余数字**必须逐位不变**（用脚本 diff 证明）。
- 结论不变：`verdict.status = WIN`、`criteria a=False b=True`。
