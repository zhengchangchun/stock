## 2. 取数（`stocklab/labweb/paper_data.py`）

`track(conn, asof)` 的每一块都指得回来源，且**不重算**：

| 数 | 来源 | 关键约束 |
|---|---|---|
| 净值 / 累计收益 / 最大回撤 / 累计成本 / 相对大盘超额 | `paper.engine.build_report` | 与 `paper show` **同源**，页面上不可能出现第二套数 |
| 逐日累计收益序列 | `paper_nav_daily.cum_return` **列** | 读库，不重算 |
| 起跑日锚点 | `paper_accounts.initial_nav ÷ params_json.initial_capital` | 两列都在库里，不是补数 |
| 大盘序列 | `bars_daily` 的 `sh000300`（`adj_mode='none'`） | 基期一律取 `start_date`，与 `return_since_start` **同一个基** |

缺值一律 `None`：折线在那里**断开**，不插值、不用前一日收盘滚动填充、不用 0 顶替
（`n_missing` 计数并写在页面上）。

`asof` 一律 `date <= asof` 取 `MAX`，**不取全表 MAX** —— 那会让历史 `--asof` 截图显示未来某天的净值
（`data._paper` 同一条纪律）。

## 5. 顺带修掉的真缺陷（ERROR_DIARY #49）

**现象**：在真库上跑「下一个交易日」的 `paper step`：

```
STEP FAILED: IntegrityError CHECK constraint failed: qty > 0
```

`step` 是一个事务 ⇒ 当天五个账户**一条净值都没落**，且**每天**都会重现。

**根因**：`rules.plan_stop_loss(qty=0)` 在「收盘跌破止损线」时**无条件**返回
`action="sell", qty=0`（规则说「整清」，没问「手里还有没有货」），而
`Decision.is_trade` 只判方向 ⇒ 「卖 0 股」通过了下游每一道守卫，一直撞到
`paper_trades` 的 `CHECK (qty > 0)`。触发路径很平常：**昨天已按这条线整清，今天收盘仍在线下**。
`plan_trim`（`sell <= 0` → hold）与 `plan_etf_buy`（`qty <= 0` → hold）**都有这道守卫**，
只有止损漏了 —— 守卫写在三个平级的规则函数里，就成了三份要各自维护的真相。

**修法**（三层，每层各有测试）：

1. 规则层：`plan_stop_loss` 在「跌破但持仓 0 股」时回 `hold`（理由写明「不是忘了卖」），
   判定仍出现在 `evaluate`/报告里；
2. 不变量层：`Decision.is_trade` 加上 `qty > 0` ——「只有方向没有股数的成交」不是成交；
3. 写入层：`insert_trade` 直接校验 `action` 与 `qty`，报**点名规则层**的 `ValueError`
   （不再让 sqlite 的 `CHECK` 兜底，那个错误信息会把人引到 schema 上）。

**验证**：逐条回退实验 —— 只回退规则层守卫 ⇒ `test_stop_loss_with_no_position_is_a_hold_…` 红；
两层都回退 ⇒ 跨天回归测试红，且报的是可读的 `ValueError` 而不是 `IntegrityError`。
