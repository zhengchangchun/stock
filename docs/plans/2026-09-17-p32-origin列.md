# P32 —— 给 `predictions` 增 `origin` 列：回放/实时分段从「推断」变「断言」

## 目标

1. `predictions` 增 `origin TEXT CHECK(origin IN ('live','replay'))` 列（append-only 兼容、PIT 安全），入库时就确定这条预测是「回放」还是「实时」。
2. `chain accuracy` 改为：`origin` 非 NULL 的行按字段**断言**分段；`origin IS NULL` 的历史行退回现有 `created_at[:10] == asof_date` 推断；报告里**显式分列**「断言 n 行 / 推断 n 行」。
3. 让 N3 的「实时段」可信可累积（样本够了才叫准确率结论）。

## 写入口判据（逐个决定）

| 入口 | origin | 判据 |
|------|--------|------|
| `cli/main.py::cmd_predict_run` | `live` | 生产每日预测路径（`predict run`），asof=最新会话，当日收盘后出次日预测 |
| `verify/replay.py::backfill` | `replay` | PIT 历史回放（`verify backfill`），一次补几年，刻意不是实盘 |

两者都走 `predict.store.insert_prediction`，故给它加必填关键字参数 `origin`（不设默认值，杜绝静默漏标）。

## 迁移（append-only 安全）

- schema.sql：`CREATE TABLE IF NOT EXISTS predictions` 追加 `origin TEXT CHECK (origin IN ('live','replay'))`（放在 `created_at` 之后，与 `ALTER TABLE ADD COLUMN` 追加到尾部的顺序一致）。
- migrate.py：新增 `migrate_p32_predictions_origin(conn)`，用 `PRAGMA table_info` 判列是否存在，不存在则 `ALTER TABLE predictions ADD COLUMN origin TEXT CHECK (origin IN ('live','replay'))`；在 `init_db` 里调用（P28 迁移之后）。
- **不许回填**：`ALTER ADD COLUMN` 天然让老行 `origin` 为 NULL。NULL 通过 CHECK（`NULL IN (...)` → NULL 非 FALSE），且 NULL 语义 = 「无来源标记，退回推断」，不冒充事实。

## 报告改造（只动 chain，不动 P11 review）

- `session/review.py::load_rows`：SELECT 多取 `p.origin AS p_origin`，输出 dict 加 `"origin"` 键；`provenance` 仍 = `classify()`（推断）**不改**，保证 P11 复盘与 `rolling_accuracy` 逐字节不变。
- `chain/accuracy.py::build_chain_accuracy`：
  - 有效口径 `origin if origin in ('live','replay') else classify()`；
  - 报告新增 `origin_segmentation: {rule, asserted, inferred}`（断言 n 行 / 退回推断 n 行）；
  - `_written_by_origin` 同口径化（写入口计数也按断言优先）；
  - 更新 `ORIGIN_FIELDS` / `ORIGIN_LIMITS` 文案（不再写「这是推断而非断言」）。
- 渲染：markdown §0 加「断言 n 行 / 推断 n 行」。

## 硬性约束

- 老行 origin 一律 NULL，绝不回填成 live/replay。
- 回放段数字（0.3818 ± 0.0070 / Brier 0.6581 / range_80 81.69%）逐位不变；红线三目标全绿且不跑 `--regen`。
- 不改 MODEL_VERSION / 预测口径 / cron / nginx；`docs/experiments/`、`docs/portfolio/` 只读不写。
- 不删历史、不加滚动清理。
