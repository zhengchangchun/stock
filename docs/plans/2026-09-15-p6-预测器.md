## 2. `target_date` 与 `asof` 的判定口径

两个来源，取**交集**用于校验 `asof`，日历用于推 `target_date`：

- **日历轴** `calendar.all_dates()` ← `trading_calendar`
- **行情轴** 各标的 `bars_daily` 出现过的日期
- **`asof` 合法性**：`asof ∈ 日历 ∩ 行情轴`。不满足 → **硬拒绝**（退出码 2），
  理由写清是哪一侧缺失。这就是「当日有无 K 线」的现有硬判据（`trend_ma._generate`
  里 `bars[-1].date != date` 的同一条规则）加上日历侧校验。
- **`target_date`** = 日历中 **严格大于 `asof`** 的第一个日期。
  - **为什么不与行情轴取交集**：未来交易日在 `bars_daily` 里必然不存在（还没发生），
    取交集会恒为空。故 `target_date` 只用日历。
  - **日历耗尽时**（当前 `trading_calendar` 最大值 = `2026-09-14`，即**现在就是耗尽态**）：
    退化为「`asof` 之后的第一个工作日（周一~周五）」，并在载荷
    `evidence.target_date_source = "weekday_fallback"` 里**显式写明**这是日历外推，
    不是真实交易日历。这是本任务**最弱的一个字段**，已在遗留问题里列出。

## 3. 载荷每个字段的计算口径

模型 id：`pit_rw_v1`（PIT random-walk with empirical volatility）。
**模型只用复权 K 线的 OHLC，不读 `features_daily` 的任何一列**
（`regime_label` / `main_net_5d` / `pe_pct_3y` 全 NULL，NULL 不得当 0）。

### 3.1 `direction` —— 唯一的概率来源

```
r_i   = ln(C_i / C_{i-1})            # 最近 WINDOW=60 个交易日的对数收益（≤ asof）
mu    = mean(r)                       # 漂移：真实但**最弱**的证据（见 §4 披露）
sigma = stdev(r, ddof=1)              # 波动率
X ~ Normal(mu, sigma)                 # 次日对数收益的分布
上下界 = ln(1 ± FLAT_BAND), FLAT_BAND = 0.005     # 与总纲 §8.2 的 ±0.5% 一致
p_down = Phi(ln(0.995))  p_up = 1 - Phi(ln(1.005))  p_flat = 1 - p_up - p_down
```

- 用 `statistics.NormalDist()`（标准库，无第三方依赖、无魔数近似）。
- `p_up` / `p_down` 先各自 round(6)，`p_flat` 用**减法**得到 → 三者之和**恒等于 1**
  （不是「近似等于 1」）。`sigma <= 0` → 硬拒绝（价格恒定给出不了分布，不许编）。
- **没有自由参数可被调**：`WINDOW` / `FLAT_BAND` 都是**口径**不是旋钮，
  且 `FLAT_BAND` 由总纲 §8.2 规定。本任务**不做任何参数搜索**。

### 3.2 `range_80`

```
z80 = NormalDist().inv_cdf(0.90)                    # ≈1.2816，标准库算出，不写死
lo  = round(C * exp(mu - z80*sigma), 2)
hi  = round(C * exp(mu + z80*sigma), 2)
```

口径：**模型 N(mu, sigma) 的中心 80% 分位区间**。它是**模型分位数**，不是拟合出来的
覆盖率 —— 所以 §8.2 的「长期命中率 ≈ 80%，偏离即校准问题」对它才是**真的检验**。
（弱点：近似正态、忽略跳空与日内路径，已在 §5 披露。）

### 3.3 `key_levels`

```
support    = min(low  over 最近 LEVEL_WINDOW=20 根，含 asof)
resistance = max(high over 最近 LEVEL_WINDOW=20 根，含 asof)
up_ext = mean((high_i - close_i)/close_i)   # 上影线幅度，实测（≤ asof）
dn_ext = mean((close_i - low_i)/close_i)    # 下影线幅度，实测
p_touch(resistance) = 1 - Phi(ln(R / (C*(1+up_ext))))
p_touch(support)    =      Phi(ln(S / (C*(1-dn_ext))))
```

把「触及」近似成「收盘价 × 实测日内延展」够到该价位 —— 用**实测**的上/下影线均值，
不引入任何魔数。（弱点：忽略日内路径顺序与跳空，已披露。）

### 3.4 `action` / `size_pct`

```
若 p_flat >= p_up 且 p_flat >= p_down  → action = "wait", size_pct = 0.0
否则若 p_up > p_down                   → action = "add",  size_pct = 100*(1 - p_down)
否则                                   → action = "trim", size_pct = 100*(1 - p_up)
```

`size_pct` 的含义是**「1 − 不利方向的概率质量」= 模型隐含目标仓位**。
**它不是可执行建议**：没有成本、没有风险预算、没有持仓约束（那些属 P8）。
载荷里用 `evidence.action_note` 原样写明这一点。
本模型**不知道用户的实际持仓**（没有 positions 表）—— 载荷是**按标的方向性**的，
把它与「000333 50% + 现金 50%」的实际盘子合并是 P6 下半 / P8 的事，本任务不做，
也不假装做了。

### 3.5 `invalidate_if`

由**算出来的**关键位导出，不是罐头文案：
`"收盘跌破 {support:.2f}（20日低点）或收盘站上 {resistance:.2f}（20日高点）"`。
它是「该预测在什么条件下算错」的**可证伪条款**，P7 验证器直接读它判 `invalidated`。

### 3.6 `strategy_mix` —— **退化情形必须显式**

总纲 §8.1 的形状是 `{"trend_ma": 0.4, ...}`，但那个形状**表达不了「一个有效策略都没有」**。
故本任务把它写成对象（`weights` 子字段保持 §8.1 的语义）：

```json
{
  "weights": {},
  "degenerate": true,
  "note": "无任何「未被否证」的方向性策略参与 —— 方向概率全部来自 pit_rw_v1 统计模型",
  "benchmark_only": ["buy_and_hold"],
  "excluded": {"trend_ma": "docs/experiments/2026-09-15-trend_ma-default-walkforward.md：样本外扣成本 510.79% vs buy_and_hold 881.75%，被否证"},
  "schema_note": "总纲 §8.1 的 {id: weight} 平铺形状无法表达退化态，故包一层；权重仍逐字在 weights 里"
}
```

份额来源：`stocklab/predict/version.py::FALSIFIED_STRATEGIES`（**一处**常量，
注明引用哪份实验台账）。`buy_and_hold` 标为 `benchmark_only` —— 它不提供次日方向信息，
给它权重就是「假装有多策略集成」。

### 3.7 `model_version`

`stocklab/predict/version.py::MODEL_VERSION = "pit-rw-v1.0.0"`，**一处定义**。
同附 `MODEL_SPEC`（本文件的公式摘要），CLI/报告把 `model_version` 与
`payload_sha256` 一起输出 → 数字是哪个公式算的可追溯。

## 4. 落库：四态 + 结构性唯一键

`schema.sql` 增 `CREATE UNIQUE INDEX IF NOT EXISTS uq_predictions_identity
ON predictions (code, asof_date, model_version)`。
**结构性防线优先于代码检查**：唯一索引让「静默覆盖」在 SQLite 层面就不可能，
即便将来有别的写入方。

四态（对齐 `insert_feature_snapshot` / `cmd_features_build` 的既有做法）：

| 态 | 条件 | 行为 |
|----|------|------|
| `inserted` | 无同键行 | 写入 |
| `identical` | 同键行存在，且**由该行反算出的载荷 hash == 新 hash** | 不写，成功返回 |
| `conflict` | 同键行存在，hash 不同 | **拒绝**，退出码 1，不覆盖 |
| `skipped` | 无可用复权窗口 / 历史不足 / 当日无 K 线 | 不写，记原因 |

hash 覆盖范围**恰好是总纲 §8.1 的契约字段**（`code / asof_date / target_date /
direction_up|flat|down / range_lo|hi / key_levels / action / size_pct /
invalidate_if / strategy_mix / model_version`）—— `pred_id` / `created_at` 不参与，
所以「同 asof 同 model_version 重复运行逐字节一致」是可验证的。

## 6. 已知弱点（写进载荷与交付报告，不许粉饰）

1. `target_date` 目前是 **weekday 外推**（日历只到 2026-09-14），不是真实交易日历。
2. `direction` 的漂移项 `mu` 是 60 日均值，标准误大；它是**最弱**的输入。
3. `range_80` / `p_touch` 假设对数正态、独立同分布，忽略跳空、涨跌停与日内路径。
4. `size_pct` 无成本/风险预算，**不可直接执行**。
5. 集成退化：`trend_ma` 被否证、`buy_and_hold` 只是对照 → **方向概率 100% 来自统计模型**。
6. 只有 2 只标的；`feature_snapshot_id` 留 NULL（模型不消费特征）。
7. 本任务**不产出任何准确率数字**。

## 8. 真实数据回放发现并修掉的一个 bug（v1.0.0 → v1.0.1）

首次在真实库上跑 `predict run --asof 2026-09-14`，载荷的 `key_levels` 里
4 个价位的 `p_touch` **全是 `0.0`**，而 000333 阻力位离现价只有 ~2%。
手算应为 ≈0.30。根因是 `z` 已标准化却又喂给了 `NormalDist(mu, sigma)`
（**二次标准化** → 尾部恒饱和 0/1）。详见 `docs/errors/ERROR_DIARY.md` 2026-09-15 #6。

修掉之后同一天同一价位的真实值：阻力 `0.300823`、支撑 `0.000731`
（000333）/ `0.002492`、`0.066817`（600690）—— 支撑位接近 0 是**正确**的
（离现价 5% 以上，20 日区间内本来就不该够得着）。

**为什么要升 `model_version` 而不是原地改**：`(code, asof_date, model_version)`
是 `predictions` 的唯一键，载荷 hash 覆盖 `key_levels`。改了公式就等于换了
模型，同一版本号下重跑必然 hash 冲突。升版本后：
- `pred_id` 1-2（`pit-rw-v1.0.0`）**原样保留**，`p_touch: 0.0` 这个错误预测
  留在库里 —— 它是历史事实，也是「append-only 真的生效」的物证；
- `pred_id` 3-4（`pit-rw-v1.0.1`）是新预测。

**这条纪律的代价与收益**：代价是库里会有多版本预测；收益是**任何一天都能
回答「当时的模型说了什么」**。P7 验证器必须按 `model_version` 分组归因，
否则把两个模型的成绩混在一起统计 —— 那是无效结论。

**变异 5** 钉住了这个 bug 不再溜过去（`scripts/mutations_p6.py`）。
它与变异 1-4 的性质不同：那 4 条是预防性的，这条是**回放先暴露、再补的反证**。
