# 智能体动态编排对照臂（`arm-agent`）— 设计 + 澄清 + 任务书

- 日期：2026-09-21
- 触发：用户要求「加入智能体动态编排的能力：智能体反复调整策略和提示词、改工作流和函数，
  然后调整；一种现有的模拟，另一个智能体动态规划模拟」
- 结论：**能做，但必须做成「可审计的对照臂」**。否则成绩一定是过拟合的产物：
  一个能反复改规则、又能看结果的智能体，天然会把历史噪声调成「策略」。
  所以本设计把「动态编排」的自由度**全部留在明处**（变更留痕、试错计数、PIT 门禁、
  随机改对照组），而不是留在结果里。
- 归属：需求澄清与口径 → nanobot（本文档）；实现 → Claude Code + superpowers（§9 任务书）

---

## 1. 两条线怎么摆（用户原话的直译）

| 臂 | 规则来源 | 会不会变 | 现状 |
|---|---|---|---|
| `arm-discipline-{05,10,15}` | **写死条文**（止损 + 单票 ≤40% + ETF 分散） | 永不 | 已在跑 |
| `arm-agent`（**新增**） | 智能体在每个决策点产出的**策略规格（spec）** | 每 N 个交易日复审一次 | 本文档 |
| `arm-agent-random`（**新增，关键**） | 与 `arm-agent` 同频率、同预算，但**随机**改 spec | 同样频率 | 本文档 |

**为什么必须有第三条（随机改）**：`arm-agent` 的成绩里混着两样东西 ——
「编排带来的信息」和「同一套模板里多试几次总能试到的好运」。
`arm-agent-random` 用**完全相同的试错预算与变更空间**、但把「智能体选的 spec」换成
随机抽取的 spec，于是：

- 若 `agent ≤ random` ⇒ 「智能」没有贡献，成绩来自试错次数本身；
- 若 `agent > random` 且 CI 不跨 0 ⇒ 才谈得上「动态编排有增量」。

没有这条对照，任何 `arm-agent` 跑赢 `arm-discipline-10` 的读数都**不可解释**。

## 2. 决策点与调用频率

- 命令：`paper agent-review --asof <T> --arm arm-agent`（幂等：**同 (arm, asof) 只能有一版 spec**；
  重复运行要么给出逐字节相同的 spec，要么以「不可复现」报错退出 1）。
- 频率：**每 N 个交易日一次**（默认 N=5，自然周频）。非复审日 `paper step` 直接沿用当前 spec。
- 接入：收盘链第 8 步 `paper step` **之后**新增第 9 步 `paper agent-review`；`paper step` 本身
  一字不改（它只读「当前有效 spec」，不看它怎么来的）。
- 预算：每次复审最多 K 次试错（默认 K=3），**试错次数写进 spec 记录**（§5）。

## 3. 变更空间（参数层）—— 白名单，不是自由发挥

智能体每次只能动这几个字段，且必须落在区间内（越界 = 拒绝，不是夹紧）：

| 字段 | 含义 | 允许区间 | 默认 |
|---|---|---|---|
| `etf_target_pct` | 分散工具目标占比 | 5–25 | 10 |
| `stop_loss_pct` | 止损线（相对成本） | −3 ~ −15（或 `off`） | −5.4（=82.14/86.80−1） |
| `max_single_pct` | 单票上限 | 20–50 | 40 |
| `rebalance_cadence` | 复审节奏 | {3, 5, 10} 交易日 | 5 |
| `cash_floor_pct` | 现金下限 | 0–30 | 45 的对应值见 §3.1 |

**明确不许**（越界即拒绝，并记入 `rejected_reasons`）：

- 引入方向信号（模型概率、资金流、均线、任何「涨跌预测」）⇒ 违反模拟盘纪律（P19 §config）；
- 加杠杆、融券、加白名单外标的；
- 改成本口径 / 改 PIT 判据 / 改整手口径 / 改 append-only 纪律；
- 扩大自己的变更空间（改 `SPEC_SCHEMA` 的区间）—— 这是「智能体给自己发权限」。

### 3.1 现金下限的口径

现有 `arm-discipline` 的现金带是硬约束（`C_CASH_FLOOR`）。`arm-agent` 的
`cash_floor_pct` 同样**只能是收紧方向**（`≥` 静态臂的值），理由与 P19 一致：
风险规则的方向性错误必须是**少投而不是多投**。

## 4. 代码层（「改工作流和函数」）—— 走既有的插桩状态机

用户要的不只是调参，还有「改工作流和函数」。这一层**不新开机制**，直接复用项目已有的
`plugin_scripts` 插桩链：

1. 智能体把新规则写成 **Python 源码文本**提交（`plugin.submit`）→ 落库带 `sha256` 版本指纹；
2. AST 预检 + 受限执行（`plugin/sandbox.py`，`signal.setitimer` 超时）；
3. 状态机 `draft → pending_review → active/archived`，**`approve` 只能由人工 CLI 调用**
   （源码扫描测试钉住：智能体不能给自己放权）；
4. `arm-agent` 的 spec 里用 `script_id` 引用「哪一版 active 规则」（与候选池同一套
   `lifecycle.active_script_id` 反查，不抄第二份映射）。

⇒ 于是「智能体改函数」= 一次**可回滚的版本升级**，而不是就地覆盖。

## 5. 新表 `paper_agent_decisions`（append-only）

一次复审 = 一行（外加每次被拒的试错 = 一行）。字段：

| 列 | 说明 |
|---|---|
| `decision_id` | 自增 |
| `arm` / `asof` | 幂等键（`UNIQUE(arm, asof)`） |
| `agent_kind` | `llm` / `random`（第三臂用同一张表，`agent_kind` 区分） |
| `model_id` / `prompt_sha256` / `seed` | **口径的一部分**：换模型、换提示词、换种子 = 换口径，必须留痕 |
| `context_sha256` | 喂进去的 PIT 快照指纹（可复算：同输入应得同 spec） |
| `spec_before_json` / `spec_after_json` | 前后规格 |
| `n_trials` | 本次试了几版（预算 K） |
| `rejected_json` | 被白名单/区间拒掉的版本与理由 |
| `rationale` | 智能体自述依据（**只作展示，不作证据**） |
| `created_at` | append-only 时间戳 |

护栏：`BEFORE UPDATE/DELETE` 触发器 `RAISE(ABORT)` + `recursive_triggers`
（与 `paper_*` 三表同一套，见 `paper/store.py` 头部注释）。

## 6. 可复现性与 PIT 门禁（这两条决定成绩有没有意义）

1. **PIT 门禁**：喂给智能体的上下文由 `paper/agent_context.py::build_context(conn, asof)`
   构造，**只查 `date <= asof`**；复用 `paper.rules.check_no_lookahead` 的同一条判据，
   并加测试：把 `asof` 之后的行塞进库，上下文指纹**不许变**。
2. **同输入同输出**：`(context_sha256, model_id, prompt_sha256, seed)` 相同 ⇒ spec 必须相同；
   做不到就是「不可复现」，该行标记 `reproducible=false` 并在报告里单列（**不许**静默平均）。
   LLM 的采样随机性因此必须由 `seed` + 温度固定下来（温度进 `prompt_sha256` 的覆盖范围）。
3. **不许看 test/封存窗**：`arm-agent` 的复审只喂当前时点与**已过去的**净值；
   回放式评估（§8 阶段 3）必须沿用现有的 train/validate/test 切分与封存规则。

## 7. 评价口径（怎么读 `arm-agent` 的成绩）

报告里 `arm-agent` 那一节必须**同时**出现：

- `n_reviews`（复审次数）、`n_trials_total`（累计试错次数）、`n_rejected`（被拒次数）；
- 与 `arm-agent-random` 的**成对差分**（同一天、同一预算）± CI；
- 标注 `selection_bias: present, n=C(n_trials_total)` —— 明确写「这个读数是**上界**，
  不是期望」；
- 样本门槛：< 120 个交易日一律「仅供观察」（沿用 P7 既有规则）；
- 结论判据（预注册，跑之前写死）：`Δ(agent − random)` 的按日聚类 CI 下界 > 0
  **且** `Δ(agent − arm-discipline-10)` CI 下界 > 0，才记 `WIN`。

## 8. 阶段划分（建议按此顺序，每阶段独立可验收）

| 阶段 | 内容 | 风险 | 建议 |
|---|---|---|---|
| 0 | 本文档 + 澄清点答复 | 无 | 现在 |
| 1 | `paper/agent_spec.py`（spec schema + 白名单校验 + 纯函数执行）；`arm-agent` 账户接入 `paper step`；**先用手写 spec**（不接 LLM）跑通 | 低（口径新增，静态臂不动） | 建议立刻做 |
| 2 | `paper agent-review` + `paper_agent_decisions` 表 + 幂等/复现守卫 + 报告节 | 中（引入 LLM 调用与留痕） | 阶段 1 验收后 |
| 3 | `arm-agent-random` 对照臂 | 低 | 与阶段 2 同批 |
| 4 | 回放式评估（历史逐点复审） | **高**（多重比较 + 过拟合） | 最后做，且必须封存 test 段 |
| 5 | 「改函数」接插桩状态机（§4） | 中（人工 approve 是硬门槛） | 与阶段 2 可并行 |

**默认走「前进式」**（从今天起真跑，样本自然累积）：无过拟合风险、成本低
（每 5 交易日 1 次调用），缺点是几个月内没有结论。回放式（阶段 4）快到多，
但它把「试错次数」变成隐形的选择偏差来源，必须最后做且带封存段。

## 9. 最小改动清单（实现者按此落地）

1. `stocklab/paper/agent_spec.py`（新）：`SPEC_SCHEMA`（字段/区间/默认）、`validate_spec()`、
   `apply_spec()`（纯函数，与 `paper/rules.py` 同风格：不碰数据库、不读时钟）。
2. `stocklab/paper/config.py`：新增 `ARM_AGENT` / `ARM_AGENT_RANDOM` 常量与
   `AGENT_*` 默认值；**不动** `ETF_TRANCHES`、`RULE_CITATIONS` 等既有常量。
3. `stocklab/paper/engine.py`：`step()` 对 `arm-agent*` 取「当前有效 spec」再走同一执行内核
   （**不复制**纪律臂的执行逻辑）。
4. `stocklab/paper/store.py`：`paper_agent_decisions` 读写函数（只增不改，与现有一致）。
5. `stocklab/data/schema.sql`：新表 + 两个触发器。
6. `stocklab/paper/agent_context.py`（新）：PIT 上下文构造 + 指纹。
7. `stocklab/cli/main.py`：`paper agent-review` 子命令（`--asof/--arm/--agent-kind/--seed`）。
8. `tests/`：spec 校验（越界拒绝、区间端点）、幂等（同 asof 重跑一致）、PIT（塞未来行不改变
   指纹）、append-only 触发器、报告节字段（`n_trials` 等必须出现）、
   `arm-agent-random` 与 `arm-agent` **共用同一预算**的断言。
9. `/lab/paper` 页面：新增一节「动态编排臂」，显示 `n_reviews / n_trials / Δ vs random`。
10. 收盘链 cron 正文追加第 9 步（`paper agent-review`），并把本文档挂进 `docs/README.md`。

**既有护栏不许放松**：`tests/test_paper_discipline_guard.py`（禁 import
`predict/verify/risk/plugin/candidate/experiments`）在阶段 1 仍然生效 —— 所以
`arm-agent` 的**执行路径**照样不许碰模型；它只在自己的「复审」路径里读历史净值，
而那条路径**不改执行内核**。这一点必须由测试钉住（阶段 1 验收项）。

## 11. 什么结果**不算**证据（提前写死，防止事后找理由）

- `arm-agent` 在 < 120 交易日内的任何领先；
- 不报 `n_trials` 的任何 `arm-agent` 读数；
- 与 `arm-agent-random` 的差 CI 跨 0；
- 回放式评估里「试了很多版、选了最好那版」的结果 —— 它是**上界**，不是期望；
- 智能体自述的 `rationale`（那是它的解释，不是证据）。
