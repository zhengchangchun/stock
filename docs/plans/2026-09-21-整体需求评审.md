## 0. 结论

8 份文档作为「目标态」是自洽的、边界写得比多数项目清楚。问题不在想法，在**时效**：它们写于 09-18，之后代码跑到了前面，于是现在同时存在三类问题：

## 2. 硬伤（必须改）

### W1 需求 03 §4.1 已经说反了 —— 沙盒回放与过拟合标记**已实现**

03 原文：`sandbox.overfit_flag` 是占位返回值、`verdict` 固定 `INCONCLUSIVE`（replay 是 fail-closed 空实现）、**没有代码层面的过拟合检测**。

实际（09-20 起）：`stocklab/candidate/replay.py` 回放引擎 + `stocklab/plugin/sandbox.py` 判定 + `cli/plugin.py` 接入，口径落 ADR-017（调仓周期为观测单元 / 70-30 时序切分 / **120 个调仓周期**门槛 / bootstrap CI / 基准 `index_300`）；`overfit_flag(train_mean, validate_mean)` 是**真逻辑**（`train − validate > 阈值` → `'suspected'`，方向固定只标训练段更好）。

**危害**：Claude Code 照 03 干活，会把已完成的当待办重做，或按「空实现」的假设去设计下游调用方。03 是四份文档里唯一一份「现状体」，**它的价值全在准确，一旦过期就是负资产**。

### W2 需求 05 与需求 03 对「过拟合」的口径互相打架

- 05 §已知风险 2：「AI 优化脚本极易出现历史过拟合；**依赖过拟合检测模块拦截**」。
- 03 §4.2：「**没有代码层面的过拟合检测**……本期只在规约层约束」。

而且即便按实现，`overfit_flag` 也只是**打标记**，不阻断任何流程 —— 05 里的「拦截」在系统里**不存在**。两份文档必须先对齐一个口径（建议：改成「依赖 ADR-017 的 70/30 切分 + `overfit_flag` **标记** + 人工复查」，明确标记 ≠ 拦截）。

### W3 脚本/策略版本状态枚举有**三套**口径

| 来源 | 枚举 |
|---|---|
| 需求 02 | 草稿｜沙盒回测中｜等待人工审核｜**验证中**｜**策略冻结**｜策略失效归档｜**已回滚**（7 态） |
| 需求 06 | 草稿/沙盒回测中/等待审核/线上/归档（5 态） |
| 实现 `plugin/lifecycle.py::STATES` | `draft` / `pending_review` / **`rejected`** / `active` / `archived`（5 态） |

差异的实质不是措辞，而是**模块2 的状态**：需求 02 的「验证中」「策略冻结」「已回滚」在实现里没有对应物（因为模块2 未落地），而实现独有 `rejected`。三套口径并存时，任何「按状态查线上版本」的实现都会分叉。**必须先指定唯一主口径**。

### W4 需求 07 的四类定时任务，**执行面当前为 0**

- 现挂 cron（`~/.nanobot/workspace/cron/jobs.json`）：只有 `heartbeat`、`dream` 和 3 条与股票无关的（抖店周策略、抖店发布窗口、机票抢票）。

更麻烦的是 07 §调度约束 1「多任务同时触发则低优先级排队等待，禁止并发」与 nanobot cron 的**实际行为不匹配**：`docs/TODO.md` §E 已实测「cron 任务与用户会话**共用同一条会话**，会话忙时任务停在 `queued`」——不是设计出来的优先级队列，而是抢占式的排队。这条不改，07 无法验收。

### S2 需求 02 的「提前熔断」没有阈值数字

自己定的硬约束，数据字典撑不住。

### S4 「AI」到底指谁？—— 这条决定要不要自动化

- 00 §1「AI 仅允许修改沙盒插桩脚本」、01 §AI优化子流程 第 3 步「AI 生成新版本插桩脚本」；

### S5 需求 06 数据字典已严重滞后

只列 4 张表（候选池快照 / 插桩版本 / 预测记录 / 策略评估记录），实际库 **39 张表**（财报、估值、资金流、审计、实验、账本、模拟盘、质量…）。当「摘要」可以，但当**开发输入**不行 —— Claude Code 会以为表就这么点。建议改名并加一句「全量见 `stocklab/store/schema.sql`」，或补齐。

### S6 需求 07 与现有 P11 调度链的关系未定义

### S7 需求 04 的 P1「基准对标系统」和模块1 已有实现重叠

沙盒回放已产出「候选 vs 基线相对 `index_300` 的超额」（ADR-017 + `SandboxDeps.benchmark_excess`）。04 是以模块2 口吻写的（AI 模拟 vs 人工 vs 基准）。同一件事两个位置，需要指定唯一归属，否则会做出两套「跑赢沪深300」的口径。

### S8 需求 03 §2.2 的 TOTAL_EQUITY 疑点已在评审里定位
