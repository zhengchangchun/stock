# P28：估值 / 资金流「采集路径」（先把数据采进来，不碰策略）

日期：2026-09-17 ｜ 状态：计划 ｜ 前置：ADR-003（数据源口径）、ADR-009（raw_cache 当日时效）、ADR-005（幂等键取语义）

## 1. 目标与非目标

**目标**：给 `valuation_daily` / `money_flow_daily` 建**采集路径**（联网抓取 + 落 PIT 表 + 幂等 + raw_cache），
让 `regime_label` / `main_net_5d` / `pe_pct_3y` 的**数据来源**从「无」变「有」。

**非目标（本轮明确不做）**：
- ❌ 不接任何策略 / 不跑任何评测 / 不写 `docs/experiments/`（那是 nanobot 的地盘，P29 才做）；
- ❌ 不回填 `bars_daily.turnover`（可选加分项，预算够才单独立项，本计划默认不做）；
- ❌ 不碰 `predictions` / `verifications` / `bars_daily` OHLC / `MODEL_VERSION`；
- ❌ 不引入 cron / 常驻进程（ADR-001 D-05）。

### 2.1 单位交叉验证（⚠️ 必须实测，不许猜）

任务书点名：同一交易日 `bars_daily.turnover` 实测 `0.43`（百分数口径），新浪返回 `turnover=43.346` → **量级差 100 倍**。
本计划的处理：**两个源都原样入库**，在 `money_flow_daily.turnover` 存新浪口径、在 `bars_daily.turnover` 存百分数口径，
并在字段注释里写明「新浪 turnover 是百分数值 ×100，与 `bars_daily.turnover` 差 100 倍」。
**最终结论以本轮实测数字为准**（见 §9 验收 e），对不上就如实记录「对不上」，不凑。

其余单位：`netamount` / `r0_net` / `ratioamount` = 元（新浪原值）；`TOTAL_MARKET_CAP` = 元、`TOTAL_SHARES` = 股、`CLOSE_PRICE` = 元、`CHANGE_RATE` = %（东财原值）。

## 3. 表结构（改现有两张空表）

现状：两表**已存在但 0 行、无触发器**（`CREATE TABLE IF NOT EXISTS` 老 shape）。
老 shape 是「拍脑袋预留」，与实际源字段对不上（money_flow 没有 `small/mid/big_net` 来源；valuation 缺 `ps_ttm`/`total_shares`/`close_price`）。
**趁空重定义**，不迁移数据。

### 3.1 valuation_daily（append-only，PIT）

```sql
CREATE TABLE IF NOT EXISTS valuation_daily (
    code          TEXT NOT NULL,      -- 6 位代码
    date          TEXT NOT NULL,      -- TRADE_DATE 裁剪为 YYYY-MM-DD
    pe_ttm        REAL,               -- 东财 PE_TTM
    pb            REAL,               -- 东财 PB_MRQ（最新季报口径）
    ps_ttm        REAL,               -- 东财 PS_TTM
    total_mv      REAL,               -- TOTAL_MARKET_CAP 元
    total_shares  REAL,               -- TOTAL_SHARES 股
    close_price   REAL,               -- CLOSE_PRICE 元（当日收盘，交叉校验用）
    change_rate   REAL,               -- CHANGE_RATE %
    source        TEXT NOT NULL,
    fetched_at    TEXT NOT NULL,      -- 入库审计时刻（PIT 键是 date，不是它）
    created_at    TEXT NOT NULL,
    resp_sha256   TEXT NOT NULL,      -- 该行来源响应体的 sha256（可复现/可溯源）
    cache_key     TEXT,               -- raw_cache 的 params_key（可直接定位原始响应）
    PRIMARY KEY (code, date)
);
```

### 3.2 money_flow_daily（append-only，PIT）

```sql
CREATE TABLE IF NOT EXISTS money_flow_daily (
    code          TEXT NOT NULL,
    date          TEXT NOT NULL,      -- opendate（新浪原生即 YYYY-MM-DD）
    close         REAL,               -- trade 收盘价 元
    change_ratio  REAL,               -- changeratio %
    turnover      REAL,               -- 新浪口径换手率（×100 于 bars_daily.turnover，见 §2.1）
    main_net      REAL,               -- netamount 主力净额 元（= 超大单 + 大单）
    xl_net        REAL,               -- r0_net 超大单净额 元
    ratio_amount  REAL,               -- ratioamount 元
    source        TEXT NOT NULL,
    fetched_at    TEXT NOT NULL,
    created_at    TEXT NOT NULL,
    resp_sha256   TEXT NOT NULL,
    cache_key     TEXT,
    PRIMARY KEY (code, date)
);
```

**被移除的列**：`valuation_daily.div_yield / pe_pct_3y`、`money_flow_daily.small_net / mid_net / big_net`。
理由：源 A/B 都不给这些字段，留着只会是「永远 NULL 的假列」。`pe_pct_3y` 是**派生特征**（3 年分位），
应由特征层从 `valuation_daily` 历史算出（P29 之后），不该当原始数据存。

### 3.3 append-only 触发器（补齐，跟 `features_daily` 同款）

两表各加 `trg_*_no_update` / `trg_*_no_delete`，`RAISE(ABORT, '… is append-only')`。
`recursive_triggers=ON`（`connect()` 已开）保证 `INSERT OR REPLACE` 的隐式 DELETE 也被拦。

### 3.4 迁移策略（空表重定义，有数据即拒绝）

- `schema.sql` 保持 `CREATE TABLE IF NOT EXISTS`（新 shape）→ 新库/测试库直接得新结构。
- 老库（现 `data/stocklab.db`）的两张表是**老 shape**，`CREATE IF NOT EXISTS` 不会改列 →
  加一个迁移函数：**表为空时** `DROP TABLE` + 重建（数据零损失）；**表非空**则抛错拒绝（绝不静默删历史）。
  该迁移挂在 `init_db` 里，ingest 命令入口也走 `init_db` 前滚（与 `cmd_features_build` 同款）。

## 4. PIT 硬口径

- 下游**只允许读 `trade_date <= asof`**（本轮不写下游读层，但表语义已钉死：`date` 就是 PIT 键）。
- `fetched_at` / `created_at` 入库，但**历史行一次写入后永不改写**（append-only 触发器 + `ON CONFLICT DO NOTHING`）。
- **非 PIT 风险（显式写明）**：东财 datacenter 可能按**最新股本重算整条历史 PE/PB**（"RPT_VALUEANALYSIS_DET" 是重算报表）。
  即「今天抓到的 2018 年 PE」≠「2018 年当时能看到 的 PE」。
  **对策**：首写保留 —— 第一次抓到的值永久入库，源站日后修订**不覆盖**（`ON CONFLICT DO NOTHING`），
  且重采时检测到「同 (code,date) 值变了」→ 记 `system_events` warn（**不许静默**）+ 计入 `restated` 上报。
  这是「非 PIT 里最接近 PIT 的选择」：第一次观测离那天最近，比让最新股本反复洗历史更可信。
  该局限**写进表注释与文档**，下游（P29）引用时必须在报告里披露「估值序列可能被源站整体重算」。
- 空值语义：源拿不到 → 写 `NULL`（`to_float` 对 `"-"`/空串返回 None），**不许填 0、不许估算**。
  ETF 没有估值/资金流 → **显式覆盖记录**（§6），不静默缺失。

## 5. 幂等键

- 两表 `PRIMARY KEY (code, date)` + `ON CONFLICT(code, date) DO NOTHING` → **同一区间重跑新增 0 行**（验收 d）。
- 「重采但值变了」单独走 `restated` 计数（不覆盖、只留痕），与 `insert_corp_actions` 的 `restated` 同款语义。

## 6. 失败口径（fail-closed）

- 解析失败 / 非合法 JSON / 空页异常 → 抛 `FetchError`，**整批不落库**（不许把半截数据当完整）。
- 分页完整性：东财按 `result.pages` 翻到底，任一页行数不符预期（非末页 < pageSize）→ 报错；
  新浪翻页直到空页，翻页次数超上限 → 报错（防死循环，同 `fetch_daily_bars`）。
- 单标的抓取异常 → 记 `system_events` error + 计入 failed，**不拖垮其它标的**（同 `ingest_daily_bars`）。
- ETF（510300/518880 等 `asset_type='etf'`）→ 源没有估值/资金流行时，写一条 `system_events` warn
  显式记录「{code} 无估值/资金流数据（{源返回空}）」，**不写假行、不静默**（验收 f 如实报告）。

## 7. 缓存键（遵 ADR-009）

- 估值：`valuation:{code}:{end}:{page}:{pageSize}`；资金流：`moneyflow:{code}:{end}:{page}:{num}`。
  第 3 段 = 锚点 `end` 日 → ADR-009 的 `is_intraday_snapshot` 自动生效：
  **盘中抓的快照不进正式缓存、读侧视为未命中**（不冻结未完成数据）。
- 写侧已有 `RawCache.store` 兜底（ADR-009），本层不另造逻辑，只保证 key 第 3 段是 `end` 日期。

## 8. CLI（照现有 `ingest` 命名风格）

```bash
.venv/bin/python -m stocklab.cli.main ingest valuation --codes 000333 --days N
.venv/bin/python -m stocklab.cli.main ingest moneyflow --codes 000333 --days N
```

- `--codes`（可重复，默认全集 `DEFAULT_UNIVERSE`，`--code` 兼容别名）、`--days`（默认回补日历天数，估值为 2500 / 资金流为 2500）、`--start`/`--end` 可选覆盖。
- 限速 + 重试：复用 `Settings` → `RetryPolicy`（`http_min_interval=0.35s`、`retry_attempts=4`、指数退避上限 8s）。
- 两个新域名进 `ALLOWED_HOSTS` 白名单：`datacenter-web.eastmoney.com`、`vip.stock.finance.sina.com.cn`。
- 输出 JSON 摘要：每标的 `{rows, first_date, last_date, restated}` + 全局 `{ok, failed}`，退出码 0/1。
