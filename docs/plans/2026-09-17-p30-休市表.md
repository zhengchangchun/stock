# P30 计划 —— 交易日历「未来休市表」（缺口队列第 3 项）

- 日期：2026-09-17
- 依据：`docs/TODO.md` §B P30 / §A2 残留边界（「只能覆盖已发生的交易日，明天节假日仍靠工作日近似」）
- 前置实测（本轮**新做**，见 §1）：上交所休市安排公告**可从 `www.sse.com.cn` 直接取到**，
  列表页 `.../closed/list/` 是**服务端渲染**的（不是背景里说的「纯 JS 外壳」），
  文章页是普通 HTML，2026 全年休市安排**逐条可解析**。

## 0. 问题

`Calendar` 只用「已采集到的指数日线日期集合」构建，语义是「某个日期是不是**已采集到的**交易日」。
`predict.service.resolve_target_date` 在日历里找不到 > asof 的日期时退化为**纯工作日外推**
（`weekday_fallback`）→ **节假日被当成交易日**。下一个长假（2026 中秋 9/25、国庆 10/1–10/7）
就会算错 `target_date`。

## 1. 数据源实测（本轮新增，命令与输出见 §5 证据）

| 项 | 实测结果 |
|---|---|
| 列表页 | `https://www.sse.com.cn/disclosure/dealinstruc/closed/list/` → **HTTP 200 / 32873 字节**，**服务端渲染**，含 15 条 `关于YYYY年…休市安排的公告` 链接 + 标题 |
| 文章页 | `https://www.sse.com.cn/disclosure/announcement/general/c/c_YYYYMMDD_NNNNN.shtml` → **HTTP 200 / 约 26KB**，正文可正则解析 |
| 年度通知 | `c_20251222_10802507.shtml` =《关于上海证券交易所**2026年**部分节假日休市安排的通知》（上证公告〔2025〕45号，2025-12-22）→ **2026 全年**休市安排逐条列出 |
| 单节公告 | `c_20260611_10821419.shtml` =《关于2026年端午节休市安排的公告》→ 6/19–6/21 休市，正文引用年度通知 |
| 深交所 | 背景里那个 URL 404，**本轮不采**（见 §7 遗留） |

正文格式（两类文档同构，正则可覆盖）：

```
（六）中秋节：9月25日（星期五）至9月27日（星期日）休市，9月28日（星期一）起照常开市。
（七）国庆节：10月1日（星期四）至10月7日（星期三）休市，10月8日（星期四）起照常开市。
              另外，9月20日（星期日）、10月10日（星期六）为周末休市。
```

**关键可利用的自校验**：公告把每个边界日的**星期**写进了正文 → 解析出的日期必须与
「该日期的真实星期」逐字相符，否则**解析失败**（fail-closed）。这一条能把「年份认错 /
正则吃错字符」这类错误在**入口处**变成显式失败，而不是把错日期写进表里。

## 2. 设计

### 2.1 新表 `market_holidays`（append-only，**不复用 `trading_calendar`**）

```sql
CREATE TABLE IF NOT EXISTS market_holidays (
    date         TEXT NOT NULL,      -- YYYY-MM-DD
    is_open      INTEGER NOT NULL CHECK (is_open IN (0,1)),
    source       TEXT NOT NULL,      -- 机构：'sse'
    doc_kind     TEXT NOT NULL CHECK (doc_kind IN ('annual','holiday')),
    covered_year INTEGER NOT NULL,   -- 这份公告覆盖的年份
    source_url   TEXT NOT NULL,
    published_at TEXT NOT NULL,
    created_at   TEXT NOT NULL,
    PRIMARY KEY (date, source_url)
);
```

- **主键取 `(date, source_url)` 而不是 `date`**：同一日期可能被「年度通知」与「单节公告」
  各写一条（内容相同，无害）；若哪天上交所**改期**（临时休市/公告调整），新公告是**新行**，
  读取侧取 `published_at` 最新者 —— 全程**只有 INSERT**，不触发 append-only 触发器，
  也不会出现「`INSERT OR IGNORE` 把已改期的旧值静默留住」这种错误。
- **append-only 触发器**照抄其它表的写法（`BEFORE UPDATE/DELETE ... RAISE(ABORT)`）。
- **为什么另起一张表**：`trading_calendar` 的语义是「**已采集到的**交易日」，是**回看**；
  本表是「**已公告的**开/休市」，是**前瞻**。混进去会让 `Calendar.load` 把未来日期也算作
  「已采集交易日」，直接污染回测轴与 `session_check`。
- **`covered_year` 的意义（覆盖判据）**：只有**年度通知**（`doc_kind='annual'`）才代表
  「该年**全部**日期的开/休市都已公告」——单节公告只覆盖那一个节。读取侧因此有明确判据：
  `covers(d) := int(d[:4]) ∈ {annual 的 covered_year}`。**覆盖不到的日期不许假装知道**。

### 2.2 解析器 `stocklab/calendar/holidays.py`

- `parse_holiday_notice(html, *, source_url, published_at, doc_kind, covered_year) -> list[MarketHoliday]`
  - 先去标签取纯文本（`<script>/<style>` 先摘掉），再正则：
    `(\d{1,2})月(\d{1,2})日[（(]星期([一二三四五六日天])[)）]\s*至\s*(\d{1,2})月(\d{1,2})日[（(]星期([一二三四五六日天])[)）]\s*休市`
  - `另外，…为周末休市` 子句里的孤立日期也收进来（它们是**公告明说的休市日**）。
  - 三条硬校验（任一不过 → `HolidayParseError`）：
    ① 起止日的**星期必须与正文所写一致**；② 区间长度与星期推进一致（`Δ天 < 7`）；
    ③ 标题/正文含「休市」却**一条都解析不出** → 报错（**不许**静默返回空表）。
- `weekday_of(y, m, d)`：Sakamoto 公式**单一真源**（`predict.service._weekday` 改为引用它，
  消除两份实现）。
- `HolidayTable`：`closed`（已公告休市日集合）、`annual_years`、`is_closed(d)`、`covers(d)`、
  `bounds()`。
- `save_holidays(conn, rows, *, now)` → `INSERT OR IGNORE`，返回**实际新增行数**。
- `load_holiday_table(conn)` → `HolidayTable`（表不存在/空表 → 空表对象，`covers` 恒 False）。

### 2.3 `resolve_target_date` 接休市表（**旧语义一字不改**）

```python
resolve_target_date(calendar, asof, *, holidays=None) -> (date, source)
```

| 场景 | 结果 |
|---|---|
| 日历里有 > asof 的日期 | 原样：`(later[0], "trading_calendar")` |
| 日历耗尽 + `holidays is None` | 原样：`(下一个工作日, "weekday_fallback")` |
| 日历耗尽 + 休市表**覆盖**该年 | 沿着休市日往后推到第一个开市日 → `"holiday_table"` |
| 日历耗尽 + 休市表**覆盖不到**（如 2027 元旦，尚未公告） | 原样退回 `"weekday_fallback"` |

- `notes.target_date`：`trading_calendar` 分支**逐字节不变**（回归红线盯的就是它）；
  `holiday_table` 分支新增文案；`weekday_fallback` 分支**保留原来的整句**
  （`"不是交易日历"` 必须在，`tests/test_predict_service.py:194` 有断言），
  只在有休市表但覆盖不到时**追加**一句说明。
- `PitCache` 加 `holidays()`（回放期只读记忆化，理由同其它缓存的字段）。

## 3. PIT 纪律判断（写进 ADR-013）

休市安排是**交易所提前公告的公开日历信息**，不是价格/成交量 —— 它描述的是**未来的已知事实**，
在预测时点（asof）就已经公开可得，因此**允许**用于决定 `target_date`。
风险边界（ADR 里逐条写清）：
1. **临时休市**（台风/熔断/纪念活动）无法预知 → 表里没有、只能事后补录（新公告=新行）；
2. **公告调整**（改期）→ 靠 `(date, source_url)` 多行 + `published_at` 最新者胜出来表达，**不覆盖旧行**；
3. **只有部分年份可查** → `covered_year` 判据明确，覆盖不到的年份**如实退回** `weekday_fallback`；
4. **`target_date` 只用于「算哪一天」**，不参与任何收益/因子计算 → 不引入价格类前视。

## 6. 红线预判

两个 redline predict 目标（`predict_real_2026-09-14`、`predict_synthetic`）的 `target_date`
**都取自 `trading_calendar`**（合成库特意多给 3 天日历，注释写明「让 target_date 能由
trading_calendar 解析出来」）→ 本轮**不应**改变它们的产物。
验收时若红线仍红，走基线文件自带的归因三步（回退重跑 `cmp` → 确认差异来源 → 才 `--regen`）。

## 7. 已知遗留（交付时必须原样上报）

1. **深交所未采**（入口 404）。
2. **表覆盖范围 = 已公告的年份**：本轮实测拿到 2026 全年（年度通知）+ 2024/2025 若干单节公告；
   **2027 年及以后没有公告** → 那些日期**仍然**是 `weekday_fallback`（如实标注，不假装知道）。
3. **临时休市无法预知**。
4. 公告的**「周末休市」子句**只作补充收录，判「哪天开市」仍以「非休市日 + 非周末」为准。
