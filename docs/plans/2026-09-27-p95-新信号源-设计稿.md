## 3. Q2 第一候选 `gm_yoy_pp` 的 +0.0134：真信号还是多重比较偶然？

### 3.1 先把读数摆全（全部为引用 / 实测，未重算）

| 项 | 值 | 来源 |

| 95% CI（按日 2000 次 bootstrap，seed 20260918） | **[+0.001323, +0.025447]**（不含 0） | 同上 `ci_low` / `ci_high` |
| 验证段 n / std / IR / t | **171 / 0.083211 / 0.161 / 2.111** | 同上 `validate` |
| 训练段 n / mean / t | 399 / +0.012163 / **2.729** | 同上 `train` |
| 全窗 570 个调仓日均值 | +0.012544 | 同上 `mean_all` |
| 覆盖 | 非空覆盖度日 P50 = **344**、截面 P50 = **329.5**（min 150 / max 460）、跳过日 **0**、`LOW_COVERAGE` = **false** | 同上 `value_coverage_p50` / `xsec_size_*` |

| 负对照（刻意跑） | — | 本站**未**跑任何 negative control：跑它需要改 harness（D1 禁止）⇒ 记入 §7.4 未做成口子 |

### 3.2 多重比较量化（第一层：族大小）

- 名义口径：5 个次读数各自独立判 ⇒ 真实 IC 全为 0 时「至少一个 95% CI 不含 0」的概率
  **= 1 − 0.95⁵ = 0.2262（22.6%）**。⇒ 单看「有 1 条不含 0」不构成证据。
- **相关系数修正（关键）**：这 5 个**同源**——都从同一份财报（`load_financials` 同一 `asof` 切片）、
  同一个 4 季 TTM 窗口、同一个 `notice_date` 现算：
  - `gross_margin = (income − cost)/income`；`gm_yoy_pp = gm − gm_{去年同季}`（共享 `income`/`cost` 的**口径**）；
  - `inv_days = 365·inv_avg/cost`（共享 `cost`）；`fcf_margin = (ocf − capex)/income`（共享 `income`）；
  - `roe` 实际不可用 ⇒ **有效参检因子只有 4 个，不是 5 个**。
  ⇒ 「有效独立检验次数」介于 **2 与 4** 之间（**推断**，依据是共享分母与同源窗口；**本稿未实测它们的横截面秩相关矩阵**——
  那需要跑 `factor-ic`（D2 禁止），故此处只给区间不下断言）。
  ⇒ 族大小校正后，FWER 从 22.6%（k=5）降到 18.6%（k=4）甚至 14.3%（k=3）——**区间内任一点都不改变结论**（见 3.4）。
- **Bonferroni 口径的等价说法（推断，纯算术）**：族内 5 判要控 5% FWER ⇒ 名义 α = 0.05/5 = **0.01** ⇒ 相当于要求 99% CI。
  用报告里已有的均值/标准差/n 做正态近似：
  `se = 0.083211/√171 = 0.006363`；`t = 0.013433/0.006363 = 2.111`（与报告一致 ⇒ 正态近似在本例站得住）。
  - 正态 95% CI = **[+0.000961, +0.025905]**（与 bootstrap 的 [+0.001323, +0.025447] 贴合 ⇒ 交叉验证通过）；
  - 正态 **99% CI = [−0.002957, +0.029824]** ⇒ **含 0**。
  ⇒ **在 Bonferroni 校正口径下，`gm_yoy_pp` 不显著。** 这是算术外推（不是 bootstrap 实测），但因为它与 bootstrap 95% CI 一致，可以当作可靠的量级判断。

### 3.3 样本独立性：把「n=171」折算成「有效观测 ≈ 季度数」

**项目前科（逐字引用）**：`docs/experiments/README.md` 的 `2026-09-22-financials-quality-prior` 那条写的是
「质量分按季度常数（validate 里每期公告中位复用 **47** 交易日）⇒ 独立观测量级 ≈ **9 季**，名义样本量 532 日但**检验力很弱**」，
两个变体最终都 `LOSE`。⇒ **同样的算术必须在 `gm_yoy_pp` 上重算一遍。**

**本站只读实测（§11.3）**，窗口 = 验证段 `2023-03-17 .. 2026-09-16`（171 个调仓周期 = 855 个交易日）：

| 量 | 实测值 |
|---|---|
| 宇宙内 800 只里，验证窗内有财报公告的 | **800 / 800** |
| 每只标的在验证窗内的 `notice_date` 条数 | min **10** / **P50 = 15** / max **30** |
| 相邻两次公告的**交易日间隔** | n=8164，min **0** / **P50 = 83** / max **241** |
| 验证窗内出现的不同 `notice_date` 个数 | **119** |
| 2015 起的不同报告期（季度）数 | **47** |

**折算（推断，算式写出）**：`gm_yoy_pp` 只在**新报告期披露**时改变取值 ⇒ 一只标的在 855 个交易日里大约只有
**15 个不同的因子值**（P50）。171 个按日 IC 因此**高度自相关**：同一因子值被连续复用
`855/15 = 57` 个交易日（中位间隔 83 日）。
- 令 `n_eff ≈ 15`：`t_eff = t·√(n_eff/n) = 2.111·√(15/171) = 2.111/3.376 = **0.63**` ⇒ 远不到显著。
- 即便乐观取 `n_eff = 25`：`t_eff = 0.81` ⇒ 仍不显著。
- ⇒ **报告里的 95% CI（按日重采样 2000 次）在「按日独立」这一假设下算出来，而该假设被实测否证** ⇒
  这条 CI 是**过窄**的。点估计 +0.0134 的正负号也许是真的，但**它比 CI 显示的要不确定得多**。

### 3.4 判定：不许写「有 IC ⇒ 采纳」，也不许写「次读数 ⇒ 忽略」

本稿的正面结论是**第三条路**：

> `gm_yoy_pp` 的 +0.0134 是**当前口径下唯一一条 CI 不含 0 的读数**，但在
> ① 族大小 22.6% 的 FWER、② 折算后 `t_eff ≈ 0.63`、③ Bonferroni 99% CI 含 0
> 三条独立理由下，**既不构成采纳依据，也不构成忽略依据**。
> 它唯一合法的用法是：**作为下一个单变量预注册实验的假设来源**（hypothesis generator），
> 并在该实验的预注册里**预先写死**检验力折扣与族大小校正 —— 然后让它**独立地**跑到判决。

### 3.6 口径核对（`gm_yoy_pp` 的定义、单位、缺失处理、`LOW_COVERAGE` 阈值）

**逐字实现**（`stocklab/candidate/indicators.py:164-175`）：

```
gm_yoy = (gm − (inc_p − cost_p)/inc_p) × 100.0
其中 gm     = (income − cost) / income                     # 当期 TTM 毛利率
     inc_p  = _value_at_ttm(reports, "total_operate_income", year−1, quarter)
     cost_p = _value_at_ttm(reports, "operate_cost",        year−1, quarter)
前提：gm 可算 ∧ inc_p ∉ {None, 0} ∧ cost_p ≠ None
```

- **单位**：个百分点（`×100.0`）。即「毛利率同比变化（pp）」。
- **缺失处理**：任一分项不可算 ⇒ `None`（**不补 0**）；`na_reasons` 写明「当期毛利率不可算」或「去年同期毛利率不可算（需 8 个单季）」。
- **需要 8 个单季**：当期 TTM 4 季 ＋ 去年同季 TTM 4 季 ⇒ 上市满 2 年才可能有值（覆盖度 P50=344 与这个前提一致）。
- **`LOW_COVERAGE` 阈值**（`research/factor.py:387-388`）：验证段里「非空覆盖度 < `MIN_XSEC_N`(=30)」的日子占比 **> 50%** ⇒ 出 `LOW_COVERAGE` 且**不给 verdict**。实测 `gm_yoy_pp` 是 **0/171** ⇒ 不触发。
- **验证段实际观测**：171 个周期全部有 IC（跳过日 0）；每日非空 344 只、进入 IC 的截面 P50 = 329.5 只（与 800 只宇宙、与 P83 主因子的截面 P50 = 398 的差 = 财报与价量数据的可得性差）。
- **`roe` 的 `LOW_COVERAGE` 根因（本站只读实测，新增发现）**：`roe = profit / avg(parent_equity)`，而
  `parent_equity` 在宇宙全历史 59,540 行里**只有 1,369 行非空（2.3%）**，且**逐年均匀**（2015 2.3% / 2018 2.2% / 2023 2.0% / 2026 2.0%）；
  同表的 `total_equity` 是 **99.1–100%**。
  ⇒ 这**是字段填充缺口**（缺失按年在 2.0–2.3% 均匀分布，是映射漏列的指纹），**不是**「源站没有该字段」的证明。
  结论：**`roe` / `dupont` 在本题的可用性取决于一次采集侧修复，本站不修**（§9 拍板点 5）。

**采集命令（现状，不用改）**：

```bash
.venv/bin/python -m stocklab.cli.main ingest announcements --universe csi300-500 --days 90 --page-limit 3
```

（月链已挂同参数一步：`ops/chain.py::MONTHLY_STEPS` → `ingest_announcements`，`blocking=False`。

**首采耗时实测（单只只读接口，`HttpClient(cache=None)`，4 只各一次，§11.2）**：

| 标的 | 窗口 | 耗时 | 页数 | 行数 | truncated |
|---|---|---|---|---|---|
| 000333 | 90 天 | **0.14 s** | 1 | 20 | False |
| 600690 | 90 天 | **0.11 s** | 1 | 23 | False |
| 300750 | 90 天 | **0.69 s** | 2 | 51 | False |
| 600519 | 1 年 | **0.68 s** | 2 | 94 | False |
| 000651 | 1 年 | **0.77 s** | 3 | 120 | False |

- **90 天口径的 800 只外推（推断）**：单只 0.11–0.77 s，取中位 ≈ 0.14–0.35 s ⇒ **800 只 ≈ 2–5 min**

- **深历史首采（如 2015→今 ≈ 10.6 年，推断）**：以「1 年 ≈ 2–3 页」线性外推 ⇒ 单只 ≈ 20–30 页 ⇒
  **单只 ≈ 7–10 s、800 只 ≈ 1.6–2.2 h**，且**必须显式抬高 `--page-limit`**（默认 5、月链用 3，跑满就 `truncated` 并停下——
  这是 ADR-038 决定四的有意行为，不是 bug）。⇒ **深历史首采是一条独立的、要单独估机时的任务**（P96），
  不能靠月链「跑着跑着就齐了」。
- **幂等**：主键 `(code, art_code)` + 首写保留 ⇒ 90 天窗口每月重跑，重复行被 `INSERT OR IGNORE` 吃掉，**不会膨胀**。

### 4.2 北向 `northbound_holdings`


**首采实测（4 只各一次，`start="2015-01-01"`，§11.2）**：**每只都只回 1 行**，`trade_date` 恒 `2026-06-30`，

### 4.3 月链会不会自动补上？会不会要手工？

- **会**：`MONTHLY_STEPS` 已含 `ingest_announcements`（`--days 90 --page-limit 3`）与 `ingest_northbound`（`--days 120`），
  两步**均非阻断**（`blocking=False`，失败不抬升退出码，但照旧进 `steps` / `bad=` / `anomalies`）。
- **但第一次覆盖要手工，且「月链自动跑」补不出深历史**：
  1. 月链是**每月 1 日**跑（`ops/schedule.py` 时刻表）⇒ 若等它，最早 **2026-10-01** 才有第一批数据；
  2. 月链的窗口是 90 天 / 120 天 ⇒ **公告只有近 3 个月**、北向只有最新 1 期；
  3. 深历史公告（2015 起）**不可能**由月链补齐（它每轮只翻到 cutoff 即停）。
  ⇒ **深历史首采必须是一条显式命令**（P96 站），跑一次、跑完留痕；之后才轮到月链增量。
- 前置条件：真库需要有这两张表 ⇒ P88 记录「真库前滚（`db init` / `ensure_schema` 建这两张表）留给 nanobot」。
  本站**只读实测这两张表存在且为 0 行** ⇒ 表已在真库，缺的只是数据。

### 4.4 先采集还是先设计？→ **先设计（冻结关键词表），再采集；但允许月链并行自动填**

理由（这是本站的核心排序建议）：
1. 公告因子的**唯一合法构造**是「预注册冻结的关键词表 → 计数/哑变量」（D7）。关键词表**必须先冻结**，
   否则采回来的一堆标题无法归因，只会诱导事后挑词（= 过拟合）；
2. 北向已判**本档排除** ⇒ 它的采集与因子设计解耦，可以交给月链慢慢攒（攒够 8 个季度再谈）；
3. 采集**不影响**关键词表冻结 —— 冻结的是「哪些语义类算事件」，不是「哪些词出现得多」。
4. **诚实披露**：本站为了写 Q4④ 的公式，现场单只抽看了 `column_name` 的取值分布（见 §5.4），
   这属于**对数据的一次窥视**。缓解办法是冻结表按**语义类**（回购 / 减持 / 质押 / 调研 / 关联交易…）定义，
   **不按频次**挑词；且冻结动作必须发生在**跑度量之前**、写进 P98/P96 之前的预注册文件里。

## 5. Q4 候选因子构造定义（逐字公式 + PIT 锚 + 缺失/极值 + 覆盖 + 相关风险）

**通用约定**（所有候选一致，写进预注册）：
- 度量一律走 `research factor-ic` 既有 harness：Spearman rank IC、5 层、2000 次**按日**重采样 bootstrap（seed 20260918）、
  `MIN_XSEC_N=30`、`MIN_VALID_PERIODS=120`；判定词汇 `IC_SIGNIFICANT` / `IC_NOT_SIGNIFICANT` / `INCONCLUSIVE` / `LOW_COVERAGE`。
- **缺失一律 `None`，不进截面，不补 0**（与 `factor.factor_values` 同规）。
- **极值**：rank IC 对**单调变换**不变 ⇒ 不做横截面 winsorize（winsorize 只会制造并列、破坏名次）。
  但要处理**语义性极值**（负 PE、负净资产），办法是**先定义为缺失**，不是截断（见 5.2）。
- **PIT**：一律只用 `date <= asof`（或 `notice_date <= asof`）的行；**非 PIT 字段不得入因子**（`industry_name` / `instruments.sector` / `instruments.name` 的当前值 —— D8）。
- **相关风险判据**（统一，写进预注册）：候选量首先与 `mom20` / `vr15` 做**逐调仓日横截面 Spearman 相关**，
  报「平均秩相关 ρ̄」。**若 |ρ̄| > 0.5 ⇒ 判为「换皮」，该因子不进 IC 判据**，只作为附属读数；
  若 0.3 < |ρ̄| ≤ 0.5 ⇒ 必须报**正交化后残差 IC**（§3.5 P-2）才可判。⇒ 高度相关就是换皮，**先量再判，不许看 IC 猜**。

### 5.1 ① 资金流类（`money_flow_daily`，PIT 锚 = `date`，日频）

| 代号 | 逐字公式 | 对齐时刻 | 缺失 / 极值 | 预期覆盖 | 与 `mom20`/`vr15` 的相关风险 |
|---|---|---|---|---|---|
| **MF-A** `mf_ratio_5d` | `mean( ratio_amount[t] for t in 最近 5 个交易日, t <= asof )`；`ratio_amount` = 新浪 `ratioamount`（已归一占比，实测取值域 [−6.015, +7.014]） | `asof` 当日收盘后（该行 `date == asof` 已入库时） | 5 日内任一为 `NULL` ⇒ `None`（不补 0）。无横截面 winsorize | 实测宇宙内 2015+ **800/800 只、1,921,737 行 100% 非空** ⇒ 覆盖不成问题 | **高**（这是本类头号风险）：窗口 = 最近 5 日，与 `vr15`（`V[-5:]/V[-20:-5]`）的分子窗**完全重叠**，且动量与资金流经济上同源。⇒ 预注册里把 `|ρ̄| > 0.5` 直接写成**淘汰门** |
| **MF-B** `mf_net_surprise_20d` | `( main_net[asof] − mean(main_net[asof−19 .. asof]) ) / std( main_net[asof−19 .. asof] )`（**时序标准化**，只与自身历史比） | 同 MF-A | 20 日窗内任一 `NULL` ⇒ `None`；`std == 0` ⇒ `None`（不给 0，0 会被当成「无异动」）。单位是「元」，但除法已消掉量纲 | 同 MF-A（`main_net` 100% 非空） | **低-中**：时序标准化天然消掉了「大市值 = 大金额」的规模代理；与动量的相关主要是「价涨 → 资金流入」的经济联动，需实测 ρ̄ |

> **为什么不用「金额 / 市值」归一（任务书点名要回答的选择）**：`main_net / total_mv` 需要 `valuation_daily`
> ⇒ 把资金流因子绑死在 **2018+**；且 `total_mv` 是**规模**代理，除出来的比值仍有规模痕迹。
> **MF-B 用自身历史做分母**：① 不受 2018 限制（保持 2010+ 的可用窗口）；② 规模项在「同一只标的的分子分母」里自动约掉。
> ⇒ 推荐 **MF-A（比占比，最简）+ MF-B（比自身历史，最稳）** 两个都进候选，**一次只跑一个**（D6）。

2. **明确排除"无信息类"**：定期报告全文/摘要（`年度报告全文`、`一季度报告全文`、`半年度报告摘要`…）是**日历可预知**的
   ⇒ 只有「报告全文已披露」这一个事实，信息量接近 0，**不入表**。这条排除要写进预注册，防止 EV-A 被定期报告淹没。

   `回购进展情况`(5) / `员工持股计划`(4) / `高管人员任职变动`(4) / `分配预案`(4) / `调研活动`(2) / `股份质押、冻结`(2) /
   `股东/实际控制人股份减持`(2) / `关联交易`(1) / `审计机构变更`(1) …（共 41 个不同标签）。
   ⇒ 窥视内容**只用于确认「`column_name` 是可枚举的分类轴」**，**不用于挑高频词**；建表动作在 P96 采集之后、P98 度量之前完成并冻结。
4. **一个已知 PIT 陷阱（实测）**：抽到的 `000333` 首行 `notice_date = 2026-09-28`，而当日是 **2026-09-27**
   ⇒ 源站会列出**次日**的公告。⇒ PIT 筛选必须是 `notice_date <= asof`（**含当日**），并把「当日公告是否当天可得」
   这个**日内歧义**写进预注册；稳健性检查用 `notice_date < asof` 作为**独立的第二个预注册**（不许事后切换）。

### 5.5 ⑤ 北向持股变动（季度）：**本档排除**（给排除判据）

**判据（四条，任一条单独成立即排除；现在四条同时成立）**：

1. **无 PIT 锚可用**（最硬的一条）：`northbound_holdings` 的列是
   `code, trade_date, hold_shares, hold_market_cap, a_shares_ratio, hold_shares_ratio, free_shares_ratio, close_price, frequency, source, fetched_at, created_at, resp_sha256`（§11.1 实测 DDL）
   ⇒ **只有 `trade_date`（报告期末），没有披露日**。在季度末（如 2026-06-30）之后的某个调仓日使用它，
   **无法从表内证明「那天它已经公开了」** ⇒ 前视偏差。不是「收益会好看」的问题，是**无法做 PIT**。
2. **源站只给最新一期**：只读实测 4 只、`start="2015-01-01"`，**每只都只回 1 行、`trade_date` 恒 `2026-06-30`**
   ⇒ 即便采了，表内也只有 1 期/标的，**没有时序**（ADR-038 §已知代价同结论）。
3. **频率 4 点/年**：实测持仓比例 4 次/年更新，而调仓 5 个交易日一次 ⇒ 单只标的的因子值在
   **约 62 个交易日**内不变 ⇒ 与 §3.3 同一个「季度常数」问题，而且更极端（`gm_yoy_pp` 至少还有 15 个变化点，
   北向只有 4 个/年）⇒ 有效观测数远低于 CLAUDE.md 的 120 交易日门槛。
4. **无横截面时变性**：因为只有一期，`a_shares_ratio` 在**全窗**是一个常数 ⇒ rank IC 在时间维度上恒等于
   同一张截面排序的重复测量，**不构成「因子的横截面排序能力」这个问题**。

**重新考虑的条件（写死，避免以后凭感觉翻案）**：表内出现 **≥ 8 个季度、且每个季度有可证实的披露日**
（需要采集侧补一个「披露日」列或从源站字段落一个可验证的日期），并且有效观测数 ≥ 120 交易日。在此之前**不立项**。

### 6.2 **结构性难点（这才是 Q5 的真问题，不是「加个开关」）**

P83 的设计原则是「因子值取自打分用的同一个 `ctx`，**不另建价格口径**」（`research/factor.py:22-27`）。
这条原则对 `mom20` / `vr15` / 5 个财务因子成立，因为**它们本来就在 `ctx` 里**。
但 §5 的 4 类新候选（资金流 / 估值 / 公告）**全部不在 `ctx` 里**，而且按 ADR-038 决定五
**也不该进 `ctx`**（进 `ctx` = 进打分路径 = 改生产 + 多变量）。

⇒ 任何把新因子接进 harness 的方案，都**必须新增一个「研究侧取值器」**（`(conn, code, asof) -> float|None`），
这是 P83 之后第一次出现「因子值不来自 `ctx`」。**它必须被显式披露为口径扩增，不能假装是「只加名字」。**

### 6.3 三方案对比

| | **A** 扩注册表 ＋ `--factor` | **B** 新命令 `factor-ic-v2` | **C** 只加读数不改判 |
|---|---|---|---|
| 一句话 | 在 `research/factor.py` 里加注册表条目（含研究侧取值器），CLI 加 `--factor`，预注册的 `factors` 字段随之 | 新命令、新模块，与 `factor-ic` 隔离 | 不加因子，只把「相关系数 / 并列比例 / 有效样本」等**读数**加进现有报告 |
| 新概念数 | **0**（`factors` / `secondary_factors` 预注册字段已存在） | +1 命令 +1 模块 +1 预注册词汇表 | 0 |
| 对既有报告**逐位不改性** | **能做到**：`--factor` 默认 `None` ⇒ 名单不变 ⇒ `render_md` / `summary_line` 逐位相同 | 能做到（新命令不碰旧路径） | 能做到（只加键，不改既有键） |
| 对生产路径（`candidate/`）的改动 | **0**（见下 A′） | 0 | 0 |
| 会不会踩「两处相等」用例 | **只要不把新因子塞进 `FACTOR_FEATURE_KEYS` 就不会** | 不会 | 不会 |
| 重复代码 | 无 | **有**（IC / 分层 / bootstrap 要再抄一遍或抽公共层 ⇒ 又是改动面） | 无 |
| 能不能回答 Q2/Q4 的问题 | **能**（出 verdict） | 能 | **不能**（只报不判 = 现在的次读数状态） |
| 评价 | ✅ **推荐** | ❌ 重复且引入第二套词汇 | ⭕ 可作为 **A 的一个不冲突子集**先落地 |

### 6.4 推荐：**A′**（A 的收敛版 —— 只扩**研究侧**，生产路径零改）

**A′ 的本质**：新增「研究侧因子注册表」，与**生产**的 `MAIN_FACTORS` / `SECONDARY_FACTORS` **并列而不重叠**：

```
# research/factor.py（示意，本站不实现）
MAIN_FACTORS       = ("mom20", "vr15")          # 不动
SECONDARY_FACTORS  = FACTOR_FEATURE_KEYS        # 不动（用例 233-234 继续绿）
RESEARCH_FACTORS   = ("gm_yoy_pp", "mf_ratio_5d", "mf_net_surprise_20d",
                      "ep_ttm", "pe_pct_756", "ann_count_5d", "ev_<类>…")   # 新增：只用研究侧取值器
```

- `gm_yoy_pp` **同时**在 `SECONDARY_FACTORS` 和（被显式选中时）`RESEARCH_FACTORS` 里 ⇒
  **升格 = 换一个 kind（`secondary` → `main`）**，不是复制代码。取值器复用 `secondary_value`，零新增。
- 新因子（资金流/估值/公告）走新的取值器层，**取值器只读库、只被 `research/` 调用**，
  `candidate/`、`plugin/`、`predict/` 一行不碰（ADR-038 决定五继续成立）。

**改动面清单（逐文件 + 逐函数，本站不实施，仅登记）**：

| 文件 | 改动点 | 性质 |
|---|---|---|
| `stocklab/research/factor.py` | 新增 `RESEARCH_FACTORS` 常量；新增研究侧取值器（如 `_research_value(conn, code, asof, name)`）；`one_factor(...)` 的取值来源参数化（当前签名只吃 `payloads_by_mark`，见 `:336-340`）；`run_factor_ic` 的 `accessors` 组装（`:521-524`）；`PREREG_FIELDS` 视需要加一个「研究侧因子」字段；`render_md` / `summary_line` 增段（**只增键、不改既有键**） | **研究侧**，逐位不改性可控 |
| `stocklab/cli/main.py` | `rsrch_f.add_argument("--factor", action="append", default=None, …)` | **研究侧** |
| `stocklab/cli/research.py` | `cmd_research_factor_ic` 透传 `--factor`；`open_read_only` 复用现成 | **研究侧** |
| `tests/` | 新增：① `--factor` 缺省 ⇒ 与既有产物逐位相同；② 既有 `SECONDARY_FACTORS == FACTOR_FEATURE_KEYS`（`:233`）继续绿；③ 新取值器的取数正确性 | **测试**（新增，不改旧） |
| `stocklab/candidate/run.py` | **零改动**（`FACTOR_FEATURE_KEYS` / `_factor_payload` 不动） | — |
| `stocklab/candidate/score.py` | **零改动**（`ctx["features"]` 不动） | — |
| `stocklab/candidate/indicators.py` | **零改动** | — |
| `plugin/sandbox.py` / `predict/` / `paper/` / `m2/` | **零改动** | — |

**对既有报告「逐位不改性」怎么保证（可证伪）**：
1. `--factor` 缺省 ⇒ 因子名单与顺序**逐字等于** `MAIN_FACTORS` + `SECONDARY_FACTORS` ⇒
   用现有预注册重跑，产物 `renders_md` / `summary_line` / JSON **逐字节相同**（可证伪：新增用例钉住）；
2. 新因子的行**只在报告里新增段/新增键**出现，`clip_diag` / `rank_ic_reference` / `coverage` 等既有键的**值不变**；
3. `write_report` 的产物命名 `f"{end}-factor-ic-{universe_id}"` **不变** ⇒ 但**这正是风险**：
   若用同一个 `--end` + `--universe` 跑一个**新因子**实验，会**静默覆盖**旧产物（P60 已有同类前科：
   「产物文件名不含宇宙 id ⇒ 覆盖了 P60 产物」，见台账 2026-09-25 那条）。
   ⇒ **A′ 落地时必须同时把实验短名或因子名写进产物文件名**（例如 `<end>-factor-ic-<universe>-<factor>.{json,md}`），
   并在预注册里冻结命名规则。**这是 Q5 里唯一一个「不做就会丢数据」的点。**

**哪个方案能让「预注册 → 跑 → 判」不加新概念就复用？**
⇒ **A′**。因为 `PREREG_FIELDS` 里**已经有** `factors` / `secondary_factors`，`validate_prereg` 已经逐字段比对；
把新因子放进 `factors` 字段即可复用同一条 fail-closed 链（`--prereg` 不一致 ⇒ exit 2、零输出）。
B 需要新增一套预注册字段与判定词汇；C 根本不出 verdict。

## 7. Q6 样本与检验力（数字说话）

### 7.1 调仓边界与切分（只读实测，§11.3）

| 量 | 实测值 |
|---|---|
| 窗口内交易日（`2015-01-01`..`2026-09-24`） | **2,852**（首 2015-01-05、末 2026-09-24） |
| 调仓边界 marks（每 5 个交易日一个） | **571**（首 2015-01-05、末 2026-09-23） ✅ 与任务书 §3.8 的 571 一致 |
| 周期数 | **570** |
| 训练段 / 验证段（`SPLIT_TRAIN_RATIO=0.7`，按周期序号） | **399 / 171**（`n_train = int(570×0.7) = 399`） |
| 验证段边界 | **2023-03-17 .. 2026-09-16** |
| 验证段 n=171 ✅ | 与任务书 §1 Q6、P78/P83 一致 |

### 7.2 逐年 mark 分布与「2018 之前有多少个」

| 年 | 2015 | 2016 | 2017 | 2018 | 2019 | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| marks | 49 | 49 | 49 | 48 | 49 | 49 | 48 | 49 | 48 | 49 | 48 | 36 |

- **`marks < 2018-01-02`：147 个**（= 2015+2016+2017 的 49+49+49；因为 `valuation_daily` 从 **2018-01-02** 起，
  2017 年最后一个 mark 也取不到估值）。
- **完全落在 2018 之前的周期：146 个**；以「周期起点 `d0 >= 2018-01-02`」为可用判据，则
  **可用周期 = 423**（**train 252 / 399**、**validate 171 / 171**），首个可用周期起点 `2018-01-05`。

### 7.3 结论：估值类因子的代价全在**训练段**，验证段**一个都不少**

```
（推断，算式在上）估值类因子（VAL-A / VAL-B）：
  训练段：399 → 252（丢 147 个周期 = 36.8%）
  验证段：171 → 171（丢 0 个）
  ⇒ 判决所依赖的 n_validate = 171 不受 2018 起点影响；
     受影响的是「训练段是否够用来定任何东西」——而本 harness 的训练段只用来看
     是否背离（`overfit_flag`），不参与判决。
```

**这修正了一个直觉**：直觉是「2018 起点 ⇒ 验证段变短 ⇒ 样本不够」。实测**不成立**，
因为验证段本来就是**最后 30%**（2023 起），早已在 2018 之后。
⇒ 真正要付的代价是：`VAL-B`（`pe_pct_756`）需要 3 年历史 ⇒ 实际起点 ≈ **2021-01** ⇒
它的训练段只剩 `2018-01` 之后的一部分，且**训练段里没有「跨 2018」的对照**。

### 7.4 「因子没 edge」与「样本不够」必须分开说（逐候选预判）

| 候选 | 判决时最可能撞上哪一堵墙 | 为什么（依据） |
|---|---|---|
| `mf_ratio_5d` / `mf_net_surprise_20d` | **样本够**（2010+ 或 2015+ 全窗、800/800 只、字段 100% 非空）⇒ 若 `IC_NOT_SIGNIFICANT`，那就是**没 edge**，不是样本问题 | 实测覆盖 |
| `ep_ttm` | **样本够**（validate 171/171）⇒ 若 `IC_NOT_SIGNIFICANT` = 没 edge | §7.2 |
| `pe_pct_756` | **样本可能不够**（实际起点 ≈2021 ⇒ 训练段被砍到很小；验证段仍需实测确认是否有 ≥30 只/日）⇒ 可能出现 `INCONCLUSIVE` | §5.2 的 3 年窗要求 |
| `gm_yoy_pp` | **两个都不是**：样本量名义够（171）、覆盖够（0 跳过日），但**有效观测 ≈ 15 个季度状态** ⇒ 属「**名义样本足够、有效样本不足**」这一第三类 | §3.3 |
| `ann_count_5d` / `ev_*` | **样本够**（采集后日频/事件频），但**分辨率可能不够**（零值占多数 ⇒ 大量并列）⇒ 须并列报「并列比例」 | §5.4 |

⇒ 报告措辞纪律（写进预注册）：**`IC_NOT_SIGNIFICANT` 只在「覆盖 ≥ `MIN_XSEC_N` 且有效样本折扣后仍有足够独立观测」时才可读成「没 edge」**；
否则一律读成「测不出」（`LOW_COVERAGE` / `INCONCLUSIVE` / 或显式标注「有效样本 ≈ N 个季度状态」）。
**两个都不许糊成一句「不显著」。**

## 8. Q7 后续任务书拆分（4 个，逐个给大小与依赖）

### P96 ｜ 采集站：公告深历史首采（＋北向作为数据面完整性）

- **目标**：把 `announcements` 从 0 行采到「够做事件因子」的量级（至少覆盖验证段 2023-03-17 起；若机时允许则 2015 起）。
- **改动面**：**可能零代码**（`ingest announcements --universe csi300-500 --days <大> --page-limit <大>`）；若要走 `/tmp` 副本实测写路径，需 `--db`（命令已支持）。无 `stocklab/` 改动。
- **判据**：① 真库 `announcements` 行数 > 0 且 `MIN(notice_date)`、`MAX(notice_date)` 覆盖目标窗口；② 高公告量标的的 `truncated` 计数被如实记录（不静默）；③ 前后真库 sha 差异被显式记账；④ **不接任何消费路径**（ADR-038 决定五）。
- **依赖**：无（表已存在）。
- **规模**：小（机时 5 min–2.2 h，取决于是否做深历史，见 §4.1）；**单变量：只加数据，不动因子**。

### P97 ｜ 度量扩展站：`--factor` ＋ 研究侧因子注册表（A′ 落地）

- **目标**：让新因子能进既有 harness 出 verdict，且既有产物逐位不变。
- **改动面**：`research/factor.py`（新增注册表 + 研究侧取值器 + 报告新段）、`cli/main.py`（`--factor`）、`cli/research.py`（透传）、`tests/`（新增用例）；**产物命名加因子/实验短名**（防静默覆盖，§6.4）。
- **判据**：① `--factor` 缺省 ⇒ 既有预注册重跑产物**逐字节相同**；② `tests/test_research_factor.py:233` 继续绿；③ 生产路径 `candidate/` **零 diff**；④ 新因子的 `LOW_COVERAGE` / 并列比例等读数齐备。
- **依赖**：P96（事件类因子需要数据）；资金流/估值类因子**不依赖** P96，可先做。
- **规模**：中。**单变量：只加「怎么量」，不改「判什么」**。

### P98 ｜ 单因子预注册实验站（一次一个因子，按优先级）

- **目标**：对 §5 的候选**逐个**跑 `research factor-ic`，每个一份新预注册。
- **建议顺序（每次只上一个）**：
  1. `gm_yoy_pp`（唯一无需新取值器；预注册 `rule` 里**写死**季度常数折扣 + 族大小校正 + 相关性门）；
  2. `mf_ratio_5d`（覆盖最好，但相关风险最高 ⇒ 先量 ρ̄）；
  3. `ep_ttm`；
  4. `ann_count_5d` / `ev_回购`（P96 之后）。
- **改动面**：零代码（纯跑 + 预注册 + 产物）。**注意产物覆盖风险**（P97 修好命名之前，用不同 `--end` 或先做 P97）。
- **判据**：预注册 fail-closed（`--prereg` 逐字段比对，不一致 exit 2 零输出）；判据原文**只许**用既有词汇表；**不许**在同窗上调参 / 换门槛 / 换分层数（§3.5 ❌ 列）。
- **依赖**：P97（`gm_yoy_pp` 升主读数需要它）；事件类还需要 P96。
- **规模**：小-中；**每次一次长跑 ≈3.7 h**（P83 实测 13,485.2 s ⇒ 外推量级，不是本站实测）。

### P99 ｜ 进池站（**条件性，现在不立**）

- **前置**：P98 判出 `IC_SIGNIFICANT` **且**相关门通过（或残差 IC 成立）。
- **性质**：**策略改动**（改 `score` 的合成 / 改 `m2_a1` 插桩）⇒ 必须**另立任务书 + 预注册 + 单变量 + 扣成本 + 基准对照**（`CLAUDE.md` 度量纪律 4/5）。
- **依赖**：P98 的判决。
- **规模**：大。**本站明确不预判它会成立** —— 现在的证据不支持任何方向承诺（D9）。
