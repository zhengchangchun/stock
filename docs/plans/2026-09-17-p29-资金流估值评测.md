## 1. 设计决策（brainstorming 收敛）

### 1.1 变体注册：新增两个 `mu_mode` 取值（不是新字段）

沿用既有 `index_sign` 的模式——`mu_mode` 是本次实验**唯一**的旋钮：

- `MU_MODES` 扩为 `("sample_mean", "zero", "index_sign", "mf_sign", "val_pe_pct")`
- V1 `Variant(id="mf-dir-prior", spec=ForecastSpec(mu_mode="mf_sign", ...))`
- V2 `Variant(id="val-pe-pct-mu", spec=ForecastSpec(mu_mode="val_pe_pct", ...))`

不新增 `ForecastSpec` 字段：`changed_fields()` 仍等于 `("mu_mode",)`，冻结项一个不动。

### 1.2 数据读取层：`compute_forecast` 加两个**数据参数**（不是 spec 字段）

`compute_forecast(..., mf_sign=None, val_sign=None)`：

- `mu_mode == "mf_sign"`：`mf_sign is None` 或 `mf_sign not in (-1,0,1)` → `DegenerateInput`；
  `mu = abs(mu_sample) * mf_sign`（`mf_sign == 0 → mu == 0`，天然覆盖 `main_net=0`）。
- `mu_mode == "val_pe_pct"`：`val_sign is None` 或 `val_sign not in (-1,0,1)` → `DegenerateInput`；
  `mu = abs(mu_sample) * val_sign`。
- 证据块（非基线）：追加 `mf_sign` / `val_sign` 到 `evidence_inputs`（与 `index_dir` 同级）。

`index_dir` 是**按天**共享（指数对全部标的一致）；`mf_sign`/`val_sign` 是**按 (code, asof)**（资金流/估值每股每行），
所以这两者由 runner **按 code 逐行**算好后传进 `compute_forecast`。

### 1.3 符号 loader（PIT 硬约束，放 `variants.py`）

- `load_mf_sign(conn, code, asof, cache=None) -> int`：
  查 `money_flow_daily` 中该 `(code, date==asof)` 行（**只取 `date <= asof`，且必须精确命中当日**）→
  `main_net is NULL` 或行不存在 → 返回 `None`；否则 `sign(main_net)`（>0→1，<0→-1，==0→0）。
  **绝不**「取最近一根」、绝不回落到基线。
- `load_val_pe_pct_sign(conn, code, asof, cache=None) -> int`：
  查 `valuation_daily` 中该 `(code, date<=asof)` 的 `pe_ttm` 序列，取**最近 756 行**；
  **必须**命中 `date==asof` 的行（缺行 → `None`），分位用「含等」约定
  `q = sum(v <= pe_asof for v in tail) / len(tail)`（`tail` 末尾是当日值）→ `q<=0.30→+1`、`q>=0.70→-1`、否则 `0`。
  `pe_ttm is NULL` → `None`。
- PitCache 加 `money_flow_series(code)` / `valuation_series(code)` 缓存（整列拿回后按 asof 二分/字典查，
  `date<=asof` 由「有序 + 精确命中」保证，不引入前视）。

### 1.4 runner 接线

`_replay` 里按 variant 判定：

- `need_mf = variant.spec.mu_mode == "mf_sign"`
- `need_val = variant.spec.mu_mode == "val_pe_pct"`

每个 (code, asof) 先算 `sign = load_mf_sign(...)` / `load_val_pe_pct_sign(...)`；
`sign is None` → 该 `(日, 标的)` 记入 `skipped`（**不回落**，两个 side 都不跑这一天这个 code？——
不：基线照常跑、只跳过变体侧并计数，见 §1.6）。

`sides` 元组扩为 5 元：`("variant", variant.spec, idx_dir, mf_sign, val_sign)`，
循环里 `compute_forecast(..., index_dir=idir, mf_sign=ms, val_sign=vs)`。

### 1.5 报告补「实际用变体的天数 vs 报告天数」

预注册要求报告**显式**给出「实际使用变体的天数 vs 报告天数」。做法：

- `run_experiment` 新增字段 `coverage = {"variant_days_used": N, "variant_days_skipped": M, "reported_days": R}`
  （`R = N + M`；`skipped` 里已有明细行）。
- markdown 渲染新增一段「变体覆盖：实际使用 N 天 / 跳过 M 天（明细见 skipped）/ 报告口径 R 天」。
- JSON 报告同字段。

### 1.6 skipped 语义（PIT 硬拒绝的落点）

沿用框架既有 `skipped` 机制：变体侧在 `(code, asof)` 缺资金流/估值行 → 该天该 code 的**变体预测**跳过并计数，
**基线侧照常**，配对指标只对「两侧都有预测」的天聚类（`pair_rows` 本已按并集配对）。
报告里 `skipped` 明细 + `coverage` 数字共同保证「实际用变体的天数」不被虚报。
基线侧缺行（bars 缺）沿用既有 skip 语义，不扩语义。
