## 1. 架构决策

### 1.1 变体预测**不落库**（最关键的一条）

`predictions` / `verifications` 是 append-only 生产表，且 `model_version` 是预测唯一键的一列。
若把实验变体写进去，会有两个后果：

1. 生产表被未经验证的实验预测污染，报告的分组口径被搅乱；
2. 违反「**只有 promoted 变体才允许新起 `model_version`**」这条约束。

**做法**：变体评估**全程在内存里跑**，一行都不写库。
打分与报告仍然走 P7 的**同一份代码**：

```
variant 预测  →  score.score_prediction(...)     # P7 打分口径，逐字复用
              →  report.summarize(...)           # P7 聚合口径，逐字复用
              →  report.render_markdown(...)     # P7 呈现口径，逐字复用
```

这不是「另写一套评估」，因为打分/聚合/呈现三层的**每一个数字**都由 P7 的函数算出。
唯一替换掉的是「预测从哪来」——那本来就是要变的那个变量。

**基线同栏对照怎么来**：同一次遍历里**同时**算基线预测与变体预测，
两者共享同一次 `load_pit_bars` / `load_scoring_bars` / `index_pct_for` 取数。
于是「同一天、同一根 bar、同一套成本」是结构性保证，而不是靠事后对齐日期。

### 1.2 变体 = 显式 spec，禁止隐式全局开关

新增 `predict.model.ForecastSpec`（frozen dataclass），`compute_forecast` 增加
**可选**参数 `spec: ForecastSpec | None = None`：

- `spec=None`（默认）→ 代码路径与 P6 **逐字节一致**（回归红线靠它保住）；
- 变体走 `spec=ForecastSpec(mu_mode=...)`，**显式传入**，无环境变量、无模块级开关。

字段只有一个：`mu_mode`，取值 `"sample_mean"`（基线）/ `"zero"` / `"index_sign"`。
`VariantSpec.changed_axis` 在注册表里声明「本变体改的是哪个变量」，
加载时用 `assert_single_variable()` 对数（与基线不同的字段数必须 **恰好 1**，且等于声明值）。

### 1.3 两个变体的操作性定义（单变量）

| 变体 | 唯一变量 | 基线 | 变体 |
|---|---|---|---|
| `rw-mu0` | `mu_mode` | `"sample_mean"`：`mu = fmean(最近 WINDOW 日对数收益)` | `"zero"`：`mu := 0.0` |
| `index-mom-dir` | `mu_mode` | 同上 | `"index_sign"`：`mu := |mu_sample| × s` |

`s` = `sh000300` 在 **`asof` 当日**的对数收益用 **同一根 `±0.5%` 标签带**分类后的符号
（`up → +1` / `down → -1` / `flat → 0`）。

- **为什么是「符号」而不是「指数收益率本身」**：指数的波动率与个股不同量纲，
  直接把指数收益当个股漂移项会同时改掉**尺度**——那就不是一个变量了。
  取 `|mu_sample| × s` 保留了基线漂移的**幅度**，只把它的**方向来源**从
  「个股自身 60 日动量」换成「指数前一日方向」。这是本变体唯一改掉的东西。
- **PIT 安全**：`s` 只用 `bars_daily` 里 `date <= asof` 的指数行（`asof` 与其上一交易日）。
  指数数据缺失 → `DegenerateInput` 硬拒绝（**不许**静默退回 `s=0`，那是拿「不知道」当「没有」）。

### 1.4 三段切分与「test 只打开一次」

`SplitConfig(train=0.60, validate=0.20, test=0.20)`，按**日期**在评分日轴上连续切分，
边界（首日/末日/天数）写进报告。

```
gate(validate) ∈ {WIN, LOSE, FLAT}
  WIN  = Δ方向按日配对 的 95% CI 下界 > 0  且  ΔBrier 的 95% CI 上界 < 0
  LOSE = Δ方向均值 < 0 或 ΔBrier均值 > 0      （至少一个指标符号是错的）
  否则  = FLAT（符号对但不显著）

WIN(validate) → 打开 test 一次 → WIN(test) ? promoted : falsified
LOSE(validate) → falsified（test 不打开）
FLAT(validate) → inconclusive（test 不打开）
任一决策 split 有效交易日 < 120 → inconclusive（覆盖上述全部）
```

**为什么用配对日差而不是两个独立均值相减**：基线与变体跑在**同一批日**上，
按日配对相减可以把当天全市场共同的涨跌（A 股同涨同跌）消掉，
剩下的才是「变体相对基线多出来的那点信息」。这是按日聚类纪律在**比较**上的落地。

**`test_evaluated` 标记**：validate 没到 WIN 就**不打开 test**，
报告如实写 `test_evaluated: false` 并给出原因 —— 这正是「禁止用 test 结果回头挑选变体」
的结构性实现。「test 赢不了就是 falsified/inconclusive」在 WIN 分支里照常适用。

### 1.5 口径冻结

- `METRIC_VERSION = "p8-metrics-v1"`，写进实验报告顶层；
  两个报告相比时 `assert_metric_version()` 不一致 → `MetricVersionMismatch`，**报错而不是照比**。
- 标签带冻结：变体 spec 里**不存在**改 `FLAT_BAND` 的字段；`summarize` / `score_prediction`
  都从 `predict.model.FLAT_BAND` 唯一取源，报告里打印实测值。
- 幂等：报告正文不含任何时间戳；同参数两次运行 sha256 必须相等。
