## 1. 任务拆分

### Task 26 — 统一策略接口 + 注册表（`stocklab/strategies/`）

**为什么单开一个包**：`backtest/strategies.py` 里的 `BuyAndHold` 自己声明为「非生产」。
生产策略要有**参数模式、必需特征声明、PIT 裁剪**三样东西，这些属于策略层不属引擎层；
且策略要能被 P6（预测）复用，塞进 `backtest/` 会让预测路径反向依赖回测内核。

**交付**
- `base.py`：`ParamSpec`（类型/默认/合法区间）、`resolve_params`（未知名/越界 → `ParamError`，**不 clamp**）、
  `Strategy`（抽象基类，`generate` 为模板方法 + `__init_subclass__` 禁止覆写）、
  `clip_history` / `clip_features`（**强制** PIT 裁剪）、`FeatureView`（只有声明过的字段可读）。
- `registry.py`：`StrategyRegistry`，`register`（重复 id → `DuplicateStrategy`）、
  `get`（未注册 → `NotRegistered`）、`meta`（参数模式，供报告展示）。
- `evaluate.py`：`evaluate_walk_forward(...)` —— **只接受 `strategy_id`**，
  内部经注册表取实例。这是「未注册策略不允许进评估」从口号变成接口约束的位置。

**关键设计决策（防前视的结构位置）**

| 决策 | 理由 |
|------|------|
| 裁剪放在 `Strategy.generate`（基类模板方法）**派发之前** | 与 Task 19 教训同款：防线要在结构上，不能靠调用方自觉。策略作者写不出前视代码，因为 `_generate` 根本收不到未来数据。 |
| `__init_subclass__` 禁止子类定义 `generate` | 否则子类覆写即可绕过裁剪。这是**类型层面**的保证，不是注释里的约定。 |
| `FeatureView` 未声明字段访问即抛 `UndeclaredFeature` | 直接实现「缺失字段不得当作 0 或默认值」：`features.get("regime_label", 0)` 这种写法**会抛错**。 |
| `features` 改为**日期键控**（`{date: {code: {...}}}`）并在引擎侧累积 ≤T 的快照 | 原先引擎只传当日的 `{code: {...}}`，策略层无从判断 PIT。改成日期键控后，策略层可以自己再裁一次（双重防线）。 |

**验证**：单测覆盖参数校验 / PIT 裁剪 / 特征声明 / 注册表语义；变异反证见 §3。

### Task 27 — `trend_ma` + `buy_and_hold`（对照）注册

**交付**
- `trend_ma.py`：MA20 上穿 MA60 买入、下穿卖出、ATR 止损（`fast=20, slow=60, atr_mult=2.0`）。
  **只用价量**（OHLC），`required_features = ()` —— 结构上读不到 `main_net_5d` / `pe_pct_3y` / `regime_label`。
- `buy_hold.py`：`buy_and_hold` 进注册表，与 `backtest/strategies.py::BuyAndHold`（单标的、非生产）
  和 `metrics.buy_and_hold_nav`（首日开盘买入）的口径差异写进 docstring 与报告披露。

**口径差异（必须披露，不许当成成本差异）**

| 实现 | 买入时点 | 用途 |
|------|----------|------|
| `metrics.buy_and_hold_nav` | 区间**首日开盘** | 基准净值曲线 |
| `backtest/strategies.py::BuyAndHold` | 首日收盘出信号 → **次日开盘**成交（滞后 1 日） | 引擎联通验证 |
| `strategies/buy_hold.py`（本任务） | 每折运行窗首日收盘出信号 → 次日开盘成交，**每折重新建仓** | walk-forward 同尺对照 |

第三行「每折重新建仓」会让成本被折数放大 —— 这一点写进报告披露，不粉饰。

**纪律**：`trend_ma` 参数**一律用文档默认值**，本任务不做任何搜索。
若默认参数跑不赢基准，**照实报告**（禁止为了「跑赢」调参 —— R7 红线）。

### Task 28 — walk-forward 串联 + 绩效报告

**交付**
- `evaluate.py::evaluate_walk_forward`：逐折 `run_backtest`（运行窗 = `train_start ~ test_end`，
  训练窗用于指标预热），样本外 NAV 复利拼接成连续曲线。
- 新增 CLI：`stocklab backtest strategy --strategy trend_ma --code 000333 --code 600690 ...`
  → `reports/2026-09-15-<strategy>-walkforward.{md,json}`。
- 报告必含：折数、**样本外交易日数**（`effective_n`，非行数）、总收益、年化、最大回撤、Sharpe、
  成交笔数、换手、成本合计、**index_300 同区间对照 + 是否跑赢**。

**每折用全新策略实例**：跨折共享状态会让第 k 折的仓位受第 k−1 折影响 —— 那是隐性泄漏。

**样本量口径**：沿用 Task 24 的 `sample_size_report` / `threshold_arithmetic`，
`effective_n` = **交易日**数，`oos_rows`（标的-日行数）只作核对、**不得**当样本量上报。
