# 回放成本口径 · 仓位假设 —— 设计评审

- **日期**：2026-09-21
- **评审对象**：`docs/superpowers/specs/2026-09-21-回放成本口径-仓位假设-design.md`（提交 `8d0ea8c`）
- **代码基线**：`feat/financials`，`stocklab/candidate/replay.py::period_returns` + `stocklab/config/costs.py`
- **证据**：本机实测（`/tmp/replay.db` 的 89,781 个 (标的×交易日) 价格点 × `CostModel` 实算），复现命令见 §附录
- **本评审的定位**：只给结论与最小改动清单，**是否改出 v2 由用户拍板**（未进入实现）

---

## 0. 结论

**方向对、可以做。** 「100 股当名义市值」确实是离群值而不是另一种口径，§5「跑之前把采信条件写死」+ §6「明说会翻转」也是防「调到好看」的正确姿势。

**但有三处必须先改，否则这一轮会把自己卡死或得出错误结论：**

1. **§5 / §8 的采信条件「逐位相同」不可达** —— 在「名义额 ≥ 2 万、最低佣金已不生效」的区间内，不同 N 档仍**不是逐位相同**（实测 5万 vs 10万：79.5% 的价格点费率不同，最大差 `1.486e-07`/笔）。按 §5 写死的规则，第一轮就会被自己判成「推导有误」而停摆。
2. **§3 的充分条件写错** —— 真正的条件是「**每笔实际名义额** ≥ 2 万」，不是「N ≥ 2 万」。实测 N=2 万时 **73.15%**（131,341 / 179,562）的计费点名义额仍 < 2 万（`int()` 向下取整所致）。
3. **滑点根本没被扣，而 ADR-017 D-04 声明要扣** —— `fee_ratio = fee / (qty × 成交价)` 的分母与 `fee` 用的是同一个成交价，5 bps 滑点在除法里被约掉了。量级 **≈ 0.045%/期**，与修正后的**全部**成本拖累（0.0454%/期）一样大，也正好是 §6「翻正」幅度的 65%。

另有一条 dormant 硬伤（空池→建仓期归一化放大 6 倍）、一条文档纪律问题和一条留痕问题，见 §2。

## 2. 必须改的

### R1（硬伤）§5 / §8 的「逐位相同」不可达

即便在最低佣金**完全失效**的区间，不同 N 档的费率也不是逐位相同的。实测（买卖双向 179,562 个计费点）：

| 档位对 | 费率不同的点 | 最大绝对差/笔 |
|---|---|---|
| 20,000 vs 50,000 | 173,866（96.8%） | `3.025e-05` |
| 50,000 vs 100,000 | 142,686（79.5%） | **`1.486e-07`** |
| 100,000 vs 500,000 | 176,811（98.5%） | `6.010e-08` |

**两个原因（都是实现细节，不是推导错）：**

1. `qty = int(N / px)` **向下取整** ⇒ 实际名义额 `floor(N/px) × px ≠ N`（N=10 万、px=173.66 时名义额 99,999.5 之类），分母不同。
2. `CostModel.fees()` 末尾 `round(commission + transfer + stamp, 2)` —— **舍入到分**。同一费率在不同 qty 下舍到不同的分。

差量比「是否绑最低佣金」小 3 个数量级，纯舍入噪声；但 §5 的判据是「**有任何一档不同 → 停止，说明我对最低佣金的推导有误**」，所以它 100% 会误报。**判据要改成容差式**（建议稿见 §4），并在测试注释里点名这两个原因。

### R2（硬伤）§3 的充分条件：是「实际名义额 ≥ 2 万」，不是「N ≥ 2 万」

`qty = int(N / px)` ⇒ 实际名义额 = `floor(N/px) × px < N`。实测「最低佣金仍生效」的占比：

| N | 名义额 < 2 万的计费点 | 最大正偏离（佣金费率 vs 常数费率） |
|---|---|---|
| 10,000 | 179,562 / 179,562 = **100.00%** | `3.911e-04`（0.0391%/笔） |
| 20,000 | 131,341 / 179,562 = **73.15%** | `3.041e-05`（0.00304%/笔）@ **贵州茅台 2,230 元 × 8 股 = 17,831 元** |
| 50,000 | 0 / 179,562 = **0.00%** | — |
| 100,000 | **0.00%** | — |

**结论不变，论证要重写：**

- 选 **10 万** 仍然稳（落在 0% 绑定区），C1 可以保留；
- 但 §3 的「N ≥ 2 万 ⇒ 完全相同」要改成「**每笔实际名义额 ≥ 2 万** ⇒ 佣金项等于纯费率项」，并给出闭式充分条件：`N ≥ 20,000 + px_max`（本池 `px_max = 2,601`（600519 历史最高收盘）⇒ **N ≥ ≈ 22,601** 才 100% 满足）；
- 2 万–2.26 万 是一段**过渡带**（最坏 0.003%/笔 ≈ 对 5 日池成本项 +3.8%、对净超额 +0.0694% 是 2.5%），量级可忽略，但**不能声称「逐位相同」**；
- 依赖 `px_max`：将来种子池若加入更高价标的，过渡带上界会跟着动 → 判据要写成判据式（看名义额），不要写成常数式。

### R3（硬伤，dormant）空池 → 建仓期的归一化放大 6 倍

```python
n_hold = max(len(hold), 1)      # hold == [] 时取 1
...
for c in new:                   # new = nxt - hold，空池时 = nxt 的全部 6 只
    fee_ratio += fee / (px * LOT) / n_hold     # ← 分母是 1，应该是 6
```

空池期组合 100% 现金，期末买入 `nxt` 的 6 只、每只名义额 = 组合 / 6，每笔费率相对组合应为 `1 / (6N)`；代码给 `1 / N` ⇒ **该期成本放大 6 倍**。

- 本仓库自己的注释（`replay.py` 194–196 行）只论证了**记账时点**（「新一期买入计入本期」），没有论证这个分母 → 判断为**宿病而非设计意图**。
- **当前零影响**：诊断实测空池率 0%（533 / 134 / 45 个调仓日全部满仓 短 6 / 中 8 / 长 5 只）⇒ 修正**不改变任何现有数字**。
- 但本设计改的正是这几行，且 C3 明确「`n_hold` 归一化方式不变」= 把这条错误**冻结**。建议二选一：
  - **(a) 顺手修**：`hold == []` 时 `n = len(nxt) or 1`，加一条钉住测试（空池 → 6 只建仓 ⇒ 成本 = 6 笔买入费 / (6N)）。因为改了不改数字，风险近乎零。
  - **(b) 不动**，但在 §9 已知限制里点名「空池→建仓期成本放大 `1/len(nxt)`，当前 0 空池故未浮现」。

### R4（硬伤，本次改动**直接相关**）滑点从未进入周期收益

设计 C2 的公式是「费率 = `fee / (qty × 成交价)`」。而 `fee` 正是用**同一个成交价**（`fill_price = px × (1 ± 5bps)`）算出来的 ⇒ **5 bps 滑点在除法里被彻底约掉**。

对照 `stocklab/backtest/portfolio.py`（122–123、154–155 行）：那里把 `fill_price` 当**真实成交价**写进现金与持仓 → 滑点是**计入**的。**同一个 `CostModel`，回放与回测两套口径**，且回放这一侧更乐观。ADR-017 D-04 原文写的是「成本 `CostModel` 扣：A 股最低佣金 5 元/笔 + 印花税 + **滑点**」⇒ **代码与 ADR 声明不一致**，属实现缺陷，不是口径选择。

量级（用 §2 的换手反推，每期 2.67 对买卖）：

```
滑点/期 = 5.38 笔 × 5 bps ÷ 6 只 ≈ 0.0448%
```

- 与修正后的**全部**成本拖累 `0.0454%/期` 同量级 ⇒ 等于说「修正后的成本几乎只有滑点那么大，而滑点没算」；
- 与 §6 要宣布的 `+0.0694%/期（跑赢）` 相比，占 **65%**。若如实计入，短期池净超额回落到 ≈ **+0.024%/期** —— 仍在噪声内，「由负转正」这句话就站不住了。

**最小修法（二选一，建议 (a)）：**

- **(a) 如实计入**：每笔成本率 = `(|成交价 − 收盘价| × qty + 费用) / (px × qty)`，并加一条测试钉住「滑点确实进了成本项」（`slippage_bps=0` 与 `=50` 两个模型结果必须不同）。
- **(b) 不改**：§9 与报告里写死「**本口径不含滑点**」，并把 §6 的措辞降级为「+0.069%（未含滑点；含滑点约 +0.024%）」，**不得**直接说「短期池跑赢」。

同时 §9.3「滑点 / 印花税 / 过户费与 N 无关（都是比例费率），本设计只修最低佣金那一项」这句要改：把滑点与另两项并列，会让读者以为滑点已经扣了。

### R5（文档纪律）C4 就地改写 ADR-017 D-04 会抹掉留痕

`2026-09-20-沙盒真回放-验收记录.md` 里 `−0.4228%`（395 / 408 行）等数字的**唯一解释**就是「当时按 100 股名义市值扣成本」。就地改写 D-04，日后无法回答「为什么 2026-09-20 的记录是 −0.42%」。按本仓库自己的先例（ADR-017 D-04 的 Fix Wave 用「原写…有误」+ 追加说明；验收记录保留作废节）：

- **保留 D-04 原句** + 标注「**已被 D-12 取代**（2026-09-21：每只按 `POSITION_NOTIONAL` 元名义仓位计）」；
- 或**新增 ADR-018**（我更推荐：这是一条独立决策，要承载 §3 的推导与 §5 的采信条件，塞进 D-12 会让 ADR-017 变胖且难引用）。

### R6（留痕）§2 的成本分解只活在设计文档里

全库 `grep`：`+0.5375%` / `+0.2064%` **只出现在这份设计文档的 §2**；`−0.4228%` 在验收记录里，但「毛超额 / 成本拖累 / 净超额」三元组、空池率 0%、换手 45% 这些都只在设计文档或 `/tmp/replay.db` 里 —— **`/tmp` 会被清理，C5 的重跑数字届时无从对照**。

建议：把诊断固化成 `scripts/replay_cost_probe.py`（`--db` 参数化）+ 输出落 `artifacts/`/评审附录。顺带把「平均选中标的价」也打出来：按 A2 的反推应 ≈ **8–10 元**，若实跑是 40 元量级，说明 §2 的反推链有问题，要回头查（这条正是让口径修正**可当场验证**的抓手）。

## 4. 建议的采信条件（替换 §5）

**跑之前写死，不看结果改。** 三条**独立**断言，任一不过则停：

| # | 断言 | 预期（基于本机实测） | 不过时怎么办 |
|---|---|---|---|
| E1 | **结构性**：对全部 (标的 × 调仓日) 价格点，`floor(N/px) × px ≥ 20,000` | N = 50,000 / 100,000 / 500,000 三档 **100% 满足**；N = 1 万 / 2 万 不满足（100% / 73.15%） | 说明 px_max 变了或取整口径变了 → 重算充分条件，**不是**「推导有误」 |
| E2 | **数值**：N ∈ {5万, 10万, 50万} 三档，逐周期收益序列最大绝对差 `≤ 1e-6`（费率层 `≤ 1e-9`），且**符号不变** | 费率层实测最大差 `1.486e-07`（5万 vs 10万）⇒ 周期层约 `1e-7` 量级，`1e-6` 有充分余量 | 先查 `int()` 取整与 `round(..., 2)`，**不得挑 N** |
| E3 | **边界（反向证伪）**：N = 1 万 与 N = 10 万 必须**可分辨** | 费率层 100% 的点不同，最大差 `3.914e-04`（0.039%/笔） | 若相同 ⇒ 最低佣金没生效 ⇒ 真推导有问题，回来重查 |

**为什么不再写「逐位相同」**：它把两个无关实现细节（`int()` 取整、`round(...,2)`）的噪声误判成逻辑错误，会让人在错误的地方停下（R1）。**为什么保留 E3**：只有「大 N 之间不可分辨 + 小 N 可分辨」两条同时成立，才构成「2 万以上是常数区间」的完整证据。

## 5. 附录：复现命令

```bash
cd ~/Documents/Workspace/stock
/opt/homebrew/bin/python3.12 - <<'PY'
import sqlite3, sys, itertools
sys.path.insert(0, '.')
from stocklab.config.costs import CostModel
from stocklab.candidate.seeds import SEED_CODES
conn = sqlite3.connect('/tmp/replay.db'); conn.row_factory = sqlite3.Row
c = CostModel()
NS = [10000, 20000, 50000, 100000, 500000]
rows = [(code, float(r[0])) for code in SEED_CODES
        for r in conn.execute("select close from bars_daily where code=? and close>0", (code,))]
print("价格点 =", len(rows))                       # 89,781

def fee_ratio(side, px, N):
    qty = max(1, int(N / px))                      # 与设计 C2 一致
    fill, fee = c.total(side, px, qty)
    return fee / (fill * qty), qty, fill * qty     # 分母 = 成交价 ⇒ R4 的滑点约掉

tab = {}
for N in NS:
    bind = 0; worst = (0, None)
    for code, px in rows:
        for side in ("buy", "sell"):
            rr, qty, notional = fee_ratio(side, px, N)
            tab[(code, px, side, N)] = rr
            comm = max(notional * c.commission_rate, c.min_commission)
            if comm > notional * c.commission_rate + 1e-12:
                bind += 1
                dev = comm / notional - c.commission_rate
                if dev > worst[0]:
                    worst = (dev, code, px, side, qty, round(notional, 2))
    print(f"N={N:>7,}: 最低佣金生效 {bind}/{len(rows)*2} = {bind/(len(rows)*2):.2%}", worst)

for a, b in itertools.combinations(NS, 2):
    worst = 0.0; nd = 0
    for code, px in rows:
        for side in ("buy", "sell"):
            d = abs(tab[(code, px, side, a)] - tab[(code, px, side, b)])
            nd += d > 0; worst = max(worst, d)
    print(f"{a:>7,} vs {b:>7,}: 不同 {nd}/{len(rows)*2} = {nd/(len(rows)*2):.1%}  最大差 {worst:.3e}")
PY
```

**依赖**：`/tmp/replay.db`（2026-09-21 诊断所用库：`bars_daily` 92,446 行、`1993-11-19 → 2026-09-18`，其中 `close > 0` 的 **89,781** 个 (标的 × 交易日) 计费点；`600519` 最高收盘 2,601 元）。**它会没** —— 见 R6。

**本评审未复核的两条**（来自设计文档，未独立验证，建议 C5 重跑时一并输出）：
1. 空池率 0%（需要 712 次 `score_pipeline`，≈ 20 min，本次未跑）；
2. 换手率 45%/期（已由 §2 的拖累数字**间接反推**一致，见 A2，但未直接测）。
