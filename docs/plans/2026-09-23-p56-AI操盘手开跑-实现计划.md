# P56 AI 操盘手开跑 —— 实现计划

> 任务书（唯一真源）：[`docs/tasks/2026-09-23-p56-AI操盘手开跑.md`](../tasks/2026-09-23-p56-AI操盘手开跑.md)
> 口径：[`docs/plans/2026-09-21-需求澄清录.md`](../plans/2026-09-21-需求澄清录.md) §8.6 的 D-48 / D-49 / D-50

**目标**：把 P52 的决策台账接成**能日更跑**的操盘手 —— AI 臂的日终认领权从 `paper step`
划给决策循环，并补齐「PIT 输入唯一源 / 预注册机械执行 / 缺决策看得见」三样缺的东西。

**架构**：不改 `engine.external_executor` 的**让出逻辑本身**，只把「谁写 `params.executor`
这个键」从只有通路 A 扩到 `agent_decision`；`_step_all` 多一个 `claim_handover` 开关，
让新命令 `paper agent run` 作为**被指定的执行者**绕过让出（让出仍然照旧作用于 `paper step`）。

**技术栈**：Python 3.12 / SQLite / argparse / pytest（全离线 fixture）。

## 全局约束（每个任务都隐含包含）

- 真库 `data/stocklab.db` **只读**；写库验证一律在 `/tmp` 的 `cp -c` 副本上做。
- 不改主干常量（成本口径 / PIT 判据 / 整手 / 护栏 / 熔断阈值）；不做参数搜索。
- `ops/chain.py` **不碰**；不把 `paper agent run` 塞进 `CLOSE_STEPS`，也不在 `ops patrol` 里补跑。
- 项目内零 API key、零联网、零模型调用（`enroll` 只存 `model_id` 字符串）。
- 不 `git commit`、不建分支/worktree。
- 既有用例只许**同步改写**、不许删。
- 解释器 `.venv/bin/python`；基线 `2788 collected / 2786 passed / 2 skipped`。

## 两处判断（任务书未明写，本站按最严口径落地，实施记录里点名）

1. **预注册是硬闸门**：`paper agent decide` 要求账户行里有预注册；**没有预注册即拒**
   （点名报错，exit 2、零写入）。理由：§1.4「预注册是机械的」＋硬约束 2「一个字都不许松闸门」
   ＋硬约束 6 的 fail-closed 精神。**后果（必须上报）**：内置 `arm-agent` 从此不能再写
   `llm` 决策，只能跑平盘 + 页面显示「今日无决策」；接模型必须开 `arm-agent-<版本>`（D-48）。
2. **`context_sha256` 由 `validate_payload` 机械校验**：新增可选的 `expected_context_sha256`
   参数；CLI 的 `decide`/`random` 两条路径**总是**传入真值 ⇒ 载荷缺该键或不一致一律拒
   （D-49）。`validate_payload` 的直接调用方（纯函数用例）不受影响 —— 默认 `None` = 不启闸。
