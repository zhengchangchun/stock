## 1. 页面内容（与设计一致）

- **当前快照**块：快照 `#id` / `asof · run_kind` / 参数（种子 21 只 · TOPN 短6 中8 长5）/
  生成于（**+08，并同时标注库中 UTC 原值**）/ 成员行数 · 淘汰条数 / 报告路径；
- **快照选择器**：一条一个链接（`?asof=…&run_kind=…`），当前那条带 `aria-current`；
- **三池分区**：代码 / 名称 / 原始分 / 调整分 / 理由 / 风险 / 状态；表格按
  `load_snapshot` 的 `(pool, adj_score DESC, code)` 顺序，**页面不重排**；
- **淘汰记录**：按 `stage` 分组（盘前排雷 / 行业排雷 / 打分未过），条数在首屏、明细进 `<details>`；
- **未出现差集**：`SEED_CODES − 成员 − 淘汰`，附「这是差额不是原因」的说明；
- **诚实性**：`risk_json == []` → 「无」；解码失败 → 「风险明细解析失败（原文…）」；
  `plugin_id IS NULL` → 「未知」；空池 → 「本池为空」（不写 0）；无快照 → 「还没有跑过候选池」（不显示空表格）；
  请求的 `(asof, run_kind)` 不存在 → **回落到最新一条并明说**（不是一个走不到的 404）。

## 2. 写路径（`POST /candidate/run`）

1. `_token` **先于一切**：失败 403，库一个字节不动（有测试钉住）；
2. token 一律 `ctx.lab.asof` 签发/校验（§3.1）—— 用**快照 asof** 签的 token 有反向用例钉住必须 403；
3. 参数校验：`asof` 走 `date.fromisoformat`（严格 `YYYY-MM-DD`）、`run_kind ∈ {light, weekly, quarterly}`，
   非法 → **400 且不写库**；
4. `ensure_schema()`（P33）→ 起子进程跑 `candidate run`（见 §5.1）→ 读回 `snapshot_id`；
5. 303 回 `GET /candidate?asof=…&run_kind=…&ran=new|exists&sid=…`（PRG；刷新不重发），
   页面据 `ran` 给横幅：「已跑出新快照 #N」或「已有快照 #N，**未重跑**（幂等）」；
6. 失败（超时 / 非零退出码 / 退出码 0 却没落快照）→ **500 + 子进程原话**，不吞错。

## 5. 与设计稿的三处偏离（都要你过一眼）

### 5.1 写路径改成**子进程跑 CLI**（必须改，否则按钮点不了）

设计稿写的是「请求线程里直接调 `run_candidate`」。**实测做不到**：插桩执行器的超时用
`signal.setitimer`，而 `signal` 只允许主线程调用（`stocklab/plugin/runtime.py` 的模块 docstring
早就写明这条约束），labweb 是 `ThreadingHTTPServer`，请求都在工作线程里 ——
实测第一个插桩调用就抛 `ValueError: signal only works in main thread`，
客户端只看到 `RemoteDisconnected`（服务端有完整 traceback，客户端啥也没有）。

改法：`POST` 起子进程 `python -m stocklab.cli.main candidate run --db … --asof … --run-kind … --out …`
（`cwd` = 仓库根，`PYTHONPATH` 显式给）。子进程的主线程满足 signal 前提，**沙盒一行不改**，
页面与命令行仍是同一段生产代码（§3.1 的「同源」用例就是钉这条）。附超时 300s（实测一次 <1 秒）。
已记入 `docs/errors/ERROR_DIARY.md` **#45**。

### 5.2 `write_report_file` 落在 `candidate/report.py`，不是 `cli/candidate.py`

设计 §4.2 写的是 `cli/candidate.py`，评审说「`candidate/run.py` 或 `cli/candidate.py` 都行」。
我放在 `candidate/report.py`：文件名规则与「渲染报告」同属报告模块，
且 `labweb` 不该依赖 `cli`（跨层依赖会绕回来）。CLI 与页面都调它，**产出物仍同源**。

### 5.3 快照选择器是**链接**，不是 `<select>`

原生 `<select>` 只能提交一个参数，而快照的唯一键是**两个**（`asof` + `run_kind`）——
要塞进一个控件就得自己发明分隔符并再解析一遍。链接既保住 §3.2 的 URL 契约
（`?asof=…&run_kind=…`），又零 JS。当前库里 2 条快照，一屏内可点。

> 另两处**与设计一致、但值得记一句**：「最新」= `created_at` 降序（同秒按 `(asof, run_kind)` 字典序）；
> 「已存在 / 新跑」在子进程方案下改为「跑之前查一次」（`RunResult.skipped` 跨进程拿不到）。

### 6.1 第二轮归因（2026-09-21 补做）：两个变量＋一个空账本 —— 确定是「库变了」，不是回归

第一轮只证明「与本次候选池改动无关」。第二轮做了**单变量实验**：把库副本的 `instruments`
里非 09-16 清单的 15 只个股全部置 `active=0`（只留 `000333`/`600690`＝ 09-16 的
`DEFAULT_UNIVERSE`），再重跑 `check_redlines.py --only predict`：

- `.evidence.000651.*` 整段差异**消失** ⇒ 那部分来自「标的清单 6 → 21」；
- 但 `n_bars_used 6062 → 7807`、`.evidence.600690.inputs.first_bar "2001-01-15" → "1993-11-19"`
  **仍在** ⇒ 还有第二个变量：**同一只标的的历史被向前回填了**。

直查库（`data/stocklab.db`）印证：

| 标的 | 行数 | 起 | 止 |
|---|---|---|---|
| 600690 海尔智家 | 7811 | **1993-11-19** | 2026-09-18 |
| 000651 格力电器 | 7013 | 1996-11-18 | 2026-09-18 |
| 000333 美的集团 | 3099 | 2013-09-18 | 2026-09-18 |

`n_bars_used = 7807` ≈ 600690 的 7811 行（去预热）⇒ 模型吃的是**该标的全历史**，
历史一向前回填，`mu`/`sigma`/`drift_t` 与 `direction` 全跟着动 —— 这是**数据变多了**，不是代码回归。
`/tmp/replay.db`（09-21 00:21 的副本）已含长历史 ⇒ 回填发生在 09-20 那次
`ingest bars --days 12000` 前后（`system_events` 里没留痕，只能由数据本身推断）。

**backfill 那条是另一回事，而且更重**：它的差异是 `.model_versions.pit-rw-v1.0.1.*` **整棵子树消失**
（89 个数字叶子），原因直查库即明——本机 `data/stocklab.db` 里
`predictions = 0 行`、`verifications = 0 行`：它（09-21 从 `/tmp/replay.db` 落下的那份）
**根本没有预测/验证账本**，而基线是 09-16 在一份**有内容**的库上取的。
⇒ 这条红线在本机**要等数据链真的写出 predictions/verifications 之后才有意义**。

顺带查清一个容易误读的设计事实：`predict run` 的标的清单取自**库里的 `instruments` 表**
（`active=1 AND type='stock'`，`stocklab/predict/service.py`），**不是**代码常量 —— 所以
「改代码里的种子清单」本身不改预测口径，得 `ingest` 把新标的写进库才算。

**结论**：两条真实库红线转红＝ **库变了**（标的 6→21、历史回填到位、且当前库缺预测账本），
与本次候选池改动、与任何代码回归**都无关**。按基线文件口径，前两个变量属于
「有意且已归因 ⇒ 可重新基线」；但 `backfill` 那条**不能只靠 regen 掩盖** —— 得先跑出账本
（或明确改成「库里没有账本时就跳过」）。`--regen` 与台账 append 仍等你点头（§7 第 2 条）。

**若要重新基线，落地清单（照做即可）**：

1. `.venv/bin/python scripts/check_redlines.py --regen`（会重写三个条目；
   `predict_synthetic` 是 hermetic 的，值应当**零变化** —— 变了就说明有真回归，先查那里）
2. 往 `docs/plans/2026-09-15-p8-实验流水线.md` 与 `docs/experiments/README.md` **只追加不删**：
   旧值 `b69afb71…` / `18f2eeef…`（失效于 2026-09-21；原因：库扩充 —— 标的 6→21、
   600690 历史回填至 1993-11-19、本机库 `predictions/verifications = 0`），新值＋日期＋本节为证据。
3. 建议同时把「**库指纹**」写进两个 `real_db` 条目（`universe` 代码清单、各标的 bar 起止与总行数、
   账本行数），以后再红时能一眼分辨「数据涨了」还是「代码变了」—— 这条动 P25 的产物，**等你点头**。
