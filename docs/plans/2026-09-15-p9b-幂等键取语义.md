# P9-b 计划 · 实验决策台账的幂等键改取语义

> 只做这一件事：**换幂等键**。不开新实验、不动任何闸门数字、不重跑除自证以外任何变体。

## 1. 问题（ERROR_DIARY #17，已核实）

`experiment_decisions` 的幂等键含 `report_sha256`（**整份报告字典**的哈希）。
后果已实际发生：上一轮修 #16 那句「谎报 gate=WIN」的文案 → 报告文本变 → 哈希变 →
判定成「新决策」→ `inserted: 4`，`sigma-vol-z` 从 4 行涨到 8 行，台账 **16 → 20 行**。

代码注释写的是「覆盖全部闸门数字」，实现是「覆盖一切文本」——
**改一个标点就多判一条决策**，append-only 台账被措辞刷行。

## 2. 目标 / 非目标

**目标**

1. 幂等键改成语义键：`(variant_id, split, metric, metric_version, gate_status, delta, ci_low, ci_high)`。
2. 措辞 / 时间戳 / 排版 / `report_sha256` 都不再进键。
3. 既有 20 行台账**一行不动**（append-only，不回删、不改写、不加作废字段）。
4. 用测试钉住两侧：只改措辞 → 幂等；任一闸门数字变 → 新决策。
5. 端到端自证：重跑 `sigma-vol-z` → `inserted: 0, identical: 4`，台账仍 20 行，数字逐位一致。

**非目标（硬红线）**

- 不改任何闸门数字 / 口径 / 标签带 / 切分边界 / 标的集合；`test_evaluated` 仍为 `false`。
- 不重跑其他变体、不新增变体、不碰采集、不挂 cron、不扩池。
- `predictions` / `verifications` 各 6055 行不得被写；基线 sha256 `a61d026b…f4eb` 不变。
- 不删既有测试、不改断言凑绿。

## 3. 设计决策

### 3.1 键 = 语义；比较集 = 语义 + `decision`

- `IDEMPOTENCY_KEY`（查库用的 WHERE 条件）严格按上面 8 个字段。
- 命中后「是否 identical」的比较集 = `IDEMPOTENCY_KEY + ("decision",)`，
  **排除 `report_sha256`**。`decision` 是整场实验的 verdict，属决策内容；
  它不在键里，但可以不同 —— 键字段全等却 verdict 不同 → 说明结论来源不同
  （`selection_split` / `test_evaluated` 这类不进键的开关不同）→ 仍抛 `DecisionConflict`，不静默。
  这样错误路径（不覆盖、不静默）不变成死代码。

### 3.2 `report_sha256` 仍在表里，只是不进键

列保留、照常写入、照常可查（审计要它指回报告文件）；它只是**不再参与身份判定**。
CLI 不因此改动。

### 3.3 空值比较必须 null-safe

`delta` / `ci_low` / `ci_high` 可为 `NULL`（`INSUFFICIENT` 段无 CI）。
SQLite 里 `NULL = NULL` 为 NULL（假）→ 老的 `=` 会让「同一条决策」查不到 → 重复插入。
改用 `IS`（SQLite 的 null-safe 等值）。（这是本键从「必含 sha」改宽后才会暴露的坑：
以前 sha 一定非空，能兜住。）

### 3.4 DDL 同源：新库新约束，老库不动

`schema.sql` 的 `UNIQUE` 与 `IDEMPOTENCY_KEY` 同源，一起改。
**但既有库不迁移**：SQLite 改 UNIQUE 要重建表 = 改写历史，违反 append-only。
既有库保留老约束，那 4 行重复是新键生效前的历史遗留，**只记账、不清算**。

## 5. 风险与既有测试的处置（**必须留痕**）

三条既有测试用 `report_sha256` 当「换配置」的替身，键一改就失效。
处置原则：**保住原意，换掉替身**，不改宽断言。

| 测试 | 原意 | 键改后的问题 | 处置 |
|------|------|--------------|------|
| `test_a_changed_report_appends_new_rows_instead_of_rewriting` | 换了区间/配置 → 追加，旧行保留 | 只改 sha，数字没变 | 改成**改闸门数字**（delta）+ 新 sha → 追加；原意不变且更真实 |
| `test_same_key_with_different_content_is_refused_not_overwritten` | 同键内容不同 → 抛错 | 改 delta 现在=新键 | 改成**同键不同 `decision`** → 仍抛 `DecisionConflict` |
| `test_conflict_rolls_back_the_whole_batch` | 部分写入比不写更糟 | 同上，靠改 gate 撞键 | 前几行改数字（新键），末行同键不同 `decision` → 批量回滚 |

> 这三条不是「凑绿」：它们断言的行为（追加 / 拒覆盖 / 整批回滚）**一条没少**，
> 换的只是触发条件的替身。替身当初能成立，正是因为键取宽了 —— 键一改，替身自然失效。
