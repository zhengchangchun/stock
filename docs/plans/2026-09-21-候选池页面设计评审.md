# 候选池页面（模块1 展示层）—— 设计评审

- **日期**：2026-09-21
- **评审对象**：`docs/superpowers/specs/2026-09-21-候选池页面-design.md`（提交 `8d0ea8c`）
- **代码基线**：`feat/financials`，`stocklab/labweb/`（app 653 行 / render 1,295 行 / data 351 行）、`stocklab/cli/main.py::cmd_lab_serve`、`stocklab/candidate/{run,snapshot,seeds}.py`
- **证据**：本机实测（读 `/tmp/replay.db`，并在 `cp` 出来的 `/tmp/candprobe.db` 上真跑过一次 `candidate run`），命令见 §6
- **定位**：只给结论与最小改动清单，**是否改出 v2 由用户拍板**（未进入实现）

---

## 0. 结论

**落点和边界都对，但按现在的写法有 4 处会直接做不出来 / 做出来是错的。**

- 结构选择（扩现有 lab 应用、新开 `cand_data.py` / `cand_render.py`、`render.py` 只动 NAV 一行、写路径复用 `run_candidate`）**全部认可**，理由（`render.py` 66KB 不该再塞）成立。
- 但：**Context 加必填字段会打破 §6 自己的「现有三个测试文件一条不改」**（W1）；**本页 asof 是历史日期，用它签 `_token` 会永久 403**（W2）；**asof 不是快照的唯一键，同一 asof 跑一次 `light` 页面立刻歧义**（W3）；**「名称」列没有数据源，与 §5「只读三表」自相矛盾**（W4）。
- 另有一条**数据事实必须写进设计**：**「淘汰记录」不是完整差集** —— 实测 21 只种子 → 13 只入池 + **1 条淘汰** + **7 只既不入池也没有淘汰记录**，而两个旧快照的淘汰是 **0 条**。页面若只显示淘汰区，用户最想问的「另外几只知道去哪了」就成了黑洞（S1）。

## 2. 硬伤（必须改）

### W1 `Context` 加**必填**字段 ⇒ §6 的「现有三个测试文件一条不改」做不到

设计给的签名是 `lab / cand / signer / base_path`，`cand` 无默认值。但现有构造点全是关键字形式，**缺 `cand` 会直接 `TypeError`**：

| 位置 | 代码 |
|---|---|
| `stocklab/labweb/app.py:624` | `Context(lab=Lab(db_path, asof=asof), signer=..., base_path=...)` |
| `tests/test_labweb_app.py:54 / 593 / 620` | `Context(lab=Lab(...), signer=TokenSigner(SECRET))` |
| `tests/test_labweb_overview.py:78` | `Context(lab=Lab(...), signer=...)` |

**最小修法**：字段放到**最后**并给默认值 —— `cand: CandLab | None = None`（模块2 的测试不碰 `/candidate`，`None` 不影响它们）；生产路径在 `cmd_lab_serve` 里显式注入 `cand=CandLab(db)`。若坚持「必填」，就等于承认要改那 4 处测试 —— 与 §6「无回归」自相矛盾，二选一必须写明。

**顺带补漏**：§2 的文件清单漏了 **`stocklab/cli/main.py`（`cmd_lab_serve` 构造 Context 处 +1 行）**。不列出来的后果是「新页面在测试里全绿、一 `lab serve` 就 500/TypeError」。

### W2 本页 asof 是**历史日期**，绝不能用它签 `_token`

`_token_ok(ctx, fields)` 的实现是 `ctx.signer.verify(token, today=ctx.lab.asof)`（`app.py:163-164`），而 `verify` 只接受「该 day 与其前一天」。实测：

```
mint("2026-09-18")  → verify(today=ctx.lab.asof=2026-09-21) == False   # 快照 asof 签的 token
mint("2026-09-21")  → verify(today=ctx.lab.asof=2026-09-21) == True    # ctx.lab.asof 签的 token
```

候选池页的 asof **恒为库里快照的历史日期**（§3 明确「不是今天」），所以实现者顺手写成「表单 `_token` 用本页 asof 签」→ **写路径永远 403**，且报错文案是「无权限」，看起来像系统坏了。

**最小修法**：设计里写死一条 —— 候选池页表单的 `_token` **一律用 `ctx.lab.asof` 签发与校验**（即复用 `_token_ok`，不新写一套），跨零点由既有的「今天+昨天」窗口兜住。§6 的「写：无 token → 403」用例补一条反向用例：**「用快照 asof 签的 token → 必须 403」**（把这条坑钉住，而不是靠注释）。

### W3 「asof 选择器」不足以定位一个快照：快照键是 `(asof, run_kind)`

`candidate_snapshots` 的 UNIQUE 是 `(asof, run_kind)`；而 §4 的写路径允许 `light` / `weekly` / `quarterly`。于是**一次点击就能造出歧义**：用户在 `2026-09-18` 上跑一次 `light`，从此 `/candidate?asof=2026-09-18` 有两条候选快照，页面要取哪条没有定义。（当前库里恰好只有 `weekly`，所以这个洞在验收时**不一定**暴露，上线第一天必暴露。）

**最小修法（推荐 ①）**：

1. 选择器列出 **`(asof, run_kind)` 组合**（label 写成 `2026-09-18 · weekly`），URL 带两个查询参数；或
2. 保留单参 `asof`，但**明写排序键**（`ORDER BY asof DESC, run_kind` 还是 `created_at DESC`）并在页面上显示「实际取到的是哪一条快照 #id · 哪个 kind」，歧义时并列显示。

无论选哪个，§3 的「默认最新一条」都要把「最新」定义清楚（按 asof 还是按 created_at —— 实测快照 #1 的 asof 比 #2 新，但两者 created_at 只差 4 秒，这两者不是一回事）。

### W4 「名称」列没有数据源，与 §5「只读三表」冲突

三段分区表都有「名称」列，但 `candidate_members` 的列是 `snapshot_id / code / pool / raw_score / adj_score / reason / risk_json / status / entered_at` —— **没有 `name`**（实测 schema 与真数据一致）。名称只在 `instruments.name`。

**最小修法**：§5 改成「只读 `candidate_*` 三表 + `instruments`（只取 `code → name`，只读）」，或把「名称」列从 §3 去掉。前者更符合「页面回答『系统选出了什么』」的初衷（用户记 6 位代码不划算）。

## 3. 该补的（不是错，但不补会在验收时发现「看不到」或「看到的不是全部」）

### S1 「淘汰记录」不是完整差集 —— **这是本设计最该补的一条**

实测（新跑 `2026-09-11 weekly`，`/tmp/candprobe.db`）：

```
入池：短期 6 / 中期 8 / 长期 5（跨池去重后 13 只）
淘汰：1 条 —— 002032 / stage=pre_screen / reason=consecutive_limit_down / plugin_id=NULL
既不在 members 也不在 rejects 的种子：7 只
  = 000858 五粮液、600690 海尔智家、600941 中国移动、300750 宁德时代 + 4 只 ETF
```

两个**旧快照的淘汰记录是 0 条**（`candidate_rejects` 只有新跑那次写过 1 行）。也就是说：**页面照 §3 做出来，在真实数据上「淘汰记录」区要么空白、要么只有 1 条，而 21 只种子里有 7–11 只去向不明。**

而这恰恰是本页的立身之本（「系统选出了什么、**为什么**」）。建议：

- **最少**：淘汰区加脚注「只含被显式记录的淘汰，**不构成完整差集**（实测 21 只种子 → 13 只入池 / 19 个池内席位 + 1 条淘汰）」；
- **更该做**：加一块「**未出现**」差集 = `SEED_CODES − members − rejects`，并明说「这些标的既未入池、也没有淘汰记录 —— 原因不在快照里」。注意这需要引入 `candidate.seeds.SEED_CODES`（常量，不是表），并注明「种子清单是**当前**常量，快照时点的清单可能不同」（`params_json` 只存 `seed_count`，不存清单）。

顺带：这也是一条**要上报的缺陷线索**（为什么 ETF 与部分个股会静默消失、为什么旧快照淘汰为 0）—— 值得在设计里点名，别让页面的静默把问题藏住。

### S2 `reason` / `stage` 是机器名，`plugin_id` 可能是 NULL

实测淘汰行：`stage=pre_screen`、`reason=consecutive_limit_down`、`plugin_id=NULL`。§3 的规则表只说了 `risk_json` 要「原样展示 + 解码失败明说」，没说这两列。按本仓库既有规矩（`render.py` 的 `STATUS_CN` / `CHECK_CN`「**只换标签，不改判据**；认不出的原样显示机器名」）：

- 加一张 `stage` / `reason` → 中文的映射表，认不出就显示机器名；`NULL` 显示「未知」（不写 0、不写空）。
- 同理 `risk_json == "[]"` 是**已知的「无风险项」**，应显示「无」，不要显示「0 条」（与 §3 自己那条「不写 0」的规矩对齐）。

### S3 `created_at` / `entered_at` 是 **UTC**，页面必须转 Asia/Shanghai

实测快照 `created_at = "2026-09-20T08:38:06.386144+00:00"`（CLI 用 `datetime.now(timezone.utc)`，`candidate.py`）；而 labweb 其它页面的「页面生成于」走 `data.py::now_iso()`（Asia/Shanghai）。设计 §3 画了「生成于 2026-09-18 17:22」但没说转换 ⇒ 不写清楚就会**同一屏里两个时间差 8 小时**。一行说明即可：渲染前用 `data.TZ` 转本地，与 `now_iso()` 同源。

### S4 页面跑不落 markdown 报告，CLI 落 —— 同一件事两套产出

`cmd_candidate_run` 里除了跑 `run_candidate`，还**总是**把 `result.report_md` 写到 `reports/candidate/<asof>-<run_kind>.md`（`skipped=True` 时也写）。设计的 POST 只调 `run_candidate` ⇒ **页面跑过的 asof，报告文件不存在**；用户按文档去 `reports/candidate/` 找会找不到，而这与「页面不另写一套逻辑」的原则相冲突（产出物都不同源了）。

**最小修法**：把 CLI 里那段（`out = ...; out.parent.mkdir(...); out.write_text(...)`）抽成一个共享函数（例如 `candidate.run.write_report_file(result, out_dir)`），CLI 与页面都调它。

### S5 「库不存在」这条 UI 分支**只有测试可达**

`cmd_lab_serve` 在起服务前就 `if not db.exists(): return 2`，**根本进不到页面**。所以 §3 的「库不存在 → 明说『数据库文件不存在：<路径>』，不是 500」与 §6 的同名用例只能靠直接调 `handle(ctx=...)` 命中。这不是错（fail-fast 更好），但设计要**明说**，否则验收时会反复尝试却看不到那句话。

同理两点实测补充：

- 起服务前还有一次**模块2 预检**（`ctx.lab.overview()`，失败退出码 2）。我实测它在 `/tmp/replay.db` 上**成功**（不会挡住本页），但这条依赖值得在设计里记一笔：**本页的可达性依赖模块2 能算出来**；
- `lab serve` 启动时就调 `ensure_schema(db)` ⇒ **打开 `/tmp/replay.db` 这件事本身会前滚 schema（写库）**。若想绝对只读地看，验收命令应先 `cp` 一份（§5 的验收步骤建议补 `cp /tmp/replay.db /tmp/probe.db`）。

### S6 §3 的 mock 和真实数据不符（会让实现者照着一个不存在的状态做 UI）

| mock 展示 | 真实（快照 #1，`/tmp/replay.db`） |
|---|---|
| 短期池 3 只、首行 `000333 美的集团 82.1 / 74.3` | 短期池 6 只、首行 `603868 飞科电器 82.14 / 77.14`（000333 在 mid/long，不在 short） |
| 中期池「本池为空」 | 中期池 8 只 |
| 淘汰记录 18 条（行业排雷 2 + 打分未过 16） | **0 条**（两个旧快照都是 0） |
| 快照 #2 · 2026-09-18 · 生成于 17:22 | 2026-09-18 是**快照 #1**，`created_at` 是 UTC 08:38（北京 16:38） |

建议：mock 直接抄真实快照 #1（短 6 / 中 8 / 长 5、淘汰 0），把「空池 / 有淘汰 / `risk_json` 解码失败」这三种**真实数据里没有**的状态明确标成「**只能由 fixture 覆盖**」。否则会出现「UI 做完了，但验收时一个都看不到」。

## 5. 对 §6 测试表的修正与补充

| 用例 | 原设计 | 建议 |
|---|---|---|
| 同源（页面 POST 与 CLI 产出相同成员） | 「同一 asof 上产出相同成员」 | ⚠️ **这条按写法证伪不了「页面另写一套」**：第二次调用只会命中幂等、走 `load_snapshot`，比的是加载器。改为**两个独立库、同一 asof、两条路径各跑一次**再比成员 |
| 无 token → 403 且库不动 | ✅ 保留 | 补反向用例：**用快照 asof 签的 token 必须 403**（钉住 W2），以及**被拒绝时 `candidate_snapshots` 行数不变**（现有钉法照抄） |
| 幂等 | ✅ 保留 | 断言两次 POST 后 `candidate_snapshots` 只 1 行**且第二次响应里出现「已存在」**（体现 `skipped=True` 被真的用上） |
| 渲染：空池 / 无快照 / 库不存在 | ✅ 保留 | 明确写「**只有 fixture 能覆盖空池与淘汰**；库不存在只有直接调 `handle()` 能覆盖」（S5/S6） |
| —（缺） | — | 补：**同一 asof 两种 run_kind** 并存时页面不歧义（钉住 W3）；**淘汰 `reason` 是机器名时原样显示 + 认得的换中文**（钉住 S2）；**`created_at` 渲染为 Asia/Shanghai**（钉住 S3，可用固定时间戳断言字符串） |
| —（缺） | — | 补：**写路径也落 markdown 报告**（断言 `reports/candidate/<asof>-<run_kind>.md` 存在，钉住 S4） |
