## 1. 目标

在模拟盘里新增一条**由智能体动态编排的对照臂**，与现有「写死条文的纪律臂」并列对照，
并且**让「编排」这件事本身可审计**：改了什么、试了几版、用的什么模型与提示词、
输入快照是什么，全部落在 append-only 台账里，而不是留在结果里。

**非目标**（本阶段明确不做）：LLM 调用（阶段 2）、随机改对照臂（阶段 3）、回放式评估（阶段 4）、
由智能体提交源码改规则（阶段 5）、任何形式的方向择时。

## 2. 三线对照

| 账户 | 规则来源 | 变更频率 |
|---|---|---|
| `arm-discipline-05/10/15` | 写死条文（回归 `portfolio/discipline.py`） | 永不 |
| `arm-agent` | 台账里**当前有效的 spec** | 每 5 交易日复审（阶段 2 起自动） |
| `arm-agent-random` | 同预算、同变更空间，spec 随机抽（阶段 3） | 同频率 |

`arm-agent-random` 是**必需的对照**：没有它，`arm-agent` 的成绩无法区分
「编排带来信息」与「多试几次的好运」。

## 3. 数据模型

### 3.1 新表 `paper_agent_decisions`（append-only）

```sql
CREATE TABLE IF NOT EXISTS paper_agent_decisions (
  decision_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  arm             TEXT    NOT NULL,
  asof            TEXT    NOT NULL,
  agent_kind      TEXT    NOT NULL,          -- 'manual' | 'llm' | 'random'
  model_id        TEXT    NOT NULL,          -- 'manual' / '<模型名>'
  prompt_sha256   TEXT    NOT NULL,
  seed            INTEGER NOT NULL DEFAULT 0,
  context_sha256  TEXT    NOT NULL,          -- 喂进去的 PIT 快照指纹（可复算）
  spec_before_json TEXT   NOT NULL,
  spec_after_json  TEXT   NOT NULL,
  n_trials        INTEGER NOT NULL DEFAULT 1,
  rejected_json   TEXT    NOT NULL DEFAULT '[]',
  rationale       TEXT    NOT NULL DEFAULT '',
  created_at      TEXT    NOT NULL,
  UNIQUE (arm, asof)
);
CREATE TRIGGER paper_agent_decisions_no_update BEFORE UPDATE ON paper_agent_decisions
  BEGIN SELECT RAISE(ABORT, 'append-only：paper_agent_decisions 不许 UPDATE'); END;
CREATE TRIGGER paper_agent_decisions_no_delete BEFORE DELETE ON paper_agent_decisions
  BEGIN SELECT RAISE(ABORT, 'append-only：paper_agent_decisions 不许 DELETE'); END;
```

- **当前有效 spec** = `SELECT spec_after_json ... WHERE arm=? AND asof<=? ORDER BY asof DESC LIMIT 1`；
  没有行 → 用 `AGENT_DEFAULT_SPEC`（与 `arm-discipline-10` 等价，保证同一起跑口径）。
- 幂等由 `UNIQUE(arm, asof)` 兜底；`UNIQUE` 冲突**不是**用来静默覆盖的（见 §5）。
- 触发器要能被 `INSERT OR REPLACE` 的隐式删行拦住 ⇒ 沿用 `paper/store.py` 的
  `recursive_triggers` 打开方式（P6 踩过的坑）。

### 3.2 规格（spec）与变更白名单

| 字段 | 区间/取值 | 默认 | 说明 |
|---|---|---|---|
| `etf_target_pct` | 5–25 | 10 | ETF 目标占比（对齐 `arm-discipline-10`） |
| `stop_loss_pct` | −15 ~ −3 或 `"off"` | −5.4 | 相对成本价的止损线（现值 = 82.14/86.80−1） |
| `max_single_pct` | 20–50 | 40 | 单票上限 |
| `rebalance_cadence` | 3 / 5 / 10 | 5 | 复审节奏（交易日） |
| `cash_floor_pct` | 与静态臂同值或**更紧** | 45 | 现金下限，**只许收紧**（风险规则错的方向必须是少投） |

**拒绝规则**：未知字段、越界值、类型不符 → `SpecViolation`（不夹紧、不静默丢弃）；
`cash_floor_pct` 放宽 → 拒绝；任何试图改变白名单/成本/PIT/整手口径的字段 → 未知字段，拒绝。

## 4. 模块接口（阶段 1 交付）

### 4.1 `stocklab/paper/agent_spec.py`（新）

```python
SPEC_SCHEMA: dict[str, SpecField]          # 字段 → 类型/区间/默认/单位
AGENT_DEFAULT_SPEC: dict[str, object]      # 默认规格（= arm-discipline-10 口径）

def validate_spec(spec: Mapping[str, object]) -> dict[str, object]   # 越界 → SpecViolation
def spec_sha256(spec: Mapping[str, object]) -> str                   # canonical JSON 的 sha256
def current_spec(conn, arm: str, asof: str) -> dict[str, object]     # 台账里最近一版，缺 → 默认
def record_decision(conn, *, arm, asof, spec_before, spec_after, agent_kind,
                    model_id, prompt_sha256, seed, context_sha256,
                    n_trials, rejected, rationale, now, commit=True) -> int
```

- 纯函数约定与 `paper/rules.py` 一致：**不读时钟、不碰网络**；`conn` 只出现在
  明确的读写函数里。
- `SpecViolation(Exception)` 带 `field` / `value` / `reason` 三个属性（可断言、可渲染）。

### 4.2 `stocklab/paper/rules.py`（**参数化，不许改口径**）

把「已经在写死常量上跑」的规划函数改成显式吃参数，**默认值 = 现有常量**
⇒ 静态三臂的行为必须逐字节不变（§6 验收项 2 就是对拍这件事）。

### 4.3 `stocklab/paper/engine.py`

`step()` 分派：`arm-hold` / `arm-now` / `arm-discipline-*` 走原路径；
`arm-agent*` 取 `current_spec()` 后走**同一执行内核**（不复制规则代码）。
`init` 新增两个账户（`arm-agent`、`arm-agent-random`，后者阶段 3 才有交易）。

### 4.4 `stocklab/paper/agent_context.py`（新）

```python
def build_context(conn, *, arm: str, asof: str, prices) -> dict
def context_sha256(context: Mapping) -> str
```

上下文**只含 `date <= asof` 的行**（净值、现金、持仓、指数收盘、当前 spec）。
喂进 `asof` 之后的行，指纹必须不变（§6 验收项 6）。

### 4.5 CLI

```bash
.venv/bin/python -m stocklab.cli.main paper spec set --arm arm-agent --asof 2026-09-22 \
    --spec '{"etf_target_pct": 12, "stop_loss_pct": -6.0}'        # 增量合并到当前 spec
.venv/bin/python -m stocklab.cli.main paper spec show --arm arm-agent
```

- `spec set`：`agent_kind='manual'`、`model_id='manual'`、`seed=0`、
  `prompt_sha256=sha256('manual')`（阶段 2 换成真 LLM 的指纹）。
- **幂等**：同 `(arm, asof)` 且合并结果与已存行**一致** → exit 0（打印"已存在且一致"）；
  不一致 → **exit 1**，原行一个字节都不改（append-only）。
- 退出码：越界/未知字段 → 2；冲突 → 1；成功 → 0。

### 4.6 报告与页面（阶段 1 只做 `paper show` 的 JSON + `/lab/paper` 一节）

`paper show` 输出新增 `agent` 块：`arm` / `spec`（当前有效）/ `n_reviews` /
`n_trials_total` / `n_rejected` / `history`（最近 5 版）。
`delta_vs_random` 阶段 3 之前恒为 `null` 且**必须出现**（不许省略字段）。

## 5. 可复现性与 PIT（决定成绩有没有意义）

1. 同 `(context_sha256, model_id, prompt_sha256, seed)` ⇒ spec 必须相同；做不到的标
   `reproducible=false` 并在报告里**单列**（不许静默平均）。
2. 温度进 `prompt_sha256` 的覆盖范围（换温度 = 换口径）。
3. 复审只喂 `<= asof` 的数据；回放式评估（阶段 4）必须沿用既有 train/validate/test 封存规则。

## 7. 阶段 5 的一条硬约束（先写下来，免得以后踩）

「让智能体改函数」要复用插桩状态机（`draft→pending_review→active`，`approve` 只能人工）。
但 `paper/` **不许 import `stocklab.plugin`**（§6 最后一条护栏）⇒ 执行层只能
**走子进程 CLI**（`python -m stocklab.cli.main plugin call ...`），与 labweb 写路径同一手法
（ERROR_DIARY #45 的教训：沙盒用 `signal.setitimer`，只能主线程）。

## 8. 什么结果**不算**证据（沿用设计文档 §11）

< 120 交易日；不报 `n_trials`；与 `arm-agent-random` 的差 CI 跨 0；
回放式里「试多版选最好」的读数（那是上界）；智能体自述的 `rationale`。
