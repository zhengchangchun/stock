# 沙盒真回放 · 设计

- **日期**：2026-09-20
- **状态**：待实现（已通过设计评审）
- **前置**：`docs/superpowers/specs/2026-09-18-插桩候选池骨架-design.md`（插桩机制）、`docs/superpowers/specs/2026-09-20-财报数据层与中长池因子-design.md`（财报与因子）
- **分支**：`feat/financials` 之上的后续轮次

---

## 1. 背景

沙盒（`stocklab/plugin/sandbox.py`）的**判定框架已经建成**：窗口、有效样本计数、verdict 判定、bootstrap CI、`overfit_flag` 都在。唯独 `_replay_daily_excess` 返回**空列表** —— 这是刻意的 fail-closed：当时的设计文档写明「草草接一个不严谨的回放会产出**假的 WIN**」。

后果：**所有 verdict 恒为 `INCONCLUSIVE`**，「提交新版本 → 沙盒对比 → 上线」这条链只演示机制、不产生任何性能结论。

本轮把回放做成真的。**这是「财务因子能否提升准确率」唯一能回答的路径**，也是「按结果反推」的前置条件。

---

## 2. 前置决策（已定）

| # | 决策 | 内容 |
|---|---|---|
| D1 | **观测单元** | **调仓周期**（非重叠），不是交易日。每个周期一个观测 |
| D2 | **窗口切分** | 训练段（前 70%）+ 验证段（后 30%）。**verdict 只看验证段**；过拟合标记用两段差距 |
| D3 | **数据前置** | 一并把 21 只的日K 分页回溯到**上市首日**（ADR-003 已验证可行） |
| D4 | **判定** | verdict 以**「新版 − 旧版」**的 Δ 为准；**同时报告**两个版本各自相对 `index_300` 的超额 |
| D5 | **门槛** | 有效**周期**数 < 120 → `INCONCLUSIVE`。**不为了让长期池能出结论而降门槛** |

### D1 的后果（必须显式知道）

「120 个调仓周期」比原来的「120 个交易日」**严格得多**。按本机现有 11 年数据估算：

| 池 | 总周期 | 验证段(~30%) | 能否出结论 |
|---|---|---|---|
| 短期(5日) | 533 | ~160 | ✅ |
| 中期(20日) | 133 | ~40 | ❌（补历史后有望 ✅） |
| **长期(60日)** | 44 | ~13 | ❌ |

**长期池的沙盒事实上永远出不了结论** —— 要 120 个验证周期需约 400 个总周期 ≈ 24000 交易日 ≈ 95 年。这是算术后果，不是实现缺陷。**替代方案是缩短长期池的调仓周期，那是改策略、不是改回放**，本轮不做，只如实写进已知限制。

## 3. 范围

### 做

- 把主流程的**打分级内核**从 `run_candidate` 中抽出，做成**只读、不写库**、可传**插件版本覆盖**的函数
- `_replay_daily_excess` 的真实实现：逐调仓日重放 → 周期收益 → 版本对比
- 训练/验证切分与 `train_gap` 驱动的 `overfit_flag`
- 下游评估器（等权、扣成本、涨跌停/停牌不可成交、空池持现金）
- 21 只标的历史补到上市首日
- 报告里同时给出「版本 Δ」与「两版相对 index_300 的超额」

### 不做（明确排除）

- **不改任何门槛去迁就结果**（长期池永远 INCONCLUSIVE 就永远 INCONCLUSIVE）
- **不改长期池的调仓周期**
- **不做多折滚动 walk-forward**（本轮用训练/验证两段；多折是后续轮次）
- **不改模块2**：`predict/`、`verify/`、`chain/`、`paper/`、`portfolio/` 一行不动

## 4. 时间轴与观测单元

```
窗口 = [window_start, window_end]（默认：补数据后的全历史）
调仓日 = 从窗口起点起，每 K 个交易日一个（K = REBALANCE_DAYS[pool]）
周期   = 相邻两个调仓日之间；末尾不足一个周期的部分**丢弃**
切分   = 前 70% 周期为训练段，后 30% 为验证段（按周期序号切，不按日历）
```

- **末尾不足一个周期直接丢弃**，不截断成短周期 —— 否则周期长度不一致，收益不可比。
- **切分在周期级做**，保证两段的周期长度相同。

## 5. 回放执行路径

### 5.1 抽出「打分级内核」（无副作用）

现在的 `run_candidate(conn, asof=..., run_kind=...)` **会写快照**。回放要跑几百个历史调仓日，绝不能往 `candidate_snapshots` 灌几百行历史回放数据。

**做法**：把主流程的打分部分抽成一个只读函数

```python
def score_pipeline(conn, *, asof, run_kind, plugin_overrides=None) -> PipelineResult
```

它跑：`screen → 插桩0 → 三池分流 → 插桩1/2/3 → 插桩4 → select_top`，**只返回结果、不写任何表**。返回的成员与淘汰记录用**值对象**（`MemberRow` / `RejectRow`），与 `run_candidate` 现在的产物同型。

`run_candidate` 改为**调用它**、再自己负责落库。这样**回放与生产走同一段打分代码** —— 否则回测的不是生产的那套逻辑，结论无意义。

**这条要用测试钉住**（见 §10.1）：同一个 asof 下，`run_candidate` 与 `score_pipeline` 产出的池成员必须**完全相同**。

### 5.2 单变量：只换被比较的那个插件

沙盒比的是**同一个 `plugin_id`** 的两个版本。回放时：

- 该插件：分别用 `candidate` 与 `baseline` 版本各跑一遍
- **其余所有插件**：一律用**当前 active** 版本

`plugin_overrides: dict[str, int]`（plugin_id → script_id）就是这个口子。**没有它，「改下游」会成为另一条提分路径，归因立刻失效**（`CLAUDE.md` 单变量原则）。

`lifecycle.call_active` 已有「解析 active 版本并执行」的职责，本轮扩展为「解析指定版本（覆盖优先）并执行」。

## 6. 历史 ctx 的构造

**不需要为回放另写 PIT 逻辑** —— 直接复用 `candidate/score.py::build_ctx`：

- K 线：只读 `date <= asof`
- 财报：只读 `notice_date <= asof`
- 横截面分位：按当天的**已公告**期现算（`cross_section.build` 已是纯函数，输入就是当天的横截面）

PIT 因此是**构造性的**，不是靠回放层记得过滤。这是既有设计的好处，回放层不该重复实现。

---

## 7. 下游评估器（固定规则，不随插桩版本变）

| 规则 | 内容 |
|---|---|
| 持仓 | 当期 `select_top` 的成员，**等权** |
| 持有 | 到下**一个**调仓日 |
| **空池** | **持现金**（不猜、不补别的标的） |
| 成本 | 每次调仓扣成本，复用 `config/costs.py::CostModel`（股票/ETF 分口径，ADR-008） |
| 涨跌停 / 停牌 | **不可成交**，复用 `backtest/portfolio.py` 的 `LIMIT_BY_BOARD` 与「买在涨停、卖在跌停不成交」；板别未知时保持 `BoardUnknown` **拒绝猜**的行为 |
| 基准 | `index_300` 同区间 |

**下游规则写死在代码里，不随插桩版本变化** —— 否则「改下游」也是一条提分路径。

## 8. 判定：两个比较，都要报

### 8.1 verdict 以「版本对比」为准

验证段内，每个周期得到一个 Δ = `候选版本的周期收益 − 基线版本的周期收益`。
对 Δ 序列做周期级 bootstrap 95% CI：

| 条件 | verdict |
|---|---|
| 有效周期数 < 120 | `INCONCLUSIVE`（逐字写「样本不足，不构成结论」） |
| Δ 的 95% CI **下界 > 0** | `WIN` |
| 其余 | `LOSE` |

**常量改名**：`sandbox.MIN_VALID_DAYS: int = 120` → **`MIN_VALID_PERIODS: int = 120`**，docstring 从「最少有效**交易日**」改为「最少有效**调仓周期**」，并在 docstring 里显式写明**它比原来的 120 交易日严格得多**（因为一个周期含 K 个交易日）。旧名不保留别名 —— 留着会让「120 日」与「120 周期」两种读法并存。

### 8.2 同时报告「相对 index_300 的超额」

铁律要求「任何策略必须与 `index_300` 比较，**跑不赢就明说**」。所以报告里**分别**给出候选版本与基线版本相对 `index_300` 的超额与其 CI。

**这两种结论要能同时看见**，例如「新版显著跑赢旧版，但两者都跑输指数」—— 这必须一眼看得出来，不许只报一个。

### 8.3 `overfit_flag` 改为 `train_gap` 驱动

现在 `overfit_flag` 用的是「CI 跨 0 且区间宽 > |Δ| 的 2 倍」这个启发式 —— 那是**没有训练段时的替代品**。本轮有了真训练段，改用设计文档 §8.4 原本要求的判据：

```
train_gap = 训练段 Δ 的均值 − 验证段 Δ 的均值
```

**方向固定**：`train_gap > 0` 表示**训练段比验证段好看** —— 这才是过拟合的形态。`train_gap < 0`（验证段反而更好）不标记。

阈值 `OVERFIT_TRAIN_GAP = 0.005`（即训练段日均超额比验证段高出 **0.5 个百分点**）。**这个数是我定的**，来源是「两段差距到了半个百分点，多半不是噪声」这个直觉的数值化 —— 编不出来源，与 ADR-012 的跌破线、ADR-016 的断更阈值同属**自创取值**，逐条列在 ADR 里，觉得不合适就改。

旧的 CI 宽度启发式**删除**（留着会让两种判据打架），并用源码扫描测试钉住它不再出现。

## 9. 数据前置：历史补到上市首日

本机现有 11 年（2015-10 起）。ADR-003 已验证腾讯日K 用 `end` 锚点分页**可回溯至上市首日**。

- 采集 21 只的历史（一次性、联网、`scripts/` 级动作）
- **ADR-003 的坑要记住**：腾讯 qfq 上限 800 且 801–2000 区间会**静默降级回 640 且不报错** → 写入口对 `adj_mode != 'none'` 早已硬拒绝，保持
- 采完记录**每只的最早期与行数**（报告里给出），确认真的回溯到了上市首日而不是被静默截断

## 10. 测试策略

**全部离线**（fixture 回放），真实联网只在标注的录制/采集脚本里。

### 10.1 无副作用（本轮重点）

| 测试 | 断言 |
|---|---|
| **回放不写库** | 跑一次回放前后，`candidate_snapshots` / `candidate_members` / `candidate_rejects` 行数**完全不变** |
| 内核与生产同源 | `run_candidate` 与回放内核在同一个 asof 上产出**相同的池成员**（证明回测跑的就是生产逻辑） |

### 10.2 单变量

| 测试 | 断言 |
|---|---|
| 只换目标插件 | 给定 `plugin_overrides`，其余插件的调用**仍解析到 active 版本**（用桩记录每次调用的 script_id 验证） |
| 缺 active 版本 | 未覆盖的插件没有 active → `NoActivePlugin` 抛出（**不兜底**） |

### 10.3 时间轴与切分

| 测试 | 断言 |
|---|---|
| 调仓日间隔 | 相邻调仓日恰好相差 K 个交易日 |
| 末尾丢弃 | 末尾不足一个周期的部分不产生观测 |
| 切分在周期级 | 训练段与验证段的周期数之比 ≈ 70/30，且**两段周期长度相同** |
| 周期数不足 | 验证段 < 120 → `INCONCLUSIVE`，且 note 逐字含「样本不足」 |

### 10.4 下游规则

| 测试 | 断言 |
|---|---|
| 空池持现金 | 池为空时该周期**不产生持仓收益**，但仍计**清仓成本**（把上一期的持仓卖掉）；断言该周期收益 = **清仓成本的负值**，不是 0，也不是「跳过该周期」 |
| 涨停不可买 / 跌停不可卖 | 构造涨停日买入 → 不成交，持仓不变 |
| 板别未知 | `BoardUnknown` 抛出（不猜） |
| 成本进净值 | 有换手的周期收益**低于**无成本的同周期收益 |
| 扣成本可复现 | 同输入两次回放，Δ 序列逐位相同 |

### 10.5 判定与报告

| 测试 | 断言 |
|---|---|
| CI 跨 0 → LOSE | 构造 Δ 均值附近有正有负的序列 |
| CI 下界 > 0 → WIN | 构造全正 Δ |
| **两版都跑输指数也要报出来** | 构造「Δ 为正但两版超额皆负」→ verdict=WIN，**且报告里两个负超额都在** |
| `train_gap` 驱动 overfit | 训练段好、验证段差 → `suspected`；两段一致 → `None` |
| 旧 CI 宽度启发式已删 | 源码里不再有那条判据（源码扫描） |

## 12. 已知限制（不美化）

1. **长期池的沙盒事实上永远出不了结论。** 「60 日调仓 + 120 个独立观测」在可预见的历史长度内不可兼得（需约 95 年）。**这是算术，不是缺陷；降门槛是改口径迁就结果，不做。**
2. **两段切分不是多折 walk-forward。** 只有一次训练/验证切分，比 `experiments/` 的多折滚动弱。本轮如此，多折是后续轮次。
3. **周期级观测的样本量本就有限。** 即便补到上市首日，中期池的验证段也只是刚过门槛，CI 会宽 —— **能出结论 ≠ 结论强**，报告里必须给出 n 与 CI 宽度，让人自己判断。
4. **回放用的是当前 active 的其它插件。** 若那些插件以后被替换，同一份回放重跑结果会变。报告里要记下回放时各插件的 script_id。
5. **数据只有 21 只种子。** 横截面薄，选出来的池子规模小（`POOL_TOPN` 上限 6/8/5），单期收益的噪声大。
6. **本轮仍产不出「财务因子是否有效」的最终答案** —— 它只把**回答那个问题的能力**建起来。真正跑因子对比实验是下一轮。

## 13. 未决项

- 多折滚动 walk-forward（替代两段切分）
- 长期池的调仓周期是否要缩短（**策略决策**，不是回放问题）
- 回放的并行化（几百个调仓日 × 完整主流程，可能慢）
