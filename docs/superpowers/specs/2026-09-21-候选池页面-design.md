# 候选池页面（模块1 展示层）

- **日期**：2026-09-21
- **状态**：待实现（设计已认可）
- **前置**：模块1 插桩候选池骨架（`candidate/`）、现有 labweb（P15，模块2 持仓台账）

---

## 1. 背景

模块1（候选池 + 插桩 + 沙盒回放）三轮做下来，**产出全是 CLI + markdown 报告，一行前端都没有**。
现有 web（`stocklab/labweb`，`lab serve`）只覆盖模块2 的持仓与纪律台账。

本设计补上模块1 的**第一个**页面：**候选池快照** —— 回答「系统选出了什么、为什么」。

**明确只要这一块**：插桩迭代台账、回放结论看板是后续轮次，本轮只留出导航位。

---

## 2. 落点与文件结构

扩展**现有 lab 应用**，与模块2 共用一个服务器、一个壳、一套 token：

```
stocklab/labweb/
  cand_data.py     ← 新增：模块1 只读数据层（CandLab）
  cand_render.py   ← 新增：模块1 渲染（复用 layout/CSS/rail）
  app.py           ← 改：+2 条路由；Context 加一个字段
  render.py        ← 只改 1 行（NAV_ITEMS 加导航项）；渲染逻辑一行不加
  data.py          ← 不动
```

**为什么新建文件而不是塞进 `render.py`**：`render.py` 已 **66KB**，再往里加模块1 的
渲染会把它变成什么都装的杂物间。模块边界按**职责**切，不按技术层切。

命令不变：`lab serve` 打开后导航多一项「候选池」，地址 `<base>/candidate`。

### Context 的改法

```python
@dataclass
class Context:
    lab: Lab                      # 模块2（持仓）—— 不动
    cand: CandLab                 # 新增：模块1
    signer: TokenSigner
    base_path: str = DEFAULT_BASE_PATH
```

`CandLab` 与 `Lab` 同形（`db_path` + `asof` + `conn()` 上下文管理器），但**是独立的类**：
两者读的表、页面的"今天"含义都不同，硬塞进一个类会让 `asof` 语义打架。

## 3. 页面内容（`GET <base>/candidate`）

```
┌──────────────────────────────────────────────────────────────┐
│ stock-lab        asof [2026-09-18 ▾]        [跑一次]          │
│ 持仓与纪律台账 ←导航→ 候选池                                   │
├──────────────────────────────────────────────────────────────┤
│ 快照 #2 · 2026-09-18 · weekly · 生成于 2026-09-18 17:22       │
│ 参数：种子 21 只 · TOPN 短6 / 中8 / 长5                        │
│                                                               │
│ ── 短期池（5 日调仓）── 3 只                                    │
│  代码     名称      原始分  调整分  理由           风险  状态  │
│  000333  美的集团   82.1   74.3   量价配合…       中    观察中 │
│  …                                                            │
│                                                               │
│ ── 中期池（20 日调仓）── 本池为空                               │
│ ── 长期池（60 日调仓）── 2 只                                   │
│                                                               │
│ ▸ 淘汰记录（18 条）                                            │
│    行业排雷 2 条 ｜ 打分未过 16 条                              │
└──────────────────────────────────────────────────────────────┘
```

**规则**

| 项 | 规则 |
|---|---|
| asof 选择器 | 列出库里**有快照的** asof（降序）；默认最新一条 |
| 写「本池为空」 | 空池**不写 0**，明说「本池为空」（沿用现有 lab「没数的地方写未知，不写 0」的规矩） |
| 淘汰记录 | **按环节分组**（`pre_screen` / `industry_screen` / `score`），每组标条数，折叠显示 |
| 风险 | 显示 `risk_json` 的**条目数**与摘要；解码失败明说"风险明细解析失败"，不静默吞 |
| 没有快照 | 明说「本库还没有跑过候选池」+ 指向「跑一次」按钮；**不显示空表格** |
| 库不存在 | 明说「数据库文件不存在：<路径>」，不是 500 |

**asof 的语义**：本页 asof = **快照的 asof**（那天的选股结果），**不是"今天"**。
所以 `CandLab` 不接受 `--asof` 固定值语义的覆盖 —— 它的"当前"由用户在下拉框里选。

## 4. 写路径（`POST <base>/candidate/run`）

- 表单字段：`asof`（必填，YYYY-MM-DD）、`run_kind`（`light`/`weekly`/`quarterly`，默认 `weekly`）、`_token`
- **先校验 token**：失败 → **403，数据库一个字节都不动**（沿用现有规矩，有测试钉住）
- **写库前 `ensure_schema(db_path)`**：项目规约 P33「写库入口统一前滚」
- 内部调 **`stocklab.candidate.run.run_candidate(conn, asof=, run_kind=, now=)`** ——
  与 CLI **同一段生产代码**，页面**不另写一套打分逻辑**（否则页面显示的不是系统真实产出）
- **幂等**：`run_candidate` 自带幂等（`(asof, run_kind)` UNIQUE，命中直接加载既有快照）。
  页面区分两种结果并**分别提示**：「已存在，展示既有快照（未重跑）」/「新跑，已写入」
- 成功后 **303 重定向**回 `GET /candidate?asof=...`（PRG，刷新不会重发 POST）
- 耗时约几秒（21 只标的一遍打分）

**沙盒回放不在页面上**：一次回放约 **25 分钟**，做成按钮不现实。回放仍走 CLI
（`plugin sandbox`），其结果显示在后续的「迭代台账」页。

## 5. 数据来源与库

- 只读 `candidate_snapshots` / `candidate_members` / `candidate_rejects` 三表
- 库路径：`--db`（默认 `stocklab.config.paths.DB_PATH` = `data/stocklab.db`），与 CLI 同源
- **本页不引入任何新表**，不写 `candidate_*` 之外的表

**当前实际状态（实现时必须知道）**：默认路径 `data/stocklab.db` **不存在**。
有完整数据的只有 `/tmp/replay.db`（39 表、财报 1443 行、7 个插桩版本、2 个快照），
而 `/tmp` 会被系统清理。**本设计不含"自动建库/自动采数"** —— 那需要联网，属采集脚本的职责。
验收时用 `--db /tmp/replay.db`（或先复制到 `data/stocklab.db`）。

## 6. 测试（全离线）

| 测试 | 断言 |
|---|---|
| 渲染：有快照 | 三池分区都在；成员行的代码/分数/理由出现在 HTML 里 |
| 渲染：空池 | 出现「本池为空」，且该池**不出现数字 0** |
| 渲染：淘汰分组 | 三个环节各自分组，条数与库中一致 |
| 渲染：无快照 | 出现「还没有跑过」文案；**不出现空表格** |
| 渲染：库不存在 | 出现「数据库文件不存在」；HTTP 不是 500 |
| 写：无 token | **403**，且 `candidate_snapshots` 行数不变（钉住"一个字节都不动"） |
| 写：幂等 | 同一 `(asof, run_kind)` POST 两次 → 只有 1 行；第二次提示「已存在」 |
| 写：新跑 | 库里快照 +1；成员/淘汰行数 > 0；响应是 303 |
| 写：坏参数 | 非法 asof / 未知 run_kind → 400 级错误，**不写库** |
| 同源 | 页面 POST 与 CLI `candidate run` 在同一 asof 上产出**相同成员**（证明用的是同一段代码） |
| 无回归 | **现有 labweb 三个测试文件一条不改**（证明没伤模块2） |

## 7. 明确不做

- **不做沙盒回放**（25 分钟）
- **不做插桩版本的 submit/approve**（审核闸门留在 CLI，页面不给一键上线）
- **不做**「新进 / 移出」的历史对比
- **不做**多快照 diff
- 不动模块2 的 `data.py` / `render.py` 逻辑
- 不自动建库、不联网采集

---

## 8. 已知限制

1. **默认库是空的**：不跑一次就没有东西看。页面会明说，但这意味着"打开就有内容"不成立。
2. **只读 + 一个写按钮**：改插桩版本、跑回放都还得回命令行。
3. **`risk_json` 是原样展示**：不做结构化解析（各插桩的风险条目 schema 不统一）。
4. **共享 lab 服务器的回环限制**：`lab serve` 只绑 127.0.0.1（既有安全设计），本页同样受此约束。
5. **单页快照**：一屏只看一个 asof，没有趋势。
