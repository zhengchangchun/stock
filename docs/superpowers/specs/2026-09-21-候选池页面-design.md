# 候选池页面（模块1 展示层）

- **日期**：2026-09-21（rev2，按 review 逐条订正）
- **状态**：待实现（设计已认可）
- **前置**：模块1 插桩候选池骨架（`candidate/`）、现有 labweb（P15，模块2 持仓台账）

---

## 1. 背景

模块1（候选池 + 插桩 + 沙盒回放）三轮做下来，**产出全是 CLI + markdown 报告，一行前端都没有**。
现有 web（`stocklab/labweb`，`lab serve`）只覆盖模块2 的持仓与纪律台账。

本设计补上模块1 的**第一个**页面：**候选池快照** —— 回答「系统选出了什么、为什么」。

**明确只要这一块**：插桩迭代台账、回放结论看板是后续轮次，本轮只留出导航位。

## 2. 落点与文件结构

扩展**现有 lab 应用**，与模块2 共用一个服务器、一个壳、一套 token：

```
stocklab/labweb/cand_data.py     ← 新增：CandLab（模块1 只读数据层）
stocklab/labweb/cand_render.py   ← 新增：模块1 渲染（复用 layout/CSS/rail）
stocklab/labweb/app.py           ← 改：+2 条路由；Context 加末位可选字段；handle() 的 docstring
stocklab/labweb/render.py        ← 只改 NAV_ITEMS 一行（加导航项）；渲染逻辑一行不加
stocklab/labweb/data.py          ← 不动
────────────────────────────────────────────────────────────────
stocklab/cli/main.py             ← 改：cmd_lab_serve 注入 cand=CandLab(db, asof=...)
stocklab/cli/candidate.py        ← 改：抽出 write_report_file()，CLI 与页面共用
stocklab/candidate/snapshot.py   ← 改：新增 list_snapshot_keys(conn)
```

**为什么新建文件而不是塞进 `render.py`**：`render.py` 已 **66KB**，
再往里加模块1 的渲染会把它变成什么都装的杂物间。模块边界按**职责**切，不按技术层切。

### 2.1 Context 的加法（**必须用末位可选字段**）

现有 `Context` 的构造点（`main.py:2079`、`app.py:624`、5 个测试文件）**全部是关键字形式**。
插一个必填字段进去 → 这些点全部 `TypeError`。所以新字段必须是**末位 + 有默认值**：

```python
@dataclass
class Context:
    lab: Lab
    signer: TokenSigner
    base_path: str = DEFAULT_BASE_PATH
    cand: "CandLab | None" = None        # 末位可选；不写默认值会让 6 个构造点全炸
```

**必须补的一处注入**（设计初稿漏了，不补就是「测试全绿、一 `lab serve` 就炸」）：

```python
# stocklab/cli/main.py::cmd_lab_serve，与 lab= 同一处
ctx = labweb.Context(lab=labweb.Lab(db, asof=args.asof),
                     cand=labweb.CandLab(db, ...),
                     signer=...)
```

**`handle()` 的 docstring** 现写着「只经 `ctx.lab` 读库」（`app.py:477`），要改成
「只经 `ctx.lab` / `ctx.cand` 读库」。

### 2.2 `CandLab` 与 `Lab` 的关系

同形（`db_path` + `conn()` 上下文管理器），但**独立的类**：两者读的表不同，
且"当前"的含义不同（见 §3）。硬塞进一个类会让 `asof` 语义打架。

### 3.1 token 与「当前」的口径（**写死**）

**候选池页表单的 `_token` 一律用 `ctx.lab.asof` 签发与校验**，复用既有 `_token_ok`，
**不得用快照 asof**。

> 实测依据：`mint("2026-09-18")` 配 `verify(today=ctx.lab.asof)` → **False**。
> 用快照 asof 签 = **永久 403**（用户看到的是"系统坏了"，而不是"你点错了"）。

### 3.2 选择器是 `(asof, run_kind)` 组合，不是一个 asof

快照唯一键是 `(asof, run_kind)`，而 `POST` 允许 `light` / `weekly` / `quarterly`
⇒ **同一个 asof 可以有多条快照**。只用一个 asof 参数取哪条是未定义的。

- 下拉项 label：`2026-09-18 · weekly`
- URL 带**两个**参数：`?asof=2026-09-18&run_kind=weekly`
- **「最新」的定义**：按 `created_at` 降序取第一条（**不是**按 asof —— asof 会撞车）；
  `created_at` 相同则按 `(asof, run_kind)` 字典序，保证确定性

### 3.3 渲染口径

| 项 | 规则 |
|---|---|
| 池标题 | `── 短期池（5 日调仓）── N 只`；`N` 是**成员行数**（同一代码可在两池同时出现，行数 ≠ 去重后的只数） |
| **空池** | 写「本池为空」，**不写 0**（沿用现有 lab「没数的地方写未知，不写 0」的规矩） |
| 名称 | 来自 `instruments`（`code → name`）；查不到 → 显示代码本身，不编名字 |
| **风险** | `risk_json == []` → 写「**无**」（不是「0 条」）；非空 → 写条目数 + 摘要；解码失败 → 明说「风险明细解析失败」，不静默吞 |
| **淘汰分组** | 按 `stage` 分组（`pre_screen` / `industry_screen` / `score`），每组标条数，折叠显示 |
| **stage / reason 中文** | 按 `CHECK_CN` 规矩：映射表**只换标签、不改判据**，**认不出就原样显示机器名**（实测如 `pre_screen`、`consecutive_limit_down`） |
| `plugin_id IS NULL` | 写「**未知**」（`RejectRow.plugin_id` 可为 None） |
| **时间戳** | `created_at` / `entered_at` 是 **UTC**（实测 `…08:38+00:00`）。渲染前转 **Asia/Shanghai**，转换源与 `data.now_iso()` 同一处 |
| **未出现差集块** | 种子清单 − 入池成员 − 淘汰记录。实测 21 只种子 → 13 只入池、1 条淘汰、**7 只去向不明**；旧快照淘汰 0 条 → 8 只不明。**不显示这块就是把「另外几只知道去哪了」留成黑洞** |
| 无快照 | 明说「本库还没有跑过候选池」+ 指向「跑一次」；**不显示空表格** |
| 库不存在 | 明说「数据库文件不存在：<路径>」，不是 500。**该分支只有测试可达**（见 §4.3） |

### 3.4 asof 的语义

本页 asof = **快照的 asof**（那天的选股结果），**不是"今天"**。
所以 `CandLab` 的"当前"由选择器决定，**不接受** `Lab` 那种 `--asof` 固定值语义。
`ctx.lab.asof` 只用于 **token 与"生成于"时刻**，不用于选快照（见 §3.1）。

### 3.5 mock 用真实数据

§3 上方那张示意图用**真实快照 #1**（短 6 / 中 8 / 长 5、淘汰 0、首行 603868
82.14 / 77.14）。

**「空池」/「有淘汰」/「风险解码失败」三种形态真实库里当前都不存在**，只能由
fixture 覆盖 —— 示意图里不出现它们，避免把"没见过的东西"画成"系统会这样"。

## 4. 写路径（`POST <base>/candidate/run`）

### 4.1 流程

- 表单字段：`asof`（必填，YYYY-MM-DD）、`run_kind`（默认 `weekly`）、`_token`
- **先校 token**：失败 → **403，数据库一个字节都不动**（沿用现有规矩，有测试钉住）
- **写库前 `ensure_schema(db_path)`**：项目规约 P33「写库入口统一前滚」
- 内部调 **`stocklab.candidate.run.run_candidate(conn, asof=, run_kind=, now=)`** ——
  与 CLI **同一段生产代码**，页面**不另写一套打分逻辑**
- **「已存在 / 新跑」直接用 `RunResult.skipped`**，不自己再查一次库
- **报告落盘**：调**共享的** `write_report_file(result, out_dir)`（见 §4.2）
- 成功后 **303 重定向**回 `GET /candidate?asof=…&run_kind=…`（PRG，刷新不会重发 POST）
- 耗时约几秒（21 只标的一遍打分）

### 4.2 抽出共享的 `write_report_file`

现状：CLI **总是**落 `<asof>-<kind>.md`（`skipped` 也写），页面若跑完不落 →
**两条路径产出物不同源**。所以把它抽出来：

```
stocklab/cli/candidate.py::write_report_file(result, out_dir) -> Path
    # CLI 与页面都调它；路径规则 <out_dir>/<asof>-<run_kind>.md 只有一处定义
```

### 4.3 「库不存在」只有测试可达

`lab serve` 在**启动期**就检查库并 `return 2`，且启动会 `ensure_schema` 前滚 schema。
所以：

- 「库不存在」的 UI 分支**正常跑不到**，只有测试直接构造 `Context` 才可达
- **验收统一先复制一份 `replay.db` 再开**，不要在默认路径上直接开（会被前滚改写）

## 5. 数据来源

- 读 `candidate_snapshots` / `candidate_members` / `candidate_rejects`
  **+ `instruments`（只取 `code → name`）** —— 不需要 `instruments` 就删掉「名称」列，二者只能留一个
- **不引入任何新表**，不写 `candidate_*` 之外的表
- **快照读取一律走 `snapshot.load_snapshot` / `snapshot.find_snapshot`，不另写 SQL**
- 唯一需要新写的查询是「**有快照的 `(asof, run_kind)` 列表**」——
  按项目分层，这查询加在 **`candidate/snapshot.py`**（`list_snapshot_keys`），**不写在页面里**

**当前实际状态（实现时必须知道）**：默认路径 `data/stocklab.db` **不存在**。
有完整数据的只有 `/tmp/replay.db`（39 表、财报 1443 行、7 个插桩版本、2 个快照），
而 `/tmp` 会被系统清理。**本设计不含"自动建库/自动采数"** —— 那需要联网，属采集脚本职责。

## 6. 测试（全离线）

| 测试 | 断言 |
|---|---|
| 渲染：有快照 | 三池分区都在；成员行的代码/分数/理由出现在 HTML 里；UTC 时间戳已转 +08 |
| 渲染：空池 | 出现「本池为空」；该池**不出现数字 0** |
| 渲染：淘汰分组 | 三环节各自分组，条数与库中一致；认不出的 stage **原样显示机器名** |
| 渲染：未出现差集 | 条数 = 种子数 − 去重入池数 − 淘汰数；对得上 |
| 渲染：风险口径 | `risk_json == []` → 「无」；`plugin_id IS NULL` → 「未知」 |
| 渲染：无快照 | 出现「还没有跑过」；**不出现空表格** |
| 渲染：库不存在 | 出现「数据库文件不存在」；HTTP 不是 500 |
| 写：无 token | **403**，且 `candidate_snapshots` 行数不变 |
| 写：**快照 asof 签的 token** | 用快照 asof 而非 `ctx.lab.asof` 签 → **403**（钉死 §3.1） |
| 写：幂等 | 同 `(asof, run_kind)` POST 两次 → 只有 1 行；第二次提示「已存在」 |
| 写：**同 asof 两种 run_kind 不歧义** | light 与 weekly 各一条，选择器两项、URL 各取各的 |
| 写：新跑 | 快照 +1；成员/淘汰行数 > 0；响应 303 |
| 写：**也落报告** | POST 后 `<out_dir>/<asof>-<kind>.md` 存在且内容 = `RunResult.report_md` |
| 写：坏参数 | 非法 asof / 未知 run_kind → 400 级错误，**不写库** |
| **同源** | **建两个独立库**，同一 asof，一个走 CLI、一个走页面各跑一次，**再比成员** —— 不是同一个库跑两次（那样第二次只命中幂等，比的是加载器） |
| 无回归 | **现有 labweb 三个测试文件一条不改**（证明没伤模块2） |

## 7. 明确不做

- **不做沙盒回放**（25 分钟）
- **不做插桩版本的 submit/approve**（审核闸门留在 CLI，页面不给一键上线）
- **不做**「新进 / 移出」的历史对比、多快照 diff
- 不动模块2 的 `data.py` / `render.py` 逻辑
- 不自动建库、不联网采集

---

## 8. 已知限制

1. **默认库是空的**：不跑一次就没东西看。页面会明说，但"打开就有内容"不成立。
2. **只读 + 一个写按钮**：改插桩版本、跑回放都还得回命令行。
3. **`risk_json` 原样展示**：不做结构化解析（各插桩的风险条目 schema 不统一），只给条目数与摘要。
4. **未出现差集是"差额"，不是"原因"**：它只能说"这几只没出现在任何一栏"，**不能**解释为什么（可能被排雷、可能打分未过、也可能是该轮根本没覆盖）。
5. **共享 lab 服务器的回环限制**：`lab serve` 只绑 127.0.0.1（既有安全设计），本页同样受约束。
6. **单页快照**：一屏只看一条，没有趋势。
7. **同一代码可在多池出现**：成员"行数"与"只数"不同，页面必须分别口径显示，不能混。
