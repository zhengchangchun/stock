## 1. 假设

> 财报里已经公告的质量信息，对**次日个股方向**有信息量，且方向为「质量高 → 次日正漂移」。
> 两个变体各自独立判定（**不合并、不取最好**）。

- **V1 `fin-quality-pct`（横截面轴，本项目的**第一条**横截面轴）**：
  `asof` 时点按 PIT 取每只标的**最新已公告期**的财报 → `indicators.factors()` → 取可用因子在
  **横截面**上的分位（`cross_section.py` 的极性规则，统一「越大越好」）→ 合成质量分
  `q_raw = mean(可用因子分位)`（要求**至少 3 个因子可用**，否则该标的当日剔除）；
  再对 `q_raw` 取横截面分位得 `q ∈ [0,1]`；令
  `q ≥ 0.70 → mu = +|mu_sample|`、`q ≤ 0.30 → mu = −|mu_sample|`、其余 → 符号 0（`mu = 0`）。
- **V2 `fin-roe-yoy`（时序轴）**：自身 `roe(TTM)` 相对**去年同期**的变化：
  `Δ = roe(TTM, 本期) − roe(TTM, 去年同期)`；`Δ > +0.01` → `+1`、`Δ < −0.01` → `−1`、其余 `0`。

## 2. PIT 约束（提前写死）

- 只允许读 `notice_date <= asof` 的行（口径选「**视公告日为当日起可用**」，与既有 `features_daily` 一致）；
  **`notice_date > asof` 的期数一律不可见**，不许「取最近一根」兜底。
- `report_date < notice_date <= report_date + 120 天` 外的行 → 不参与（该约束已在采集层 warn，此处再挡一道）。
- 横截面分位只允许用**同一 `asof` 当日可见**的行；**不许**把未来公告期拉进来凑样本量。
- `asof` 当日无可用财报（上市前 / 未公告 / 金融股缺列导致可用因子 < 3）→ 返回 `None` →
  `DegenerateInput` **硬拒绝**，该 `(日, 标的)` 记入 `skipped` 并在报告里**显式列出「实际用变体的天数」**。
  **绝不**退化成基线或静默回落（`index-mom-dir` 的同类坑）。
- 财报是低频数据 → 同一期公告在连续多日复用是**正确**的（不是重复计数）；报告需给出
  「每期公告被使用了多少个交易日」的分布，便于判断样本独立性。

## 3. 判据（提前写死）

| 判据 | 阈值（validate 段） | 结论 |
|---|---|---|
| **主判据** | 方向准确率 Δ 的 95% CI（按日聚类 bootstrap）**下界 > 0** 且点估计 > 0 | 达标 |
| **副判据** | Brier Δ 的 95% CI 上界 < 0（校准不劣化） | 达标 |
| **样本量** | validate 段有效交易日 ≥ 120 | 否则标注「样本不足，仅供观察」，不得据此改策略 |
| **覆盖** | 变体实际生效天数 / 应生效天数 ≥ 0.50 | 否则结果**不可归因**（等于测了另一种东西） |

- **决策规则**：主判据 + 副判据 + 样本量 + 覆盖**全过** → 记 `WIN`，允许**打开 test 段跑一次**
  （只跑一次）；否则记 `LOSE` / `falsified`，**test 段封存不开**，`WIN` 也照样只跑一次。
- **不做**：参数搜索（`±1` 阈值、`0.70/0.30` 分位、`0.01` 变化阈值、因子子集选择**全部写死**在本文件）。
  单因子拆分（把合成分拆成 6 个单因子各跑）**属于第二个实验**，须单独预注册 —— 否则就是多重比较。

## 4. 已知局限（提前写明，避免结果被过度解读）

1. **横截面只有 17 只**（4 只 ETF 无财报）→ 分位是粗粒度排序，n 小、检验力弱；金融股
   （招行/工行/平安）无 `operate_cost`/`inventory` → 可用因子天然少于 3 个时会被剔除，
   **中期池的「金融股命运」问题与本实验同源**。
2. **`sector` 非 PIT**（东财当前行业归属）；本实验不用 `sector`，故不受影响。
3. **多重比较**：此前 9 次否证全在**时序轴**（漂移方向 / 指数动量 / σ 条件化 / 区间形状 / 趋势状态），
   本实验是本项目**第一条横截面轴**（V1）；V2 与 `rw-mu0` 同轴但独立变量（自身 ROE 同比）。
   结论上报时必须写明「这是第 10/11 次预注册检验」，且**不许**用「累积跑了很多次总会有信号」当借口。
4. **本实验回答的是「财报有没有方向信息」，不是「能不能跑赢大盘」** ——
   后者需要**横截面选股组合**（top-N 等权、月度调仓、扣成本、对照 `index_300` + `buy_and_hold`），
   而当前回测引擎是**单标的沿时间轴**的形状，做不了横截面组合 → 属于**另一个任务**（P42，待本实验有信号再谈）。

## 6. 结论

> 本节由实现方（Claude Code，P40）在各跑**一次**之后追加。上面第 1–5 节一行未改。
> 判据、阈值、区间口径全部照 §1–§3 执行，**没有参数搜索、没有单因子拆分、没有重跑**。

**两个变体各自独立判定，均 `LOSE`（`falsified`）→ test 封存段一次都未打开。**

| 判据（validate，n=532 日 / 门槛 120） | V1 `fin-quality-pct` | V2 `fin-roe-yoy` |
|---|---|---|
| 主判据 `Δdirection`（CI 下界 > 0 且点估计 > 0） | ❌ **−0.0004**，CI [−0.0167, +0.0159]（点估计 ≤ 0，符号错） | ❌ **−0.0035**，CI [−0.0192, +0.0123]（点估计 ≤ 0，符号错） |
| 副判据 `Δbrier`（CI 上界 < 0） | ❌ −0.0030，CI [−0.0061, **+0.0001**]（跨 0） | ❌ −0.0028，CI [−0.0058, **+0.0003**]（跨 0） |
| 样本量 ≥ 120 交易日 | ✅ 532 | ✅ 532 |
| 覆盖 ≥ 0.50 | ✅ 26861/33261 = **80.8%** | ✅ 32770/33261 = **98.5%** |
| **gate** | `LOSE` | `LOSE` |

**撤规则生效（照 §6/§3 执行）**：两个 `mu_mode`（`fin_quality_pct` / `fin_roe_yoy`）**均不采纳**，
不得进入预测报告的任何默认路径；默认仍是 `mu_mode='sample_mean'`，`MODEL_VERSION` 仍为
`pit-rw-v1.0.2`（**未改**）。这是本项目的**第 10 / 11 次**预注册检验（§4.3 要求写明）。

**读数字时必须一起读的四条**：

1. **V1 是样本内/外背离的教科书案例**：`train` 段 Brier Δ = −0.0033，CI [−0.0055, −0.0011]
   **显著变好**；同一口径到 validate 就跨 0、方向点估计还翻了符号。**train 段那个数字不是证据**
   —— 它是本项目「样本内表现仅用于调试」这条纪律的现场样本。
2. **横截面质量分是「按季度的常数」**：实测 validate 窗口里，每只标的的「最新已公告期」
   平均被复用了 **47 个交易日**（中位；min 1 / max 124，共 153 次公告），一个季度内符号基本不动。
   所以 532 个「有效交易日」对**信号本身**而言远不是 532 个独立样本，独立观测量级 ≈ **9 个季度**
   → §3 的「样本量门槛」名义上过了，**检验力仍然很弱**（与 §4.1 一致）。
3. **金融股如 §4.1 预测被整段剔除**：600036 / 601318 / 601398 各被剔除 2127 个对子
   （银行/保险无 `operate_cost`/`inventory` → 可用因子 < 3）。这不是 bug，是预注册写明的
   「中期池的金融股命运」问题的现场复现。
4. **两个变体的 `Δbrier` 点估计都是负的（校准略改善）但 CI 跨 0，方向却明确是错的** ——
   按 §3「主判据 + 副判据全过才算 WIN」，主判据符号错即 `LOSE`，**不许拿 Brier 说事**。

**两处与预注册的偏离（如实登记，供 nanobot 复核）**：

- **§5 的复现命令逐字跑不起来**：CLI 的 `experiment run` 把 `--from` / `--to` 设为必填
  （`stocklab/cli/main.py:2827-2830`），逐字执行 → `argparse` 报错、退出码 2（实测，见 §7）。
  本次沿用**同构先例 P29 V1 的区间** `2013-04-16 → 2026-09-14`（该文件明确写「与既有基线报告同区间」），
  标的池用 CLI 默认（17 只 active stock，ETF 无财报自然排除）。**区间是跑前未在 §5 写死的口径**，
  这是本预注册的一处缺口。
- **§2 的「`report_date < notice_date <= report_date + 120 天`」这道额外过滤未在代码里实现**：
  任务书 T1 明确写「只此一句 PIT 边界」（即 `notice_date <= asof`），且实测库里 **41 行**
  法定回退公告日恰为 `report_date + 121 天`（年报 4/30，闰年），照字面实现会把**合法行**误剔。
  故代码只保留单一 PIT 边界；此偏离是**有意的**，记录在此。
